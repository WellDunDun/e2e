テストは 3 種類のステップを組み合わせます。

| ステップ | API | モデル呼び出し |
| --- | --- | --- |
| [ゴール](#goals) | `agent.act` | あり。ただし[キャッシュ](/cache)がリプレイする場合は除きます |
| [アサーション](#assertions) | `agent.assert`、`agent.waitFor`、`agent.extract` | あり |
| [ロケーター](#locators) | `screen` と `expect` | なし |

[カスタムエグゼキューター](/executors)を使うと、`act` と `assert` にモデルは不要です。

```ts title="tests/todos.e2e.ts"
import { describe, test, expect } from 'e2e';

describe('todos', () => {
  test('the Done filter shows only completed todos', async ({ app, agent, screen }) => {
    await app.open('/todos');
    await agent.act('add todos "Buy milk" and "Walk the dog"');
    await agent.act('complete "Buy milk"');
    await agent.waitFor('"Buy milk" is completed and "Walk the dog" is open');

    await screen.getByRole('tab', 'Done').tap();

    await expect(screen.getByTestId('todo')).toHaveCount(1);
    await agent.assert('the only todo listed is "Buy milk"');
  });
});
```

各テストは 1 つの振る舞いを 3 つのブロックで確認します。開始状態を準備し、
振る舞いを実行し、結果をアサートします。

エージェントの呼び出し、screen の呼び出し、`expect.poll` はそれぞれ await してください。ステップの実行中にテストが戻ると、
テストは `STEP_NOT_AWAITED` で失敗します。

## ゴール

`agent.act` は 1 つのゴールを受け取り、必要な操作を行います。ゴールが完了すると戻り、
ゴールが失敗すると例外を投げます。

```ts
await agent.act('complete checkout with the test card');
await agent.act('invite {email} as an editor', { params: { email: 'ada@example.test' } });
```

各ゴールはアトミックに保ちます。つまり、1 つのチェックで確認できる 1 つの結果にします。指示の 2 つの部分がそれぞれ
確認する価値のある状態を残すなら、それは 2 つのゴールです。
1 つのテストに多くのゴールがあってもかまいません。

```ts title="Bad: three goals in one call, no check between them"
await agent.act('open the Pro plan, set the seats to {seats}, and check out', {
  params: { seats: 3 },
});
```

```ts title="Good: one atomic goal per call, arrange, act, assert"
test('checks out the Pro plan', async ({ app, agent, screen }) => {
  await app.open('/plans');
  await agent.act('open the Pro plan');
  await agent.act('set the seats to {seats}', { params: { seats: 3 } });
  await agent.waitFor('the cart shows the Pro plan with 3 seats');

  await agent.act('check out');

  await expect(screen.getByText('Order confirmed')).toBeVisible();
});
```

準備のためのゴールが最初に来て、それらが到達する状態を待つ処理で終わります。
次にテスト対象のゴールが来ます。その結果に対するアサーションが最後に来ます。
こうすると、失敗時にどのゴールが壊れたかがわかります。各ゴールはそれぞれの記録からリプレイされ、
それぞれにモデル呼び出しと操作の[予算](/reference/agent#budgets)が割り当てられます。1 つの結果に向けた操作はゴールではありません。
たとえば、コントロールがある画面やメニューを開く、そこまでスクロールする、
バナーを閉じる、1 つのフォームのフィールドを入力する、といった操作です。

- ゴールの順序はあなたが決めます。操作はエージェントが選びます。
- テストは結果に対する `expect` で終えます。[リプレイキャッシュ](/cache)は、
  後続のチェックや待機が成功した後にのみゴールを記録します。
- 画面に表示されている言葉を使います。
- テストデータは `params` で渡します。パスワードには `Secret` を渡します。モデルが
  その値をテキストとして受け取ることはありません。[認証](/authentication)を参照してください。
- 実行ごとに変わる値には `unique()` を使い、
  [キャッシュがステップをリプレイできる](/cache#what-must-match)ようにします。

```ts
import { unique } from 'e2e';

const email = `ada+${Date.now()}@example.test`;
await agent.act('sign up with email {email}', { params: { email: unique(email) } });
```

`act` は必要なときにスクリーンショットを取得します。一部のエンジンでは、
画像内の座標をタップしたり、そこに入力したりできます。

ゴールが失敗した場合は、レポートを読み、指示をより具体的にします。
多くのゴールで使う言葉は、エージェントの [`context`](/agents) に入れます。

## アサーション

アサーションは画面を判定します。モデルが見るのは、ステートメント、現在の画面の秘匿化された
テキストスナップショット、その位置、エージェントのコンテキストです。
それより前のステップや `act` の要約は見ません。

- `agent.assert` は現在の画面を調べます。ステートメントが偽の場合は
  `ASSERTION_FAILED` で失敗します。根拠が不十分な場合は
  `ASSERTION_INCONCLUSIVE` で失敗します。
- `agent.waitFor` は条件が真になるまで待ちます。モデルを呼び出すのは、
  画面またはその位置が変わったときだけです。
- `agent.extract` は画面からデータを読み取り、
  Zod などの [Standard Schema](https://standardschema.dev) の型に変換します。

```ts
import { expect } from 'e2e';
import { z } from 'zod';

await agent.assert('the dashboard shows a trial badge');
await agent.waitFor('a download link appears', { timeout: 120_000 });
await agent.assert('the chart trends upward', { vision: true });

const data = await agent.extract('every todo title', {
  schema: z.object({ titles: z.array(z.string()) }),
});
expect(data.titles).toContain('Buy milk');
```

モデルが書いたテキストについては、文全体ではなく意味を確認します。
正確なテキストが重要な場合は、[ロケーター](#locators)を使います。

グラフやレイアウトなどの視覚的なチェックには、`vision: true` を追加します。
スクリーンショットだけで判定するには、`vision: 'only'` を使います。画像は入力トークンを増やします。
[エージェントのリファレンス](/reference/agent#vision)を参照してください。

## ロケーター

ロケーターは、既知のコントロールをモデル呼び出しなしで見つけます。
正確な操作や正確な値がわかっているときに使います。

```ts
// Role and name first, label second, test ID last.
await screen.getByRole('button', 'Sign in').tap();
await screen.getByLabel('Email').fill('ada@example.test');

// Scope into a row.
const row = screen.getByRole('listitem').filter({ hasText: 'Design review' });
await row.getByRole('button', 'Archive').tap();

// Gestures and coordinates.
await screen.swipe({ direction: 'up' });
await screen.getByRole('image', 'Seat map').tap({ position: { x: 120, y: 48 } });

// Assertions retry until they pass or time out.
await expect(screen.getByRole('status')).toHaveText('2 remaining');
```

- 操作、読み取り、単一ノードのアサーションは、クエリが複数のノードを見つけると失敗します。
  1 つのノードに絞るには `.filter()`、`.first()`、`.nth()` を使います。
- `textContent()` などの直接の読み取りは、一致するノードを待ってから 1 回だけ読み取り、
  値を得るためのリトライはしません。

[screen のリファレンス](/reference/screen)と
[expect のリファレンス](/reference/expect#locator-matchers)を参照してください。ルート、Cookie、
ダイアログ、ダウンロードについては、[ブラウザを扱う](/browser)を参照してください。

## テストを整理する

```ts
import { beforeEach, describe, test } from 'e2e';

describe('billing', { tags: ['billing'] }, () => {
  beforeEach(async ({ app }) => { await app.open('/billing'); });

  test('upgrades', { retries: 2, timeout: 60_000 }, async ({ agent }) => {
    await agent.act('upgrade to Pro');
  });
});

test('needs two organizations', async ({ app }) => {
  test.skip((await countOrganizations()) < 2, 'nothing to switch to');
  await app.open('/organizations');
});
```

- 各テストはそれぞれの試行で実行されます。確認する画面の近くからテストを開始すると、
  毎回の実行でそこに至るまでのクリックを省けます。テストのデータはフィクスチャ
  またはフックで作成します。ブラウザでは、[保存したセッション](/authentication)を復元し、
  パスで画面を開きます。デバイスでは、
  [ディープリンク](/mobile#the-device-fixture)を開きます。
- `test.skip(condition, reason)` は、条件が真のときにテストを
  `skipped` として停止します。
- 多くのテストにまたがるフローでは、グループに `{ serial: true }` を設定します。
  テストは 1 つのワーカーで順番に実行され、まとめてリトライされます。
- 準備と後片付けには `test.extend` を使います。
  [フィクスチャを書く](/fixtures)を参照してください。
- `browser` または `device` フィクスチャに型を付けるには、`@e2e-dev/web` または `@e2e-dev/mobile` から
  `test` をインポートします。

すべてのオプションは[テストのリファレンス](/reference/test)に記載されています。

## 1 つのテストを実行する

<CodeGroup>
```bash npm
npx e2e run tests/signup.e2e.ts:12   # the test at line 12
npx e2e run --grep checkout          # tests with a matching title
npx e2e run --target web             # one target
```

```bash pnpm
pnpm exec e2e run tests/signup.e2e.ts:12   # the test at line 12
pnpm exec e2e run --grep checkout          # tests with a matching title
pnpm exec e2e run --target web             # one target
```

```bash bun
bunx e2e run tests/signup.e2e.ts:12   # the test at line 12
bunx e2e run --grep checkout          # tests with a matching title
bunx e2e run --target web             # one target
```
</CodeGroup>

すべてのフラグは [CLI のリファレンス](/reference/cli#e2e-run)に記載されています。
