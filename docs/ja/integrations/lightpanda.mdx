[Lightpanda](https://lightpanda.io) は、Chromium を使わずにゼロから書かれたオープンソースのヘッドレスブラウザです。
数ミリ秒で起動し、Chrome のごく一部のメモリしか使わず、Chrome DevTools Protocol を話します。
`@e2e-dev/lightpanda` の `lightpanda()` は、Lightpanda 向けの
[ブラウザプロバイダー](/browser#hosted-browsers)です。各ワーカースロットには
専用の `lightpanda serve` が割り当てられます。これは実行の開始時に空いているポートで起動し、
実行の終了時に停止します。テストと CI はそのままで、設定で変わるのは
ターゲットの `browser` だけです。

Lightpanda にはレイアウトエンジンがありません。DOM を構築し、JavaScript を実行し、
エンジンが読み取るアクセシビリティツリーを公開します。これがロケーター、
アサーション、[エージェントステップ](/agent-steps)の使うものです。ノードが描画される位置に依存するものは、
すべて異なる振る舞いになります。テストスイートを移行する前に、
[動作しないもの](#what-does-not-work)を確認してください。

## セットアップ

パッケージをインストールします。

<CodeGroup>
```bash npm
npm install --save-dev @e2e-dev/lightpanda
```

```bash pnpm
pnpm add -D @e2e-dev/lightpanda
```

```bash bun
bun add -d @e2e-dev/lightpanda
```
</CodeGroup>

さらに、プロバイダーが起動する Lightpanda の nightly バイナリもインストールします。

<CodeGroup>
```bash macOS
brew install lightpanda-io/browser/lightpanda
```

```bash Linux
curl -L -o lightpanda https://github.com/lightpanda-io/browser/releases/download/nightly/lightpanda-x86_64-linux
install -D -m 755 lightpanda ~/.local/bin/lightpanda
```
</CodeGroup>

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { lightpanda } from '@e2e-dev/lightpanda';

export default {
  targets: [
    {
      name: 'lightpanda',
      engine: web({ browser: lightpanda() }),
      app: { url: 'http://localhost:3000' },
    },
  ],
} satisfies E2EConfig;
```

プロバイダーは、`PATH`、`~/.lightpanda/lightpanda`、
`~/.local/bin/lightpanda`（いずれも
[agent-browser](https://agent-browser.dev/engines/lightpanda) も探す場所です）にある `lightpanda`、
`e2e run` を開始する環境の `LIGHTPANDA_PATH` が指すバイナリ、
またはオプションの `binary` を実行します。どれも見つからない場合は、テストの前に実行が失敗し、
インストールページが示されます。
各ワーカーが専用のサーバーを持つため、`workers` で同時に実行するサーバーの数が決まります。
実行のログにはそれぞれのサーバーが示されます。

```text
ℹ lightpanda (1 of 2): lightpanda 1.1.0-nightly at ws://127.0.0.1:51165/
```

## 実行中のサーバーに接続する

CI の Docker イメージのように、すでに実行中の Lightpanda は、プロバイダーではなく
[`connect`](/reference/web#options) のターゲットになります。
エンジンはその CDP エンドポイントに接続し、サーバーは実行したままにします。

```ts title="e2e.config.ts"
web({ connect: { cdpEndpoint: () => process.env.LIGHTPANDA_URL ?? 'ws://127.0.0.1:9222/' } })
```

```bash
docker run -d --name lightpanda -p 127.0.0.1:9222:9222 lightpanda/browser:nightly
```

この場合、すべてのワーカーがそのサーバーを共有します。1 つの `lightpanda serve` はデフォルトで 16 の
接続を受け付けます。それより多く実行する場合は、`--cdp-max-connections` を `workers` より大きくしてください。

## オプション

| オプション      | デフォルト                      | 意味 |
| --------------- | ------------------------------- | ------- |
| `binary`        | `LIGHTPANDA_PATH`、なければ検出したもの | 起動するバイナリ。パス、または `PATH` 上の名前です。 |
| `loadResources` | `[]`                            | サーバーが取得するサブリソース: `iframe`、`image`、`stylesheet`。[ページをより多く取得する](#fetch-more-of-the-page)を参照してください。 |
| `args`          | `[]`                            | プロバイダーが設定するフラグの後に追加する、`lightpanda serve` のフラグ。 |

プロバイダーは、実行の間、ワーカースロットごとに 1 つのサーバーをリースします。
`scope: 'attempt'` はありません。試行ごとのリースが再接続に使うデフォルトコンテキストの識別情報を、
Lightpanda が公開していないためです。10 秒以内にポートで応答しないサーバーはリースを失敗させます。
先に終了してしまうバイナリも同様で、その stderr がメッセージに含まれます。

## ページをより多く取得する

`lightpanda serve` はデフォルトでサブリソースを要求しません。画像も、
外部スタイルシートも、iframe も取得しません。`loadResources` を使うと、それぞれを有効にできます。
これはサーバーの `--load-resources` に相当します。

```ts
web({ browser: lightpanda({ loadResources: ['stylesheet', 'iframe'] }) })
```

インラインスタイル、`<style>` ブロック、`hidden` 属性は、もともと表示状態の判定に使われます。
`stylesheet` を指定すると外部ファイルのルールも考慮されるため、
リンクされたスタイルシートが非表示にするノードはクエリからも非表示になります。`image` は画像の
ヘッダーを取得するため、`load` と `error` が実際の状態を反映します。

## 動作するもの

2026 年 10 月中旬の Lightpanda nightly で e2e のテストベッドのローカルスイートを実行したところ、
次のものは変更なしで成功しました。

- `app.open`、`app.back`、`expect(browser).toHaveURL` と `toHaveTitle`。
- すべての `screen` クエリ（`getByRole`、`getByLabel`、`getByText`、
  `getByTestId`、フィルター、`nth`）と、それらに対する操作: `tap`、`fill`、
  `check`、`select`、`press`、キーボード入力。
- テキスト、値、件数、状態に対するポーリングアサーション。
- `browser.route` のモックとリクエストの待機。
- ページを開いた後に、テストから行う `browser.setCookies`。
- `app.screenshot` と、失敗時のスクリーンショット。Lightpanda が描画するのは DOM の
  簡素なレンダリングで、Chrome で表示されるようなページではありません。
- エージェントステップ: `agent.act`、`agent.assert`、`agent.extract`、
  `agent.waitFor` は画面のツリーを読み取り、Lightpanda はそれを完全に提供します。
  テストベッドのエージェントスイートでは、ツリーに基づくフロー（todo、ウィザード、
  サインイン、ホバー、コンテキストメニュー、長押し、アップロード）が成功します。失敗するのは、
  canvas に描画されるもの、ドラッグするもの、スクロールしないと見えない位置にあるものです。
  ピクセルに基づく判定は簡素なレンダリングを見ることになるため、エージェントにはツリーを使わせてください。

ユーザーに何が見えるかをアサートし、それがどこに描画されるかはアサートしないテストは、
そのまま移行できます。

## 動作しないもの

次のいずれも、ハングではなく、エンジンの通常のエラーでテストを失敗させます。
原因は Lightpanda 側にあり、そのほとんどは Lightpanda の
[Playwright 互換性の issue](https://github.com/lightpanda-io/browser/issues/3076)
で追跡されています。

| 機能 | 何が起こるか | 理由 |
| ------- | ------------ | --- |
| [セッション](/authentication)（`session.save` を使う `test.setup`、テストの `session:`） | セットアップは成功してセッションも保存されますが、それを復元したテストはサインアウトした状態で開きます。 | 最初のページが存在する前にコンテキストに設定された Cookie は破棄されます。代わりに、`app.open` の後にテストから `browser.setCookies` で設定してください。 |
| [ダイアログ](/browser#handle-a-dialog) | `browser.onDialog` は実行されますが、その後 `ENGINE_FAILURE` でテストが失敗します。`Page.handleJavaScriptDialog` がダイアログがないと報告するためです。 | Lightpanda は、クライアントが応答する前に `alert`、`confirm`（`false`）、`prompt`（`null`）に自分で応答します。 |
| [ダウンロード](/browser#download-a-file) | `browser.waitForDownload` がタイムアウトします。 | CDP でダウンロードイベントが送られません。 |
| [iframe](/browser#reach-into-an-iframe) | `frameLocator` が何も見つけません。 | iframe はデフォルトで読み込まれません。`loadResources: ['iframe']` で読み込むと、クエリと入力は動作しますが、フレームが作成した要素に対するホストページ側のリスナーは発火しません。 |
| ドラッグ: `screen.swipe`、`locator.swipeTo`、ボタンを押したままの `browser.mouse` の移動 | `Input.setInterceptDrags` を示す `ENGINE_FAILURE`。 | Playwright はドラッグにこのコマンドを必要としますが、Lightpanda はまだ実装していません。 |
| `browser.setViewport` | ページは新しいサイズを測定しますが、`resize` リスナーは実行されません。 | `resize` イベントがディスパッチされません。 |
| [メディアエミュレーション](/reference/web#media-emulation): `colorScheme`、`reducedMotion`、`browser.emulateMedia` | ページは `light` とフルモーションを報告し続けます。 | `Emulation.setEmulatedMedia` を使っても、`matchMedia` の応答は変わりません。 |
| スクロール: `scrollIntoView`、`scrollUntilVisible`、「ビューポートの外側」にあるノードに対する操作 | スクロールは何もせず、操作可能になるのを待つ処理がタイムアウトすることがあります。 | レイアウトがないため、動かすべきスクロール位置がありません。簡素なレンダリングではすべてのブロックが 1 列に積み重なるため、Chrome よりもページの多くの部分が画面外の下側に置かれ、そこにあるものには何も到達できません。 |
| `<canvas>` の内容: 2D コンテキストで描画された PIN、キーパッド、グラフ | スクリーンショットには何も描画されず、canvas は領域を占めません。エージェントのピクセル層（`tap_at`、`type_at`、ビジョンによる判定）には見るものがありません。 | `getContext('2d')` は、描画処理が描くものを何も記録しないコンテキストを返します。 |

Lightpanda のリリースでこれらのいずれかが解消されれば、e2e 側の変更なしで上の該当行はなくなります。
エンジンは Chrome に送るのと同じ CDP コマンドを送るためです。

## 適した用途

Lightpanda は、エージェントによる画面の読み取りが多く、ジオメトリへの依存が少ないテストスイートに向いています。
たとえば、スモークテストのフロー、フォーム、ナビゲーション、API をバックエンドとするページ、
テキストと状態で確認する `agent.act` ステップです。そのようなテストスイートを、Chrome のごく一部の時間とメモリで、
Chrome がインストールされていないマシン上で実行できます。

それ以外のテストには Chromium のターゲットを残し、両方が 1 つの設定にある場合はターゲットで選択します。

```bash
e2e run --target lightpanda
e2e run --target chromium
```
