`@e2e-dev/limrun` は、モバイルエンジン用のホスト型デバイスプロバイダーです。
ワーカーごとにデバイスを作成してアプリをインストールし、実行の終了時にデバイスを解放します。
標準の `app`、`screen`、`expect` API を使って、アプリのユーザーフローをテストします。

## インストールと認証

モバイルエンジンとそのピア依存パッケージと一緒にインテグレーションをインストールします。

<CodeGroup>
```bash npm
npm install --save-dev e2e @e2e-dev/mobile @e2e-dev/limrun @limrun/api
```

```bash pnpm
pnpm add -D e2e @e2e-dev/mobile @e2e-dev/limrun @limrun/api
```

```bash bun
bun add -d e2e @e2e-dev/mobile @e2e-dev/limrun @limrun/api
```
</CodeGroup>

e2e を起動する環境に `LIMRUN_API_KEY` を設定します。CI ではシークレットとして保存してください。
インスタンスを作成・制御する権限を持つキーを使います。
プロバイダーは実行の環境変数を読み取ります。`lim login` のセッションや `LIM_API_KEY` は読み取りません。

テストランナーには Node.js とパッケージの依存関係が必要です。Android の場合は、
[Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools) の
`adb` を `PATH` に置いてください。ローカルのエミュレーターは不要です。iOS のランナーには、
ローカルの Xcode やシミュレーターは不要です。アプリは、iOS シミュレーター向け、または
Android の APK として別途ビルドしてください。

## ターゲットを設定する

モバイルエンジンに `device: limrun()` を設定し、`appPath` でビルドを指定します。
この設定は、Limrun の
[app-flow のサンプル](https://github.com/limrun-inc/testerarmy-e2e-limrun) にある SwiftUI アプリを実行します。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';
import { limrun } from '@e2e-dev/limrun';

export default {
  targets: [{
    name: 'ios',
    engine: mobile({ platform: 'ios', device: limrun() }),
    app: {
      bundleId: 'dev.e2e.examples.swiftui',
      appPath: 'build/HelloApp.app',
    },
  }],
  workers: 2,
} satisfies E2EConfig;
```

Android の場合は、`platform: 'android'` を使い、`bundleId` にアプリのパッケージ名を、
`appPath` に APK を指定します。パスはプロジェクトのルートを基準に解決されます。
プロバイダーは、テストの開始前にビルドをインストールします。

## アプリのフローをテストする

安定したテスト ID と表示テキストを使って、フォームに入力し、その結果を確認します。
このテストは、空の送信を修正し、挨拶のスクリーンショットを保存します。

```ts title="tests/greeting.e2e.ts"
import { expect } from 'e2e';
import { test } from '@e2e-dev/mobile';

test('corrects an empty submission', async ({ app, screen }) => {
  await app.open();
  await screen.getByTestId('greet').click();
  await expect(screen.getByText('Enter a name first.', { exact: true })).toBeVisible();

  await screen.getByTestId('name').fill('Ada');
  await screen.getByTestId('greet').click();
  await expect(screen.getByText('Hello, Ada!', { exact: true })).toBeVisible();
  await expect(screen.getByText('Enter a name first.', { exact: true })).not.toBeVisible();
  await app.screenshot('greeting');
});
```

Limrun は、SwiftUI と Compose のアプリで同じ 5 つのテストを使う
[実行可能なサンプル](https://github.com/limrun-inc/testerarmy-e2e-limrun) を管理しています。
初期のフォーム、バリデーションからの回復、トリムされた入力、繰り返しの送信、アプリの再起動をカバーしています。
Limrun が両方のアプリをリモートでビルドし、設定には両方のターゲットが含まれています。AI のキーは不要です。

## 実行を録画する

すべての試行を録画するには `--video` を追加します。

<CodeGroup>
```bash npm
npx e2e run --video
```
```bash pnpm
pnpm exec e2e run --video
```
```bash bun
bunx e2e run --video
```
</CodeGroup>

動画とスクリーンショットは、実行レポートと並んで `.e2e/` の下に置かれます。

## デバイスのオプションを選ぶ

| オプション | デフォルト | 目的 |
| --- | --- | --- |
| `region` | Limrun が選択 | `eu` や `us-east1` などのリージョンの希望。容量によっては別のリージョンに割り当てられることがあります。 |
| `hardTimeout` | `1h` | 放棄された実行も含めた、デバイスの最大存続時間。`30m` や `2h` などの Go の duration 形式で指定します。 |
| `ios.model` | Limrun が選択 | `iphone` または `ipad`。 |
| `android.model` | Limrun が選択 | `phone` または `tablet`。 |
| `android.osVersion` | `15` | スケジューリングの手がかりとして要求する Android のメジャーバージョン。 |

各ワーカーは、テストランナー上の独立した agent-device デーモンと、1 つの Limrun インスタンスを受け取ります。
デーモンは、アプリの制御と録画に agent-device の Limrun ドライバーを使います。
インテグレーションはモバイルエンジンと同じ agent-device のバージョンを固定しており、
割り当ての前にそれを確認します。

デバイスは 5 分以内に準備を完了し、インストールを終える必要があります。
プロバイダーはセットアップの失敗後にクリーンアップを行い、エンジンは実行が終了または中断されたときに
取得したすべてのデバイスを解放します。他のターゲットの実行中は、プロバイダーがアイドル状態のドライバーの
リースを更新します。デーモンはコマンドの間もアクティブなデバイスを維持します。ランナーが消えた場合は、
ハードタイムアウトが上限になります。実行時間より長いタイムアウトを選んでください。

インスタンス ID は進捗の出力に表示されます。実行のインスタンスは、Limrun の `source=e2e` と
`run=<run id>` のラベルで探せます。録画は通常のモバイルのアーティファクトパスを使い、
各試行のディレクトリ内の `video/video.mp4` に保存されます。

## アプリの互換性を確認する

Limrun の iOS トランスポートは、`locator.press('Enter')` などのキーボード操作を `UNSUPPORTED_CAPABILITY` で拒否します。
フローに送信ボタンがある場合は、そのボタンをタップしてください。

アプリが使うロケーターとライブラリを、そのターゲットのランタイムでテストしてください。
挨拶のサンプルはネイティブのフォームフローを示すもので、すべてのモバイルフレームワークやコントロールとの互換性を保証するものではありません。
