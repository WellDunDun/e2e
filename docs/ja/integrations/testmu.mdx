`@e2e-dev/testmu` は、ターゲットを
[TestMu AI](https://www.lambdatest.com)（旧 LambdaTest）上で実行します。`testmu()` は
Android エミュレーター、iOS シミュレーター、実機向けの
[デバイスプロバイダー](/mobile#hosted-devices) です。`@e2e-dev/testmu/web` の
`testmuBrowsers()` は、ホスト型の Chrome と Edge 向けの
[ブラウザプロバイダー](/browser#hosted-browsers) です。テストはそのままです。

## 認証する

`e2e run` が起動する環境（CI のシークレットなど）に `LT_USERNAME` と `LT_ACCESS_KEY` を
設定します。これらは **Account Settings → Password &
Security → Username and Access Key**
（[accounts.lambdatest.com/security/username-accesskey](https://accounts.lambdatest.com/security/username-accesskey)）
からコピーしてください。どちらかがないと、テストが始まる前にリースが失敗します。
`testmuBrowsers()` はこれらを各セッションの CDP URL でのみ送信し、ログ行には決して出しません。

## モバイルターゲットをデバイスで実行する

各ワーカースロットは、実行の開始時にデバイスを 1 台リースし、実行の終了時に解放します。

<Tip>
ホスト型デバイスで e2e を実行するのに、Mac、Xcode、Android SDK は必要ありません。
</Tip>

モバイルエンジンと一緒にインテグレーションをインストールします。

<CodeGroup>
```bash npm
npm install --save-dev e2e @e2e-dev/mobile @e2e-dev/testmu
```

```bash pnpm
pnpm add -D e2e @e2e-dev/mobile @e2e-dev/testmu
```

```bash bun
bun add -d e2e @e2e-dev/mobile @e2e-dev/testmu
```
</CodeGroup>

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';
import { testmu } from '@e2e-dev/testmu';

const apk = 'https://prod-mobile-artefacts.lambdatest.com/assets/docs/proverbial_android.apk';
const ipa = 'https://prod-mobile-artefacts.lambdatest.com/assets/docs/proverbial_ios.ipa';

export default {
  targets: [
    {
      name: 'android-emulator',
      engine: mobile({
        platform: 'android',
        device: testmu({ device: 'Galaxy S22 Ultra 5G', osVersion: '14', app: apk }),
      }),
      app: { bundleId: 'com.lambdatest.proverbial' },
    },
    {
      name: 'ios-real',
      engine: mobile({
        platform: 'ios',
        device: testmu({ device: 'iPhone 16', osVersion: '18', app: ipa, deviceType: 'real' }),
      }),
      app: { bundleId: 'proverbial' },
    },
    {
      name: 'android-real',
      engine: mobile({
        platform: 'android',
        device: testmu({ device: 'Pixel 6', osVersion: '14', app: apk, deviceType: 'real' }),
      }),
      app: { bundleId: 'com.lambdatest.proverbial' },
    },
  ],
  workers: 1,
} satisfies E2EConfig;
```

`device` と `osVersion` は、[capabilities generator](https://www.lambdatest.com/capabilities-generator)
に記載されているとおり、TestMu AI のカタログと完全に一致する必要があります。仮想 iOS デバイスは
`18.0`、実機は `18`、Android は `14` です。実機と仮想デバイスのカタログは別々です。

`app` は、TestMu AI がすべてのセッションでインストールするビルドです。`lt://` のアプリ id、
`https` の URL、またはローカルパスを指定します。ローカルパスは `e2e.config.ts` のディレクトリを
基準に解決され、アップロードされます。Android では `.apk` または `.aab`、iOS シミュレーターでは
zip 圧縮した `.app`、iOS 実機では署名済みの `.ipa` を使います。ターゲットの `app.appPath` は
省略し、`app.open()` のために `app.bundleId` は残してください。

<Accordion title="テストの例">

```ts title="tests/home.e2e.ts"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('Proverbial home screen', async ({ app, screen }) => {
  await app.open();
  await expect(screen.getByText('Proverbial')).toBeVisible();
  // Android labels the button GEOLOCATION, iOS GeoLocation.
  await expect(screen.getByRole('button', /^geolocation$/i)).toBeVisible();
});
```
</Accordion>

## Web ターゲットをブラウザで実行する

各ワーカースロットは、実行のために専用の Chrome または Edge のセッションを取得します。
ローカルでの実行と同じく、各試行はそのセッション内で新しいブラウザコンテキストを取得するため、
テストが別のテストの Cookie、ストレージ、権限を目にすることはありません。

Web エンジンと一緒にインテグレーションをインストールします。

<CodeGroup>
```bash npm
npm install --save-dev e2e @e2e-dev/web @e2e-dev/testmu
```

```bash pnpm
pnpm add -D e2e @e2e-dev/web @e2e-dev/testmu
```

```bash bun
bun add -d e2e @e2e-dev/web @e2e-dev/testmu
```
</CodeGroup>

ターゲットの `browser` を `testmuBrowsers()` に設定します。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { testmuBrowsers } from '@e2e-dev/testmu/web';

export default {
  targets: [
    {
      name: 'testmu-web',
      engine: web({ browser: testmuBrowsers(), viewport: null }),
      app: { url: 'https://staging.example.com' },
    },
  ],
} satisfies E2EConfig;
```

## デバイスのオプション

| オプション    | デフォルト      | 意味 |
| ------------- | --------------- | ------- |
| `device`      | 必須            | TestMu AI のカタログに記載されているデバイス名（`'Galaxy S22 Ultra 5G'`、`'iPhone 16'`）。 |
| `osVersion`   | 必須            | そのデバイスについてカタログに記載されている OS バージョン。 |
| `app`         | 必須            | TestMu AI がインストールするビルド。`lt://` のアプリ id、`https` の URL、またはローカルパス。 |
| `deviceType`  | `'virtual'`     | エミュレーターまたはシミュレーターには `'virtual'`、実機には `'real'`。 |
| `project`     | `'e2e'`         | セッションをまとめるダッシュボードのプロジェクト。 |
| `build`       | 実行 id         | セッションをまとめるダッシュボードのビルド。 |
| `sessionName` | `e2e-<run id>-<target>-<slot>` | ダッシュボード上のセッション名。ワーカースロットが複数ある場合は `-<slot>` が付加されます。 |
| `orientation` | デバイスの設定  | `'portrait'` または `'landscape'`。 |
| `geoLocation` | TestMu AI の設定 | デバイスの IP の位置情報となる国コード（`'US'`）。 |
| `timezone`    | デバイスの設定  | タイムゾーン（`'UTC+05:30'`）。 |
| `language`    | デバイスの設定  | 言語コード（`'fr'`）。 |
| `locale`      | デバイスの設定  | ロケール（`'fr_FR'`）。 |
| `appiumVersion` | TestMu AI の設定 | セッションの Appium バージョン（`'2.16.2'`）。 |

デバイスの機能はセッションの開始時に設定され、セッション全体を通じて保持されます。
不明なオプションや無効な値は、設定の読み込みを `INVALID_CONFIG` で失敗させます。

## ブラウザのオプション

| オプション | デフォルト | 意味 |
| ------ | ------- | ------- |
| `browserName` | `'Chrome'` | `'Chrome'` または `'MicrosoftEdge'`。Web エンジンは CDP で接続するため、それ以外のブラウザは設定を失敗させます。 |
| `capabilities` | なし | `browserName` と一緒に送られる `browserVersion`、および `platform`、`geoLocation`、`timezone`、`video`、`network`、[TestMu AI Tunnel](https://www.lambdatest.com/support/docs/testing-locally-hosted-pages/) 用の `tunnel` と `tunnelName` などの TestMu AI の `LT:Options` フィールド。 |

プロバイダーは、`capabilities` で設定されていない限り、`platform`（TestMu AI は
これのないセッションを拒否するため `Windows 11`）、`build`（実行 id）、`project`（`e2e`）、
`idleTimeout`（600 秒）を送信します。Edge のセッションには、`capabilities` で設定されていない限り、
`browserOptions` に `--user-data-dir=remote-debug-profile-edge` が付きます。
`user`、`accessKey`、`name` はプロバイダー自身が設定するため、これらのいずれかを設定する
`capabilities` は設定を `INVALID_CONFIG` で失敗させます。ネストした `LT:Options`、
`browserName`（オプションを使ってください）、JSON で表現できない値、綴りを間違えた
`testmuBrowsers()` のオプションも同様です。それ以外の `capabilities` のキーは、確認されずに
TestMu AI に送られます。

```ts
testmuBrowsers({
  browserName: 'MicrosoftEdge',
  capabilities: { browserVersion: '140', platform: 'Windows 10', build: `checkout ${process.env.GITHUB_SHA}`, video: true },
})
```

## セッションと動画を見つける

デフォルトでは、ダッシュボードは各セッションに `e2e-<run id>-<target>-<slot>` という名前を付けます。

[動画](/reference/config#video) を記録する試行には、次のものが付きます。

- **デバイスの場合**、`build` と `sessionName` で見つけた、TestMu AI によるセッションの
  録画へのリンク。録画はセッション全体を対象とするため、1 つのワーカースロット上のすべての
  試行は同じ動画にリンクします。重なって実行され、固定の `build` と `sessionName` を共有する
  実行どうしは、互いの動画にリンクすることがあります。デフォルトではそうなりません。
- **ブラウザの場合**、ローカルでの実行と同じく、Web エンジンによるページのスクリーンキャスト。
  `capabilities: { video: true }` を渡すと、TestMu AI がセッションの画面を録画します。
  TestMu AI のダッシュボードで視聴してください。

## 制限

- **並列セッション。** `workers` と TestMu AI のターゲット数の積を、プランの並列セッション数の
  範囲内に収めてください。プランを超えたブラウザセッションは TestMu AI のキューで待機します。
- **デバイスのセッションはリース中に課金されます。** デバイスのセッションは、そのスロットが
  リースされたときに開始し、それには約 30〜75 秒かかります。テストが実行されていなくても、
  実行がそれを解放するまで課金されます。
- **デバイス上でランナーが停止した場合。** ランナーがデバイスを解放する前に強制終了されると、
  セッションに次のコマンドを送るものはなくなります。TestMu AI の
  [アイドルタイムアウト](https://www.lambdatest.com/support/docs/desired-capabilities-in-appium/)
  （デフォルトで 120 秒）が、最後のコマンドから約 3 分後にセッションを終了します。
- **確認できない解放は実行を失敗させます。** agent-device がデバイスのセッションの終了を
  確認できない場合、すべてのテストが成功していても、解放は実行を失敗させます。デーモンの
  強制停止、シャットダウン報告の消失、実行中に終了したデーモンなどが原因です。ダッシュボードで
  `build` と `sessionName` からセッションを見つけてください。
- **デバイスの設定とログ。** デバイスの設定（権限、位置情報、ネットワーク、外観）、
  システムアラート、agent-device による録画とデバイスログ、ポートのリバースは利用できません。
  ログは TestMu AI のダッシュボードで確認し、自分のネットワーク上のサーバーにアクセスするには
  TestMu AI Tunnel を使ってください。
- **ブラウザ接続は 60 秒。** Web エンジンは、ブラウザセッションが CDP 接続を受け付けるまで
  最大 60 秒待ちます。`launchTimeout` を短くすると待機は早く終わりますが、長くしても延長されません。
  その時点でまだキューに入っているかプロビジョニング中のセッションは、`LAUNCH_TIMEOUT` で、
  または `launchTimeout` が 60 秒を超える場合は `ENGINE_FAILURE` で失敗します。
- **切断されたブラウザ接続。** ブラウザセッションは再開できないため、接続が切れると
  その試行は失敗します。
- **ブラウザのダウンロード。** TestMu AI のブラウザはダウンロードを自身のマシンに保存するため、
  `browser.waitForDownload` は `ENGINE_FAILURE` で失敗します。代わりに、ダウンロードリンクや
  リクエストに対してアサーションを行ってください。
