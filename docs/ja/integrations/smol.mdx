`@e2e-dev/smol` の `smol()` は、あなたのコンピューター上の
[smol machines](https://smolmachines.com) の microVM で Chromium を実行する
[ブラウザプロバイダー](/browser#hosted-browsers) です。各ワーカースロットは
1 台のブラウザマシンを起動します。デフォルトでは、各テストの試行はそのマシンの
コピーオンライトのブランチで実行されます。ブランチは約 1 秒で準備でき、
すべてのリトライが同じブラウザ状態から開始します。アプリのデータがリセットされるのは、
アプリが [マシン内で動作する](#run-the-app-in-the-machine) 場合だけです。
あなたのコンピューター上や外部サービスの状態は共有されたままです。

## プロバイダーをセットアップする

<Note>
smol machines は、Apple Silicon の macOS、または KVM（`/dev/kvm`）が使える Linux で動作します。
アカウントや API キーは不要です。初回の起動では Playwright の Ubuntu イメージを取得するため、
時間がかかります。
</Note>

プロバイダーと smol machines SDK をインストールします。

<CodeGroup>
```bash npm
npm install --save-dev @e2e-dev/smol smolmachines
```

```bash pnpm
pnpm add -D @e2e-dev/smol smolmachines
```

```bash bun
bun add -d @e2e-dev/smol smolmachines
```
</CodeGroup>

ターゲットの `browser` を `smol()` に設定します。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { smol } from '@e2e-dev/smol';

export default {
  targets: [
    {
      name: 'web',
      engine: web({ browser: smol({ hostPorts: [3000] }) }),
      app: {
        url: 'http://localhost:3000',
        command: { executable: 'npm', args: ['run', 'dev'] },
      },
    },
  ],
  workers: 4,
} satisfies E2EConfig;
```

マシン内では、`localhost` はマシン自身を指します。`hostPorts` には、ブラウザが自身の
`localhost` としてアクセスする、あなたのコンピューター上のポートを列挙します。
そのため `app.url` は `http://localhost:3000` のままで構いません。

<Warning>
`hostPorts` は許可リストではありません。マシンは `host.smolvm.internal` を通じて
あなたのコンピューターの任意のループバックポートにアクセスでき、外向きのネットワークにも
制限なくアクセスできます。信頼できないアプリを `smol()` でテストする前に、
機密性の高いループバックサービスを停止してください。
</Warning>

## すべてのテストをサインイン済みの状態で開始する

`prepare` は、どの試行もブランチを作成する前に、ウォーム状態の各ブラウザを 1 回だけ操作します。
そのスロットのすべての試行は、`prepare` が残した Cookie、ストレージ、ページの状態から開始します。
これは `'attempt'` スコープでは使えない [セッション](/authentication) の代わりになります。

`prepare` はブラウザの DevTools エンドポイントを受け取ります。試行が実行される
デフォルトのコンテキストで操作してください。`prepare` が解決される前に接続を切断し、
ブラウザは起動したままにしておきます。

<Accordion title="Playwright でサインインする">
`@e2e-dev/web` が固定している `playwright-core` のバージョン（現在は 1.65.1）をインストールし、
アップグレード時にはそれに合わせてください。pnpm では、設定から依存パッケージの依存関係を
import できません。

<CodeGroup>
```bash npm
npm install --save-dev playwright-core@1.65.1
```

```bash pnpm
pnpm add -D playwright-core@1.65.1
```

```bash bun
bun add -d playwright-core@1.65.1
```
</CodeGroup>

```ts title="Provider options"
import { chromium } from 'playwright-core';

smol({
  hostPorts: [3000],
  prepare: async (cdpEndpoint) => {
    const browser = await chromium.connectOverCDP(cdpEndpoint);
    const page = browser.contexts()[0]!.pages()[0]!;
    await page.goto('http://localhost:3000/login');
    await page.getByLabel('Email').fill('qa@example.com');
    await page.getByLabel('Password').fill(process.env.QA_PASSWORD!);
    await page.getByRole('button', { name: 'Sign in' }).click();
    await page.waitForURL('**/dashboard');
    await browser.close();
  },
})
```

`connectOverCDP` で取得したブラウザでは、`browser.close()` は接続を切断するだけです。
</Accordion>

## アプリをマシン内で実行する

`app` を使うと、テスト対象のアプリはあなたのコンピューターではなく各ブラウザマシン内で動作します。
そのため、テストやエージェントがアプリに行わせる処理は、どれもホスト上では実行されません。
[プロバイダーをセットアップする](#set-up-the-provider) で警告しているとおり、
マシンからはあなたのループバックポートに引き続きアクセスできます。`'attempt'` スコープでは、
各試行が、ローカルデータベースを含め、実行中のアプリとそのファイルの独自のコピーを受け取ります。

```ts title="Provider options"
smol({
  app: {
    source: '.',
    setup: 'npm ci && npm run db:seed',
    start: 'npm start',
    port: 3000,
    env: { DATABASE_URL: 'file:/app/dev.db' },
  },
})
```

`app.url` を `http://localhost:<port>` に設定し、`app.command` は宣言しません。
`setup` と `start` は、マシンが起動するたびに `prepare` の前に実行されます。

| `app` のフィールド | 意味 |
| ----------- | ------- |
| `start`     | 必須。アプリを配信するシェルコマンドで、`/app` 内でバックグラウンド実行されます。プロバイダーは、アプリが `port` で応答するまで最大 180 秒待ちます。 |
| `port`      | 必須。マシン内でアプリが待ち受けるポートです。ブラウザが使う 80 と 9229 は使えず、`hostPorts` に含まれるポートも使えません。 |
| `source`    | `/app` にコピーされるディレクトリで、`node_modules`、`.git`、`.e2e` は除外されます。実行を開始した場所を基準に解決されます。デフォルトは `.` です。 |
| `setup`     | `start` の前に `/app` 内で root として実行されるシェルスクリプトです。イメージには Node.js と npm が含まれているため、`npm ci` でマシンの Linux 用の依存関係をインストールできます。 |
| `env`       | `setup` と `start` 用の環境変数です。名前はシェル変数名として有効である必要があります。 |

## スコープを選ぶ

デフォルトの `scope: 'attempt'` では、すべての試行がスロットのウォーム状態のブラウザから
独自のブランチを受け取ります。[試行ごとのリース](/browser#hosted-browsers) の制限が適用されます。

`scope: 'worker'` では、実行の間、ワーカースロットごとに 1 台のマシンを保持します。
ローカル実行と同様に、各試行はそのマシン上で新しいブラウザコンテキストを受け取るため、
セッションや `headers`、`locale` などのオプションが機能します。ブランチは作成されず、
`prepare` を指定すると `INVALID_CONFIG` になります。

## オプション

| オプション      | デフォルト     | 意味 |
| ----------- | ----------- | ------- |
| `scope`     | `'attempt'` | [スコープを選ぶ](#choose-a-scope) を参照してください。 |
| `prepare`   | なし        | [すべてのテストをサインイン済みの状態で開始する](#start-every-test-signed-in) を参照してください。 |
| `hostPorts` | `[]`        | [プロバイダーをセットアップする](#set-up-the-provider) を参照してください。80 と 9229 は使えません。 |
| `app`       | なし        | [アプリをマシン内で実行する](#run-the-app-in-the-machine) を参照してください。 |
| `setup`     | なし        | Chromium の起動前に各マシンで root として実行されるシェルスクリプトです。たとえば、フォントを追加するための `apt-get update && apt-get install -y fonts-noto-cjk` などです。 |
| `cpus`      | `2`         | マシンあたりの vCPU 数です。 |
| `memoryMb`  | `2048`      | マシンあたりのメモリ（MiB）です。 |

## ローカルブラウザとの違い

ブラウザの戻る/進むキャッシュは無効になっているため、戻る操作でページが再読み込みされます。
`browser.waitForDownload` はローカルと同じように動作します。

## 残ったマシンをクリーンアップする

ランナーは、実行の終了時に、クラッシュしたワーカーのものも含めて、その実行のマシンを削除します。
キャンセルされた CI ジョブなどでランナーが強制終了された場合、`'worker'` スコープのマシンが
停止状態のまま残ります。名前は `e2e-` で始まります。[smol CLI](https://smolmachines.com) で
一覧表示して削除してください。たとえば `smol machine ls` を使います。
