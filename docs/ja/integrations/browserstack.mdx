`@e2e-dev/browserstack` の `browserstack()` は、
[BrowserStack App Automate](https://www.browserstack.com/app-automate) の実機の
Android と iOS デバイス用の [デバイスプロバイダー](/mobile#hosted-devices) です。
各ワーカースロットは、実行の開始時に 1 台のデバイスをリースし、実行の終了時にそれを解放します。

<Tip>
ホスト型デバイスで e2e を実行するのに、Mac、Xcode、Android SDK は必要ありません。
</Tip>

## セットアップ

モバイルエンジンと一緒にインテグレーションをインストールします。

<CodeGroup>
```bash npm
npm install --save-dev e2e @e2e-dev/mobile @e2e-dev/browserstack
```

```bash pnpm
pnpm add -D e2e @e2e-dev/mobile @e2e-dev/browserstack
```

```bash bun
bun add -d e2e @e2e-dev/mobile @e2e-dev/browserstack
```
</CodeGroup>

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';
import { browserstack } from '@e2e-dev/browserstack';

const apk = 'https://www.browserstack.com/app-automate/sample-apps/android/WikipediaSample.apk';

export default {
  targets: [
    {
      name: 'pixel-7',
      engine: mobile({
        platform: 'android',
        device: browserstack({ device: 'Google Pixel 7', osVersion: '13.0', app: apk, appiumVersion: '3.2.0' }),
      }),
      app: { bundleId: 'org.wikipedia.alpha' },
    },
  ],
  workers: 1,
} satisfies E2EConfig;
```

`device` と `osVersion` は、BrowserStack の App Automate カタログと完全に一致させる必要があります。
[デバイスリスト](https://www.browserstack.com/list-of-browsers-and-platforms/app_automate)
に表示されているとおりに指定してください。Android では `13.0`、iOS では `18` のようになります。

`app` は、BrowserStack がすべてのセッションでインストールするビルドです。以前のアップロードで得た
`bs://` のアプリ ID、BrowserStack が実行ごとに 1 回取得する `https` の URL、または
`e2e.config.ts` のディレクトリを基準に解決されてアップロードされるローカルパスを指定します。
Android では `.apk` または `.aab` を、iOS では署名済みの `.ipa` を使います。
ターゲットの `app.appPath` は省略し、`app.open()` 用に `app.bundleId` は残してください。

`appiumVersion` を設定してください。設定しないと、BrowserStack はデフォルトの Appium 1.x を実行します。
これには、ディープリンクやハードウェアボタンが使う `mobile:` コマンドがありません。

テストはローカルデバイスの場合と同じです。

```ts title="tests/home.e2e.ts"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('Wikipedia home screen', async ({ app, screen }) => {
  await app.open();
  await expect(screen.getByText('Search Wikipedia').first()).toBeVisible();
});
```

## 認証する

`e2e run` が起動する環境（CI のシークレットなど）に `BROWSERSTACK_USERNAME` と
`BROWSERSTACK_ACCESS_KEY` を設定します。これらは **Account & Profile →
My profile → Authentication & Security** からコピーしてください。ユーザー名は
そこに表示されているもので、メールアドレスではありません。どちらかがないと、
何も開始する前にリースが失敗します。プランに App Automate が含まれている必要があります。

## オプション

| オプション           | デフォルト         | 意味 |
| ---------------- | --------------- | ------- |
| `device`         | 必須        | App Automate カタログに記載されているデバイス名（`'Google Pixel 7'`、`'iPhone 16'`）。 |
| `osVersion`      | 必須        | そのデバイスについてカタログに記載されている OS バージョン。 |
| `app`            | 必須        | BrowserStack がインストールするビルド。`bs://` のアプリ ID、`https` の URL、またはローカルパス。 |
| `project`        | `'e2e'`         | セッションをまとめるダッシュボードのプロジェクト。 |
| `build`          | 実行 ID      | セッションをまとめるダッシュボードのビルド。 |
| `sessionName`    | `e2e-<run id>-<target>-<slot>` | ダッシュボード上のセッション名。ワーカースロットが複数ある場合は `-<slot>` が付加されます。 |
| `orientation`    | デバイスの設定    | `'portrait'` または `'landscape'`。 |
| `geoLocation`    | BrowserStack の設定  | デバイスの IP が位置づけられる国コード（`'US'`）。 |
| `timezone`       | デバイスの設定    | タイムゾーン（`'New_York'`）。 |
| `language`       | アプリの設定       | 言語（`'fr'`）。 |
| `locale`         | デバイスの設定    | ロケール（`'fr_FR'`）。 |
| `appiumVersion`  | BrowserStack の設定（1.x） | セッションの Appium バージョン（`'3.2.0'`）。 |
| `networkProfile` | なし            | 名前付きのネットワーク条件プロファイル（`'4g-lte-advanced-good'`）。`customNetwork` とは併用できません。 |
| `customNetwork`  | なし            | カスタムのネットワーク形状。`networkProfile` とは併用できません。 |
| `noResignApp`    | `false`         | iOS のみ。BrowserStack による再署名の代わりに、アップロードしたアプリの署名を保持します。再署名ではプッシュ通知などのエンタイトルメントが削除されます。 |

デバイスの機能はセッションの開始時に設定され、セッション全体を通じて保持されます。
不明なオプションや無効な型のオプションがあると、設定の読み込みが `INVALID_CONFIG` で失敗します。
カタログの値とプラットフォーム固有の制約は、デバイスのリース開始時に確認されます。

[動画](/reference/config#video) を記録する試行は、`build` と `sessionName` で見つけた
BrowserStack のセッション録画にリンクします。録画はセッション全体をカバーするため、
ワーカースロット上のすべての試行が同じ動画にリンクします。固定の `build` と `sessionName` を
共有する、時間が重なる実行は、互いの動画にリンクする可能性があります。デフォルト値ではそうなりません。

## 制限事項

- 各セッションは、e2e がターゲットを準備している間、そのスロットのデバイスがリースされた時点で開始します。
  プロビジョニングには約 20〜50 秒かかり、テストが実行されていなくても、実行がセッションを
  解放するまで課金されます。`workers` と BrowserStack ターゲットの数の積を、プランの
  並列セッション数の範囲内に収めてください。
- BrowserStack は、アップロードを最後の使用から 30 日間保持します。`app` に `https` を指定した
  実行では再度アップロードされます。それを避けるには `bs://` の ID を再利用してください。
- デバイスを解放する前にランナーが強制終了された場合、BrowserStack のアイドルタイムアウトにより、
  最後のコマンドの後でセッションが終了します。
- agent-device がセッションを終了したことを確認できない場合、すべてのテストが成功していても、
  解放によって実行が失敗します。原因は、セッションの終了処理が agent-device の約 3 秒の
  シャットダウン期間を超えた場合、デーモンが強制停止された場合、シャットダウンの報告が失われた場合、
  またはデーモンが実行中に終了した場合です。ダッシュボードで `build` と `sessionName` から
  セッションを探してください。
- デバイスの設定（権限、位置情報、ネットワーク、外観）、システムアラート、agent-device による
  録画とデバイスログ、ポートのリバースは利用できません。ログは BrowserStack のダッシュボードで確認し、
  ネットワーク上のサーバーにアクセスするには BrowserStack Local を使ってください。
