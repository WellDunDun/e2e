`@e2e-dev/kernel` の `kernel()` は、[Kernel](https://kernel.sh) 用の
[ブラウザプロバイダー](/browser#hosted-browsers) です。
各ワーカースロット、または各試行が、独自のホスト型 Chromium を受け取ります。
テストはそのままで、変わるのはターゲットの `browser` だけです。

## セットアップ

プロバイダーと Kernel SDK をインストールします。

<CodeGroup>
```bash npm
npm install --save-dev @e2e-dev/kernel @onkernel/sdk
```

```bash pnpm
pnpm add -D @e2e-dev/kernel @onkernel/sdk
```

```bash bun
bun add -d @e2e-dev/kernel @onkernel/sdk
```
</CodeGroup>

ターゲットの `browser` を `kernel()` に設定します。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { kernel } from '@e2e-dev/kernel';

export default {
  targets: [
    {
      name: 'kernel',
      engine: web({ browser: kernel() }),
      app: { url: 'https://staging.example.com' },
    },
  ],
} satisfies E2EConfig;
```

`e2e run` が起動する環境（CI のシークレットなど）に `KERNEL_API_KEY` を設定します。
`workers` で、同時に実行するブラウザの数を設定します。

キーがない場合や Kernel のエラーが発生した場合、リースはそのメッセージとともに失敗します。
`worker` スコープでは、どのテストも実行される前に実行が終了します。`attempt` スコープでは、
その試行だけが失敗します。

## 画面いっぱいに表示する

Kernel の `viewport` で画面サイズを設定し、Web エンジンの `viewport: null` を指定して、
ページがウィンドウのサイズになるようにします。

```ts
web({
  browser: kernel({ viewport: { width: 1920, height: 1080 } }),
  viewport: null,
})
```

ウィンドウは最大化された状態で開き、ページは [ウィンドウいっぱいに表示されます](/web#fill-the-window)。
1920×1080 の画面では 1920×993 になります。Web の `viewport` を固定すると、ライブビューでは
ページが切れて表示されるか、ウィンドウの一部に表示されます。

## オプション

`kernel(options)` は、Kernel のブラウザ作成のリクエストボディをそのまま受け取ります。
`stealth`、`headless`、`timeout_seconds`、`profile`、`proxy_id`、`viewport`、`tags`、
そして `@onkernel/sdk` の `BrowserCreateParams` のその他の項目です。さらに 2 つのオプションを追加します。

| オプション   | デフォルト    | 意味 |
| -------- | ---------- | ------- |
| `scope`  | `'worker'` | ワーカースロットごと、または試行ごとに 1 つのブラウザ。[スコープ](#scopes) を参照してください。 |
| `replay` | `true`     | Kernel のリプレイ、またはエンジンのスクリーンキャスト。[録画](#recordings) を参照してください。 |

## スコープ

`scope: 'worker'` では、実行の間、ワーカースロットごとに 1 つのブラウザを保持します。
ローカル実行と同様に、各試行はそのブラウザ上で新しいブラウザコンテキストを受け取るため、
テストが他のテストの Cookie、ストレージ、権限を目にすることはありません。Kernel の最初のタブは
その背後で開いたままになります。Kernel の `profile` はブラウザのデフォルトコンテキストにのみ
適用されるため、効果はありません。

`scope: 'attempt'` では、リトライを含め、試行ごとに新しいブラウザをリースします。
試行はデフォルトコンテキストの最初のタブで実行されるため、`profile` が適用され、ライブビューには
1 つのタブが表示されます。各テストでブラウザの起動のコストがかかり、セッションを含め
[試行ごとのリースの制限](/browser#hosted-browsers) が適用されます。

## 録画

[動画](/reference/config#video) を記録する試行は、ブラウザの画面の Kernel リプレイを受け取り、
アーティファクトディレクトリに `video/replay.mp4` として保存します。リプレイには、タブやアドレスバーを
含むウィンドウ全体が、Kernel の `viewport` で設定したサイズで表示されます。

リプレイは Kernel のデフォルトの 10 fps で記録されます。これを変更するには、Kernel のリプレイ開始の
リクエストボディ（`framerate`、`max_duration_in_seconds`、`record_audio`）を渡します。
`kernel({ replay: { framerate: 20 } })` のように指定します。`framerate` を 20 より大きくするには、
ブラウザに `gpu: true` が必要です。

Kernel がリプレイを記録するのは、デフォルトであるヘッドありのブラウザだけです。`headless: true` または
`replay: false` の場合は、代わりに Web エンジンがページのスクリーンキャストを記録します。

## ダウンロード

`browser.waitForDownload` は、どちらのスコープでもローカルと同じように動作します。
プロバイダーは、各ファイルをブラウザのディスクから試行のアーティファクトにコピーします。

## ブラウザを監視してクリーンアップする

レポーターは、新しいブラウザごとに `browser <id>, watch at <live view URL>` をログに出力します。
各ブラウザには、指定した `tags` に加えて、`e2e_run`、`e2e_target`、`e2e_slot`、そして
`'attempt'` スコープでは `e2e_attempt` のタグが付きます。これにより、Kernel のダッシュボードに
ブラウザを起動した実行の名前が表示されます。

実行が終了すると、プロバイダーは、異常終了したワーカーのブラウザを含め、その実行とターゲットのタグが付いた
すべてのアクティブなブラウザを削除します。実行自体が先に異常終了した場合、Kernel は各ブラウザを
`timeout_seconds` のアイドル時間の後に削除します。独自の値を渡さない限り、これは 600 です。
