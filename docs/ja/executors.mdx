ステップエグゼキューターは、エージェントの `agent.act` と `agent.assert` のステップを実行します。
`system` プロンプトと[プロジェクトツール](/tools)では足りない場合は、独自のものを書いてください。

| 選択肢 | あなたが書くもの | ランナーが保持するもの |
| --- | --- | --- |
| `e2e/agent` の `createToolLoopExecutor` | ツールとプロンプト。ループが追加するのは `complete_step` だけです。 | 予算、繰り返し呼び出しの検出、判定、使用量の集計、デバッグ用のトランスクリプト |
| `StepExecutor` | `runStep(ctx)`。モデルは任意で、`e2e` と `e2e/engine` の型は `ai` パッケージなしでコンパイルできます。 | ステップの期限、マスクされた観察結果、チェック済みのアクション、判定の記録 |

どちらかを agents エントリーの `executor` に設定します。エントリーは引き続き
`model`、`judge`、`context`、予算を読み取りますが、`system` と `tools` は拒否します。
これらは `createToolLoopExecutor` に渡してください。限られた選択肢を返すプロバイダーについては、
[デシジョンエグゼキューター](/decision-models)を参照してください。

## ループはそのままに、語彙を変える

このエージェントには 2 つのツールがあります。1 つは画面を読み取り、もう 1 つは ID でノードをタップします。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { createToolLoopExecutor } from 'e2e/agent';
import { web } from '@e2e-dev/web';
import { gateway, tool } from 'ai';
import { z } from 'zod';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  agents: {
    default: {
      model: gateway('openai/gpt-6-luna-fast'),
      maxModelCalls: 15,
      executor: createToolLoopExecutor({
        name: 'tap-only',
        system: 'Read the screen before acting. Tap controls by their id from the latest read.',
        buildPrompt: (ctx) => ctx.step.instruction,
        tools: (ctx, { guard }) => ({
          read_screen: tool({
            description: 'Read the screen as text, one node per line as #id role "name"',
            inputSchema: z.object({}),
            execute: () => guard(async () => (await ctx.observe()).text),
          }),
          tap: tool({
            description: 'Tap a node by its id from the latest read_screen',
            inputSchema: z.object({ id: z.string() }),
            execute: ({ id }) =>
              guard(async () => {
                await ctx.actions.tap({ id: id.replace(/^#/, '') });
                return `Tapped ${id}.`;
              }),
          }),
        }),
      }),
    },
  },
} satisfies E2EConfig;
```

ループは、エントリーの `model`、または `createToolLoopExecutor({ model })` で指定した独自の
モデルを使って、ステップごとに最大 `maxModelCalls` 回のモデルターンを実行します。エグゼキューターは
`judge` を持ち込むこともできます。エントリーが同じオプションを設定している場合、両者は同じ
プロバイダーとモデルを指定している必要があり、そうでなければ設定の読み込みが `INVALID_CONFIG` で
失敗します。

`buildPrompt` は文字列またはメッセージ履歴を返します。`prepareMessages` はターンの間に実行されて
履歴を短くするか、ステップが進展しない場合は `{ messages, stop }` を返します。
これがその場で、または置き換えによって書き換えたメッセージは、リクエストのプレフィックスを編集します。
思考がプレフィックスに結び付いている Anthropic のモデルでは、ループはそのメッセージ以降の推論を
送信しなくなります。プロバイダーがリクエストを大きすぎるとして拒否した場合、ループは履歴を短くし、
それでリクエストが小さくなるなら 1 回だけリトライし、そうでなければ `CONTEXT_OVERFLOW` で失敗します。
`inconclusiveOnOverflow: true` を指定すると、代わりにステップを `ASSERTION_INCONCLUSIVE` で
失敗させます。これは、以前の画面が証拠となるアサーションのループ向けです。`guard()` は、
ステップが終了処理に入ると新しいツール呼び出しを止め、失敗をテキストとしてモデルに返します。
`ctx.actions` は各アクションを認可し、数え、記録するため、これらのステップは
[キャッシュ](/cache)からリプレイされ、`tap` をサポートするどのエンジンでも実行できます。

組み込みのアクションを独自のツールと並べて使うには、`createGrammarTools(ctx, { guard })` を
ツールセットに展開します。これは、ターゲットのエンジンがサポートする動作に対応する
組み込みエージェントのアクションツールを返し、各結果は画面上で何が変わったかを報告します。
`BASE_RULES` は、これらのツールに対する組み込みエージェントのガイダンスです。`system` は
これで始めてください。

```ts
import { BASE_RULES, createGrammarTools, createToolLoopExecutor } from 'e2e/agent';

createToolLoopExecutor({
  name: 'with-inbox',
  system: `${BASE_RULES}\n\nCheck the inbox with read_inbox when a step mentions an email.`,
  buildPrompt: (ctx) => ctx.step.instruction,
  tools: (ctx, { guard }) => ({ ...createGrammarTools(ctx, { guard }), read_inbox: readInbox }),
});
```

ループの外では、グラマーツールは `ScreenOutput`（テキスト、またはテキストと
スクリーンショット）を返します。ツールが `isRuntimeHardStop(error)` の受け付けるエラーを
投げた場合は、ステップを終了してそのエラーを再スローしてください。

テスト用 API の呼び出しのように `ctx.actions` の外で動作するツールは、その本体を
`ctx.budgets.runTool({ name, mutates })` でラップします。これはアクションの枠を 1 つ使い、
結果を記録します。`runTool` の中で `ctx.actions` や `ctx.observe` を呼び出さないでください。
呼び出しが自分自身の後ろで待機し、デッドロックします。

## エグゼキューターを置き換える

このエグゼキューターはモデルを使わず、1 つのアサーション
`agent.assert('the screen says Ready')` だけをサポートします。それ以外のステップでは
blocked の判定を返します。

```ts title="e2e.config.ts"
import type { E2EConfig, StepExecutor } from 'e2e';
import { web } from '@e2e-dev/web';

const scripted: StepExecutor = {
  name: 'scripted',
  version: '1',
  cache: 'off',
  async runStep(ctx) {
    if (ctx.step.kind !== 'assert' || ctx.step.instruction !== 'the screen says Ready') {
      return {
        status: 'blocked',
        errorCode: 'AUTOMATION_UNSUPPORTED',
        summary: 'This executor only checks whether the screen says Ready.',
      };
    }
    const screen = await ctx.observe();
    const ready = screen.text.includes('Ready');
    return {
      status: ready ? 'passed' : 'failed',
      summary: ready ? 'The screen says Ready.' : 'Ready is absent from the screen.',
    };
  },
};

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  agents: { default: { executor: scripted } },
} satisfies E2EConfig;
```

## コンテキストが持つもの

| メンバー | 内容 |
| --- | --- |
| `ctx.step` | `kind`、指示、パラメーター、試行のタイムライン内での `index`。指示やパラメーター内の設定済みシークレットの値は `<secret:name>` と表示されます。`secrets.get()` のハンドルは名前だけのプレースホルダーとして届き、`typeSecret` がそれを入力します |
| `ctx.observe({ tree, pixels })` | マスクされた画面のテキスト。任意でノードツリーとマスクされたスクリーンショットを含みます |
| `ctx.read({ id }, { style })` | 現在リストされているノードの、シークレットがマスクされた計算済みスタイル。[プロジェクトツール](/tools#read-a-nodes-computed-style)を参照してください |
| `ctx.actions` | チェックされ記録されるアクション: `tap`、`doubleTap`、`longPress`、`secondaryTap`、`hover`、`type`、`typeSecret`、`press`、`select`、`check`、`drag`、`scrollTo`、`scrollUntil`、`upload`、`scroll`、`navigate`、`back`、`resize`、`switchTab`、`closeTab`、および後述の座標とキーボードのアクション |
| `ctx.target` | ターゲットの `name`、`platform`、`verbs`（そのエンジンがサポートするアクション）。モデルにはこれらだけを提示してください。`tapModifiers` は、`tap`、`doubleTap`、`secondaryTap` が `{ modifiers }` を受け取る場合に true になります |
| `ctx.signal` | キャンセル時、ステップの期限到達時、その他のハードストップ時に中断します。これを無視する処理は期限で止められません |
| `ctx.replayedPrefix` | キャッシュのリプレイがステップの一部を先に実行した場合に設定されます。[リプレイキャッシュ](#replay-cache)を参照してください |
| `ctx.model`、`ctx.providerOptions` | 設定されている場合、エージェントに設定されたモデルと `providerOptions` |
| `ctx.agentContext` | エージェントの `context` とテストの `agentContext` を合わせたもの |
| `ctx.ledger` | テストの完了したステップ |
| `ctx.attempt` | テストと試行の ID、テストの `titlePath`（`e2e run` の外では空）、リトライのインデックス、中断シグナル、そして報告されることのない `memory` マップ |
| `ctx.budgets` | カスタムツール（`runTool`）とモデル呼び出し（`recordModelCall`）の集計 |
| `ctx.attachTranscript(text)` | `--debug` のもとで、モデルのトランスクリプトを `log` アーティファクトとして添付します。最後に 1 回だけ呼び出してください |
| `ctx.attachTurns(turns)` | モデルのターン（`{ index, calls, outcome }`）の切り詰めた記録をステップに保持します。レポートは失敗したステップの下に最後のターンを表示します |
| `ctx.attachScreenshot(pixels, label)` | 観察したピクセルをステップの `screenshot` アーティファクトとして保持し、そのレポート ID で解決します |

`tapAt(point)` と `hoverAt(point)` は、エンジンの座標アクションを呼び出します。エンジンに
座標アクションがない場合は、その位置にあるリストされたコントロールに対して操作します。
`dragAt(from, to)` は、エンジンの `dragTo` ポインター種別を通じて 2 点間をドラッグします。
それがない場合、`dragTo` アクションを持つエンジンは、2 点が異なる 2 つのリストされたコントロール上に
あるときに ID でドラッグします。それ以外の `dragAt` は `UNSUPPORTED_CAPABILITY` で失敗します。
`hitTest(point)` は、操作せずにその位置にあるコントロールを見つけます。キーボードを持つエンジンは、
フォーカスされたコントロール用に `typeText`、`pressKey`、`dismissKeyboard` を追加します。
`upload(target, paths)` は、プロジェクトからの相対パスと、
[アップロードポリシー](/reference/agent#action-tools)に記載された `sample:` ファイルを受け取ります。
プロジェクトルートの外にあるパスや隠しパスは `POLICY_DENIED` で、存在しないファイルは
`INVALID_ARGUMENT` で拒否します。

観察結果の `keyboardVisible` は、画面上のキーボードが表示されているかどうかを示し、
エンジンが判別できない場合は存在しません。

セマンティックキャプチャが失敗した場合、観察結果は `treeUnavailable: true` を設定し、
`tree` を持たず、ポリシーが許可すればスクリーンショットを含みます。以前のノード ID は無効になり、
ツリーがないことはコントロールが存在しないことの証明にはなりません。

## エグゼキューターが扱うもの

`act` と `assert` は、エージェントの `maxSteps`、`maxModelCalls`、`timeout` とともに
`runStep` に届きます。`assert` では、エグゼキューターが `vision: true` を宣言している場合にのみ
`vision` が `ctx.step.vision` として届きます。そうでない場合、呼び出しは
`UNSUPPORTED_CAPABILITY` で失敗します。`screenshot` は、あなたの判定の後にも引き続き
証拠を添付します。

`waitFor` と `extract` は引き続き組み込みの判定を使います。モデルが設定されていない場合は
`MODEL_UNAVAILABLE` で失敗します。

## 判定

`passed`、`failed`、`blocked` のいずれかを、サマリーとともに返します。blocked の判定には
エラーコードが必要で、passed の判定にはエラーコードがありません。
[エージェントステップの仕組み](/agent-steps#how-a-step-ends)にコードの一覧があります。
`STEP_BUDGET_EXHAUSTED`、`STEP_TIMEOUT`、`CANCELLED` は、それぞれ予算を使い切った場合、
期限を過ぎた場合、テストがキャンセルされた場合にのみ返してください。ランナーはそれ以外の使い方と、
コード付きの passed の判定を `MODEL_OUTPUT_INVALID` で拒否します。

エグゼキューター自身がモデルを操作する場合、`e2e/agent` の `createVerdictTool(ctx.step.kind)` は
組み込みエージェントの `complete_step` です。モデルにその `tool` と `VERDICT_RULES` を渡し、
`verdict()` を返してください。`act` ステップでは、failed の判定から
`ASSERTION_INCONCLUSIVE` を取り除きます。

## リプレイキャッシュ

`StepExecutor` の `cache` は、その `act` ステップが[リプレイキャッシュ](/cache)をどのように
使うかを設定します。`assert` ステップはキャッシュされません。

デフォルトの `'inherit'` は、設定されたキャッシュモードに従います。記録されたステップは
`runStep` を呼び出さずにリプレイされます。`'off'` はリプレイも記録もしません。エグゼキューター
自身の履歴やメモリーが信頼できる情報源である場合に使ってください。

リプレイが途中で止まった場合、ランナーは `ctx.replayedPrefix`（リプレイされたアクションと、
リプレイが止まった理由）を付けて `runStep` を呼び出します。それらを繰り返さずに、現在の画面から
続けてください。

キャッシュは、ステップが `ctx.actions` を通じて行ったことを記録します。変更を伴うツールの
呼び出しは空白を残し、リプレイ時にエグゼキューターがそれを埋めます。エントリーのキーは
エグゼキューターではなく、設定されたエージェントとそのコンテキストであるため、エージェントの
エグゼキューターを変更してもエントリーは保持されます。

## ページを自分で操作する

Web エンジンでは、`@e2e-dev/web` の `surfaceOf(handle)` によって、現在の試行の `Page` と
`BrowserContext` を取得できます。どちらのアクセサーも、アクティブな試行の外では
`INVALID_STATE` を投げます。`page()` は、開いているページがない場合にも投げます。

```ts
import type { E2EConfig, StepExecutor } from 'e2e';
import { web, surfaceOf } from '@e2e-dev/web';

const engine = web();
const own: StepExecutor = {
  name: 'own-tools',
  version: '1',
  cache: 'off',
  async runStep(ctx) {
    const page = surfaceOf(engine)!.page();   // the page app.open() navigated
    await ctx.budgets.runTool({ name: 'click', mutates: true }, () =>
      page.getByRole('button', { name: 'Save' }).click(),
    );
    return { status: 'passed', summary: 'saved' };
  },
};

export default {
  targets: [{ engine, app: { url: 'http://localhost:3000' } }],
  agents: { default: { executor: own } },
} satisfies E2EConfig;
```

Playwright を直接呼び出すと、アクションの認可とリプレイキャッシュが省略され、
アーティファクトも残りません。ステップの期限と判定の記録は引き続き適用されます。
