`expect(locator)` はアプリの状態を待ち、`expect(screen)` は画面を保存済みのスクリーンショットと比較し、`expect(value)` は値をただちにチェックします。`expect.poll` はマッチャーが成功するまで値を読み直し、`expect.soft` は失敗をスローせずにテスト本体の最後まで保持します。また、`expect.any` などの[非対称マッチャー](#asymmetric-matchers)は、構造的な比較の中で値の代わりになります。

```ts title="tests/checkout.e2e.ts"
import { expect, test } from 'e2e';

test('checkout summary', async ({ screen }) => {
  await expect(screen.getByRole('heading', 'Checkout')).toBeVisible();
  await expect(screen.getByTestId('line-item')).toHaveCount(2);
  const total = await screen.getByTestId('total').textContent();
  expect(total).toContain('$');
});
```

## リファレンス

| 呼び出し | 戻り値 |
| --- | --- |
| [`expect(locator)`](#locator-matchers) | `AsyncExpectation` |
| [`expect(screen)`](#screenshot-matchers) | `ScreenExpectation` |
| [`expect(fixture)`](#browser-matchers) | エンジンのマッチャーセット |
| [`expect(value, message?)`](#value-matchers) | `ValueExpectation<T>` |
| [`expect.poll(read, options?)`](#polling-a-value) | `PollExpectation<T>` |
| [`expect.soft(actual)`](#soft-assertions) | 同じマッチャー（失敗は保持されます） |
| [`expect.any(Class)` など](#asymmetric-matchers) | `AsymmetricMatcher` |

`expect` は、引数が何であるかによって区別します:

- エンジンのフィクスチャはマッチャーを提供できます。たとえば `expect(browser).toHaveURL()` です。そのようなフィクスチャは `Expectable<E>` です。エンジンが [`expectable`](/reference/engine#contributed-fixtures) を通じてマッチャーセット `E` を付与しており、`expect(fixture)` はそれを返します。
- それ以外の引数には、Promise も含めて値のマッチャーが使われます。Promise は、結果を `expect` に渡す前に await してください。

宣言は[型](#types)にあります。

### ロケーターのマッチャー

`expect(locator)` は `AsyncExpectation` を返します。各マッチャーは、条件が成立するかタイムアウトに達するまで、[動作](#behavior)のルールに従ってポーリングします。そのルールには[厳密性](#strictness)、[テキストのマッチング](#text-matching)、[セキュアフィールド](#secure-fields)などがあります。オプションは [`AsyncExpectation`](#asyncexpectation-and-textmatcheroptions) にあります。

| マッチャー | 説明 |
| --- | --- |
| [`toBeVisible`](#tobevisible-and-tobehidden) | 表示されるのを待ちます |
| [`toBeHidden`](#tobevisible-and-tobehidden) | 非表示または存在しない状態を待ちます |
| [`toBeAttached`](#tobeattached) | 一致が 1 つ存在するのを待ちます |
| [`toBeEnabled`](#tobeenabled-and-tobedisabled) | 有効な状態を待ちます |
| [`toBeDisabled`](#tobeenabled-and-tobedisabled) | 無効な状態を待ちます |
| [`toBeChecked`](#tobechecked-tobeselected-and-tobeexpanded) | チェックされた状態を待ちます |
| [`toBeSelected`](#tobechecked-tobeselected-and-tobeexpanded) | 選択された状態を待ちます |
| [`toBeExpanded`](#tobechecked-tobeselected-and-tobeexpanded) | 展開された状態を待ちます |
| [`toBeFocused`](#tobefocused) | フォーカスされた状態を待ちます |
| [`toHaveText`](#tohavetext-and-tocontaintext) | 正規化されたテキストの完全一致を待ちます |
| [`toContainText`](#tohavetext-and-tocontaintext) | 正規化されたテキストを含むのを待ちます |
| [`toHaveValue`](#tohavevalue) | フォームコントロールの値を待ちます |
| [`toHaveAttribute`](#tohaveattribute) | 属性を待ちます |
| [`toHaveCount`](#tohavecount) | 一致数がちょうどその数になるのを待ちます |
| [`toHaveAccessibleName`](#tohaveaccessiblename) | アクセシブルネームを待ちます |
| [`toHaveRole`](#tohaverole) | ロールを待ちます |
| [`toHaveScreenshot`](#screenshot-matchers) | 保存済みのスクリーンショットと比較します |

#### `toBeVisible` と `toBeHidden`

`toBeVisible` は、1 つの一致が表示されるのを待ちます。`toBeHidden` は、非表示または存在しない状態を待ちます。デバイスでは、中心がソフトウェアキーボードに覆われたノードは非表示として扱われます。ただし、キーボード自身のキー、候補バー、ドック、フォーカスされたフィールド、まだ表示されている子を持つコンテナは除きます（[可視性](/reference/mobile#visibility)）。

```ts
await expect(screen.getByRole('dialog')).toBeVisible();
await expect(screen.getByRole('dialog')).not.toBeVisible({ timeout: 10_000 });
await expect(screen.getByRole('dialog')).toBeVisible({ visible: false }); // as toBeHidden()
```

#### `toBeAttached`

非表示か表示かにかかわらず、一致が 1 つ存在するのを待ちます。`toBeVisible` では表示されている一致が必要です。

```ts
await expect(screen.getByText('Loaded')).toBeAttached();
await expect(screen.getByText('Loading')).toBeAttached({ attached: false });
```

否定した場合、または `attached: false` を指定した場合は、一致がなくなるのを待ち、何も一致しなくなった時点で成功します。

#### `toBeEnabled` と `toBeDisabled`

`toBeEnabled` は有効なノードを待ち、`toBeDisabled` は無効なノードを待ちます。

```ts
await expect(screen.getByRole('button', 'Pay')).toBeEnabled();
await expect(screen.getByRole('button', 'Pay')).toBeEnabled({ enabled: false }); // as toBeDisabled()
```

ノードは、`disabled` を報告しない限り有効です。Web では、`disabled` は属性だけでなく、ブラウザが適用する状態を指します。これは Playwright の `toBeDisabled` と同じ解釈です:

- `<fieldset disabled>` 内のコントロールは、そのフィールドセットの最初の `<legend>` 内にない限り無効です。
- 祖先に `aria-disabled="true"` があると、その配下のウィジェットは、`aria-disabled="false"` によって連鎖が断たれるまで無効になります。

#### `toBeChecked`、`toBeSelected`、`toBeExpanded`

それぞれ、チェック、選択、展開の状態を待ちます。

```ts
await expect(screen.getByLabel('Subscribe')).toBeChecked({ checked: false });
await expect(screen.getByRole('tab', 'Billing')).toBeSelected();
```

`checked`、`selected`、`expanded` の状態がない場合は `false` として扱われるため、ボタンや見出しに対する `.not.toBeChecked()` は成功します。

#### `toBeFocused`

フォーカスされた状態を待ちます。

```ts
await expect(screen.getByLabel('Email')).toBeFocused();
```

#### `toHaveText` と `toContainText`

`toHaveText` は正規化されたテキストの完全一致を待ち、`toContainText` は正規化されたテキストを含むのを待ちます。どちらも単一の `TextMatch` またはリストを受け取ります。

```ts
await expect(screen.getByRole('status')).toHaveText('Saved');
await expect(screen.getByRole('alert')).not.toContainText('error', { ignoreCase: true });
await expect(screen.getByTestId('todo')).toHaveText(['Write spec', /^Ship/, 'Release']);
await expect(screen.getByTestId('todo')).toContainText(['spec', 'runner', 'Release']);
await expect(screen.getByTestId('todo')).toContainText(['spec', 'Release']);
```

リスト形式の失敗メッセージには、観測されたすべてのテキストが示されます。

| 形式 | 成立する条件 |
| --- | --- |
| `toHaveText([...])` | 一致数がリストの長さと等しく、各位置の一致がその位置のエントリーを満たす場合です。文字列は正規化後の完全一致、`RegExp` はテストで判定します。空のリストは、何も一致しない場合に成立します |
| `toContainText([...])` | Playwright と同様に、各エントリーがリストの順序どおりに、それぞれ別の一致に含まれる場合です。前後や間に余分な一致があっても問題なく、繰り返されたエントリーにはそれぞれ専用の一致が必要です。空のリストは常に成立します |

<Note>
否定した場合、`toContainText([...])` はその順序付きの部分列が存在した時点で失敗します。そのため、`not.toContainText(['Deleted'])` は、いずれかの一致が `Deleted` を含んでいる間は失敗します。
</Note>

#### `toHaveValue`

フォームコントロールの値を待ち、そのままの形で比較します。

```ts
await expect(screen.getByLabel('Email')).toHaveValue('ada@example.test');
await expect(screen.getByLabel('Search')).toHaveValue('');
```

- 正規化は行いません。改行や末尾の空白も比較に含まれ、失敗メッセージにもその形で値が出力されます。
- `contenteditable` エディターの値は、描画されたテキストで、同じくそのままの形で扱われます。空のエディターは `''` として読み取られます。
- デバイスでクリアされたフィールドのように、プラットフォームが値なしで報告するコントロールは `''` として読み取られます。
- 見出しやリンクのように、ロールが値を持たないノードは、否定の有無にかかわらず `toHaveValue` を満たしません。メッセージは `no value (not a form control)` になります。

#### `toHaveAttribute`

属性が存在するのを待ちます。`value` を指定した場合は、その値に一致するのを待ちます。

```ts
await expect(screen.getByRole('link', 'Help')).toHaveAttribute('target');
await expect(screen.getByRole('link', 'Help')).toHaveAttribute('href', '/help');
```

#### `toHaveCount`

一致数がちょうどその数になるのを待ちます。

```ts
await expect(screen.getByTestId('todo')).toHaveCount(3);
```

#### `toHaveAccessibleName`

アクセシブルネームを待ちます。

```ts
await expect(screen.getByRole('button', { name: /close/i })).toHaveAccessibleName('Close');
```

#### `toHaveRole`

1 つの一致がそのロールを持つのを待ちます。比較は文字列として行います。

```ts
await expect(screen.getByTestId('save')).toHaveRole('button');
await expect(screen.getByTestId('wifi')).not.toHaveRole('checkbox');
```

- `role` は、[`getByRole`](/reference/screen#getbyrole) と同じ語彙を受け取ります。エイリアスの `img` は `image` として読み取られます。JavaScript からは、それ以外の文字列は書かれたとおりに比較され、空文字列は `INVALID_ARGUMENT` になります。
- [`screen.tree()`](/reference/screen#screen-tree) が示すロールと比較するため、ロールの階層は考慮されません。`switch` は `checkbox` ではありません。
- Web では、編集ホスト（`contenteditable`）はタグにかかわらず `textbox` として読み取られます。ただし、`getByRole` はタグのロールでそれを見つけます。
- テキストの `<div>` のように、ツリーでロールなしと示されるノードは失敗し、失敗メッセージは `no role` になります。

### スクリーンショットのマッチャー

`expect(screen)` と `expect(locator)` は、ピクセルをキャプチャするすべてのエンジンで、テストファイルの隣に保存された PNG と比較します。ワークフローは[ビジュアル比較](/visual-testing)ガイドで紹介しています。

| マッチャー | 説明 |
| --- | --- |
| [`expect(screen).toHaveScreenshot`](#tohavescreenshot) | 画面全体を比較します |
| [`expect(locator).toHaveScreenshot`](#tohavescreenshot) | ロケーターの 1 つの一致を比較します |

#### `toHaveScreenshot`

画面、またはロケーターの 1 つの一致が、保存済みのスクリーンショットと同じ見た目になるのを待ちます。スクリーンショットは `name`、またはテストにちなんだ名前のものです。

```ts
await expect(screen).toHaveScreenshot('home.png');
await expect(screen.getByRole('navigation')).toHaveScreenshot();
await expect(screen).toHaveScreenshot('feed.png', { mask: [screen.getByTestId('timestamp')], maxDiffPixels: 50 });
```

どちらの形式も[スクリーンショットのオプション](#screenshot-options)を受け取ります。

| 項目 | 値 |
| --- | --- |
| 保存場所 | `<test file>-snapshots/<name>-<target>-<os>.png`。`.png` がない名前には `.png` が付加されます |
| 名前なし | テストのタイトルパスを小文字にしたものと連番です: `checkout-pays-by-card-1` |
| 存在しない場合 | 許容範囲内で同じだった連続する 2 枚のスクリーンショットから作成され、その後 `ASSERTION_FAILED` になります。テストの隣に書き出されます。CI で `--update-snapshots` を指定しない場合は、結果に `snapshots/<path in the project>` として添付されるだけです |
| 同じ実行内で以前に書き出された場合 | `--update-snapshots` を指定しない場合、および `.not` の場合は常に、同じ実行が書き出したスクリーンショット（リトライ、繰り返し、同じ名前を指定する別のテスト）との比較は成功しません。次の実行まで `ASSERTION_FAILED` になります。`--update-snapshots` を指定した場合、肯定のマッチャーは比較を行い、再度書き出すことがあります |
| 異なる場合 | 一致するかタイムアウトに達するまでリトライされます。その後、ステップに `-expected`、`-actual`、`-diff` の画像が付いて `ASSERTION_FAILED` になります |
| `--update-snapshots`、`-u` | 存在しない、または異なる保存済みスクリーンショットは、静止した画面から書き出され、マッチャーは成功します |
| `.not` | 画面が異なった時点で成功します。何も保存されていない場合は `ASSERTION_FAILED` になります |
| 許容範囲 | `maxDiffPixels` と `maxDiffPixelRatio` の両方を設定した場合は、小さい方が適用されます |

| エラー | 条件 |
| --- | --- |
| `INVALID_ARGUMENT` | 画面を読み取る前に発生します。パス区切り文字を含む名前、マッチャーが受け取らないオプション（Playwright の `fullPage`、`animations`、`clip`）、範囲外の値、またはフレームにスコープされた画面に対する `expect` です。その場合は、フレーム内のロケーターを比較してください |
| `ASSERTION_FAILED` | 上の表のとおり、保存済みスクリーンショットが存在しない、異なる、または同じ実行で書き出されたものである場合です |
| `POLICY_DENIED` | 画面上のすべてのセキュアフィールドがマスクされていることを、エンジンが証明できない場合です |

#### スクリーンショットのオプション

| オプション | 型 | デフォルト |
| --- | --- | --- |
| `threshold` | `number` | `0.2` |
| `maxDiffPixels` | `number` | `0` |
| `maxDiffPixelRatio` | `number` | `0` |
| `mask` | `readonly Locator[]` | - |
| `maskColor` | `string` | `#ff00ff` |
| `timeout` | `number` | `config.assertionTimeout` |

各オプションの説明は [`ScreenshotOptions`](#screenexpectation-and-screenshotoptions) にあります。

### browser のマッチャー

`@e2e-dev/web` が提供します。`BrowserExpectation` 型はこのパッケージからエクスポートされています。マッチャーの呼び出しはすべて、`expect.<matcher>` のアサーションステップとして記録されます。

| マッチャー | 説明 |
| --- | --- |
| [`toHaveURL`](#tohaveurl) | 現在の URL を待ちます |
| [`toHaveTitle`](#tohavetitle) | 現在のタイトルを待ちます |
| [`toHaveClass`](#tohaveclass) | ターゲットの `class` を待ちます |

それ以外のオプションキーは `INVALID_ARGUMENT` になります。たとえば `toHaveTitle` の `ignoreCase` で、これは Playwright でも受け付けません。

#### `toHaveURL`

現在の URL が一致するのを待ちます。

```ts
await expect(browser).toHaveURL('/dashboard');
await expect(browser).toHaveURL(/\/orders\/\d+$/);
```

- 相対的な文字列はベース URL を基準に解決され、正規化後に完全一致で比較されます。
- `RegExp` は完全な URL に対してテストされます。
- 述語関数など、それ以外のものは `INVALID_ARGUMENT` になります。
- ロケーターのマッチャーと同様に、Playwright の `ignoreCase` を受け取ります（[テキストのマッチング](#text-matching)）。

#### `toHaveTitle`

現在のタイトルが一致するのを待ちます。

```ts
await expect(browser).toHaveTitle(/Dashboard/);
```

#### `toHaveClass`

ターゲットの `class` 属性が一致するのを待ちます。文字列の場合は正規化されたクラスリスト全体と比較し、`RegExp` の場合はそれに対してテストします。

```ts
await expect(browser).toHaveClass(browser.locator('.card'), 'card active');
```

- ノードもポーリングします。まだ何にも一致しないターゲットは失敗ではなく、アサーションのタイムアウトが切れるまでポーリングが続きます。
- あいまいなターゲットは、引き続き `LOCATOR_AMBIGUOUS` でただちに失敗します。
- `class` 属性を読み取るため、`''` は `class=""` に一致しますが、`class` 属性をまったく持たない要素には一致しません。Playwright の `toHaveClass('')` は両方を受け入れます。

### 値のマッチャー

`expect(value)` は同期的に実行され、リトライしません。まだ変化する可能性がある値には、[値のポーリング](#polling-a-value)を使ってください。

| マッチャー | 説明 |
| --- | --- |
| [`toBe`](#tobe) | `Object.is` で比較します |
| [`toEqual`](#toequal) | 再帰的な構造の等価性です |
| [`toMatchObject`](#tomatchobject) | 再帰的な部分一致です |
| [`toBeTruthy`, `toBeFalsy`](#tobetruthy-and-tobefalsy) | truthy または falsy な値です |
| [`toBeNull`, `toBeUndefined`, `toBeDefined`](#tobenull-tobeundefined-and-tobedefined) | `null`、`undefined`、または定義済みです |
| [`toHaveLength`](#tohavelength) | `length` が `expected` と等しいです |
| [`toHaveProperty`](#tohaveproperty) | パス上のプロパティです |
| [`toContain`](#tocontain) | 文字列またはコレクションに含まれます |
| [`toMatch`](#tomatch) | 文字列または `RegExp` に一致します |
| [`toBeGreaterThan` など](#numeric-comparisons) | 数値の境界を満たします |
| [`toBeCloseTo`](#tobecloseto) | `10 ** -digits / 2` の範囲内です |
| [`toMatchSchema`](#matching-a-schema) | Standard Schema による検証です |

値を評価できないマッチャーは、不一致と同様に `ASSERTION_FAILED` で失敗します。たとえば数値に対する `toContain` や、数値の `length` を持たない値に対する `toHaveLength` です。そのため `expect.poll` では、まだ最終的な形になっていない値は、失敗したサンプルの 1 つとして扱われます。

#### `toBe`

`Object.is` で比較します。

```ts
expect(status).toBe('paid');
```

#### `toEqual`

Jest と同じ方法で、再帰的な構造の等価性を判定します。

```ts
expect(payload).toEqual({ ok: true, items: [{ sku: 'a' }] });
```

- プリミティブは `Object.is` で比較されるため、`NaN` は `NaN` と等しく、`0` は `-0` と等しくありません。
- 配列とプレーンオブジェクトは内容で、`Date` は時刻で、`RegExp` はソースとフラグで、`Map` と `Set` はエントリーで比較されます。
- 値が `undefined` のプロパティは存在しないものとして扱われ、疎な配列は `undefined` を含む配列と等しくなります。
- クラスの型は比較されません。クラスのインスタンスは、同じプロパティを持つプレーンオブジェクトと等しくなります。`toStrictEqual` はありません。[対象外](#not-included)を参照してください。

#### `toMatchObject`

`expected` のすべてのプロパティが再帰的に一致することを求めます。

```ts
expect(order).toMatchObject({ customer: { name: 'Ada' }, lines: [{ sku: 'a' }, { sku: 'b' }] });
```

- `expected` に含まれないプロパティは無視されます。
- `expected` 内の配列は、同じ長さの配列に要素ごとに一致し、各要素も部分一致で判定されます。
- 両側ともオブジェクトである必要があり、どちらかがプリミティブの場合は拒否されます。

#### `toBeTruthy` と `toBeFalsy`

truthy または falsy な値を求めます。

```ts
expect(created).toBeTruthy();
```

#### `toBeNull`、`toBeUndefined`、`toBeDefined`

`toBeNull` は `null` を、`toBeUndefined` は `undefined` を求めます。`toBeDefined` は `undefined` 以外の任意の値を求め、`null` は成功します。

```ts
expect(row).toBeDefined();
```

#### `toHaveLength`

`expected` と等しい `length` プロパティを求めます。文字列、配列、または配列のようなオブジェクトが対象です。

```ts
expect(items).toHaveLength(3);
```

#### `toHaveProperty`

`path` にプロパティが存在することを求めます。`expected` を指定した場合は、`toEqual` のルールでそれと等しいことを求めます。

```ts
expect(order).toHaveProperty('customer.email', 'ada@example.test');
expect(order).toHaveProperty(['lines', 0, 'sku'], 'a');
```

- `path` はドット区切り（`'user.address.city'`）またはキーの配列（`['user', 'address', 'city']`）です。キーにドットが含まれる場合や、配列を数値でインデックスする場合は配列形式を使ってください。
- 継承されたプロパティも対象になり、`undefined` を保持するプロパティは存在するものとして扱われます。
- パス上の文字列、数値、真偽値は、Jest と同様にラッパーオブジェクトを通じて読み取られます。そのため、`toHaveProperty('label.length', 3)` や `toHaveProperty(['label', 0], 'a')` で文字列の中にアクセスできます。
- `null` と `undefined` はプロパティを持ちません。

#### `toContain`

文字列またはコレクションに含まれることを求めます。

```ts
expect(total).toContain('$');
expect(rows).toContain(expect.objectContaining({ status: 'paid' }));
```

- 文字列に対しては、`expected` は文字列である必要があり、部分文字列のチェックになります。ここでは非対称マッチャーは拒否されます:
  `expect('abc').toContain(expect.stringContaining('a'))` は失敗します。
- コレクションに対しては、いずれかの要素が `expected` と等しい必要があります。この形式は[非対称マッチャー](#asymmetric-matchers)を受け付けます。

#### `toMatch`

文字列または `RegExp` に一致することを求めます。

```ts
expect(id).toMatch(/^usr_/);
```

文字列でも `RegExp` でもないパターンは `INVALID_ARGUMENT` になります。

#### 数値の比較

`toBeGreaterThan` と `toBeLessThan` は数値の境界を求め、`toBeGreaterThanOrEqual` と `toBeLessThanOrEqual` は境界を含む形で求めます。

```ts
expect(count).toBeGreaterThan(1);
expect(count).toBeLessThanOrEqual(10);
```

#### `toBeCloseTo`

`expected` から `10 ** -digits / 2` 以内の数値を求めます。

```ts
expect(totals.lineTotal).toBeCloseTo(60); // digits default: 2
```

`toBeCloseTo(60)` は 59.996 を受け入れ、59.99 を拒否します。無限大の値は、同じ無限大の場合にのみ成功します。

#### スキーマとの照合

`toMatchSchema` は、値を [Standard Schema](https://standardschema.dev) に対して検証します。Zod、Valibot、ArkType のスキーマ、またはこの仕様を実装する任意のライブラリが使えます。アプリがすでに API の解析に使っているスキーマを渡せば、API がそこから外れたときにテストが失敗します。スキーマの出力を型付きで返すため、テストの残りの部分ではキャストせずにプロパティを読み取れます。

```ts
import { z } from 'zod';

const User = z.object({ id: z.number(), name: z.string(), email: z.email() });

const users = expect(await response.json()).toMatchSchema(z.array(User));
expect(users.map((user) => user.name)).toContain('Ada');
```

- 失敗時には、すべての問題がパス付きで一覧表示されます（`1.email: Invalid email address`）。
- 出力はスキーマのものなので、デフォルト値と変換が適用されます。
- マッチャーは何かが await できるようになる前に戻るため、非同期に検証するスキーマ（非同期の refinement）は `INVALID_ARGUMENT` になります。
- 否定した場合、値が一致しなければ成功し、何も返しません。

#### 失敗メッセージ

2 番目の引数を渡すと、失敗メッセージでチェックの内容を説明できます:

```ts
expect(created, 'the company exists through the API').toBeTruthy();
// ASSERTION_FAILED: the company exists through the API: expected undefined to be truthy
```

メッセージを受け取るのは値の expectation だけです。ロケーターや `browser` の expectation では、失敗時にすでにロケーターとマッチャーが示されます。

#### 対象外

ユニットテストランナーのマッチャー（`toThrow`、`toBeInstanceOf`、`toBeNaN`、`toStrictEqual`、`resolves`、`rejects`、`expect.extend`）は `expect` には含まれません。エンドツーエンドのテストは、アプリが表示する内容と API が返す内容をチェックします。それは値のマッチャーでカバーできます。[API](/api-testing) を参照してください。コードレベルのチェックはユニットテストランナーで行ってください。

### 非対称マッチャー

非対称マッチャーは、`toEqual`、`toMatchObject`、`toContain` のコレクション形式、`toHaveProperty` の値の中で、値の代わりになります。比較で等価性をテストする箇所で、代わりにマッチャーに判定を委ねます。これらは Jest のマッチャーで、Jest のルールに従います。

| マッチャー | 一致するもの |
| --- | --- |
| `expect.any(Class)` | クラスのインスタンスです。`String`、`Number`、`Boolean`、`BigInt`、`Symbol`、`Function` の場合はプリミティブも一致します。`Object` の場合は、`typeof` がオブジェクトとみなすもので、`null` も含みます |
| `expect.anything()` | `null` と `undefined` 以外のすべてです |
| `expect.objectContaining(sample)` | `sample` のすべてのプロパティを含むオブジェクトです。各プロパティは `toEqual` のルールで比較されます |
| `expect.arrayContaining(sample)` | `sample` のすべての要素を順不同で含む配列です。各要素は `toEqual` のルールで比較されます |
| `expect.stringContaining(text)` | `text` を部分文字列として含む文字列です |
| `expect.stringMatching(text \| RegExp)` | RegExp のテストが true になる文字列です。テキストのサンプルは RegExp にコンパイルされるため、`'a.b'` は `'axb'` に一致します |

```ts
expect(created).toEqual({
  id: expect.stringMatching(/^usr_/),
  createdAt: expect.any(String),
  roles: expect.arrayContaining(['member']),
  profile: expect.objectContaining({ name: 'Ada' }),
});
expect(rows).toContain(expect.objectContaining({ status: 'paid' }));
expect(response).toHaveProperty('body.total', expect.any(Number));
```

- 失敗メッセージでは、マッチャーはその説明として出力されます: `Any<Number>`、`ObjectContaining {"name":"Ada"}`。
- マッチャーは入れ子にできます。`objectContaining` のサンプルに `expect.any` を含めることができます。
- `toContain` の文字列形式はこれらを拒否します。[`toContain`](#tocontain) を参照してください。

### ソフトアサーション

`expect.soft(actual)` は `expect(actual)` と同じものを受け取り、同じマッチャーを返します。失敗したソフトマッチャーはスローしません。失敗は実行中のアテンプトに保持され、本体の実行が続きます。

```ts
test('checkout summary', async ({ agent, screen }) => {
  await agent.act('add the "Pro" plan to the cart and open the summary');
  expect.soft(await screen.getByTestId('subtotal').textContent()).toBe('$40.00');
  expect.soft(await screen.getByTestId('tax').textContent()).toBe('$8.00');
  await expect.soft(screen.getByRole('button', 'Pay')).toBeEnabled();
  await expect(screen.getByTestId('total')).toHaveText('$48.00');
});
```

```text
ASSERTION_FAILED: 2 soft assertions failed
1. expected "$41.00" to be "$40.00"
2. expect.toBeEnabled failed
   locator: getByRole('button', 'Pay')
   expected: enabled
   observed: states: disabled (match count 1)
```

- 本体が確定した後、`afterEach` の前に、アテンプトは保持されたすべての失敗を順に列挙する 1 つの `ASSERTION_FAILED` で失敗します。エラーのソース行は、最初に失敗したソフトマッチャーです。
- ソフトなロケーターまたは `browser` のマッチャーも、失敗としてマークされた `expect.<matcher>` ステップとして記録されるため、レポートにはフローのどこで発生したかが示されます。
- ソフトな値のマッチャーは、通常のものと同様にステップにはなりません。その失敗はアテンプトのエラー記録に表示されます。
- 本体が自らスローした場合やタイムアウトした場合は、そのエラーがアテンプトの判定として残り、ソフトな失敗は `secondaryErrors` の下にあわせて記録されます。
- ソフトな失敗の後に `test.skip(...)` で自身をスキップした本体も失敗します。ソフトな失敗がアテンプトのエラーとなり、スキップの理由はアテンプトの `skip` に保持されます。
- ソフトな `toMatchSchema` は、値が一致した場合はスキーマの出力を、失敗が保持された後は `undefined` を返し、その型もそれを反映しています。

<Note>
テスト本体の外では失敗を保持する対象がないため、`expect.soft` は `expect` と同様にただちにスローします。スタンドアロンのスクリプトや、ソフトな失敗が確定した後に実行される `afterEach` フックが該当します。`expect.soft.poll` はありません。`expect.poll` には失敗の基準となる独自のタイムアウトがあります。
</Note>

### 値のポーリング

`expect.poll(read)` は、マッチャーが成功するまで値を読み直します。アプリでの操作の後に、API のレスポンスや保存されたデータを待つときに使います。

```ts
await agent.act('create a test named "AI checkout regression" described as {description}', {
  params: { description },
});
await expect
  .poll(() => getTest(workspace).then((row) => row?.title), { timeout: 15_000 })
  .toBe('AI checkout regression');
await expect.poll(async () => (await listTests(workspace)).length).toBeGreaterThan(1);
await expect.poll(() => readStatus(), { message: 'the batch never finished' }).not.toBe('running');
```

| オプション | 型 | デフォルト |
| --- | --- | --- |
| `timeout` | `number` | アテンプト中は `config.assertionTimeout`、それ以外では 5000 ms |
| `interval` | `number` | `100` |
| `message` | `string` | - |

- `timeout` はミリ秒単位の期限で、0 以上の有限の数値です。本体ではテストの期限が、`afterEach` 中はフックの `cleanupTimeout` が上限になります。`0` はその上限までポーリングするため、テストの外では `INVALID_CONFIG` になります。
- `interval` は読み取りの間隔（ミリ秒）で、0 より大きい有限の数値です。
- `message` は、タイムアウトエラーでマッチャーの行の後に追加される行です。

すべての値のマッチャーが、Promise を返す形で利用できます。

- 各サンプルは `read` を呼び出してマッチャーを実行します。マッチャーの失敗や、スローした `read` は 1 つの失敗したサンプルになります。ハングした `read` は期限で打ち切られます。
- `toMatchSchema` は、成功した読み取りに対するスキーマの出力で解決されます。
- アテンプトがキャンセルされると、ループは `CANCELLED` で停止します。アテンプトの期限に達すると、期限を示して `ASSERTION_FAILED` で停止します。実行中の `read` は停止されずに放棄されます。そこで開始された処理は続く可能性があります。
- `expect.poll` はレポートのステップとして記録されません。タイムアウトはテストの失敗としてのみ表れます。

期限に達すると、マッチャー、指定されていれば `message`、そして最後のサンプル（最後のマッチャーの失敗、最後の `read` のエラー、または `no read completed`）を示して `ASSERTION_FAILED` をスローします。

```text
expect.poll(...).not.toBe(...) timed out after 5000 ms
the batch never finished
last: expected "running" not to be "running"
```

| エラー | 条件 |
| --- | --- |
| `ASSERTION_FAILED` | 成功するサンプルがないまま期限が過ぎました |
| `INVALID_CONFIG` | 最初の読み取りの前に、`timeout` または `interval` が範囲外です |
| `CANCELLED` | アテンプトがキャンセルされたか、タイムアウトしました |
| `STEP_NOT_AWAITED` | ポーリングを開始したフェーズが、ポーリングの実行中に戻りました |
| `HOOK_FAILED` | `beforeAll` または `afterAll` フックが、ポーリングの実行中に戻りました |

<Note>
すべてのポーリングを await してください。ポーリングは、それを開始したフェーズに属します。テスト本体（フィクスチャと `beforeEach` フックを含む）、1 つの `afterEach` フックまたはフィクスチャの後片付け、1 つの `beforeAll` または `afterAll` フックです。ポーリングの実行中にそのフェーズが戻ると、ポーリングはキャンセルされ、ポーリングが成功したかどうかにかかわらず、そのフェーズは呼び出し行で `STEP_NOT_AWAITED` として失敗します。スローした本体は自身のエラーを保持し、このエラーを `secondaryErrors` の下に記録します。スイートのフックはこれを `HOOK_FAILED` として報告します。
</Note>

ポーリングが後のテストを失敗させることはありません。タイムアウトを過ぎた本体のように、フェーズが実行中のまま残した処理によって開始されたポーリングは、最初の読み取りの前にキャンセルされます。

## 動作

マッチャーのグループ全体に適用されるルールです。

### タイムアウトと失敗

| 項目 | 値 |
| --- | --- |
| デフォルトのタイムアウト | [`config.assertionTimeout`](/reference/config#assertiontimeout) |
| 上書き | すべてのロケーターと `browser` のマッチャーで、ミリ秒単位の `{ timeout }` |
| 読み取り | 開始から 0、20、50 ms、その後は 100 ms ごと |
| 不明なオプション | `INVALID_ARGUMENT`。[オプションの検証](#option-validation)を参照してください |
| 失敗コード | `ASSERTION_FAILED`、終了コード 1 |

### 否定

`.not` はマッチャーを反転させます。否定したマッチャーは、否定の条件が持続した場合にのみ成功します:

- 1000 ms 継続して成立した後に成功します。
- `{ timeout }` が 1000 ms より短い場合は、否定の条件が全期間にわたって成立していれば期限の時点で成功します。
- この期間は、否定の条件を確認した最初の読み取りが開始された時点から数えるため、遅い読み取りの時間も含まれます。

### 厳密性

- 肯定のロケーターマッチャーは、ちょうど 1 つの一致を必要とします。例外は `toHaveCount` と、`toHaveText` および `toContainText` のリスト形式です。
- 一致が 0 件の場合は、タイムアウトまでポーリングを続けます。
- 一致が複数件の場合は、`LOCATOR_AMBIGUOUS` でただちに失敗します。
- `toBeHidden`、`toBeVisible({ visible: false })`、`toBeAttached({ attached: false })`、否定した可視性のマッチャー、否定した `toBeAttached` は、0 件の一致を受け入れます。
- これらと、`toHaveCount` やリスト形式、`waitFor({ state: 'detached' })` と `'hidden'` では、ドキュメント内にないフレーム配下のロケーターは、フレームを待つのではなく 0 件の一致として扱われます。iframe が閉じた後、`toHaveCount(0)` は成功します。

### テキストのマッチング

- テキストの比較は正規化されます。先頭と末尾の空白は取り除かれ、連続する空白は 1 つのスペースにまとめられます。
- `toHaveText` と `toContainText` は、[`textContent()`](/reference/screen#locator-reads) と同じ描画されたテキスト（Web では `innerText`）を読み取ります。
- `TextMatch` の文字列は完全一致で比較されます。`RegExp` は自身のソースとフラグを使います。述語関数など、それ以外のものは `INVALID_ARGUMENT` になります。
- `toHaveText`、`toContainText`、`toHaveAccessibleName`、および `toHaveAttribute` の値形式で `ignoreCase: true` を指定すると、文字列は大文字と小文字を区別せずに比較され、`RegExp` には `i` フラグが追加されます。`ignoreCase: false` はそれを取り除きます。
- `toHaveAttribute(name, value)` は、`toHaveText` と同様に正規化後に比較します。
- [`toHaveValue`](#tohavevalue) は例外で、値をそのままの形で比較します。

### セキュアフィールド

パスワード入力欄のようなセキュアフィールドが判定されることはありません。エンジンがその値とテキストを伏せるためです。

| マッチャー | セキュアフィールドでの動作 |
| --- | --- |
| `toHaveValue`、`toHaveText`、`toContainText` | `inputValue()` や `textContent()` と同様に `POLICY_DENIED` になります。否定した場合やリスト形式でも同じです |
| `toHaveAttribute` | `getAttribute()` と同様に、すべての属性名で `POLICY_DENIED` になります。否定した場合も同じです |
| `toHaveAccessibleName`、`toHaveRole`、および状態のマッチャー | 通常どおり応答します |

伏せられた値を `''` として読み取ると、入力済みのパスワードフィールドがクリアされているとして成功してしまいます。また、伏せられた `value` 属性を存在しないものとして読み取ると、`value` 属性を持つパスワードフィールドで `not.toHaveAttribute('value')` が成功してしまいます。フィールドではなく、入力の結果をアサートしてください。

### オプションの検証

- マッチャーは、受け取らないオプションキーや、真偽値でないフラグを、画面を読み取る前に `INVALID_ARGUMENT` で拒否します。
- TypeScript では型がこれらを検出しますが、`e2e run` は型チェックを行わないため、JavaScript のテストや計算されたオプションオブジェクトに対してもこのチェックが実行されます。
- `toBeChecked` の `indeterminate` や `toHaveText` の `useInnerText` など、e2e が実装していない Playwright のオプションは、デフォルト値で成功するのではなく、このように失敗します。
- Playwright がこれらのマッチャーに提供している真偽値のオプション（`checked`、`enabled`、`visible`、`attached`）は、ここでも同じように動作します。

## 型

### `ExpectCall`、`SoftExpectCall`、`Expect`

```ts
/** `T`, or `never` when `T` is `any`, so an `any` argument skips an overload. */
type NotAny<T> = 0 extends 1 & T ? never : T;

/** The `expect(actual)` call: a locator, `screen`, an engine fixture, or a value, told apart by the argument. */
export interface ExpectCall {
  <L extends Locator>(actual: NotAny<L>): AsyncExpectation;
  <S extends Screen>(actual: NotAny<S>): ScreenExpectation;
  <E extends object>(actual: Expectable<E>): E;
  <T>(actual: T, message?: string): ValueExpectation<T>;
}

/** The `expect.soft(actual)` call: `expect(actual)` whose failures are kept instead of thrown. */
export interface SoftExpectCall {
  <L extends Locator>(actual: NotAny<L>): AsyncExpectation;
  <S extends Screen>(actual: NotAny<S>): ScreenExpectation;
  <E extends object>(actual: Expectable<E>): E;
  <T>(actual: T, message?: string): SoftValueExpectation<T>;
}

/** The `expect` entry: the call, `expect.poll`, `expect.soft`, and the asymmetric matchers. */
export interface Expect extends ExpectCall {
  /** Re-reads a value until the chosen matcher holds or `timeout` passes. */
  poll<T>(read: () => T | Promise<T>, options?: PollOptions): PollExpectation<T>;
  /** The same matchers, a failure kept on the attempt instead of thrown; the attempt fails once the body has settled. */
  readonly soft: SoftExpectCall;
  any(sample: Class | typeof BigInt | typeof Symbol): AsymmetricMatcher;
  anything(): AsymmetricMatcher;
  objectContaining(sample: object): AsymmetricMatcher;
  arrayContaining(sample: readonly unknown[]): AsymmetricMatcher;
  stringContaining(sample: string): AsymmetricMatcher;
  stringMatching(sample: string | RegExp): AsymmetricMatcher;
}
```

### `AsyncExpectation` と `TextMatcherOptions`

```ts
/**
 * The locator matchers. An option a matcher does not take, or a flag that is
 * not a boolean, is `INVALID_ARGUMENT` before the first read.
 */
export interface AsyncExpectation {
  /** Inverts the matcher. A negated matcher passes after 1000 ms of continuous truth. */
  readonly not: AsyncExpectation;
  /** Waits for visibility; `visible: false` waits for hidden or absent state, as `toBeHidden`. */
  toBeVisible(options?: { visible?: boolean; timeout?: number }): Promise<void>;
  /** Waits for hidden or absent state. */
  toBeHidden(options?: { timeout?: number }): Promise<void>;
  /** Waits for one match to exist, visible or not; `attached: false` waits for none. */
  toBeAttached(options?: { attached?: boolean; timeout?: number }): Promise<void>;
  /** Waits for enabled state; `enabled: false` waits for disabled state. */
  toBeEnabled(options?: { enabled?: boolean; timeout?: number }): Promise<void>;
  /** Waits for disabled state. */
  toBeDisabled(options?: { timeout?: number }): Promise<void>;
  /** Waits for checked state; `checked: false` waits for unchecked state. */
  toBeChecked(options?: { checked?: boolean; timeout?: number }): Promise<void>;
  /** Waits for selected state. */
  toBeSelected(options?: { timeout?: number }): Promise<void>;
  /** Waits for expanded state. */
  toBeExpanded(options?: { timeout?: number }): Promise<void>;
  /** Waits for focused state. */
  toBeFocused(options?: { timeout?: number }): Promise<void>;
  /** Waits for exact normalized text; a list waits for exactly that many matches, each with its entry's text, in order. */
  toHaveText(expected: TextMatch, options?: TextMatcherOptions): Promise<void>;
  toHaveText(expected: readonly TextMatch[], options?: TextMatcherOptions): Promise<void>;
  /** Waits for contained normalized text; a list waits for each entry to be contained by a distinct match, in order, extra matches allowed. */
  toContainText(expected: TextMatch, options?: TextMatcherOptions): Promise<void>;
  toContainText(expected: readonly TextMatch[], options?: TextMatcherOptions): Promise<void>;
  /** Waits for a form control's value, compared as it is. */
  toHaveValue(expected: TextMatch, options?: { timeout?: number }): Promise<void>;
  /** Waits for the attribute to be present; with `value`, for it to match. */
  toHaveAttribute(name: string, options?: { timeout?: number }): Promise<void>;
  toHaveAttribute(name: string, value: TextMatch, options?: TextMatcherOptions): Promise<void>;
  /** Waits for an exact match count. */
  toHaveCount(expected: number, options?: { timeout?: number }): Promise<void>;
  /** Waits for an accessible name. */
  toHaveAccessibleName(expected: TextMatch, options?: TextMatcherOptions): Promise<void>;
  /** Waits for the role; `img` is read as `image`, as `getByRole` reads it. */
  toHaveRole(role: Role | RoleAlias, options?: { timeout?: number }): Promise<void>;
  /** Waits for the one match to look like its stored screenshot; see [Screenshot matchers](#screenshot-matchers). */
```

### `ValueExpectation`

```ts
export interface ValueExpectation<T> {
  /** Inverts the matcher. */
  readonly not: NegatedValueExpectation<T>;
  /** Compares with Object.is. */
  toBe(expected: T): void;
  /** Performs recursive structural equality; `undefined` properties are ignored and class types are not compared. */
  toEqual(expected: unknown): void;
  /** Requires every property of `expected` to match recursively; extra properties on the value are fine, arrays must match element-wise with equal length. */
  toMatchObject(expected: object): void;
  /** Requires a truthy value. */
  toBeTruthy(): void;
  /** Requires a falsy value. */
  toBeFalsy(): void;
  /** Requires null. */
  toBeNull(): void;
  /** Requires undefined. */
  toBeUndefined(): void;
  /** Requires any value but undefined; null passes. */
  toBeDefined(): void;
  /** Requires a `length` property equal to `expected`: a string, an array, or anything array-like. */
  toHaveLength(expected: number): void;
  /** Requires the property at `path` to exist; with `expected`, to equal it by `toEqual` rules. */
  toHaveProperty(path: PropertyPath, ...expected: [] | [expected: unknown]): void;
  /** Requires string or collection containment. */
  toContain(expected: unknown): void;
  /** Requires a string or regexp match. */
  toMatch(expected: string | RegExp): void;
  /** Requires a numeric lower bound. */
  toBeGreaterThan(expected: number): void;
  /** Requires a numeric lower bound, inclusive. */
  toBeGreaterThanOrEqual(expected: number): void;
  /** Requires a numeric upper bound. */
  toBeLessThan(expected: number): void;
  /** Requires a numeric upper bound, inclusive. */
  toBeLessThanOrEqual(expected: number): void;
  /** Requires a number within `10 ** -digits / 2` of `expected`; `digits` defaults to 2. */
  toBeCloseTo(expected: number, digits?: number): void;
  /**
   * Requires the value to pass a synchronous Standard Schema (Zod, Valibot,
   * ArkType, ...) and returns the schema's output, typed:
   * `const users = expect(await response.json()).toMatchSchema(Users)`.
   * A schema that validates asynchronously is `INVALID_ARGUMENT`.
   */
  toMatchSchema<Schema extends StandardSchemaV1>(schema: Schema): StandardSchemaV1.InferOutput<Schema>;
}

/** `expect(value).not`: every value matcher inverted, none returning a value; `Back` is what `.not` returns to. */
export type NegatedValueExpectation<T, Back = ValueExpectation<T>> = {
  readonly not: Back;
} & {
  readonly [K in Exclude<keyof ValueExpectation<T>, 'not'>]: (...args: Parameters<ValueExpectation<T>[K]>) => void;
};

/** `expect.soft(value)`: the value matchers, with `toMatchSchema` returning `undefined` after a kept failure. */
export type SoftValueExpectation<T> = Omit<ValueExpectation<T>, 'toMatchSchema' | 'not'> & {
  readonly not: NegatedValueExpectation<T, SoftValueExpectation<T>>;
  toMatchSchema<Schema extends StandardSchemaV1>(schema: Schema): StandardSchemaV1.InferOutput<Schema> | undefined;
};

/** A class, abstract or not: what `expect.any` takes. */
export type Class = abstract new (...args: never[]) => unknown;

/** A property path for `toHaveProperty`: dotted (`'user.address.city'`) or one key per element (`['user', 'address', 'city']`). */
export type PropertyPath = string | readonly (string | number)[];
```

### `PollOptions` と `PollExpectation`

```ts
export interface PollOptions {
  /** Deadline in milliseconds. Default 5000. */
  timeout?: number;
  /** Pause between reads in milliseconds. Default 100. */
  interval?: number;
  /** Extra line in the timeout error, after the matcher line. */

/**
 * The asynchronous form of every `ValueExpectation<T>` matcher: the same
 * names and parameters, each resolving once the re-read value passes;
 * `toMatchSchema` resolves to the schema's output for the passing read.
 * Derived from `ValueExpectation<T>` so the two cannot drift.
 */
export type PollExpectation<T> = {
  readonly not: NegatedPollExpectation<T>;
} & {
  readonly [K in Exclude<keyof ValueExpectation<T>, 'not' | 'toMatchSchema'>]: (

  toMatchSchema<Schema extends StandardSchemaV1>(schema: Schema): Promise<StandardSchemaV1.InferOutput<Schema>>;
};

/** `expect.poll(read).not`: every poll matcher inverted, none resolving to a value. */
export type NegatedPollExpectation<T> = {
  readonly not: PollExpectation<T>;
} & {
  readonly [K in Exclude<keyof ValueExpectation<T>, 'not'>]: (...args: Parameters<ValueExpectation<T>[K]>) => Promise<void>;
};
```
