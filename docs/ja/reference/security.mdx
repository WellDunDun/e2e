### モデル入力

モデルはアプリのコンテンツを引用された証拠として読み取り、ランナーのポリシーや信頼済みのプロジェクトコンテキストとは区別されます。アプリのコンテンツがツール、認証情報、より大きな予算を付与することはできません。ステップの詳細は[エージェントステップの仕組み](/agent-steps)で説明しています。

| プロンプト内の項目 | 形式 |
| --- | --- |
| 指示とパラメーター | `<instruction>` 内に引用され、データとしてマークされます。`Secret` パラメーターは名前と用途のみが表示されます。 |
| 画面 | ノード ID、ロール、名前、テキスト、テスト ID、リンク先、状態を含むアクセシビリティツリーで、サイズ上限で切り詰められます。セレクターは含まれません。リンクのクエリとフラグメントは `?…` と `#…` としてのみ表示されます。セキュアなフィールドは `value=<secure>` と表示されます。 |
| 現在地 | マスキング済みで userinfo を除いた現在の URL です。判定では、アプリのオリジン上ならパスとして、それ以外ではサイズ上限で切り詰めた URL 全体として渡されます。デバイスでは、アプリと画面のタイトルです。 |
| スクリーンショット | 必要な場合または要求された場合に、エンジンがセキュアなフィールドのマスクを保証できる場合に限り含まれます。 |
| 以前のステップ | `agent.act` は、同じテストまたはシリアルグループの上限付きの記録を受け取ります。判定では、現在の画面、その現在地、指示とそのパラメーター、エージェントのコンテキストのみを使用します。 |

### ツール呼び出し

- 組み込みツールのスキーマは閉じており、エンジンがサポートしている場合にのみ表示されます。
- プロジェクトのツールは `execute` を持つ `defineTool` を使う必要があり、組み込みの名前を置き換えることはできません。
- 観測を要求できるのは読み取り専用のプロジェクトツールのみです。
- ステップが提供していないツールの呼び出しや、宣言されていない引数を伴う呼び出しは実行されません。モデルは拒否を呼び出しの結果として読み取り、再試行します。
- ランナーがモデルのテキストをコード、セレクター、シェルコマンド、設定として評価することはありません。

| 失敗時のエラー | 条件 |
| --- | --- |
| `CONFIG_LOAD_FAILED` | 設定の読み込み時に、`execute` のない `defineTool` がある場合。 |
| `INVALID_CONFIG` | `defineTool` で作成されていないツール、または組み込みツールやハーネスのツールと同じ名前のツールがある場合。 |
| `LOCATOR_NOT_FOUND` | 現在の画面に存在しないノード ID が指定された場合。アクションは失敗し、モデルは失敗を読み取って再度アクションを行います。 |

### ポリシーによる拒否

これらの呼び出しは `POLICY_DENIED` で失敗します。

| 拒否される操作 | 理由 |
| --- | --- |
| `about:blank` を除く、`http:` と `https:` 以外のスキームへのナビゲーション | `file:`、`data:`、`javascript:`、および `view-source:file:` のようなラッパーは、ローカルまたはインラインのコンテンツを読み込んでしまうためです。 |
| 不正な形式の URL | 修復は一切行われません。 |
| `Secret` が JSON のシンクに到達すること | ハンドルは値を持たず、どの値もシリアライズされてはならないためです。 |
| ゲッター、または `toHaveValue`、`toHaveText`、`toContainText`、`toHaveAttribute` マッチャーによる、セキュアなフィールドからの値、テキスト、属性の読み取り | シークレットではなく結果をアサートしてください。伏せられた値は空や欠落ではなく、マスキングされたものです。 |
| 宣言されていない名前での `type_secret` | 入力できるのはステップのパラメーターにあるシークレットのみです。 |
| 無効または編集不可のノードへの `type_secret`、または MCP の `run_code` 内の `fill` | シンクは `textbox`、`searchbox`、`combobox` です。 |
| パスワードフィールドではないフィールドへのパスワードの入力 | 用途が一致している必要があります。汎用のシークレットは任意の編集可能な入力に入力できます。 |
| 設定でシークレットが宣言されているときに、テキストの一部（正規表現、`true` 以外の `exact`、`hasText`）で見つける MCP `run_code` のロケーター | エンジンはマスキング前のテキストで照合するため、一致するかどうかによってシークレットが一文字ずつ明らかになる可能性があります。`run_code` のマッチャーは代わりにマスキング済みのテキストを比較します。 |
| 観測を要求する、状態を変更するプロジェクトツール | 観測は別の呼び出しで行ってください。 |
| ピクセルが伏せられているときの `vision: 'only'` | フォールバック先がないためです。 |
| Cookie の URL が `http:` または `https:` ではない `browser.setCookies` | Cookie を保持するのは Web のオリジンのみだからです。 |
| エンジンがすべてのセキュアなフィールドのマスクを保証できないときの `toHaveScreenshot()` | スクリーンショットは保存されません。 |
| エージェント、エグゼキューター、または MCP の `upload` による、プロジェクトルート外のファイル、隠しファイル、隠しディレクトリ配下のファイルのアップロード | フォームを通じてコンピューターの外に出られるのは、プロジェクトのファイルと、e2e に同梱されているサンプルファイル（`sample:photo.png` など）のみです。 |
| プロジェクトルート外、隠しファイル、または隠しディレクトリ配下を指す MCP `screenshot` の `path` | セッションが書き込むのはプロジェクトのファイルのみで、`.git` や `.e2e` を上書きすることはありません。 |

### ナビゲーション

| エントリーポイント | 受け付けるもの | 拒否するもの |
| --- | --- | --- |
| `app.open`、`browser.goto`、エージェントの `navigate` 動詞 | `http:`、`https:`、および完全一致の `about:blank` | その他すべてのスキーム |
| `app.linkBase` を持つデバイスターゲットでの `app.open(path)` | 結合されたリンク、または絶対リンク（アプリのカスタムスキーム、または `http:` と `https:`） | `file:`、`data:`、`javascript:`、`view-source:`、`blob:`、`filesystem:` |
| `device.openLink` | 任意の絶対 URL（アプリのカスタムスキーム、または `http:` と `https:`） | `file:`、`data:`、`javascript:`、`view-source:`、`blob:`、`filesystem:` |
| `device.openApp`、`open_app` ツール | アプリ ID | リンク |
| `e2e login` が開くブラウザ | `http:` と `https:` | その他すべてのスキーム。代わりにリンクが表示されるので、ご自身で開いてください |

- ランナーはリダイレクトを再チェックせず、ポップアップページにもアタッチしません。ブラウザのダイアログを処理するには `browser.onDialog` を登録してください。

<Warning>
オリジンの許可リストはありません。エージェントはアプリに従って他のサイトに移動し、そこでステップのシークレットを使用できます。
</Warning>

### リクエストの認証情報

ブラウザエンジンは、設定されたリクエストの認証情報を厳密なオリジンに限定します。対象は `app.url` のスキーム、ホスト、ポートと、`credentialOrigins` に列挙された追加のオリジンです。

| オプション | 送信先 |
| --- | --- |
| `headers` | 許可されたオリジンで開始されるすべてのリクエスト |
| `basicAuth` | 許可されたオリジンからの `401` チャレンジへの応答 |

- 同じホストの別のポート、サブドメイン、`vercel.app` のような共有ドメイン配下の兄弟ホストは、別のオリジンです。そこで開始されるリクエストには `headers` が付かず、そこからの `401` には応答しません。ただし、以下の項目で述べる例外があります。
- `headers` はリクエストが開始されたオリジンに従います。許可されたオリジンへのリクエストは、どのオリジンへのリダイレクトでも、すべてのリダイレクトを通じて `headers` を保持します。それ以外で開始されたリクエストには、許可されたオリジンにリダイレクトされる場合でも付きません。
- `basicAuth` は `401` を送信したオリジンに応答します。`http:` から `https:` へ、あるいは apex から `www` へのような別オリジンへのリダイレクトには、到達先のオリジンを列挙しない限り応答しません。
- WebKit では、許可されたオリジンがそのスキームのデフォルトポート上にある場合（`https://staging.example.com`）や IPv6 ホストを持つ場合、`basicAuth` は任意のオリジンからの `401` に応答します。WebKit はそのようなオリジンに認証情報を限定できないためです。
- 追加のオリジンは、`https://api.example.com` のような、パス、クエリ、フラグメントを持たない `http:` または `https:` のオリジンです。それ以外のもの、ホスト内の `*`、ポート `0` は、設定の読み込み時に `INVALID_CONFIG` になります。

### サイトの判定

ブラウザエンジンは、何をターゲットのサイトとみなすかをホスト名の比較で判断します。観測には、他のサイトの子フレームと `data:` フレームは含まれません。

この判定は、パブリックサフィックスリストを使わずに登録可能ドメインを近似します。`vercel.app` のような共有ホスティングドメインは 1 つのサイトとみなされます。

### シークレットの入力

`Secret` は平文へのアクセサーを持たない不透明なハンドルです。これを受け付けるシンクは 3 つあります。ロケーターの `fill`、エージェントステップのパラメーター、そしてそれを宣言するエンジンオプションです。

```ts title="tests/stripe.e2e.ts"
import { secrets, test } from 'e2e';

test('connect Stripe', async ({ screen, agent }) => {
  await screen.getByLabel('Secret key').fill(secrets.get('stripe-key'));
  await agent.act('Connect Stripe with the given key', {
    params: { apiKey: secrets.get('stripe-key') },
  });
});
```

| 入力方法 | 値を解決する前のチェック |
| --- | --- |
| モデル主導（`type_secret`） | ステップがシークレットを宣言していること。シークレットが設定されていること。ターゲットが最新の観測上の有効で編集可能な入力であること。パスワードはパスワードフィールドに入力されること。リプレイでもこれらのチェックが繰り返されます。 |
| 決定論的な `fill(secret)` | フィールドに対するチェックはありません。テストコードが選んだものだからです。値はマスキングのために引き続き登録されます。 |

ランナーはホスト上で値を解決し、エンジンに渡します。モデルがその値を見たり選んだりすることはありません。

### シークレット入力後のスクリーンショット

シークレットを入力してもスクリーンショットは無効になりません。モデル、ピクセルツール、ランナーが保存するアーティファクトは、入力の前後で同じマスク済みのスクリーンショットを受け取ります。

<Warning>
スクリーンショットがマスクするのはセキュアなフィールドのみです。通常の入力に入力された汎用のシークレットは画像に含まれます。パスワード表示トグルの後ろなど、アプリが他の場所に表示する値も同様です。モデルプロバイダーも画像を受け取ります。テスト用の認証情報を使い、スクリーンショットは[動画](#where-redaction-stops)と同様に扱ってください。
</Warning>

### エンジンオプション内のシークレット

`web({ basicAuth: { password: secrets.get(name) } })` のような、エンジンオプション内のシークレットは入力ではありません。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { secrets } from 'e2e';
import { web } from '@e2e-dev/web';

export default {
  targets: [
    {
      engine: web({
        basicAuth: { username: 'preview', password: secrets.get('previewPassword') },
      }),
      app: { url: 'https://staging.example.com' },
    },
  ],
  secrets: { previewPassword: () => process.env.PREVIEW_PASSWORD ?? '' },
} satisfies E2EConfig;
```

- ランナーは各試行の開始時にホスト上でこれを解決します。
- その値を、エンジンがそこから導出するものと合わせてマスキング用に登録します。ベーシック認証の場合、それは `Authorization` ヘッダー内の base64 化された `user:password` です。
- レポート、`screen-at-failure.txt`、トレースページ、モデルと `e2e mcp` セッションが読み取る内容、テキストのダウンロードからマスキングされます。
- スクリーンショットとモデルのピクセルは有効のままです。画面にパスワードを表示するページは、ピクセル上ではマスクされません。

### マスキング

ランナーは、登録されたすべてのシークレットの値を、以下の箇所で `<secret:name>` に置き換えます。

- モデル入力（プロジェクトのツールの結果、構造化テキストフィールド、ツールやエンジンのエラーメッセージを含む）
- レポートとトレースページ（スキップ理由や AI トレースのツール結果を含む）
- テキストのダウンロード
- `e2e run` 中にコードが出力する内容（テスト、設定ファイルとテストファイルのトップレベルのコード、テストフィルター、レポーター）

また、`secrets.get()` のハンドルではなくプレーンな文字列として渡された値もマスキングします。対象は、テストと `describe` のタイトル、ステップのラベル（`app.open` の URL、ロケーターのテキスト）、`fill`、`agent.act` または `agent.assert` の指示、`agent.act` のパラメーター内の文字列、`agentContext`、`e2e explore` のゴールです。

| ルール | 詳細 |
| --- | --- |
| 照合される形式 | 記述どおりの形、JSON エスケープ、HTML エスケープ、パーセントエンコードされた形を、大文字小文字を問わず（CSS の `text-transform` で隠れないように）、また空白を詰めた形でも照合します。 |
| 切り詰められたテキスト | 長さの上限で切り詰められたテキストは、値の先頭 8 文字以上、または 16 文字未満の値ならその半分で終わる場合に、記述どおりの形でも空白を詰めた形でもマスクされます。 |
| 観測された画面 | すべての文字列（名前、テキスト、値、テスト ID、属性、セレクター、フレームパス）は、モデル、エグゼキューターのツリー、リプレイキャッシュの記述子、または終了アンカーが読み取る前に一度マスキングされます。 |
| タイトル | ランナーがテストファイルを収集するときにマスキングされます。テスト ID、`--grep`、レポーター、アーティファクトや失敗ページのファイル名には `<secret:name>` が渡されます。シークレットの値だけが異なる 2 つのタイトルは、重複したタイトルパスになります。 |
| エグゼキューター | カスタムエグゼキューターの `ctx.step` と組み込みエージェントのプロンプトはマーカーを含むため、実際の値を入力できるのはハンドルのみです。 |
| 設定の出力 | 設定の読み込み中に出力された内容は、読み込み後に表示されます。読み込みに失敗した場合は表示されません。 |
| 最小の長さ | 6 文字未満の静的な値は `INVALID_CONFIG` になります。そのような値を返すプロバイダーは入力に失敗します。 |
| アサーション | 影響を受けません。マスキングが書き換えるのはランナーが報告する内容のみです。 |
| キャッシュエントリー | シークレットの値とその切り詰められた部分が含まれることはありません。 |

### マスキングが及ばない範囲

マスキングは文字列を照合します。以下はそのまま通過します。

- 末尾 4 文字のような、変換された値
- ハッシュや、テキストの[ダウンロード](#downloads)とテストフィルターの `redact` 以外での base64 のように、全体としてエンコードされた値
- シークレットが合成済みのアクセントを持つのに対して分解されたアクセントを使うなど、別の Unicode 正規化形式の値
- 値の内部の空白を取り除いたテキスト。空白を広げたテキストも通過します。ただし観測された画面では、空白を詰めた形が値を含むフィールドは、詰めた形のままマスクされます
- PIN パッドのセルごとに 1 文字ずつのように、複数のノードに分散した値
- 値に関する yes か no。`e2e mcp` の `locate` の件数は、テスト内のアサーションと同様に、エージェントが渡したテキストに画面が一致するかどうかを示します（`exact: false` を含む）
- 切り詰められたテキストのルールについて、長さが変わる大文字小文字の変換（`ß` が `SS` と表示されるなど）
- シークレットプロバイダーが返す値のうち、タイトル内、テストフィルターが参照または送信する内容内、`e2e explore --changed-since` のブリーフ内のもの。この 3 つはいずれもプロバイダーの実行前にマスキングされるためです
- 埋め込みホストが設定やテストをメモリ上で渡す場合の、ランナー自身のプロセスで実行されるテストのコンソール出力
- モデルに送られるものを含むスクリーンショット。マスクされるのはセキュアなフィールドのみなので、アプリが他の場所に表示する値は画像に含まれます
- 動画。何もマスクせず、`redaction: "incomplete"` とラベル付けされます。ホスト型ブラウザやデバイスサービスが保持する録画はそのサービスに残り、レポートにはその URL のみが含まれます
- `e2e explore --changed-since` のブリーフ内の、値の 8 文字未満の連続。たとえば、複数行のキーの短い最終行を git が単独の行として出力する場合です
- `command.log`。ランナーはアプリの出力を書かれたとおりに取得します。

### ダウンロード

ダウンロードはアプリが配信したものです。セッションがシークレットの値を把握している場合、ランナーはテキストのダウンロード（`.txt`、`.csv`、`.json`、`.html`、`.htm`）を書き換え、`redaction: "complete"` とラベル付けします。以下を `<secret:name>` に置き換えます。

- 値の完全な出現箇所すべて
- 空白を詰めているかどうかにかかわらず、その値の 8 文字以上の連続。そのため、値と 8 文字を共有する無関係なテキストもマスクされます
- そのいずれかにデコードされる base64 または base64url の連続

その他のダウンロードはすべて配信されたまま保存され、`redaction: "incomplete"` とラベル付けされます。

- その他の拡張子
- 有効な UTF-8 ではない、または書き換えられないもの
- シークレットの値を把握していないセッションからのすべてのダウンロード

### セッション

保存されたセッションは認証状態を保持します。同じ暗号文には、セットアップテストがプロバイダーから解決したシークレットの値も含まれます。それを復元するテストは、それらの値をマスキングします。エンベロープには、シークレットの名前が暗号化されずに、ただし認証された状態で保持されます。

| プロパティ | 値 |
| --- | --- |
| 場所 | [出力ディレクトリ](/reference/config#output)配下の `sessions/<runId>/`（デフォルトは `.e2e/sessions/<runId>/`）。ディレクトリのモードは `0700`、ファイルは `0600` |
| 暗号方式 | AES-256-GCM。保存ごとに新しい 12 バイトの IV |
| 鍵 | 実行ごとに生成され、メモリ上に保持される 32 バイトのランダムなバイト列。ワーカーは IPC 経由で受け取り、ディスクや環境変数を経由することはありません。 |
| 紐付け先 | 実行 ID、ターゲット、エンジン名とバージョン、プラットフォーム、アプリの識別情報。すべて追加データとして認証されます |
| 有効期間 | 最大 24 時間。保存された状態がそれより早い有効期限を宣言している場合はそれより短くなります |
| クリーンアップ | 実行の終了時にディレクトリが削除されます |

ランナーは、無効、期限切れ、欠落、または不一致のセッションを拒否します。[セッションのエラー](/reference/errors)を参照してください。

### キャッシュの信頼性

キャッシュエントリーはモデルなしでアクションをリプレイし、署名はされていません。

| ルール | 詳細 |
| --- | --- |
| 検証 | すべてのエントリーは使用前に検証されます。無効なエントリーはミスになります。 |
| ファイル名 | 期待されるキーのハッシュです。1 MiB を超えるファイルは拒否されます。 |
| キー | エージェントのコンテキストは、マスキング済みテキストのハッシュとしてのみ保持します。 |
| 内容 | アクションとマスキング済みの要約です。リプレイではアクションのみを実行します。その他の入力された値はそのまま保存されます。 |
| シークレットの入力 | 名前を保存し、リプレイ時に入力を再度承認します。 |
| エージェント | あるエージェントが記録したエントリーが、別のエージェントでリプレイされることはありません。 |
| 開始画面 | ナビゲーションで始まらないエントリーは、記録されたルート（同じパスとクエリ。生成された ID は無視されます）でのみリプレイされます。アプリ自身のオリジン上のルートは、`app.identity` を共有する任意のデプロイで一致します。別のオリジン上のルートはそのオリジンを保持します。[キャッシュ](/cache)を参照してください。 |
| CI | 設定していないキャッシュモードは、`cache.store` を設定していない限り `read-only` になります。 |
| Git | `e2e init` は `.e2e/cache/` を無視するように設定します。[記録をコミットする](/cache#commit-the-replay-cache)場合は、そのアクションと入力された値を確認してください。 |
| `cache.store` | 記録されたすべてのエントリーを受け取り、リプレイされるすべてのエントリーを提供します。戻ってきた内容は再度検証されます。 |

### アーティファクト

実行はデフォルトで `.e2e/` 配下に書き込みます。[`output`](/reference/config#output) オプションまたは `--output` で場所を変更できます。リプレイキャッシュは `cache.dir` に置かれ、`command.log` は設定したプロジェクト相対パスに出力されます。

| パス | 内容 | マスキング |
| --- | --- | --- |
| `report.json` | 実行の記録です。エラー、推論の抜粋、アクションの要約はマスキング処理を通ります。 | complete |
| `results/<test>/trace.md` | マスキング済みのレポートから書き出されたトレースページです。 | complete |
| `results/.../*.png` | セキュアなフィールドがマスクされたスクリーンショットです。 | complete |
| `results/.../*.webm`, `*.mp4` | 動画です。`video` または `--video` でオプトインします。 | incomplete |
| `results/.../downloads/*` | アプリが配信したファイルです。[ダウンロード](#downloads)を参照してください。 | complete または incomplete |
| `results/.../screen-at-failure.txt` | 失敗した時点のマスキング済みツリーです。 | complete |
| `ai-trace.json` | テストフィルターのものを除くすべてのモデル呼び出しです。`--ai-trace` でオプトインします。プロンプトはモデルが見たマスキング済みのものです。インライン画像のバイト列はそのサイズに置き換えられます。 | プロンプトと同じ |
| `sessions/<runId>/` | 暗号化されたセッションです。クリーンアップ時に削除されます。 | 暗号化 |
| `videos/<session>/*.webm`, `*.mp4` | `e2e mcp` セッションが `start_recording` で録画した動画です。削除するまで保持されます。`artifacts.store` に渡されることはありません。 | なし |
| `cache.dir`（デフォルトは `.e2e/cache/`） | リプレイキャッシュのエントリーです。 | 構造上シークレットを含まない |
| `command.log` に指定したパス | アプリの stdout と stderr をそのまま記録します。プロジェクトルート内である必要があります。 | なし |

`artifacts.store` は、各アーティファクトのバイト列を生成されるたびに、ダウンロードのマスキング後に、レポートが記録する `redaction` ラベルとともに受け取ります。

| モデルプロバイダー | モデルを呼び出すエージェントステップ。決定論的なテストと完全にリプレイされたステップはモデルを呼び出しません。 |

| Playwright のブラウザのダウンロード | ブラウザがない場合に 1 回。 |
| `web({ connect })` の DevTools エンドポイント | そのターゲットのすべての実行。 |
| GitHub API | `@e2e-dev/github` レポーターからのみ。 |
| 渡した `model` のプロバイダー | [`decisionFilter()`](/filters) からのみ。コミットによる変更の差分（作業ツリーのみが変更したファイルは名前のみ）、テストファイル、セッションを保存するセットアップファイルが、[テキストのダウンロード](#downloads)と同様にマスキングされて送られます。ただし、シークレットプロバイダーが返す値は除きます。 |

| `api.limrun.com`（または `LIMRUN_BASE_URL`）とそのデバイス | [`limrun()`](/integrations/limrun) からのみ。`LIMRUN_API_KEY` でサインインします。 |

| `mcr.microsoft.com` | [`smol()`](/integrations/smol) からのみ。Playwright のイメージを取得するためです。その後、マシンは無制限のネットワークアクセスを持ち、`hostPorts` だけでなく、`host.smolvm.internal` を通じてコンピューターのループバック上のすべてのポートに到達できます（[プロバイダーをセットアップする](/integrations/smol#set-up-the-provider)）。 |
| パッケージレジストリ | `e2e init` が依存関係をインストールするとき。 |
| テスト対象のアプリ | すべての実行。加えて、アプリ自身が読み込むもの。 |

### MCP と explore

| コマンド | ルール |
| --- | --- |
| `e2e mcp` | stdio と、テスト実行と同じアクションの承認を使用します。デフォルトで 4 つのセッションを開けます（[`--max-sessions`](/reference/mcp)、1〜16）。アイドル状態のセッションを閉じます。`open_session {engine}` は、エージェントが指定したインストール済みパッケージを読み込み、指定されたエクスポートを呼び出します。そのコードは、設定のインポートと同様に、サーバーの全権限で実行されます。`engine` はパッケージのみを指定し、パスや URL は指定できません。サーバーは何もインストールしません。 |
| `e2e explore` | 設定されたすべての認証情報をすべてのステップに提供します。エクスプローラーにはアカウント名とユーザー名が見えます。パスワードはハンドルのままで、機密情報の入力をサポートするエンジンが必要です。そのようなエンジンがない場合、エクスプローラーはパスワードをスキップします。認証情報がない場合、架空のテスト用認証情報をプレーンテキストとして入力してサインインすることがあります。 |
| `e2e explore --changed-since` | ベースからのコミットメッセージ、変更されたファイルの名前、コミットされたパッチを、コンテキストに収まるよう切り詰めてモデルに送信します。CI が書き込んだファイルのようにどのコミットも変更していないファイルや、コミット済みファイルのその後のローカルでの編集は、名前のみが送られ、内容は読み取られません。設定が文字列として与えたシークレットの値と、その 8 文字以上の連続はマスキングされます。シークレットプロバイダーの値や、設定で名前が指定されていない、リポジトリにコミットされたシークレットはモデルに届きます。 |
