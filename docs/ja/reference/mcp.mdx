`e2e mcp` を使うと、Claude Code や Cursor などのコーディングエージェントが、テストを書きながらアプリを調べ、ロケーターを試し、テスト行を実行し、マスク済みのスクリーンショットを撮れるようになります。stdio 上で動作し、プロジェクトで設定されたエンジンを使います。セットアップ方法やエージェントへの依頼内容については、[MCP サーバーガイド](/mcp-server)を参照してください。

```json title=".mcp.json"
{
  "mcpServers": {
    "e2e": { "command": "npx", "args": ["e2e", "mcp"] }
  }
}
```

4 つの MCP ツールがセッションを管理し、そのセッションで利用できるアプリツールを呼び出します。また、`run_tests` は `e2e run` と同じようにスイートを実行します。アプリツールのカタログは、セッションを開くたびに設定から再読み込みされます。

## リファレンス

### フラグ

<CodeGroup>
```bash npm
npx e2e mcp [--config <path>] [--target <name>] [--headed] [--max-sessions <n>]
```

```bash pnpm
pnpm exec e2e mcp [--config <path>] [--target <name>] [--headed] [--max-sessions <n>]
```

```bash bun
bunx e2e mcp [--config <path>] [--target <name>] [--headed] [--max-sessions <n>]
```
</CodeGroup>

| フラグ | デフォルト |
| --- | --- |
| [`--config <path>`](#config) | `e2e run` と同じ方法で検出 |
| [`--target <name>`](#target) | 唯一のターゲット |
| [`--headed`](#headed) | ヘッドレス |
| [`--max-sessions <n>`](#max-sessions) | `4`、Bun では `1` |

#### `--config`

`open_session` で指定されない限り、すべてのセッションが読み込む設定です。各セッションはサーバーの環境でこれを新たに読み込みます（[複数のセッション](#several-sessions)）。設定内の `process.env` は、エージェントのシェルではなく、MCP クライアントが `e2e mcp` を起動したときの環境変数を読み取ります。

#### `--target`

`open_session` でターゲットが指定されないときに、セッションが開くターゲットです。

- このフラグも名前の指定もない場合は、唯一のターゲットが使われます。
- ターゲットが複数あり、名前の指定がない場合は `TARGET_REQUIRED` になります。

#### `--headed`

`open_session` で `headed` を設定していないすべてのセッションで、エンジンが対応していればブラウザまたはシミュレーターを表示します。

- `e2e run` と同様に、セッションはデフォルトでヘッドレスです。

#### `--max-sessions`

同時に開けるセッションの数で、1 から 16 までです。[Bun](/reference/cli#bun) では 1 です。[複数のセッション](#several-sessions)を参照してください。

```bash
e2e mcp --max-sessions 8 # default: 4
```

### ツール

| ツール | 説明 |
| --- | --- |
| [`open_session`](#open_session) | セッションを開きます |
| [`tools`](#tools-2) | カタログ、または 1 つのツールを一覧表示します |
| [`call`](#call) | カタログのツールを 1 つ実行します |
| [`close_session`](#close_session) | セッションとそのエンジンを終了します |
| [`run_tests`](#run_tests) | `e2e run` と同じようにテストを実行します |

開いているセッションがちょうど 1 つの間は、`session` を省略できます。[複数のセッション](#several-sessions)を参照してください。

#### `open_session`

設定を読み込み、ターゲットのアプリコマンドを起動し、エンジンを立ち上げ、1 回のアテンプトを開始して、アプリを開きます。エンジンがナビゲートできる場合はアプリの URL を、デバイスでは[固定されたアプリ](/mobile#point-at-your-app)を新たに起動して開きます。ビルドはインストールしないため、ローカルデバイスのターゲットには `app.bundleId` が必要です。セッション ID、カタログ、最初の観測結果を返します。観測結果の上にあるサマリーは、テストを書いたり編集したりする前に `writing-tests` ガイド（`e2e://guide/writing-tests`）を読むようエージェントに伝えます。サーバーの指示にも同じことが書かれています。

サマリーには、アプリの URL（空きポートを使う `url` に割り当てられたポートを含む）と、アプリコマンドの情報（実行ファイル、準備完了を確認する URL、`env` と `inheritEnv` の名前、ログファイル）が示されます。`args`、`env` の値、URL のユーザー情報やクエリは出力しません。e2e は他のアプリプロセスを起動しないため、アプリが使うデータベースは e2e の外で動作します。

```text wrap
App: http://127.0.0.1:57162/ (port 57162, assigned for the declared port 0).
Process: app.command "node" (ready at http://127.0.0.1:57162/; env PORT, DATABASE_URL; log .e2e/app.log). e2e starts no other app process for this session; a database or other service the app uses runs outside e2e.
```

```txt
open_session {target: "web", headed: true}
```

| 入力 | 型 | 必須 | 動作 |
| --- | --- | --- | --- |
| `target` | string | いいえ | 開くターゲットです。指定しない場合は `--target`、それもなければ唯一のターゲットです。 |
| `config` | string (path) | いいえ | このセッションの設定です。絶対パス、またはサーバーの作業ディレクトリ（クライアントの MCP 設定の `cwd`）からの相対パスで指定します。指定しない場合は `--config`、それもなければ `e2e run` と同じ方法で検出します。 |
| `headed` | boolean | いいえ | `true` はこのセッションのブラウザまたはシミュレーターを表示し、`false` は非表示にします。指定しない場合、セッションは `--headed` に従います。 |
| `test` | string | いいえ | 最初に実行するテスト 1 つで、`e2e run` の位置引数と同じ形式で指定します。セッションはテストが停止した場所で止まります。[テストの実行](#running-a-test)を参照してください。 |
| `engine` | string or object | いいえ | 設定ファイルがないディレクトリでのセッションのエンジンで、パッケージ名または `{package, export, options}` で指定します。[設定なしで使う](#without-a-config)を参照してください。 |
| `app` | object | いいえ | `engine` セッションのテスト対象アプリで、`url`、`bundleId`、`appPath` のいずれかで指定します。 |

#### `tools`

カタログを、1 ツールにつき 1 行で返します。

```txt
tools {tool: "locate"}
```

| 入力 | 型 | 必須 | 動作 |
| --- | --- | --- | --- |
| `tool` | string | いいえ | カタログのツールです。そのツールの完全な説明と引数スキーマを返します。 |
| `session` | string | 複数開いている間 | セッション ID です。 |

#### `call`

カタログのツールを 1 つ実行します。

```txt
call {tool: "tap", args: {target: "n42"}, session: "<id>"}
```

| 入力 | 型 | 必須 | 動作 |
| --- | --- | --- | --- |
| `tool` | string | はい | カタログのツール名です。 |
| `args` | object | いいえ | ツールの引数です。 |
| `session` | string | 複数開いている間 | セッション ID です。 |

- 引数はまずツールのクローズドなスキーマに対して検証されます。型が間違っている場合や、引数を宣言しているツールが宣言していない引数がある場合は `INVALID_ARGUMENT` になり、何も実行されません。`back` と `dismiss_keyboard` は引数を取らず、渡された引数を破棄して実行されます。
- 失敗したアクションはエラー結果になりますが、再観測した画面は含まれます。結果の先頭にはツール、そのターゲット、コードが示されます:
  `navigate file:///etc/passwd failed: POLICY_DENIED: forbidden URL scheme: file:`。
- プロジェクトツールは、`execute` が文字列を返す場合も含め、AI SDK の `toModelOutput` レンダラーに従います。レンダリングされた `error-text` と `error-json` の出力は MCP のエラー結果（`isError: true`）になります。コーディングエージェントは、失敗したツール呼び出しと成功したものを区別できます。

#### `close_session`

実行中の録画を保存し、アテンプトを終了し、エンジンを破棄します。セッションが起動したアプリプロセスは、他のどのセッションも使わなくなった時点で停止します。

```txt
close_session {session: "<id>"}
```

| 入力 | 型 | 必須 | 動作 |
| --- | --- | --- | --- |
| `session` | string | 複数開いている間 | セッション ID です。 |

#### `run_tests`

`e2e run` を独自のプロセスで実行し、コマンド、終了コードとその意味、そして実行中に出力された内容を返します。デフォルトの `list` レポーターでは、各テスト、失敗ブロック、サマリーが含まれます。セッションは不要で、開いているセッションには影響しません。セッションと並行して実行する方法については、[セッションと並行してテストを実行する](/mcp-server#run-tests-next-to-a-session)を参照してください。

```txt
run_tests {files: ["tests/checkout.e2e.ts:12"]}
```

```text wrap
e2e run tests/checkout.e2e.ts:12
exit 1: a test failed or timed out

 RUN  e2e v0.22.0 /work/shop
 ...
```

| 入力 | 型 | 必須 | 動作 |
| --- | --- | --- | --- |
| `files` | string[] | いいえ | `e2e run` の位置引数です。ファイル、ディレクトリ、glob、または `file:line` を指定します。指定しない場合は、設定が検出するすべてのテストです。ファイルは `-` で始めることはできません。 |
| `config` | string (path) | いいえ | `--config` です。指定しない場合はサーバーの `--config` です。 |
| `target` | string[] | いいえ | `--target` で、1 つ以上指定します。指定しない場合はサーバーの `--target`、それもなければすべてのターゲットです。 |
| `grep`, `grepInvert` | string | いいえ | `--grep`、`--grep-invert` です。 |
| `tag`, `excludeTag` | string[] | いいえ | `--tag`、`--exclude-tag` です。 |
| `lastFailed` | boolean | いいえ | `--last-failed` です。 |
| `changedSince` | string | いいえ | `--changed-since` です。 |
| `headed` | boolean | いいえ | `--headed` です。指定しない場合はサーバーの `--headed` です。 |
| `workers`, `retries`, `repeatEach`, `maxFailures`, `actionTimeout` | integer | いいえ | `--workers`、`--retries`、`--repeat-each`、`--max-failures`、`--action-timeout` です。 |
| `noCache` | boolean | いいえ | `--no-cache` です。 |
| `updateSnapshots` | boolean | いいえ | `--update-snapshots` です。 |

- 終了コード 0 と 1 は結果です。それ以外の終了コードはエラー結果（`isError: true`）になります。
- 60,000 文字を超える出力は、失敗とサマリーがある末尾が残されます。実行がテストに到達すれば、すべての結果は `<output>/report.json`（デフォルトは `.e2e`）に保存されます。[出力](/reference/cli#output)を参照してください。
- プログレストークンがある場合、空でない stdout の各行が進捗通知になり、1,000 文字で切り詰められます。
- 呼び出しをキャンセルすると、Ctrl-C を押したときと同じように実行が中断されます。15 秒ごとに再度押したのと同じ扱いになり、3 回目の 15 秒後に強制終了されます。次の `run_tests` は、その終了を待ちます。
- サーバーがシャットダウンするときは、新しい実行を拒否し、進行中の実行を中断します。サーバーが終了した実行も、同じように自ら中断します。

| エラー | 条件 |
| --- | --- |
| `RUNNER_BUSY` | すでに実行が進行中です。 |
| `CANCELLED` | 実行が始まる前に呼び出しがキャンセルされたか、サーバーがシャットダウン中です。 |

### カタログ

`call` で実行できるものは、セッションのターゲットによって異なります。

| カタログツール | 説明 |
| --- | --- |
| [`observe`](#observe) | 新しい観測結果を返します |
| [アクション](#actions) | 観測されたノードを操作します |
| [`dismiss_keyboard`](#dismiss_keyboard) | 画面上のキーボードを隠します |
| [`locate`](#locate) | セマンティックロケーターを試します |
| [`run_code`](#run_code) | テストのステートメントを実行します |
| [`test_lines`](#test_lines) | セッションのテスト行を返します |
| [`screenshot`](#screenshot) | マスク済みのビューポートを返し、必要に応じてファイルに保存します |
| [座標ツール](#point-tools) | スクリーンショット上の座標で操作します |
| [`start_recording`, `stop_recording`](#recording) | アプリの動画を録画します |
| [プロジェクトツール](#project-tools) | `defineTool` で定義したツールです |

#### `observe`

新しい観測結果です。1 ノードにつき 1 行で `#id role "name" ...` の形式で示され、現在のパスとリビジョンが付きます。引数は取りません。

- リンクの `href` は、アプリの URL と同じオリジンであればパスで、そうでなければオリジンとパスで示されます。
- `mailto:`、`tel:`、`blob:` のターゲットはスキームを保持します。
- `…` は省略された部分を示します。`?…` はクエリ、`#…` はフラグメント、`data:…` や `javascript:…` はインラインのペイロード、末尾の `…` は 256 文字で切り詰められたターゲットです。

#### アクション

`tap`、`double_tap`、`long_press`、`right_click`、`hover`、`type`、`press`、`select`、`check`、`scroll`、`scroll_to`、`drag`、`upload`、`navigate`、`back`、`resize_viewport`、`switch_tab`、`close_tab`、`type_secret`。それぞれ、アクションのサマリー、そのアクションを再現する[テスト行](#test_lines)（ない場合はその理由）、画面上で変化した内容を返します。

| 入力 | 動作 |
| --- | --- |
| ノード ID | 最新の観測結果のものです。 |
| 値、キー、`checked` の状態、方向、ドロップ先、プロジェクト相対または `sample:` の `files`、URL、`width` と `height`、またはシークレット名 | 動詞が必要とするものです。 |
| `modifiers`（任意） | エンジンが `tapModifiers` を宣言している場合の `tap`、`double_tap`、`right_click` で使います。クリック中に押しておく `Shift`、`Control`、`Alt`、`Meta`、`ControlOrMeta` のリストです。 |

- エンジンが宣言していない動詞はカタログに含まれません。
- `upload` は、プロジェクト外のパス、隠しファイル、隠しディレクトリ配下のファイルを `POLICY_DENIED` で拒否します。`sample:` のファイルにはテスト行がありません。テスト行が必要な場合は、ファイルをプロジェクト内に保存してください。
- `type_secret` は、設定で `credentials` または `secrets` が宣言され、エンジンが `fill` アクションを宣言している場合に一覧に含まれます。平文がテキストとしてエージェントに届くことはありません。[シークレット入力後のスクリーンショット](/reference/security#screenshots-after-a-secret-fill)を参照してください。

#### `dismiss_keyboard`

画面上のキーボードを隠します。引数は取りません。デバイスエンジンのように、エンジンのキーボードが `dismiss` を宣言している場合に一覧に含まれます。

#### `locate`

セマンティックロケーターに一致するノードの数、どのノードが一致するか、そして書くべき `screen.*` の呼び出しを返します。

| 入力 | 動作 |
| --- | --- |
| `role`（任意で `name` を付ける）、`text`、`label`、`placeholder`、`testId` | このうちちょうど 1 つを指定します。 |
| `exact` | 完全一致です。`false` にすると、大文字と小文字を区別しない部分一致になります。 |

- 一致が 0 件または複数件の場合は、テストで発生するエラーが示されます。
- `name` はアクセシブルネームにのみ一致します。`observe` は `status`、`alert`、`listitem` をそのテキストで表示するため、これらのロールで名前が何にも一致しない場合は、`getByRole(role).filter({ hasText })` と `getByText` も提示されます。
- ノードについて表示される内容は、`observe` と同様にシークレット台帳を通過します。入力済みのシークレットは `<secret:name>` と表示されます。

#### `run_code`

ライブセッションでテストのステートメントを実行し、各ステートメントの成否、読み取りの値、画面上で変化した内容を返します。テストに書き込む前に、ここで行を実行してください。

```txt
call {tool: "run_code", args: {code: "await screen.getByLabel('Email').fill('ada@example.com');\nawait expect(screen.getByRole('status')).toHaveText('Saved');"}}
```

| 入力 | 動作 |
| --- | --- |
| `code` | テスト本体に書くのと同じ形式の 1 つ以上のステートメントで、`;` または改行で区切ります。 |
| `timeout` | 任意です。各ステートメントが待機できる時間（ms）で、1 から 120000 までです。デフォルトは `5000` です。 |

- ステートメントは、テストと同じ待機、ちょうど 1 つのルール、マッチャーを使って、セッションの `screen` と `app` フィクスチャ上で順に実行されます。
- 最初の失敗で呼び出しは止まります。残りは実行されず、アプリは成功したステートメントが残した状態のままになり、結果はテストで発生するのと同じコードとメッセージを持つエラー結果になります。
- 成功したステートメントは、読み取りを除き、書かれたとおりに実行順で [`test_lines`](#test_lines) のドラフトに追加されます。
- 各ステートメントは、そのステートメント自身の `timeout` オプションも含め、最大で `timeout` まで待機します。設定の [`actionTimeout`](/reference/config#actiontimeout) と [`assertionTimeout`](/reference/config#assertiontimeout) の方が短い場合はそちらが適用されます。この上限は `app.open`、`app.restart`、`app.clearState` にも適用されるため、最初の読み込みが遅い場合やデバイスの再起動を行う場合は値を大きくしてください。
- `timeout` は、マッチ中の正規表現を止めません。長い行に対する `/^(\w+\s?)*$/` のようにバックトラックする正規表現は、終わるまでサーバーをブロックします。
- 読み取りとマッチャーには、シークレットの値がある場所で `<secret:name>` が見えます。
- シークレットの `fill` は、入力先のフィールドで `type_secret` と同じチェックを通過します。設定済みのシークレットであること、有効で編集可能なフィールドであること、パスワードの場合はパスワードフィールドであることです。

コードは解析されるだけで、JavaScript として実行されることはありません。文法は次のものを受け付けます:

| 部分 | 受け付けるもの |
| --- | --- |
| ステートメント | 任意の `await` に続けて、アクションまたは読み取りで終わる `screen` か `app` のチェーン、または任意の `.not` と 1 つのマッチャーを付けた `expect(locator)` |
| ロケーター | `screen.getByRole`、`getByLabel`、`getByText`、`getByPlaceholder`、`getByTestId`、`getByDisplayValue` を、`filter`、`or`、`first`、`last`、`nth`、さらに `getBy*` で絞り込んだもの |
| 引数 | 文字列、数値、真偽値、`null`、正規表現、`${}` を含まないテンプレート、配列、オブジェクト、ロケーター、または `credentials.user(name).username` |
| シークレット | `credentials.user(name).password` または `secrets.get(name)`。`fill` の値としてのみ使えます |

対象外: エンジンが提供するフィクスチャ（`browser`、`device`）、`expect(screen)`、`toHaveScreenshot`、`app.screenshot`、`screen.debug`、`all`、`setInputFiles`、値のマッチャー（`toBe`、`toEqual`）。

| エラー | 条件 |
| --- | --- |
| `INVALID_ARGUMENT` | 解析できないコード、または文法の範囲外のコードです。たとえば別の名前、サポートされていない呼び出し、代入、関数などです。メッセージには行と列とともにその部分が引用され、ステートメントは 1 つも実行されません。 |
| `INVALID_ARGUMENT` | `<secret:name>` を期待するマッチャーです。テストは実際の値と比較するためです。ステートメントは 1 つも実行されません。 |
| `POLICY_DENIED` | `type_secret` のチェックに通らないフィールドへのシークレットの `fill` です。何も入力されません。 |
| `POLICY_DENIED` | パスワードフィールドの読み取りです。 |
| `POLICY_DENIED` | 設定でシークレットまたは認証情報が宣言されている場合に、テキストの一部で見つけるロケーターです。正規表現、`true` 以外の `exact`、または `hasText` が該当します。正確なテキストで見つけてください。ステートメントは 1 つも実行されません。 |

#### `test_lines`

セッションのアクションが出力したすべてのテスト行と、[`run_code`](#run_code) で成功したすべてのステートメントを、順にテスト本体のドラフトとして返します。引数は取りません。

各アクションの結果には、サマリーの後にその行が含まれます:

```txt
Tapped #n31.
Test line: await screen.getByRole("button", "Sign in").tap();
```

- ロケーターは、アクションの実行前に最新の観測結果が示していたターゲットから作られます。ロールと名前、ラベル、プレースホルダー、テキスト、テスト ID の順に試され、ライブ画面上でターゲットに一致し、他の何にも一致しない最初のものが採用されます。これは [`locate`](#locate) が報告する結果と同じです。
- 同じものに一致する別のノードもある場合、ロケーターは絞り込まれます。まず描画されているノード（`{ visible: true }`）に、次にコンテナの配下（`getByRole("listitem").filter({ hasText: "Offer B" })`）に、最後に位置（`.nth(1)`、その旨のコメント付き）で絞り込みます。位置が使われるのは、ライブ画面上の同一ノード群が観測結果に示されていたものであり、それぞれが元の位置にあるか、すべてが一緒に移動した場合だけです。
- ターゲットごとに試すロケーターは最大 10 個です。デバイスでは、試すたびに画面全体を読み取ります。
- ターゲットだけに到達するものがない場合、結果には `No test line:` とその理由が示されます。失敗するような行が出力されることはありません。
- 失敗したアクションは行を出力も記録もしません。ドラフトでは、行のないアクションは `//` コメントとして示されます。

| アクション | 行 |
| --- | --- |
| [`test`](#running-a-test) なしでセッションを開く | `app.open()` |
| `tap`、`double_tap`、`long_press`、`right_click`、`hover` | `tap()`、`doubleTap()`、`longPress()`、`secondaryTap()`、`hover()`。`modifiers` があればそれも含みます |
| ノードへの `type` | `fill(value)`。認証情報のユーザー名は `credentials.user(name).username` になります |
| `type_secret` | `fill(credentials.user(name).password)` または `fill(secrets.get(name))`。値そのものは決して出力しません |
| ノードへの 1 回の `press` | `press(key)` |
| `select`、`check` | `selectOption(label)`、`check()` または `uncheck()` |
| `drag`、`upload` | `dragTo(locator)`、`setInputFiles(files)` |
| ノードへの `scroll_to` | `scrollIntoView()` |
| `navigate`、`back` | `app.open(url)`。アプリと同じオリジンの URL はパスになります。`app.back()` |

行が出力されないもの: ターゲットのない `type` や `press`、`times` が 1 を超える `press`、`scroll`、テキストへの `scroll_to`、`dismiss_keyboard`、`resize_viewport`（サイズはエンジンのフィクスチャで設定します。Web では `browser.setViewport` です）、`switch_tab` と `close_tab`（Web では `browser.tabs()[tab - 1].activate()` と `.close()` です）、そしてノードがキーボード経由で受け取った `type`。[座標ツール](#point-tools)は何も出力しません。

#### `screenshot`

マスク済みのビューポートを画像として返します。

| 引数 | 型 | 説明 |
| --- | --- | --- |
| `path` | `string` | 任意です。スクリーンショットを PNG ファイルとしても保存し、その絶対パスを返します。パスはプロジェクトルートを基準に解決されます。プロジェクト外のパス、隠しファイル、隠しディレクトリ配下のパスは `POLICY_DENIED` になります。 |

```json
{ "tool": "screenshot", "args": { "path": "screenshots/checkout.png" } }
```

- 以降は、すべてのアクションの結果に新しいスクリーンショットが含まれます。
- シークレットの入力後も含め、マスクされるのはセキュアフィールドだけです。
- ファイルは、`app.screenshot` と同じようにマスクされた、フル解像度の 2 回目のキャプチャです。添付される画像は縮小されることがあります。

#### 座標ツール

各ツールは、最新のスクリーンショットのピクセル単位で `x` と `y` を受け取ります。`drag_at` は、ドロップ先の座標を `to_x` と `to_y` で受け取ります。

| ツール | 入力 | 動作 | エンジンが宣言している場合に一覧に含まれるもの |
| --- | --- | --- | --- |
| `tap_at` | `x`, `y` | エンジンの `performAt` を通じて、その座標そのものをタップします。`performAt` がない場合、座標は一覧にあるコントロール上でなければならず、そのコントロールが ID でタップされます。 | `tap` または `performAt` |
| `hover_at` | `x`, `y` | 同じ方法でホバーします。`performAt` の `hover` 種別で座標そのものに、そうでなければその下にある一覧のコントロールに ID でホバーします。 | `hover` アクションまたはポインター種別 |
| `drag_at` | `x`, `y`, `to_x`, `to_y` | `performAt` の `dragTo` 種別を通じて、最初の座標から 2 番目の座標までドラッグします。その種別がない場合、座標は一覧にある 2 つの異なるコントロール上でなければならず、それらが ID でドラッグされます。そうでなければ呼び出しは `UNSUPPORTED_CAPABILITY` で失敗します。 | `dragTo` アクションまたはポインター種別 |
| `type_at` | `x`, `y`, `value`。キーボードのあるエンジンでは `replace` も | 座標の下にある一覧の入力欄を ID で入力します。キーボードがある場合、それ以外のものはタップしてフォーカスし、`replace` が設定されていなければキャレット位置に入力します。キーボードがない場合、一覧に何もない座標では失敗します。 | `type` またはキーボード |
| `press_at` | `x`, `y`, `key` | 座標の下にある一覧のコントロールに ID でキーを送ります。キーボードがある場合、それ以外のものはタップしてフォーカスし、キーはキーボードを通じて送られます。 | `press` またはキーボード |
| `select_at` | `x`, `y`, `value`（オプションの表示ラベル） | 座標の下にある一覧のセレクト系コントロールでオプションを選択します。そこに一覧のものがなければ失敗します。 | `select` |

<Note>
セッションで最初の `screenshot` を撮る前は、各座標ツールはスクリーンショットを撮るよう伝える 1 行を返します。コストはかかりません。
</Note>

#### 録画

`start_recording` と `stop_recording` はアプリの動画を録画します。どちらも、エンジンが動画を録画できる場合に一覧に含まれます。

```txt
call {tool: "start_recording", args: {name: "checkout-flow"}}
call {tool: "stop_recording"}
```

| ツール | 入力 | 動作 |
| --- | --- | --- |
| `start_recording` | `name`（任意）: 英字、数字、`-`、`_` で 64 文字まで。英字または数字で始まる必要があります | 録画は一度に 1 つです。2 回目の開始は、実行中の録画を報告します。 |
| `stop_recording` | なし | 動画を保存し、各ファイルの絶対パス、またはプロバイダーが保管している場所の URL を返します。 |

- セッションが動画を録画するのは `start_recording` から `stop_recording` までの間だけで、必要なだけ何度でも録画できます。設定の [`video`](/reference/config#video) モードは実行に適用され、セッションには適用されません。また、セッションは[トレース](/reference/config#trace)を書き出しません。
- 各録画は `<output>/videos/<session>/<n>[-<name>].webm`（モバイルでは `.mp4`。[`output`](/reference/config#output) のデフォルトは `.e2e`）に保存されます。`n` はセッションの録画の通し番号です。
- 再起動や状態のリセットをまたぐ Web の録画は、ページごとに 1 ファイルになり、再生順に `-part2`、`-part3` などとなります。
- リース自体を録画するブラウザまたはデバイスのプロバイダーでは、代わりにそのプロバイダーがセッションを録画します。[Kernel](/integrations/kernel) はリプレイをダウンロードし、他のファイルと同様に `<n>[-<name>].mp4` としてここに保存します。録画を保管するプロバイダーの場合は、ファイルではなく URL で示されます。
- `close_session`、アイドルタイムアウト、セッションの TTL は、実行中の録画を保存し、クローズの結果にそのファイルが一覧表示されます。

<Warning>
録画はマスクされません。録画は人が見るためのファイルであり、そのピクセルを返すツールはありません。録画中に通常の入力欄に入力したシークレットは、動画で読み取れてしまいます。
</Warning>

#### プロジェクトツール

`agents.default.tools` のプロジェクトツールは、ターゲットのプラットフォームに限定されて、それぞれの名前でカタログに続けて含まれます。`mobileTools(...)` を渡すモバイルプロジェクトでは、`open_app`、`swipe`、`alert` も利用できます。

| エラー | 条件 |
| --- | --- |
| `INVALID_CONFIG` | 組み込みツールと同じ名前のプロジェクトツールです。設定の読み込み時に発生します。 |
| `UNKNOWN_TOOL` | カタログにない名前です。メッセージには名前の一覧が示されます。 |

## セットアップ

サーバーは `e2e` に同梱されています。`e2e init` は、`.mcp.json`（Claude Code）、`.cursor/mcp.json`（Cursor）、`.codex/config.toml`（Codex）への登録を提案します。依存関係をインストールし、プロジェクトディレクトリで MCP クライアントを起動すると、`npx`（Bun プロジェクトでは `bunx`）がインストール済みの e2e のバージョンを使います。手動で登録する場合:

<CodeGroup>
```bash npm
claude mcp add --scope project e2e -- npx e2e mcp
```

```bash pnpm
claude mcp add --scope project e2e -- pnpm exec e2e mcp
```

```bash bun
claude mcp add --scope project e2e -- bunx e2e mcp
```
</CodeGroup>

`mcpServers` 形式の設定を使うクライアントでは、上記のエントリーを追加してください。Codex は、プロジェクトが信頼されると、プロジェクトの `.codex/config.toml` を読み込みます。登録後は新しいセッションを開始してください:

```toml title=".codex/config.toml"
[mcp_servers.e2e]
command = "npx"
args = ["e2e", "mcp"]
```

サーバーは [MCP Registry](https://registry.modelcontextprotocol.io) にも `io.github.e2e-inc/e2e` として掲載されています。そこからインストールするクライアントは、掲載されているリリースを `npx` で実行するため、プロジェクトディレクトリで起動する必要があります。設定がそれらをインポートするため、プロジェクトには引き続き e2e とそのエンジンをインストールしておく必要があります。プロジェクトの e2e とは異なるバージョンの掲載リリースは、知らない設定キーを拒否することがあります。上記の登録方法なら、常にバージョンが一致します。

サーバーにモデルは必要ありません。オプションの `ai` パッケージがないプロジェクトでも、セッションを開き、決定論的なツールでアプリを操作できます。セッションが[実行する](#running-a-test)テストは、リプレイキャッシュで対応できないエージェントステップについて、設定されたモデルを呼び出します。

サーバーはプロジェクトディレクトリで起動してください。設定の検出は `e2e run` と同じように動作します。別の設定を使う場合は、[`--config`](#config) と [`open_session`](#open_session) を参照してください。

## 設定なしで使う

設定ファイルがないディレクトリでは、`open_session` に `engine` が必要です。セッションには、そのエンジン上のターゲットが 1 つあります。その他の設定はすべてデフォルトのため、セッションには認証情報、シークレット、プロジェクトツールがありません。

```txt
open_session {engine: "@e2e-dev/web", app: {url: "http://localhost:3000"}}
open_session {engine: {package: "@e2e-dev/mobile", options: {platform: "ios"}}, app: {bundleId: "com.example.app"}}
```

オプションが不要なエンジンであれば、パッケージ名だけで十分です。オプションを渡す場合や、エクスポートを指定する場合は、`engine` をオブジェクトとして書きます:

| フィールド | 型 | 動作 |
| --- | --- | --- |
| `package` | string | 読み込むパッケージです。`@e2e-dev/testmu/web` のようにサブパスを含めることもできます。 |
| `export` | string | 呼び出すエクスポートです。デフォルトはデフォルトエクスポートです。 |
| `options` | object | `e2e.config.ts` と同様に、ファクトリーが受け取るオプションです。 |

- **パッケージ名だけの場合**は、パッケージのデフォルトエクスポートをオプションなしで呼び出します。`@e2e-dev/web` と `@e2e-dev/mobile` はこの方法でファクトリーをエクスポートしています。[独自のエンジン](/writing-an-engine#open-it-by-name)でも同じようにできます。
- **オプションには別のファクトリー呼び出しを指定できます。** オプションの値が `package` を持ち、`export` と `options` 以外のキーを持たない場合、サーバーはそれを呼び出しとして読み取ります。その呼び出しを先に行い、結果をオプションとして渡します。エンジンにデバイスやブラウザのプロバイダーを渡すときに使います:

  ```txt
  open_session {
    engine: {package: "@e2e-dev/mobile", options: {
      platform: "ios",
      device: {package: "@e2e-dev/limrun", export: "limrun", options: {region: "eu"}}
    }},
    app: {bundleId: "com.example.app"}
  }
  ```

  上記の呼び出しは
  `mobile({ platform: 'ios', device: limrun({ region: 'eu' }) })` を構築します。プロバイダーは API キーをサーバーの環境から読み取ります。
- **検索。** サーバーは各パッケージを、プロジェクト、実行中の `e2e` の隣、`~/.e2e/engines` の順に探します。どこにも見つからない場合、エラーにはすべてのプロジェクト向けにインストールするコマンドが示されます:
  `npm install --prefix ~/.e2e/engines @e2e-dev/web`。ネットワークアクセスのないサンドボックス内のエージェントなど、そのコマンドを実行できないエージェントは、実行をあなたに依頼します。
- **`app`** は、ターゲットの [`app`](/reference/config#the-app-under-test) と同様に、`url`、`bundleId`、`appPath` を受け取ります。`@e2e-dev/web` には `url` が必要です。`@e2e-dev/mobile` には `bundleId` または `appPath` が必要です。
- **ファイル。** プロジェクトルートはサーバーの作業ディレクトリで、セッションはそこに `.e2e/` を書き出します。
- **テスト。** `run_tests` と `open_session {test}` には設定が必要です。セッションのテスト行をテストとして残すには、[`e2e init`](/reference/cli#e2e-init) で設定を作成してください。
- **複数のセッション。** `engine` で開いたセッションは並行して実行されます。設定を使うセッションは、それらと並行して開くことはできず、`CONFIG_IN_USE` で失敗します。

| エラー | 条件 |
| --- | --- |
| `CONFIG_NOT_FOUND` | `engine` なしの `open_session` で、ディレクトリに設定がありません。 |
| `ENGINE_NOT_INSTALLED` | `engine` で指定したパッケージが、3 つの検索場所のいずれにもありません。 |
| `INVALID_ARGUMENT` | `package` がパッケージ名ではない、`export` がエクスポート名ではない、`engine` が `target`、`config`、`test` と一緒に指定された、またはディレクトリに設定がある場合です。`engine` なしの `app` も該当します。 |
| `INVALID_CONFIG` | 指定したエクスポートが関数ではない、ファクトリーが `options` を拒否した、エンジンのファクトリーがエンジンを返さなかった、またはエンジンが `app` を拒否した場合です。エクスポートが関数でない場合、メッセージにはパッケージの関数の一覧が示されます。 |

## 出力

- オペレーター向けの出力は、`e2e mcp:` の接頭辞付きで stderr に出力されます。stdout にはプロトコルだけが流れます。
- コード（設定のトップレベルのコード、プロジェクトツール、セッションが実行するテスト）が `console`、`process.stdout`、`process.stderr` を通じて書き出す内容は、シークレットの値を伏せたうえで stderr に出力されます。
- 設定の読み込み中に出力された内容は、読み込みが完了した時点で表示されます。読み込みに失敗した場合、設定のシークレットが不明なため、その出力は表示されません。
- セッションのテストが reject されたままにした Promise は、実行時と同様にそのテストを失敗させます。テスト本体の終了後に reject されたものは、`close_session` の結果に `UNHANDLED_REJECTION` の行として示され、セッションが閉じた後に stderr に警告が出力されます。どのセッションもまだテストを実行していない時点での reject を含め、それ以外の誰も捕捉しなかったエラーは、伏せ字にしたうえでログに記録され、サーバーはシャットダウンします。

<Note>
サーバーの stdio を継承した子プロセスは、この仕組みを経由せずに書き出します。
</Note>

## セッション

セッションは、1 つのターゲットに対する 1 回のアテンプトです。セッションが 1 つも開いていない状態での `call` は `NO_SESSION` で失敗します。

セッションは次の場合に閉じます:

- `close_session` を呼び出したとき
- 30 分間アイドル状態が続いたとき
- 4 時間が経過したとき
- クライアントが切断したとき
- SIGINT または SIGTERM を受け取ったとき

クライアントが切断するのは、サーバーの stdin を閉じたとき、またはクライアントが終了したときです。その場合、すべてのセッションが閉じ、セッションが起動したアプリコマンドが停止し、`run_tests` の実行が中断され、サーバーが終了します。

セッションには、テストと同じ制約が適用されます:

- ノード ID は、最新の観測結果に対してのみ有効です。
- シークレットは、同じチェックのもとで `type_secret` または [`run_code`](#run_code) の `fill` を通じてのみ入力されます。
- 設定が読み込まれると、そのシークレットの値は、ツールが返すすべてのテキスト、`locate` が見つけたノード、アクションの結果、`open_session` や `close_session` の失敗、クリーンアップの行、サーバー自身のログ行から伏せられます。
- セッションで行ったことは、テスト結果として記録されません。リプレイキャッシュを読み書きするのは、セッションが実行するテストだけです（[テストの実行](#running-a-test)）。その成果物は `<output>/results/mcp/<target>-<attemptId>/` 配下に、動画は `<output>/videos/` 配下に保存されます。後の `e2e run` は `<output>/results` を消去しますが、動画は残ります。
- クライアントがキャンセルしたキュー内の呼び出しは、順番が来ても実行されません。

## テストの実行

`open_session {test}` は、セッションのアテンプト上でプロジェクトのテストを 1 つ実行し、テストが停止した画面でセッションを引き渡します。コーディングエージェントは、フローを再度クリックして進めることなく、そこから失敗したテストを修正できます。

```txt
open_session {test: "tests/checkout.e2e.ts:12"}
```

- **選択。** `test` は、`e2e run` が位置引数として受け取るものを受け取ります。その行で宣言されたテストを指す `:line` 付きのファイル、ファイル、ディレクトリ、glob、または名前です。セッションのターゲット上でちょうど 1 つのテストを選択する必要があります。行は `test(` の呼び出しがある行です。テスト内部の行では何も選択されません。
- **実行されるもの。** テストの `beforeAll` フック、`test.extend()` フィクスチャ、`beforeEach` フック、本体です。フィクスチャ、ロケーター、`expect`、`timeout`、`actionTimeout`、`assertionTimeout` は実行時と同じです。セッションは、先にアプリの URL を開いたり固定されたアプリを起動したりしません。テスト自身がアプリを開きます。
- **停止する場所。** 最初の失敗、または本体の最後です。何も破棄されません。最初のテキストの先頭には結果が示されます。成功、または失敗の場合はコード、メッセージ、失敗した行とその周辺のコード、URL、何にも一致しなかったロケーターに最も近いノード、直近 15 ステップです。その後にセッションのサマリー、カタログ、画面が続きます。
- **テスト行。** テスト自身のステップは[テスト行](#test_lines)を出力しません。セッションの行はエージェントの最初のアクションから始まり、`test_lines` はそれらをテストの続きとなる行として返します。
- **後片付け。** `afterEach` フック、フィクスチャの後片付け、`afterAll` フックは、`close_session` 時、またはセッションが自動的に閉じたときに実行されます。それらの失敗は `Cleanup (afterEach)` と `Cleanup (afterAll)` の行として示されます。
- **再実行。** `close_session` の後、再度 `open_session {test}` を呼び出します。各セッションは、設定とテストファイルを、それらがインポートするファイルも含めて新たに読み込みます。
- **リプレイキャッシュ。** テストは、実行の最初のアテンプトと同様にキャッシュを読み書きします。ステップはリプレイされ、後のチェックが成功した時点で新しい記録が保存されます。失敗すると、どのチェックでも確認されなかったエントリーは削除されます。キャッシュは本体の終了時に確定するため、`afterEach` のチェックは何も確認しません。[`cache.strict`](/reference/config#cache) は実行時と同様に適用されます。
- **含まれないもの。** テスト結果、レポート、トレースページはありません。リトライと、テストの `trace` および `video` モードは適用されません。失敗時のスクリーンショットと `screen-at-failure.txt` は、セッションの成果物ディレクトリに保存されます。
- **スクリーンショット。** `toHaveScreenshot` においては、各セッションが独立した 1 回の実行として扱われます。あるセッションが書き出したベースラインは、次のセッションで比較に使われます。
- **複数のセッション。** 2 つのセッションのテストコードは交代で実行されます。`expect.poll`、`expect.soft`、`test.skip` はプロセスごとに 1 つのスロットを通じて実行中のテストを見つけるため、テストまたは後片付けを実行できるのは一度に 1 つのセッションだけです。テストが順番を待っている間にキャンセルされたオープンでは、テストのコードは何も実行されません。

| エラー | 条件 |
| --- | --- |
| `NO_TESTS` | `test` が実行可能なテストを選択していません。`e2e run` と同様に、メッセージには原因が示されます。 |
| `TEST_AMBIGUOUS` | `test` が複数のテストを選択しています。メッセージにはそれらが `file:line` の形式で一覧表示されます。 |
| `SESSION_TEST_UNSUPPORTED` | テストがシリアルグループ内にある、セットアップテストの `session` から開始する、または複数のエージェントとして実行されます。 |
| `COLLECTION_ERROR` | `e2e run` と同様に、テストファイルの収集に失敗しました。 |

## 複数のセッション

`--max-sessions` まで、複数のセッションを同時に開けます。各セッションはそれぞれ独自のアテンプトと、独自のブラウザまたはデバイスを持ちます。コーディングエージェントのサブエージェントのような並列エージェントは、この方法で 1 つのサーバーを共有します。各エージェントがセッションを開き、その ID を `tools`、`call`、`close_session` のたびに渡します。[バグバッシュ](/bug-bash)はこの仕組みを使います。再現手順をスクリプト化されたテストに固める検証用サブエージェントは、自分専用のセッションを操作します。

| エラー | 条件 |
| --- | --- |
| `SESSION_REQUIRED` | 複数のセッションが開いている間に、`session` なしで呼び出しました。メッセージには開いているセッションの一覧が示されます。 |
| `NO_SESSION` | 開いていない `session` ID です。閉じている途中または終了したセッションの場合、メッセージにはその理由が示されます。 |
| `SESSION_OPEN` | 上限を超えた `open_session`、またはサーバーのシャットダウン中の `open_session` です。 |
| `CONFIG_IN_USE` | セッションが開いている間に別の設定で行った `open_session`、または `engine` で開いたセッションと並行して設定で行った `open_session` です。 |
| `ENGINE_IN_USE` | パッケージ内で作成されたエンジン上の 2 つ目のセッションです。 |
| `CANCELLED` | クライアントがキャンセルまたは切断した `open_session`、またはその途中でサーバーがシャットダウンした `open_session` です。開始したものが停止した時点で発生します。 |

- セッションは、`open_session` からアテンプトが閉じるまでスロットを保持します。そのため、起動中や終了処理中のセッションも上限に数えられます。
- 同時に開いているセッションは 1 つの設定を共有します。認証情報とシークレットは、プロセスごとに 1 つのレジストリを通じて解決されます。
- サーバーはシャットダウン中、まだ開いている途中のセッションをキャンセルしてその完了を待ち、すべてのセッションを閉じ、新しいセッションを拒否します。キャンセルされたオープンは、開始したもの（たとえば、まだ `readyUrl` を待っているアプリコマンド）が停止した時点で失敗します。
- 各セッションは、スプレッドするベース設定のようにパスでインポートするファイルまで含めて、設定を新たに読み込みます。そのため、各セッションは独自のエンジンインスタンスを持ちます。テストを実行するセッションは、テストファイルも同じように読み込みます。パッケージ内で作成されたエンジンは、すべてのセッションが共有する 1 つのインスタンスです。
- 同じアプリコマンドを使うセッションは、そのプロセスを共有します。最初のセッションがプロセスを起動し、最後のセッションが閉じたときに停止します。ポート `0` で宣言された URL はセッションごとに独自のポートを取得するため、プロセスもセッションごとに独立します。待機していたすべてのセッションが諦めた共有の起動はキャンセルされ、次のセッションが新たに起動します。
- モバイルでは、セッションごとに独自のシミュレーターまたはエミュレーターが必要です。デバイスごとに 1 つのターゲットを宣言し、それぞれで `device` を指定して、各セッションを独自のターゲットで開いてください。

## 終了コード

| コード | 条件 |
| --- | --- |
| `0` | セッションが開いているかどうかにかかわらずクライアントが切断した、またはシグナルによって終了しました。 |
| `1` | 捕捉されないエラーによってサーバーがシャットダウンしました。 |
| `2` | コマンドラインが無効です。 |
| エラーの[カテゴリーコード](/reference/cli#exit-codes) | 起動時の失敗です。 |

設定とエンジンの失敗は、CLI が出力するのと同じコードを持つツールエラーとして返されます。
