title: エンジンプロトコル
description: エンジンを別のプロセス、別のマシン、または別の言語で実行します。
---

エンジンプロトコルは、[エンジンコントラクト](/reference/engine)を JSON-RPC
メッセージとして表したものです。ランナーはすべてのエンジンをこのプロトコルで駆動します。
エンジンを別のプロセス、マシン、または言語で実行するには、
[エンジンサーバー](/engine-servers)を参照してください。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { connectEngine, spawnTransport } from 'e2e/engine';

export default {
  targets: [
    {
      name: 'kiosk',
      engine: connectEngine({
        manifest: { name: 'kiosk', version: '1.0.0', spiVersion: 1, platform: 'kiosk', methods: ['engine/observe'] },
        transport: spawnTransport({ command: './kiosk-engine' }),
        resolveLocators: true,
      }),
    },
  ],
} satisfies E2EConfig;
```

### `connectEngine`

エンジンサーバーを、ターゲットの `engine` が受け取る値であるエンジンハンドルに
変換します。

```ts
export function connectEngine(options: ConnectEngineOptions): EngineHandle;

export interface ConnectEngineOptions {
  /** What the server is; the server's manifest from `initialize` must match it. */
  readonly manifest: EngineManifest;
  /** How to reach the server. */
  readonly transport: EngineTransport;
  /** Engine options the server receives in `initialize`, as JSON. */
  readonly initializationOptions?: JsonValue;
  /** The `secrets.get()` handles the server may resolve. */
  readonly secrets?: readonly Secret[];
  /** Fixtures that run on the client, beside the test. */
  readonly fixtures?: Engine['fixtures'];
  /** Checks the target's app at config load, on the client. */
  readonly validateApp?: Engine['validateApp'];
  /** Answers locators on the client from observations, for a server without `engine/locate`. */
  readonly resolveLocators?: boolean;
  /** Session hooks the client answers instead of the server. */
  readonly session?: EngineSession;
}
```

ランナーは、どのサーバーも実行される前の設定の読み込み時にマニフェストを読み取ります。
マニフェストが異なるサーバーは、最初の接続で失敗します。

ハンドルは、ハーネスがエンジンを呼び出す場所で接続を開きます。ランナーでは、
ターゲットごとに 1 つの接続が `prepare` から `finish` まで存続し、サーバーが
`lifecycle/prepare` または `lifecycle/finish` に応答する場合にのみ開かれます。
各ワーカーでは、1 つの接続が `init` から `dispose` まで存続します。
`e2e doctor` は、`lifecycle/doctor` のためだけにターゲットごとに 1 つの `doctor`
接続を開き、その後に閉じます。トランスポートは `spawnTransport` のように
サーバーを起動してもかまいませんが、マシンのプロビジョニング、デバイスのリース、
アプリのインストールを行ってはいけません。doctor のシグナル時には、接続が閉じられる
前にサーバーに 5 秒の応答時間が与えられます。`init`..`dispose` の外側での操作呼び出しは
`INVALID_STATE` で失敗します。
`init` を一度も実行していないワーカーには接続がないため、サーバーはそのワーカーの
`lifecycle/dispose` を受け取りません。
2 つの接続が状態を共有するかどうかはサーバーが決めます。起動されたサーバーは接続ごとに
プロセスを持ち、ループバックやソケットのサーバーは 1 つのエンジンですべての接続を
処理できます。

`resolveLocators` を指定すると、各 `locate` は観測を行い、
[`resolveExpression`](/reference/engine#resolveexpression) で式を解決します。
`fixtures`、`validateApp`、`secrets`、`session` フックはクライアントで実行されます。
`session` フックは、サーバーの同名のメソッドを置き換えます。
[ホスト側の処理をクライアントに置く](/engine-servers#keep-host-work-on-the-client)を
参照してください。

<Warning>
`lifecycle/prepare`、`lifecycle/init`、`lifecycle/finish`、`lifecycle/doctor` は、
モデルキーや `E2E_SECRET_*` の値を含む実行環境を運び、
`attempt/resolveSecret` は平文で応答します。信頼できるサーバーにのみ接続してください。
`socketTransport` は暗号化しません。
</Warning>

| 例外 | 発生条件 |
| --- | --- |
| `INVALID_CONFIG` | マニフェストの形式が不正な場合です。未知のメソッド、2 回記載されたメソッド、または `defineEngine` が拒否するメンバー（`keyboard/press` のない `keyboard/type`、`actions` のない `engine/perform`、`engine/observe` のない `engine/perform` など）です。 |
| `ENGINE_FAILURE` | サーバーのマニフェストが異なる場合、または呼び出しの途中で接続が閉じた場合です。メッセージには、サーバーの最後の stderr 行など、トランスポートの診断情報が含まれます。 |

### `serveEngine`

`defineEngine` で構築したエンジンを、クライアントが `exit` を送信するかストリームが
閉じるまで、1 つの接続で提供します。

```ts
export function serveEngine(
  engine: EngineHandle | ((initializationOptions: unknown) => EngineHandle | Promise<EngineHandle>),
  streams?: MessageStreams, // default: process.stdin and process.stdout
): Promise<void>;
```

サーバー自身のログは stderr に出力してください。stdout はプロトコルを運びます。
[TypeScript エンジンを提供する](/engine-servers#serve-a-typescript-engine)を
参照してください。

### `describeEngine`

エンジンハンドルについて `serveEngine` が通知するマニフェストを返します。その静的メンバー、
宣言されたメンバーが応答するメソッド、そして `serveEngine` が常に応答する
`lifecycle/startAttempt` と `lifecycle/endAttempt` が含まれます。別の場所で提供される
TypeScript エンジンのマニフェストを宣言するために使います。

```ts
export function describeEngine(engine: EngineHandle): EngineManifest;
```

### `spawnTransport`

エディターが言語サーバーを起動するのと同じように、接続ごとにサーバーを子プロセスとして
起動し、その stdin と stdout で通信します。

```ts
export function spawnTransport(options: {
  readonly command: string;
  readonly args?: readonly string[];
  /** Added to the worker's environment. */
  readonly env?: Readonly<Record<string, string>>;
  readonly cwd?: string; // default: the project root
}): EngineTransport;
```

接続を閉じると stdin が終了し、`SIGTERM` が送信され、クリーンアップの予算を使い切ると
`SIGKILL` が送信されます。

### `socketTransport`

このマシンまたは別のマシンの TCP ポートですでに待ち受けているサーバーに接続します。
接続を閉じるとソケットが終了しますが、サーバーは動き続けます。

```ts
export function socketTransport(options: { readonly host: string; readonly port: number }): EngineTransport;
```

### `loopbackTransport`

インメモリのストリームを使って、このプロセス内でエンジンを提供します。すべての呼び出しは、
他のトランスポートと同様にシリアライズされ、プロトコルを経由します。

```ts
export function loopbackTransport(engine: EngineHandle): EngineTransport;
```

## メッセージ

基本プロトコルは
[Language Server Protocol のもの](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#baseProtocol)です。
UTF-8 の JSON-RPC 2.0 メッセージで、それぞれ `Content-Length` ヘッダーと空行の後に
続きます。どちらの側もリクエストと通知を送信できます。

### ライフサイクル

接続は LSP の接続と同じように開閉します。

| メッセージ | 方向 | パラメーター | 結果 |
| --- | --- | --- | --- |
| `initialize` | リクエスト、クライアントからサーバー | `{ protocolVersion: 1, clientInfo, role, initializationOptions? }` | `{ protocolVersion: 1, manifest }` |
| `initialized` | 通知、クライアントからサーバー | `{}` | - |
| `shutdown` | リクエスト、クライアントからサーバー | - | `null` |
| `exit` | 通知、クライアントからサーバー | - | - |

どちらの側も `1` 以外の `protocolVersion` を拒否します。`shutdown` の後は、
シグナルをそのままにします。`shutdown` なしで接続が閉じた場合は、保持している
すべてのシグナルを中断します。

### マニフェスト

その JSON Schema は、`e2e` パッケージに
`schema/engine-manifest-v1.schema.json` として同梱されています。

```ts
export interface EngineManifest {
  readonly name: string;
  readonly version: string;
  readonly spiVersion: 1;
  readonly platform?: string;
  readonly workers?: number;
  /** The engine methods the server answers; one left out is a capability the engine lacks. */
  readonly methods: readonly EngineMethod[];
  /** Required with `engine/perform`. */
  readonly actions?: readonly LocatorActionKind[];
  /** Required with `engine/performAt`. */
  readonly pointerActions?: readonly PointerActionKind[];
  readonly tapModifiers?: boolean;
}
```

### エンジンメソッド

各メソッドは 1 つのエンジンメンバーに対応し、クライアントからサーバーへのリクエストです。
パラメーターはメンバーの引数を名前で指定したもので、すべての `OperationContext` は
`operation` になります。`ENGINE_METHODS` にそれらが列挙されています。

| メソッド | パラメーター | 結果 |
| --- | --- | --- |
| `engine/observe` | `{ operation, options? }` | `EngineSnapshot` |
| `engine/readStyle` | `{ ref, properties, operation }` | `ComputedStyleValues` |
| `engine/locate` | `{ expression, operation }` | `SemanticNode[]` |
| `engine/perform` | `{ ref, action, operation }` | `null` |
| `engine/performAt` | `{ point, action, operation }` | `null` |
| `keyboard/type` | `{ text, options: { replace }, operation }` | `null` |
| `keyboard/press` | `{ key, operation }` | `null` |
| `keyboard/dismiss` | `{ operation }` | `null` |
| `state/capture` | `{ operation }` | `EngineState` |
| `state/restore` | `{ state, operation }` | `null` |
| `artifacts/screenshot` | `{ label?, operation }` | `{ path }` または `{ data, mediaType }` |
| `artifacts/startVideo` | `{ operation }` | `null` |
| `artifacts/stopVideo` | `{ operation }` | `VideoSegment[]` |
| `session/open` | `{ url, operation }` | `null` |
| `session/openLink` | `{ url, operation }` | `null` |
| `session/back`, `session/restart`, `session/reset` | `{ operation }` | `null` |
| `session/resize` | `{ size: { width, height }, operation }` | `null` |
| `session/switchTab` | `{ index, operation }` | `null` |
| `session/closeTab` | `{ index, operation }` | `null` |
| `lifecycle/prepare` | `log` を除いた `EnginePrepareInfo` | `EnginePrepareResult` または `null` |
| `lifecycle/finish` | `log` を除いた `EngineFinishInfo` | `null` |
| `lifecycle/doctor` | `log` を除いた `EngineDoctorInfo` | `EngineDoctorCheck[]` |
| `lifecycle/init` | `log` を除いた `EngineInitInfo` | `null` |
| `lifecycle/startAttempt` | `{ attemptId, artifactsDir, signal, screens }` | `null` |
| `lifecycle/settleAttempt`, `lifecycle/endAttempt` | `{ signal, timeoutMs }` | `null` |
| `lifecycle/dispose` | `{ signal, timeoutMs, reuseSignal? }` | `null` |

デバイス上のサーバーのように、サーバーが試行のアーティファクトディレクトリに書き込めない
場合、`artifacts/screenshot` は画像を base64 にした `{ data, mediaType: 'image/png' }`
を返します。クライアントはそれを `screenshots/` の下に書き込みます。
観測のピクセルも同じ方法で渡されます。`pixels.data` は base64 です。

`lifecycle/startAttempt` の `screens` は、試行がトレースを保持するかどうかを示します。
保持する場合に、サーバーは `attempt/screen` を送信できます。

### サーバーからクライアントへ

エンジンがハーネスに呼び返す内容は、サーバーからクライアントへのメッセージとして
渡されます。各 `attempt/*` メッセージには、それが属する `attemptId` が含まれます。
クライアントは、すでに終了した試行のメッセージを破棄します。

| メッセージ | 種類 | パラメーター |
| --- | --- | --- |
| `engine/log` | 通知 | `{ line }`、`prepare`、`init`、または `finish` から |
| `attempt/appLog` | 通知 | `{ attemptId, entry }` |
| `attempt/navigation` | 通知 | `{ attemptId, line }` |
| `attempt/environment` | 通知 | `{ attemptId, facts }` |
| `attempt/screen` | 通知 | `{ attemptId, snapshot }` |
| `attempt/resolveSecret` | リクエスト | `{ attemptId, name, derivation? }`、結果は `{ value }` |

`derivation` がある場合、クライアントは応答する前に `attempt/deriveSecret`
`{ derivation, plaintext }` で問い合わせ返します。サーバーは `{ values }` を返します。
これはエンジンが値から導き出す形式（basic 認証ヘッダーなど）で、クライアントは
それらをシークレットの名前でリダクトします。

### シグナル

`AbortSignal` は `{ id, aborted?, reason? }` として渡されます。クライアントは
シグナルごとに 1 つの ID を発行し、中断するときに `{ id, reason? }` を付けて
`$/abort` を送信します。送信時点ですでに中断されているシグナルは `aborted: true` を
持ちます。`reason` は、ハーネスがテストのタイムアウトなど独自のエラーで中断した場合の
中断理由で、失敗したメソッドの[エラー](#errors)と同じようにエンコードされた JSON-RPC
エラーオブジェクトです。サーバーはそのエラーでシグナルを中断するため、
`signal.reason` を再スローするエンジンは、プロセス内で実行した場合と同じものを送出します。
`reason` がない場合、シグナルはプラットフォームの `AbortError` で中断されます。
サーバーは、シグナルが中断されるとその ID を忘れ、`lifecycle/endAttempt` が完了すると、
試行中に初めて見たすべての ID を忘れます。その後に再び送られた ID は新しいシグナルです。

### エラー

失敗したエンジンメソッドは、JSON-RPC エラーコード `-32000` と、`data` に入れた
e2e エラーで応答します。これにより、ハーネスはリモートの失敗をローカルの失敗と
まったく同じように分類します。

| `data` | エンジンがスローしたもの |
| --- | --- |
| `{ type: 'engine', code, retryable }` | [`EngineError`](/reference/engine#engineerror)。リトライ可能にできるのは `NODE_STALE` と `FRAME_NOT_FOUND` だけです。 |
| `{ type: 'e2e', category, code, retryable, details? }` | `TestError` や `ConfigurationError` などのランナーエラー。 |

それ以外のエラーコードはメッセージだけを運びます。ハーネスはそれを、ローカルエンジンの
通常の `Error` と同じようにインフラストラクチャの失敗として扱います。すべてのエラーの
`data` には、`stack`、`errno`（`ECONNREFUSED` などの Node のエラーコード）、
そして同じ形のエラーオブジェクトである `cause` も含めることができ、レポートには
エンジンがどこで失敗したかが表示されます。

## 型

トランスポートは、1 つの接続のバイトストリームを開きます。
[トランスポートを書く](/engine-servers#write-a-transport)を参照してください。

```ts
export interface EngineTransport {
  /** For error messages: the command, or the address. */
  readonly label: string;
  open(context: TransportContext): Promise<TransportConnection>;
}

export interface TransportContext {
  readonly role: 'run' | 'worker' | 'doctor';
  readonly env: Readonly<Record<string, string | undefined>>;
  /** The project root. */
  readonly cwd: string;
  readonly signal: AbortSignal;
  /** The target's app, from `prepare`, `init`, or `doctor`: what a transport installs, since a server elsewhere cannot read the project's files. */
  readonly app?: EngineAppInfo;
}

export interface TransportConnection {
  readonly input: Readable;
  readonly output: Writable;
  /** Releases the process or socket, within `timeoutMs`. */
  close(timeoutMs: number): Promise<void>;
  /** What went wrong, for an error message. */
  diagnostics?(): string;
}
```
