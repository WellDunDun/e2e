`@e2e-dev/mobile` は、iOS シミュレーター、Android エミュレーター、接続された
スマートフォン向けのエンジンで、
[agent-device](https://github.com/callstack/agent-device) を通じて操作します。
このエンジンは `device` フィクスチャを提供します。`agent`、`app`、`screen`、
`expect` は他の環境と同じように動作します。このページでは、デバイスターゲットに
固有の内容を説明します。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';

export default {
  targets: [
    { name: 'iphone', engine: mobile({ platform: 'ios' }), app: { bundleId: 'com.apple.Preferences' } },
  ],
} satisfies E2EConfig;
```

```ts title="tests/settings.e2e.ts"
import { expect } from 'e2e';
import { test } from '@e2e-dev/mobile';

test('General opens in dark mode', async ({ app, device, screen }) => {
  await device.setAppearance('dark');
  await app.open();
  await screen.getByText('General').tap();
  await expect(screen.getByText('About')).toBeVisible();
});
```

- `device` に型を付けるには、`test` を `@e2e-dev/mobile` からインポートします。
  Web でも実行するスイートでは `requires: ['device']` を宣言してください。
- `e2e init` で **Mobile (iOS/Android)** を選ぶと、Settings の例とともに
  パッケージが追加されます。iOS には Xcode とシミュレーターが、Android には
  Android SDK とエミュレーターが必要です。
- パッケージには互換性のあるバージョンの `agent-device` が含まれているため、
  別途インストールする必要はありません。

## リファレンス

### エンジン

`mobile(options)` は 1 つのプラットフォーム向けのエンジンを作成します。テストする
プラットフォームごとに 1 つずつ作成し、プラットフォーム固有のラベルや操作を
含むテストには `platforms: ['ios']` または `platforms: ['android']` を指定します。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';
import { mobileTools } from '@e2e-dev/mobile/tools';
import { gateway } from 'ai';

const iphone = mobile({ platform: 'ios' });
const pixel = mobile({ platform: 'android' });

export default {
  targets: [
    { name: 'iphone', engine: iphone, app: { bundleId: 'Settings' } },
    { name: 'pixel', engine: pixel, app: { bundleId: 'com.android.settings' } },
  ],
  workers: 1,
  agents: {
    default: {
      model: gateway('openai/gpt-6-luna-fast'),
      tools: mobileTools(iphone, pixel),
    },
  },
} satisfies E2EConfig;
```

`mobile()` は `MobileOptions` を受け取ります。これは、エンジンがどのデバイスを
どのように操作するかを指定します。テスト対象のアプリはエンジンのオプションでは
なく、ターゲットの `app` です。[テスト対象のアプリ](#the-app-under-test)を
参照してください。

| オプション | 型 | デフォルト |
| --- | --- | --- |
| [`platform`](#platform) | `'ios' \| 'android'` | 必須 |
| [`device`](#device-option) | `string \| readonly string[] \| DeviceProvider` | 起動済みのすべてのデバイス |
| [`session`](#session) | `string` | `e2e-<target name>` |
| [`snapshot`](#snapshot) | `'full' \| 'interactive'` | `'full'` |
| [`settle`](#settle) | `number \| false` | `150` |
| [`transition`](#transition) | `number` | `500` |
| [`videoTouches`](#videotouches) | `boolean` | `true` |

省略可能な値はすべて `undefined` も受け付けるため、`process.env` から直接
読み取った値に条件付きのスプレッドは必要ありません。以下の各項目には、その
メンバーの宣言を示しています。

| スローされるエラー | 条件 |
| --- | --- |
| `INVALID_CONFIG` | `device` のリストが空である、`device` の名前が空白である、またはリストのエントリーが空白か文字列ではありません。 |
| `INVALID_CONFIG` | `device` の値が文字列、リスト、有効なプロバイダーのいずれでもありません。空でない `name` がない、`acquire()` または `release()` がない、または `record` が関数ではないプロバイダーです。 |
| `INVALID_CONFIG` | `platform` がない、または `'ios'` でも `'android'` でもありません。大文字と小文字は区別されます。 |
| `INVALID_CONFIG` | 指定した `snapshot` の値が `'full'` でも `'interactive'` でもない、または指定した `videoTouches` の値が真偽値ではありません。 |
| `INVALID_CONFIG` | `mobile({ app })` やその他の古いアプリのオプションなど、`mobile()` が受け取らないオプションです。メッセージには、タイプミスと思われる場合は最も近い既知のオプションが、そうでない場合はすべてのオプションが示されます。 |
| `INVALID_CONFIG` | `settle` または `transition` がミリ秒単位の非負の整数ではありません (`settle` は `false` も指定できます)。 |

#### `platform`

```ts
/** Platform the target's device runs. */
readonly platform: MobilePlatform;
```

```ts
mobile({ platform: 'android' });
```

- `'ios'` または `'android'` です。必須です。

#### `device` オプション

```ts
/**
 * Device to use: a simulator or emulator by name, simulator UDID, or
 * emulator serial (`emulator-5554`), or a connected phone by name. A list
 * is a pool: the engine declares one worker per entry and worker slot `n`
 * drives the `n`th, so `workers` at or above the pool size runs the target's
 * files across every device at once. Omitted, the pool is every booted device
 * of the platform at `prepare` that no other agent-device session holds, as
 * many as the run has slots. A paired iPhone or iPad that is reachable (USB or network) counts as booted and
 * joins the pool. With none booted, agent-device boots a shut-down one: on
 * iOS an iPhone over an iPad over an Apple TV, on Android a phone or tablet
 * over a TV, then the newest OS, then name order (a stopped Android emulator
 * reports no OS version, so the name decides). With every booted one held,
 * `prepare` fails. A `DeviceProvider` leases hosted devices
 * instead: one per worker slot at `prepare`, each driven through the daemon
 * and client configuration the lease names. A replacement worker resumes a
 * healthy agent-device session on the same lease. Forced worker shutdown
 * can close the session. `device.closeApp()` ends the agent-device session,
 * allowing another session to take the device. If agent-device has not
 * confirmed a recording stop, the engine resets the recording before the
 * next attempt. This reset also ends the session. The provider lease stays
 * held until run end. At run end, the engine closes its sessions and the
 * provider releases its leases.
 */
readonly device?: string | readonly string[] | DeviceProvider | undefined;
```

```ts
mobile({ platform: 'ios' }); // default: every booted iOS device no other agent-device session holds
mobile({ platform: 'ios', device: 'iPhone 17' });
mobile({ platform: 'android', device: 'emulator-5554' });
mobile({ platform: 'ios', device: ['iPhone 17', 'iPhone 17 Pro'] });
```

- 各 `device` エントリーが異なるデバイスを指定している限り、2 つのワーカーが同じ
  デバイスを操作することはありません。
- `device` を指定しない場合、別のツールが独自の agent-device セッションで保持して
  いる起動済みシミュレーターはスキップされます。手動で使っているデバイスなど、
  何にも保持されていない起動済みデバイスはプールに含まれたままです。実行に
  使わせたくない場合は、デバイスを名前で指定してください。
- [ホスト型デバイス](/mobile#hosted-devices)では、`DeviceProvider` の契約と
  プロバイダーの例を紹介しています。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';

const iphones = mobile({
  platform: 'ios',
  device: ['iPhone 17', 'iPhone 17 Pro'],
});

export default {
  targets: [{ name: 'ios', engine: iphones, app: { bundleId: 'com.example.app' } }],
  workers: 2,
} satisfies E2EConfig;
```

#### `session`

```ts
/**
 * agent-device session name, before the worker slot: slot `n` drives its
 * device under `<session>-<n>`, `e2e-<target name>-<n>` by default. One run
 * per session at a time: concurrent runs on the same session interleave
 * taps.
 */
readonly session?: string | undefined;
```

```ts
mobile({ platform: 'ios', session: 'checkout' }); // default: e2e-<target name>
```

#### `snapshot`

```ts
/**
 * What an observation captures. `full` (default) includes static text, so
 * judgments can read values; `interactive` keeps only actionable nodes and
 * is cheaper on screens with long lists.
 */
readonly snapshot?: 'full' | 'interactive' | undefined;
```

```ts
mobile({ platform: 'android', snapshot: 'interactive' }); // default: 'full'
```

#### `settle`

```ts
/**
 * How long the UI must hold still after a tap, fill, screen scroll, or
 * back before the agent observes again, in milliseconds; `false` skips the
 * wait. The wait keeps that observation off a transition frame; the runner's
 * own polling (`expect`, actions waiting for their node) covers the rest,
 * so a short window suffices. Default 150.
 * Every frame of a running animation changes the tree, so a 150 ms
 * window still catches a transition in flight; raise it for slow devices
 * or apps that settle in stages, or lower it to 0 to keep only the first
 * re-observation. A test's steps do not settle, except `device.back()`:
 * `expect` verifies their outcome, and `transition` covers a control that is
 * still arriving.
 */
readonly settle?: number | false | undefined;
```

```ts
mobile({ platform: 'ios', settle: 300 }); // default: 150
```

#### `transition`

```ts
/**
 * Wait before acting on a control that just appeared or moved, in
 * milliseconds. Default 500. Accessibility bounds cannot tell a sliding
 * control from a landed one (iOS reports the final frame at once, Android
 * the frame in flight), so the control is found again in a fresh snapshot
 * once the wait is over and acted on where it landed. Unmoved controls are
 * acted on immediately only when keyboard visibility is unchanged. Opening
 * or closing the keyboard also uses the remaining budget. Screen swipes in
 * tests wait out the remaining budget before scrolling. Raise it for slower
 * transitions.
 */
readonly transition?: number | undefined;
```

```ts
mobile({ platform: 'ios', transition: 800 }); // default: 500
```

待機中にコントロールが変化した場合、アクションはタイムアウト内でそのコントロールを再度見つけてから操作します。

[`device`](#device) の `back`、`home`、`alert`、`dismissKeyboard`、
`setOrientation`、`fold` は画面を変化させるため、タップと同じようにこの待機時間の
対象となるアクションとして扱われます。これらが表示する画面とともに現れた
コントロールは、次のアクションがそのコントロールに対して実行される前に、待機時間が
経過するのを待ちます。

`fill` と `clear` は、入力する前にフィールドを読み直します。フィールドが見つから
ない、セキュリティの状態が変わった、またはキャプチャが不完全な場合は、変更を
加える前に `NODE_STALE` を返し、新しく観測し直してからリトライします。入力欄では
ないターゲットには `UNSUPPORTED_CAPABILITY` を返します。iOS の `other`
(プラットフォームが分類しなかった要素の型) は、値またはテキストだけを持つ場合に
入力対象となります。独自に描画されたフィールド (Compose Multiplatform、Flutter) が
そのように見えることがあるためです。

#### `videoTouches`

```ts
/**
 * Whether a video recording draws agent-device's touch indicator where a
 * test tapped. Default `true`. `false` records the plain screen, and skips
 * the pass that draws the indicator once the recording stops: on a hosted
 * daemon such as Expo Simulators' that pass can outlast the attempt's
 * `cleanupTimeout`.
 */
readonly videoTouches?: boolean | undefined;
```

```ts
mobile({ platform: 'ios', videoTouches: false }); // default: true
```

#### テスト対象のアプリ

アプリはターゲットの `app` です。`bundleId`、`appPath`、`launchArguments`、
`permissions`、`identity`、`environment` については
[テスト対象のアプリ](/reference/config#the-app-under-test)で説明しています。

```ts title="e2e.config.ts"
export default {
  targets: [{ name: 'ios', engine: mobile({ platform: 'ios' }), app: { appPath: './build/MyApp.app' } }],
} satisfies E2EConfig;
```

- デバイスターゲットには `app.bundleId` または `app.appPath` が必要です。
- `app.open()` はターゲットのアプリを新しく起動します。試行は自分では何も起動
  しないため、テストは前のテストがアプリを残した状態から始まります。
- ターゲットが [`app.linkBase`](/reference/config#linkbase) を宣言している場合、
  `app.open(path)` はパスをアプリ内のリンクとして開きます。宣言していない場合、
  `app.open` はパスを受け取らず、リンクは [`device.openLink`](#openlink) で開きます。
- `app.appPath` はスイートが実行対象とするビルドです。エンジンは自分では何も
  インストールしません。[`device.installApp()`](#installapp) が、スイートが
  指定した場所でインストールします。デバイスプロバイダーは、リースしたデバイスに
  インストールします。
- `bundleId` がない場合、インストールされたバンドル ID またはパッケージが、
  `app.open()` で起動するアプリになります。
- ビルドのパスが実行ごとに変わる (パスにバージョンが含まれる) 場合は `identity` を
  宣言してください。そうすれば、名前が変わっても記録が引き継がれます。

| スローされるエラー | 条件 |
| --- | --- |
| `INVALID_CONFIG` | 設定の読み込み時: `app.bundleId` も `app.appPath` もない。`app.url` がある (まだサポートされていません)。`bundleId` にリンクがある (テストでは `device.openLink` でリンクを開きます)。不明な権限名がある。 |
| `UNSUPPORTED_CAPABILITY` | `app.bundleId` のないターゲットで、ビルドがインストールされる前に `app.open()`、`app.restart()`、または `app.clearState()` を呼び出しました。 |

#### 起動引数と権限

`app.launchArguments` と `app.permissions` は、固定されたアプリを新しく起動する
たびに適用されます。対象は `app.open()`、`app.restart()`、`app.clearState()` で、
`app.clearState()` はデータとともに権限もリセットします。

```ts title="e2e.config.ts"
export default {
  targets: [
    {
      name: 'pixel',
      engine: mobile({ platform: 'android' }),
      app: {
        bundleId: 'com.example.app',
        launchArguments: ['--ez', 'e2e', 'true'],
        permissions: { camera: 'grant', notifications: 'deny' },
      },
    },
  ],
} satisfies E2EConfig;
```

- iOS は引数をアプリのプロセスに渡します
  (`ProcessInfo.processInfo.arguments`)。Android は引数を `am start` に追加する
  ため、`['--ez', 'e2e', 'true']` は真偽値のインテントエクストラになります。
- 各権限は `grant`、`deny`、`reset` のいずれかです。`deny` は、iOS では記録された
  拒否で、アプリにはプロンプトなしで拒否が伝えられます。Android では取り消しで、
  アプリが権限を要求すると OS が改めて確認します。
- 権限は、アプリが起動する前にアプリ名で設定され、事前にアプリを開くことは
  ありません。iOS は権限が変更された実行中のアプリを終了させ、Android は権限が
  取り消された実行中のアプリを終了させるためです。
- ウォームアップでは起動引数を渡さず、権限にも触れません。
- [`device.openApp(app, { relaunch: true, launchArguments, permissions })`](#openapp)
  は、任意のアプリの 1 回の起動に対して同じことを行います。

| スローされるエラー | 条件 |
| --- | --- |
| `INVALID_CONFIG` | `app.permissions` 内で、`DevicePermission` にない権限名 (タイプミスと思われる場合は最も近い名前を示します)、または `grant`、`deny`、`reset` 以外の状態が指定されました。デバイスのコマンドを実行する前に失敗します。 |
| `INVALID_ARGUMENT` | `device.openApp` で同じ問題がある場合です。 |

#### 起動と準備

デバイスは `prepare` で起動します。これは実行ごとに 1 回、実行の時間計測が
始まる前に行われるため、CI でのコールドブートが `launchTimeout` に計上される
ことはありません。

- [`device`](#device-option) は、`prepare` がどのデバイスを使うか、エンジンが
  いくつのワーカーを宣言するかを指定します。
- iOS では、`prepare` が agent-device の `prepare ios-runner` で各デバイスの
  自動化ランナーを起動するため、初回起動のコストは最初のテストの前に支払われます。
- 次に、両方のプラットフォームで、デバイスごとにターゲットの `app.bundleId` を
  1 回開きます。スイートが自分でインストールするビルドは最初の `app.open()` で
  起動し、テストが要求するたびに新しく起動し直されます。
- 起動できないデバイスや、ランナーがビジー、停止、またはウォッチドッグの制限を
  超えている場合は、`prepare` で実行が終了します。
- それ以外の理由でランナーが起動しない場合は、ログに記録されて最初の試行に
  委ねられ、そのデバイスのアプリはそこでは開かれません。

各デバイスは、準備ステップにかかった時間を 1 行でログに出力します。失敗した
ステップも含まれます。コールド状態の iOS シミュレーターの場合:

```text
ℹ booting E93FA5E5-1592-43C7-9149-F1B5FE0AD5F5 (1 of 1)
ℹ E93FA5E5-1592-43C7-9149-F1B5FE0AD5F5: boot 36.3s, iOS runner 61.6s, open dev.e2e.benchmark 9.2s
```

- `boot` はデバイスの起動で、すでに起動しているデバイスでは数秒です。
- `iOS runner` は自動化ランナーの起動で、iOS のみです。
- `open <app>` はアプリをフォアグラウンドに表示し、コールド状態のデバイスでは
  アプリを起動します。上記のとおりオープンがスキップされたデバイスでは表示されません。

通常のアプリのオープンの失敗は専用の行にログ出力され、実行は続行されます。
その行はデバイスの所要時間の行より前に出力され、所要時間の行には失敗した
`open <app>` ステップも引き続き表示されます:

```text
ℹ E93FA5E5-1592-43C7-9149-F1B5FE0AD5F5: dev.e2e.not.installed did not open (open dev.e2e.not.installed failed: Simulator device failed to launch dev.e2e.not.installed. Hint: The app bundle is not installed on this simulator. Run install before open.); the first attempt opens it
```

<Note>
保留中のタップ、ダブルタップ、フォーカス、チェック、チェック解除は、ステップが
その完了を待つのをやめたとき、または実行が中断されたときにキャンセルされます。
これには、キーボードのヒントを閉じるタップも含まれます。

すでにデバイスに送信された入力は完了することがあります。
その他のコマンドは呼び出し元のタイムアウトより長く続くことがあり、次の試行は
それらの完了を待ちます。
</Note>

#### 機能

| 契約のメンバー | デバイスでの動作 |
| --- | --- |
| `observe` | 矩形付きのアクセシビリティツリーです。要素の型は [ロール](#roles) に記載のとおりロールに対応付けられます。`Switch` や `CheckBox`、Android の `RadioButton` は、デバイスが報告する `checked` 状態を持ちます。`SecureTextField` や、UIAutomator が `password` とフラグを付けた Android のフィールドは、セキュアな `textbox` になります。iOS のフィールドはラベルと同じ値を保持します (ラベルのないフィールドはテキストで名前が付けられます)。Android でテキストビューのラベルが値として繰り返されるものは除外されます。アクセシビリティ識別子 (iOS) またはリソース ID (Android) がノードの `testId` になります。Android のノードは、アプリが設定したコンテンツの説明 (React Native の `accessibilityLabel`) で名前が付けられ、なければテキストで名前が付けられます。また、その `text` は表示内容です。そのため、ラベル付きのテキストビューや入力済みのフィールドは、ラベルで `getByLabel` に、テキストで `getByText` に一致します。フィールドのヒントは、表示されているかどうかにかかわらず `placeholder` 属性になります。Compose Multiplatform は iOS でプレースホルダーを報告しません。空のフィールドは、描画するテキストをラベルに追加し (`Name, Ada Lovelace`)、1 つの `StaticText` の子を持ちます。そのため、そのテキストがフィールドの `placeholder` になり、子は除外されます。空のフィールドには値がありません。Android は表示中のヒントにフラグを付け、XCTest は空の iOS フィールドのプレースホルダーを値として報告します。そのため、値がプレースホルダーと (トリムした上で) 等しい iOS フィールドは、プレースホルダーと完全に一致するように入力したテキストも含めて、空として読み取られます。Android に関する 1 つの事実は、プラットフォームではなく agent-device によるものです。`rect` とすべての座標は画面の物理ピクセルで、agent-device が報告するディスプレイ密度はまだ適用されていません。Android のステータスバーとナビゲーションバー、つまり画面の端に沿った全幅の `com.android.systemui` ウィンドウと、その端の帯の中で agent-device が個別に報告する細いステータスアイコン (時計、電波、バッテリー) は除外されます。通知シェード、システムダイアログ、ヘッドアップ通知や、両端から内側に配置されたその他のポップアップは残ります。要求に応じてピクセルを返し、その際すべてのセキュアなノードの領域は黒く塗りつぶされます。 |
| `perform` | `tap`、`doubleTap`、`longPress`、`fill`、`clear`、`hover`、`check`、`uncheck`、`press` (`Enter`、`Space`、または 1 文字)、`swipe`、`dragTo`、そして編集可能なフィールドへの `focus` です。`switch` や `checkbox` へのタップは最も内側のコントロールに対して行われます。UIKit は設定の行を、実際のトグルを子に持つ 1 つのラベル付きスイッチとして報告するためです。`check` と `uncheck` には `checked` 状態が必要です。スイッチは両方のプラットフォームで状態を報告し、ネイティブの Android の `CheckBox` も同様です。React Native のチェックボックスやラジオボタンは、アプリが `accessibilityState.checked` を設定した場合にのみ状態を報告します。状態のないコントロールは `UNSUPPORTED_CAPABILITY` になるため、代わりにタップしてください。`doubleTap` は 2 回の押下で、iOS では 284〜285 ms の間隔です (agent-device の XCTest のタップの間隔)。agent-device 独自のダブルタップジェスチャーは、React Native の `Pressable` には 1 回の押下として届きます。ウィンドウが 300 ms 以下の検出器は、この 2 回を 2 つのシングルタップとして読み取ることがあります。`longPress` は、テストが `duration` を渡さない限り 1 秒間押し続けます。これは React Native の `Pressable` の `delayLongPress` である 500 ms や、アプリが設定するより長いしきい値を超える長さです。agent-device 独自のデフォルトの押下時間はより短く、それらではタップとして認識されます。`selectOption`、`setInputFiles`、`scrollIntoView`、`secondaryTap` は宣言されておらず、`tapModifiers` も宣言されていないため、`modifiers` を指定した `tap` や `doubleTap` は `UNSUPPORTED_CAPABILITY` になります。より新しいスナップショットで置き換えられたノードへのアクションは、別の要素を操作するのではなく、そのノードを再度見つけます。 |
| `performAt` | 画面上の座標に対する `tap`、`doubleTap`、`longPress`、`swipeTo` です。これにより、`screen.tapAt`、`screen.doubleTapAt`、`tap({ position })`、`screen.swipe({ from, to })`、エージェントの `tap_at` で、ツリーに含まれないコントロールにも到達できます。座標に対する `hover`、`secondaryTap`、`dragTo` はありません。タッチにはノードなしでこれらの操作がないため、`hover_at` には一覧に含まれるコントロールが必要です。 |
| `keyboard` | フォーカスされたフィールドへの `type` と `press` (ターゲットなしのエージェントの `type` と `press`、および `type_at` と `press_at` のフォールバック) と、`dismiss` (エージェントの `dismiss_keyboard`) です。 |
| `locate` | すべての `screen` クエリです。デバイスはテキストとラベルの両方をツリーの上位に繰り返し報告するため (React Native の入力欄はホストビューとその中のフィールドで、どちらもラベル付き)、テキストとラベルのクエリは最も内側の一致を返します。Android では、テスト ID のクエリ (文字列または RegExp) は、画面上の何も完全な ID に一致しない場合、フレームワークの `android` 以外の任意のパッケージについて、`<package>:id/` プレフィックスを除いたリソース ID にも一致します。`screen.locator('id=…')` は agent-device のセレクターで、完全な ID を受け取ります。 |
| `validateApp` | `app.bundleId` または `app.appPath` を必須とし、現時点では `app.url` を拒否します。その際、プラットフォームのデバイスからこのマシンに到達する方法についての注記を示します。どちらかを持つターゲットは `native-app` ターゲットになるため、`requires: ['native-app']` でデバイスターゲットを選択できます。 |
| `session` | `back`、`restart`、`reset`、`openLink` です。`openLink` は、`app.linkBase` を持つターゲットでの `app.open(path)` の裏で使われます。`open` はありません。パスなしの `app.open()` は、固定されたアプリを新しく起動する `restart` で処理されます。エージェントの `navigate` 動詞は使用できず、`device.openLink(url)` でディープリンクや Web リンクを開きます。 |
| `artifacts` | `screenshots/NNN-<label>.png` 配下の秘匿処理済みのスクリーンショットです。秘匿処理できないスクリーンショットは、書き出されずに失敗します。動画は、試行の [video モード](/reference/config#video) が録画する場合に `video/video.mp4` として、またはデバイスプロバイダー独自の録画として保存されます。 |
| `location` | `<bundle id> / <screen title>` で、リプレイキャッシュのアンカーです。タイトルは、iOS ではナビゲーションバーのもの、Android ではツールバーのものです。 |
| `state` | 宣言されていません。`test.setup` と `session:` は使用できません。 |

#### `unstable_raw`

```ts
/**
 * The raw driver session this test drives, for what the methods here do
 * not cover. Calls through `client` bypass e2e: they are not steps, so the
 * report and trace leave them out, the agent's cache does not replay them,
 * their arguments reach the driver unredacted, and nothing waits for the
 * screen to settle after one. Unstable: it may change or go away in any
 * release.
 */
readonly unstable_raw: DeviceSession;
```

```ts
const { client, selection } = device.unstable_raw;
await client.apps.list(selection);
```

`client` の型は `@e2e-dev/mobile` からエクスポートされる `DeviceSessionClient` です。
その操作は不安定で、どのリリースでも変更される可能性があります。
ワーカーがセッションを破棄した後に `unstable_raw` または `client` を読み取ると、
`INVALID_STATE` をスローします。

#### `locator`

```ts
/**
 * A locator from an agent-device selector (`'id=SW_VERSION_SPECIFIER'`,
 * `'role=text label="26.2"'`), for nodes the closed `screen` query
 * vocabulary cannot name. Same polling and strictness as any locator.
 */
locator(selector: string): Locator;
```

```ts
await expect(device.locator('role=navigation-bar id=About')).toBeVisible();
await expect(device.locator('role=text label="iOS Version"')).toHaveText('iOS Version');
await device.locator('id=SW_VERSION_SPECIFIER role=button').tap();
```

セレクターの項とそのルールは agent-device のもので、`agent-device
find ... list` が適用するものと同じです:

- 項: `id`、`role`、`text`、`label`、`value`、`appname`、`windowtitle`、
  およびフラグの `visible`、`hidden`、`editable`、`selected`、`focused`、
  `enabled`、`hittable`。
- `role` は agent-device の種類、つまり `agent-device snapshot` が出力する
  ロールを受け取ります: `button`、`text`、`text-field`、`navigation-bar`、
  `scroll-area`、`switch`、`image`。これは `getByRole` のロール (`textbox`) では
  ありません。
- テキストの項は、空白をまとめた後に大文字と小文字を区別せずに比較します。
- `visible` は、ノードがヒット可能であるか、空でないフレームを持つことを意味します。
  `hidden` はその逆です。
- `text` は、最初の空でないラベル、値、または識別子を読み取ります。

<Note>
複数のノードに一致するセレクターへのアクションは失敗します。一方、agent-device の
アクションは、あいまいな `||` の選択肢をスキップします。
</Note>

#### `installApp`

```ts
/**
 * Installs a build (an iOS `.app` bundle or an Android `.apk`, resolved
 * against the project root) on the device; without a path, the target's
 * `app.appPath`. The engine installs nothing on its own, so a suite that runs
 * against a build calls this once per device, in a fixture or a test.
 * `reinstall: true` removes the app first so it starts with no data; a
 * plain install replaces the binary and keeps its data. Resolves to the
 * identity to `openApp` it by, which becomes the app `app.open()` launches
 * when the target's build is installed and no `app.bundleId` is pinned.
 */
installApp(appPath?: string, options?: InstallAppOptions): Promise<InstalledApp>;
```

```ts
await device.installApp(); // the target's app.appPath
const { app } = await device.installApp('./build/MyApp.app', { reinstall: true });
await device.openApp(app);
```

- 実行対象のビルド、またはアップグレードパス上の別のビルドに使います。
- 解決される ID は、agent-device がビルドから読み取ったバンドル ID または
  パッケージで、なければ渡された `app` です。

| スローされるエラー | 条件 |
| --- | --- |
| `APP_NOT_OPEN` | パスが渡されず、ターゲットに `app.appPath` がありません。または、`app` が渡されず、固定されたアプリもない (`app.bundleId` がなく、ビルドもまだインストールされていない) 状態で `reinstall: true` が指定されました。 |
| `ENGINE_FAILURE` | agent-device が ID を報告せず、`app` も渡されませんでした。この場合、ファイルパスを ID として扱うことはしません。[トラブルシューティング](/mobile#troubleshooting)を参照してください。 |

#### `openApp`

```ts
/**
 * Brings an app to the foreground by bundle id, package, or display name;
 * `relaunch` restarts it fresh. `launchArguments` and `permissions` apply
 * to this launch alone; the target's configured ones apply to a `relaunch`
 * of the pinned app, and to no foreground-only open. A link is
 * `INVALID_ARGUMENT` (`file:`, `data:`, `javascript:`, `view-source:`,
 * `blob:`, and `filesystem:` are `POLICY_DENIED`): `openLink` opens one.
 */
openApp(app: string, options?: OpenAppOptions): Promise<void>;
```

```ts
await device.openApp('Settings');
await device.openApp('com.example.app', { relaunch: true, permissions: { camera: 'grant' } });
```

- agent-device は `scheme:rest` 形式の文字列をすべて URL として開くため、リンクは
  デバイスに届く前に拒否されます。

| スローされるエラー | 条件 |
| --- | --- |
| `POLICY_DENIED` | `file:`、`data:`、`javascript:`、`view-source:`、`blob:`、`filesystem:` のリンクです。 |
| `INVALID_ARGUMENT` | その他のリンクで、メッセージは `openLink` を案内します。または、無効な権限名や状態です ([起動引数と権限](#launch-arguments-and-permissions)を参照)。 |

#### `openLink`

```ts
/**
 * Opens a deep link (`myapp://orders/42`) or a web link (`https://...`)
 * into `app` (default: the pinned app), which the session observes
 * afterwards. iOS launches the app for a web link and then opens the URL;
 * a web link the app does not claim goes to Safari, and the next
 * observation brings the app back. Android starts the link on that
 * package. Without an app, Android lets the OS route the link; iOS needs
 * one (`INVALID_ARGUMENT` without). `file:`, `data:`, `javascript:`,
 * `view-source:`, `blob:`, and `filesystem:` links are `POLICY_DENIED`.
 */
openLink(url: string, options?: { app?: string }): Promise<void>;
```

```ts
await device.openLink('myapp://orders/42');
await expect(screen.getByText('Order #42')).toBeVisible();
```

- マジックリンクによるサインインやディープリンクのルートに使います。
- アプリを指定しない場合、Android はリンクを検証済みのアプリリンクの所有者または
  ブラウザにルーティングし、セッションはリンクを受け取ったパッケージに追従します。
- デバイスのリンクはどのアプリのカスタムスキームでも使えるため、このルールは
  Web のように http(s) だけを許可するのではなく、以下のスキームを拒否します。
- レポートには、ログイン情報やマジックリンクのトークンが含まれる userinfo
  (`user:password@` や `token@`)、クエリ、フラグメントを除いたリンクが表示されます。

### エージェントのツール

`@e2e-dev/mobile/tools` の `mobileTools(...engines)` は、エージェントの `tools` に
デバイス用のツールを追加します。

```ts
tools: mobileTools(iphone, pixel),
```

- 少なくとも 1 つのエンジンを受け取ります。すべてのデバイスエンジンを 1 回の
  呼び出しで渡してください。ツールは現在の試行のエンジンを使います。

| ツール | リプレイ | 用途 |
| --- | --- | --- |
| `open_app` | ギャップ | ID を指定してアプリをフォアグラウンドに表示します。必要に応じて再起動します。ID がない場合はターゲットのアプリに戻ります。`device.openApp` と同様に、リンクは拒否されます。 |
| `swipe` | ギャップ | 論理ピクセル単位の 2 点間で自由にスワイプします。 |
| `alert` | ギャップ | システムアラートを承認または閉じます。タップがリプレイされる、一覧に含まれるボタンを優先してください。 |

| スローされるエラー | 条件 |
| --- | --- |
| `INVALID_STATE` | `mobile()` が返したものではないエンジンです。設定内では、これにより読み込みが `CONFIG_LOAD_FAILED` で失敗し、そのメッセージにこのメッセージが含まれます。 |

組み込みのエージェントステップの実行中に失敗したツールは、呼び出しの結果として
`Tool "<name>" failed: <message>` をモデルに返し、ステップは続行されます。
`open_app` は、アプリを指定せず、ターゲットに `app.bundleId` がなく、`app.appPath`
のビルドがまだ何によってもインストールされていない (`device.installApp()` も
デバイスプロバイダーによるインストールもない) 場合に `INVALID_STATE` で失敗します。
インストールされていないアプリやリンクを指定した場合は `INVALID_ARGUMENT` で、
禁止されたスキームのリンクの場合は `POLICY_DENIED` で失敗します。デバイスの試行が
実行されていない場合や、1 つのワーカーで複数のデバイスの試行が実行されている
場合は、どのツールも `INVALID_STATE` で失敗します。

文法の動詞にはツールパックは不要です。エンジンが宣言したアクションによって、
エージェントは次のものを使えます:

- `tap`、`double_tap`、`long_press`、`hover`、`type`、`press`、`check`、
  `scroll`、`drag`、`text` による `scroll_to` (そのテキストを表示する行が描画される
  までリストをページ送りします)、`back`、`dismiss_keyboard`。
- ピクセルツールの `screenshot`、`tap_at`、`hover_at` (一覧に含まれるコントロール
  のみ)、`drag_at` (一覧に含まれる 2 つの異なるコントロール間のみ)、`type_at`、
  `press_at`。座標に対するアクションでは、アクセシビリティツリーにないコントロール
  もタップできます。
- `type_secret`。ステップが宣言したシークレットだけを入力します。

デバイスには `right_click`、`select`、ノード ID による `scroll_to`、`upload`、
`navigate` はなく、`select_at` も提供されません。

<Note>
エンジンがマスキングを証明できないピクセルは、`MASKING_UNPROVEN` として提供されません。
アクセシビリティのキャプチャが失敗した場合も、観測は停止します。デバイスの
スクリーンショットのマスクは、そのキャプチャから得たセキュアなフィールドの領域に
依存するため、それがないとエンジンはフォールバックのスクリーンショットが安全で
あることを証明できません。
</Note>

#### `unstable_deviceSession`

`@e2e-dev/mobile/tools` の `unstable_deviceSession(...engines)` は、カスタムツールに
実行中の試行の `DeviceSession` を渡します。これは、テストが
[`device.unstable_raw`](#unstable_raw) から読み取るものと同じオブジェクトです。
その `client` は、e2e がまだラップしていない機能のために、エンジンのデーモン、
リース、ワーカーごとのセッションに紐付けられています。`client` の型は
`DeviceSessionClient` です。
次の例は、現在のドライバーが `settings.update` をサポートしていることを前提としています。

```ts
import { tool } from 'ai';
import { z } from 'zod';
import { defineTool } from 'e2e/agent';
import { unstable_deviceSession } from '@e2e-dev/mobile/tools';

const mobileData = defineTool(
  tool({
    description: 'Turn cellular mobile data on or off. Wi-Fi is not affected.',
    inputSchema: z.object({ on: z.boolean() }),
    execute: async ({ on }) => {
      const { client, selection } = unstable_deviceSession(iphone, pixel);
      await client.settings.update({ ...selection, setting: 'mobile-data', state: on ? 'on' : 'off' });
      return on ? 'mobile data is on' : 'mobile data is off';
    },
  }),
  { mutates: true, platforms: ['android'] },
);

tools: { ...mobileTools(iphone, pixel), mobileData },
```

- `mobileTools` と同様に、設定で宣言したすべてのデバイスエンジンを渡します。
  試行の外では `INVALID_STATE` をスローします。
- エンジン自身の呼び出しと同様に、`selection` を呼び出しにスプレッドしてください。
  そうすれば、セッションでアプリが開かれる前でもワーカーのデバイスに届きます。
- クライアントの呼び出しはステップではありません。レポートにはツールの呼び出しが
  表示され、クライアントが行ったことは表示されません。また、キャッシュのリプレイでは
  `mutates: true` のツールはライブで実行されます。
- `unstable_raw` と同様に、クライアントの呼び出しは e2e のガードを迂回します。
  ツールが返すスナップショットやスクリーンショットは、シークレットの入力後であっても
  秘匿処理もマスクもされません。呼び出し後に画面が落ち着くのを待つこともありません。
  また、呼び出しがデバイスを変更するツールは `mutates: true` を宣言する必要があります。
- `unstable_raw` と同様に、どのリリースでも変更される可能性があります。

## ロール

デバイスでの `getByRole` は、各要素の型が対応付けられたロールに一致します。
一覧にない型は、小文字のケバブケースにした独自の名前 (`picker-wheel`) のままと
なるため、その名前が `getByRole` のロール (`group`、`table`) である場合にのみ
一致します。プラットフォームが編集可能と報告するノードは、すでに `combobox` に
対応付けられている場合を除き、`textbox` になります。

アクセシビリティの値 (`checkbox, unchecked`) に、Android ではロールの説明
(`Tab List`) に書き込みます。次のいずれかの説明を持つノードは、その型のロールの

`menu bar`、`menu item`、`progress bar`、`radio button`、`radio group`、
`scroll bar`、`spin button`、`switch`、`tab`、`tab list`、`timer`、`tool bar`。

`expanded` を設定します。それより後に続くものだけがノードの値になります。

`WebView` は `document` です。どちらも `getByRole` のロールではありません。
テキストは `getByText` で検索してください。

## 表示状態

デバイスのノードは、プラットフォームが画面外にあると報告した場合、または
ソフトウェアキーボードがその中心を覆っている場合に非表示になります。そのため、
`toBeVisible()`、`scrollUntilVisible`、`getByRole` は、キーボードの下にある
フィールドを、スクロールして見えなくなったフィールドと同じように扱います。
キーボード自体のキー、候補バー、ドック、そしてフォーカスされたフィールドは表示
されたままです。

- キーボードの領域は、agent-device が計測するフレームです。キャプチャにフレームが
  ない場合、領域はツリー内のキーボードの上端から画面の下端までです。
- 中心がキーボードの下にあるコンテナは、子のいずれかがキーボードより上に表示されて
  いる間は表示されたままです。
- キーボードによって押し上げられたフッターなど、別のビューの下にあるノードは
  非表示にはなりません。agent-device が覆っているものを検出した場合、そのノードへの
  タップは `ACTION_FAILED` で失敗し、メッセージには覆っているものが示されます。
  キーボードの下へのタップも同様に失敗します。覆っているものを閉じるか、
  ターゲットが覆われない位置までスクロールしてください。

## 動画録画のクリーンアップ

保留中の agent-device の画面録画の停止は、後続の呼び出し元や試行のクリーンアップと
共有されます。ある呼び出し元の待機をキャンセルしても、停止が繰り返されたり、最終的な
完了が破棄されたりすることはありません。デバイスでの停止が失敗した場合、
クリーンアップで再試行できます。キャンセルされた呼び出し元は、それでもキャンセルを
報告します。

停止に失敗したプロバイダーの録画は、そのワーカーが所有したままになります。
エンジンは、試行の終了時、そのワーカーでの次の試行の前、そしてワーカーの破棄中に
停止をリトライします。保留中の停止は共有されます。各リトライは、元の試行の動画
ディレクトリを使います。

次の試行は、プロバイダーが停止を確認した後にのみ開始されます。停止の待機が失敗
またはキャンセルされた場合、その試行は開始されません。確認済みの停止は、返された
アーティファクトが無効であっても繰り返されません。
プロバイダーでの停止が失敗しただけでは、ワーカーの置き換え時に正常な agent-device
セッションが閉じられることはありません。

リトライによって回収された録画はレポートに追加されません。そのファイルは元の試行の
動画ディレクトリに残ることがあり、返された URL は破棄されます。最初の停止が失敗した
必須の動画は、クリーンアップの失敗のままです。

これらの録画のハンドルは、ワーカーの終了後には残りません。実行の終了時に、エンジンは
agent-device のセッションを閉じ、プロバイダーはリースを解放します。プロバイダーは、
リースを解放する際に残っている外部の録画をすべてクリーンアップする必要があります。
agent-device のセッションを閉じても、任意のクラウドの録画が停止することは保証
できません。プロバイダーの停止コールバックが失敗しても、録画が停止したことの確認
にはなりません。

## デバイスでのリプレイキャッシュ

リプレイキャッシュは、デバイスが報告する [`location`](#capabilities)
(`<bundle id> / <screen title>`) をアンカーにします。
`com.apple.Preferences / General` で記録されたステップは、Settings が再び General を
表示しているときにのみリプレイされます。

```ts
await app.open();
await screen.getByText('General').tap();
await agent.act('Open About and read the iOS version');
```

- `open_app` のような変更を伴うプロジェクトツールの呼び出しは、リプレイを終了させます。
- ステップが同じ画面から始まるように、`app.bundleId` を宣言し、最初に `app.open()` を
  呼び出してください。
- アプリの切り替えは、ステップの中ではなく、ステップの間に `device` フィクスチャで
  行ってください。
- [`device.openLink`](#openlink) の後に記録されたステップは、リンクが再び同じ画面に
  遷移したときにリプレイされます。

`MobileOptions`、`MobilePlatform`、`DevicePermission`、`LaunchPermissions`、
`PermissionState`、`DeviceClientConfig`、`DeviceConnection`、`DeviceDaemon`、
`DeviceProvider`、`DeviceLease`、`DeviceReleaseContext`、`DeviceRequest`、
`Device`、`DeviceSession`、`DeviceSessionClient`、`DeviceSelection`、`DeviceOrientation`、`BiometricSensor`、`ForegroundApp`、
`FoldPose`、`InstallAppOptions`、`InstalledApp`、`OpenAppOptions` は
`@e2e-dev/mobile` からエクスポートされます。ランタイムのエクスポートは `mobile` と、
`device` フィクスチャで型付けされた `test`、`describe`、`beforeEach`、`afterEach`、
`beforeAll`、`afterAll` です。`mobileTools` は `@e2e-dev/mobile/tools` から
提供されます。
