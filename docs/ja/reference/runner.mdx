`e2e/runner` は、CLI を呼び出さずにコードからスイートを実行します。`run` はテストを実行してそのレポートを返し、`explore` は 1 回の探索を実行してその発見事項を返し、`list` は選択内容を返し、`openHost` は別のテストランナー内で e2e のセッションをホストします。テストファイルから `e2e` をインポートしても、ランナーは読み込まれません。

<Note>
`run`、`list`、`explore`、`openHost` には Node.js が必要です。Bun では `NODE_UNSUPPORTED` をスローします。Bun では [CLI](/reference/cli#bun) でテストを実行してください。
</Note>

```ts title="scripts/run-e2e.ts"
import type { E2EConfig } from 'e2e';
import { run } from 'e2e/runner';
import { web } from '@e2e-dev/web';

const config: E2EConfig = {
  targets: [{ name: 'web', engine: web(), app: { url: 'http://localhost:3000' } }],
};
const controller = new AbortController();
const result = await run({
  config,
  files: ['tests/signup.e2e.ts'],
  interruptSignal: controller.signal,
  onEvent(event) {
    if (event.type === 'test-started') console.log(event.title);
  },
});

console.log(result.status, result.report.run.summary);
```

## リファレンス

### 関数

| 関数 | 戻り値 |
| --- | --- |
| [`run`](#run) | `Promise<RunResult>` |
| [`explore`](#explore) | `Promise<ExploreResult>` |
| [`list`](#list) | `Promise<ListResult>` |
| [`openHost`](#openhost) | `Promise<E2EHost<Fixtures>>` |
| [`isE2EError`](#ise2eerror) | `boolean` |

#### `run`

`run(options?: RunOptions)` は完全なスイートを実行します。解決する前にクリーンアップを完了し、呼び出し元のプロセスを終了させることはありません。

```ts
const result = await run({ files: ['tests/signup.e2e.ts'] });
process.exitCode = result.exitCode;
```

##### オプション

| オプション | 例 | 型 | デフォルト |
| --- | --- | --- | --- |
| `cwd` | `'apps/web'` | `string` | 現在の作業ディレクトリ |
| `config` | `'e2e.ci.config.ts'` | `string \| E2EConfig` | 検出された `e2e.config.ts` |
| `files` | `['tests/signup.e2e.ts:12']` | `readonly string[]` | 設定されたスイート |
| `changedSince` | `'origin/main'` | `string` | - |
| `interruptSignal` | `controller.signal` | `AbortSignal` | - |
| `onEvent` | `(event) => {}` | `RunEventSink` | - |

- `files` には、パス、glob、ファイル名のみ、または `file:line` を指定できます。
- `changedSince` は [`--changed-since`](/filters) と同様に動作します。
- `interruptSignal` を中断すると、テストが中断され、ティアダウンが実行されます。
- `onEvent` は型付きの進捗イベントを受け取ります。ターミナルの進捗表示はオフになります。ブロックしてはいけません。スローまたはリジェクトするコールバックは、実行を失敗させることなく無効化されます。
- リトライやワーカーなどの実行設定は、設定に記述してください。
- ランタイム設定（`E2EConfig` の値）は、呼び出し元のプロセス内で 1 つのワーカーで実行されます。ファイルの設定では、設定されたワーカープロセスがサポートされます。

##### 結果

| フィールド | 意味 |
| --- | --- |
| `exitCode` | CLI と同等の終了コード：`0`、`1`、`2`、`3`、`4`、`130` のいずれかです。 |
| `status` | `passed`、`failed`、`blocked`、`error`、`interrupted` のいずれかです。 |
| `report` | 完全なレポートです。結果については `report.run.results`、`report.run.errors`、`report.run.summary` を参照してください。 |
| `reportPath` | `report.json` への絶対パス。書き込めなかった場合は `undefined` です。 |
| `aiTracePath` | AI トレースのパス。AI トレースが書き込まれなかった場合は `undefined` です。 |

テストの失敗、設定の失敗、中断は、そのステータスとレポート内のエラーとともに解決されます。

| スローされるエラー | 条件 |
| --- | --- |
| `RUNNER_BUSY` | 別のスイートが実行中か、ホストが開いている場合。スイートを実行する前にすべてのホストを閉じ、ホストを開く前にスイートを await してください。 |

- テストファイルがインポートするヘルパーモジュールは、1 つのプロセス内の `run` 呼び出し間でキャッシュされたままになります。それらを編集した場合は、新しいプロセスが必要です。
- レポートを返す各実行は、CLI と同じオプトアウト設定のもとで、匿名の [`e2e_run_completed`](/telemetry) イベントを 1 件送信します。最初の呼び出しでは、stderr にテレメトリーの通知が表示されることがあります。
- スイートの出力は UTF-8 テキストのマスキングを使用し、バイナリデータは保持しません。アプリケーションのログと進捗コールバックの出力は、ご自身の管理下にあります。

#### `explore`

`explore(options?: ExploreOptions)` は、`e2e explore` が開始する実行である[探索](/explore)を 1 回実行します。解決する前にクリーンアップを完了し、呼び出し元のプロセスを終了させることはありません。

```ts title="scripts/explore-e2e.ts"
import type { E2EConfig } from 'e2e';
import { explore } from 'e2e/runner';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';

const config: E2EConfig = {
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
  targets: [{ name: 'web', engine: web(), app: { url: 'http://localhost:3000' } }],
};
const controller = new AbortController();
const result = await explore({
  config,
  goal: 'Explore the checkout flow like a first-time buyer and report anything off',
  maxSteps: 4,
  interruptSignal: controller.signal,
  onEvent(event) {
    if (event.type === 'explore' && event.progress.phase === 'finding') console.log(event.progress.finding.title);
  },
});

console.log(result.status, result.explore.ended, result.explore.findings.length);
```

##### オプション

| オプション | 例 | 型 | デフォルト |
| --- | --- | --- | --- |
| `cwd` | `'apps/web'` | `string` | 現在の作業ディレクトリ |
| `config` | `'e2e.ci.config.ts'` | `string \| E2EConfig` | 検出された `e2e.config.ts` |
| `goal` | `'Explore the login flow'` | `string` | `'Explore the app and find bugs'`。`changedSince` を指定した場合は `'Explore what this change affects and find bugs in it'` |
| `target` | `'web'` | `string` | 最初に設定されたターゲット |
| `agent` | `'smart'` | `string` | `agents.default` |
| `session` | `'loggedIn'` | `string` | - |
| `changedSince` | `'origin/main'` | `string` | - |
| `maxSteps` | `4` | `number` | `8` |
| `timeoutMs` | `300_000` | `number` | `600_000` |
| `interruptSignal` | `controller.signal` | `AbortSignal` | - |
| `onEvent` | `(event) => {}` | `RunEventSink` | - |

- `goal` は最大 2,000 文字です。
- `session` は、[セットアップテスト](/authentication)が保存するセッションの名前を指定します。`--session` と同様に、そのセットアップが最初に実行され、探索はそこから開始します。
- `changedSince` は、[`--changed-since`](/reference/cli#e2e-explore) と同様に、その ref 以降の変更を探索します。
- `maxSteps` は 1 から 100 です。`timeoutMs` は `180000` から `7200000` です。
- `onEvent` は `run` と同じイベントに加えて、計画上の判断、ステップ、発見事項ごとに `explore` イベントを受け取ります。選択したターゲットなど、実行開始前に `e2e explore` が出力する内容は、ターゲット `run` の `notice` イベントとして、`plan` イベントより前に届きます。
- `video`、`trace`、`output` などの録画と出力の設定は、設定から取得されます。

##### 結果

`ExploreResult` は、[`RunResult`](#run) のすべてのフィールドに加えて、`report.run.explore` も保持する記録である `explore` を持ちます。

| フィールド | 意味 |
| --- | --- |
| `explore.goal`, `explore.budgets` | シークレットの値がマスキングされたゴールと、実行時のステップと時間の予算です。 |
| `explore.ended` | 探索が停止した理由：`finished`、`skipped`（`changedSince` を指定した場合に、ユーザーに見える変更がないとプランナーが判断したもの。実行はパスします）、`step-limit`、`time`、`stuck`、`aborted` のいずれかです。 |
| `explore.summary` | エージェントが最終評価を出した場合の、その評価です。 |
| `explore.change` | `changedSince` を指定した場合に、計画の元になった変更です。`base` はマージベース、`files` は変更されたファイル数です。 |
| `explore.steps` | エージェントが計画して実行した各ステップと、そのステータス：`passed`、`failed`、`blocked`、`exhausted` のいずれかです。 |
| `explore.findings` | 各発見事項：`kind`、1 から 5 の `severity`、`title`、`expected`、`actual`、`reproduction` です。`issue` は実行を失敗させますが、`warning` は失敗させません。 |

探索が開始されると、発見事項、失敗、中断は、そのステータスとともにレポート内で解決されます。探索を開始できないオプションや設定は、対応する `e2e explore` フラグと同様に、先にリジェクトされます。それらは [`isE2EError`](#ise2eerror) で判別してください。

| スローされるエラー | 条件 |
| --- | --- |
| `INVALID_CONFIG` | `goal`、`maxSteps`、`timeoutMs` が範囲外であるか、`agent` が設定されたエージェントを指定していない場合。 |
| `UNKNOWN_TARGET` | `target` が設定されたターゲットを指定していない場合。 |
| `MODEL_UNAVAILABLE` | エージェントにモデルがない場合。 |
| `INVALID_CHANGED_SINCE` | `changedSince` が空、`-` で始まる、または git が変更を測定できない ref を指定している場合。 |
| `RUNNER_BUSY` | スイートや探索が実行中か、ホストが開いている場合。 |
| `run` が記録するコード | 設定が見つからないか、ローダーが設定を拒否した場合。 |

レポートを返す各探索は、`run` と同様に、匿名の [`e2e_run_completed`](/telemetry) イベントを 1 件送信します。

#### `list`

`list(options?: ListOptions)` は、[`e2e list`](/reference/cli#e2e-list) と同じ方法で収集と選択を行い、そこで停止します。アプリのプロセス、エンジン、ワーカーは起動せず、何も書き込まれません。

```ts
import { isE2EError, list } from 'e2e/runner';

const { pairs, unmatched, targets } = await list({
  files: ['tests/signup.e2e.ts'],
  grep: [/checkout/],
});

for (const pair of pairs) {
  console.log(`${pair.id} ${pair.disposition} ${pair.titlePath.join(' › ')}`);
}
```

呼び出しのたびにテストファイルを再度インポートするため、同じプロセス内の後続の `list()` は編集内容を反映します。

##### オプション

| オプション | 例 | 型 | デフォルト |
| --- | --- | --- | --- |
| `config` | `'e2e.ci.config.ts'` | `string \| E2EConfig` | `e2e list` と同じ探索方法で `cwd` から検出 |
| `targets` | `['web']` | `readonly string[]` | - |
| `cwd` | `'apps/web'` | `string` | 現在の作業ディレクトリ |
| `files` | `['tests/', 'signup.e2e.ts:12']` | `readonly string[]` | 設定されたスイート |
| `tags`, `tagMode`, `excludeTags` | `{ tags: ['smoke'], tagMode: 'all' }` | `readonly string[]`, `'any' \| 'all'` | - |
| `grep`, `grepInvert` | `[/checkout/]` | `readonly RegExp[]` | - |
| `lastFailed` | `true` | `boolean` | - |
| `shard` | `{ index: 1, total: 4 }` | `{ index, total }` | - |
| `changedSince` | `'origin/main'` | `string` | - |
| `passWithNoTests` | `true` | `boolean` | - |
| `output` | `'.e2e'` | `string` | 設定の `output` |
| `env` | `{ ...process.env, CI: '1' }` | `NodeJS.ProcessEnv` | `process.env` |

- `targets` は、`--target` と同様にターゲットを指定します。
- `files` は位置引数によるファイルの選択です。パス、glob、ファイル名のみ、`file:line` を指定できます。
- `tags`、`tagMode`、`excludeTags` は、`--tag`、`--tag-mode`、`--exclude-tag` のフィルターです。
- `grep` と `grepInvert`：テストの describe のタイトルとタイトルをスペースで結合したものが、いずれかの `grep` パターンに一致し、どの `grepInvert` パターンにも一致しない必要があります。
- `lastFailed` は、`output` 配下の `report.json` から読み取り、前回の実行でパスしなかったテストのみを残します。
- `shard` は `--shard index/total` による分割です。
- `changedSince` は `--changed-since` と同様に動作します。[テストフィルター](/filters)は呼び出し元のプロセスで実行されます。`list` はそれらの行を一切出力しませんが、`e2e list` は出力します。
- `passWithNoTests` を指定すると、実行可能なテストがない場合に `NO_TESTS` をスローせずに解決します。
- `output` は結果のディレクトリです。
- `env` は設定の解決に使われる環境変数です。

##### 結果

`ListResult` は `{ pairs, unmatched, targets }` です。

- `pairs` は、テスト、ターゲット、エージェントごとに 1 つの `ListedPair` で、選択順に並び、フィルターで除外されたペアも含みます。繰り返しは展開されません。
- `unmatched` は、検出されたファイルを 1 つも選択しなかった位置引数を、記述どおりに並べたものです。
- `targets` は、選択されたターゲット名を設定の順序で並べたものです。

| フィールド | 意味 |
| --- | --- |
| `id` | `report.json` が繰り返し 0 に対して保存する結果 ID です。 |
| `file`, `title`, `titlePath`, `kind`, `tags` | 収集されたテストです。`kind` は `test` または `setup` です。テストがタグを宣言していない場合、`tags` は `[]` です。 |
| `source` | プロジェクト相対の宣言位置：`{ file, line, column }` です。テストが記録していない場合は `undefined` です。 |
| `session` | テストまたはその describe チェーンから得られる、テストが使用するセッションです。使用しない場合は `undefined` です。 |
| `sessions` | セットアップが生成するセッション名です。通常のテストでは `[]` です。 |
| `serialId` | テストがシリアルグループに属する場合に設定され、そうでない場合は `undefined` です。 |
| `target`, `agent` | このペアが実行されるターゲット名と、設定されたエージェントです。 |
| `disposition` | `run`、`skip`、`filtered` のいずれかです。 |
| `reason` | `title does not match --grep` のような、ペアがスキップまたは除外された理由です。実行される場合は省略されます。 |
| `filter` | ペアを除外したテストフィルターの名前です。選択フラグで除外されたペアにはありません。 |

`e2e list` は、`run` と `skip` のペア、およびテストフィルターが除外したペアを出力します。`list` はすべての `filtered` ペアを返します。

##### エラー

失敗は、`e2e list` が終了時に返すのと同じ分類済みのエラーです。[`isE2EError`](#ise2eerror) で判別し、`error.code` で分岐してください。

```ts
import { isE2EError, list } from 'e2e/runner';

try {
  await list({ targets: ['missing'] });
} catch (error) {
  if (isE2EError(error) && error.code === 'UNKNOWN_TARGET') {
    console.error(error.message);
  }
}
```

| スローされるエラー | 条件 |
| --- | --- |
| `NO_TESTS` | 選択が空で、`passWithNoTests` が設定されていない場合。`ConfigurationError` です。テストフィルターによって実行対象が何も残らない場合は、すべてのペアが `filtered` または `skip` の状態で `list` が解決します。 |
| `UNKNOWN_TARGET` | `targets` 内の名前が設定されたターゲットではない場合。 |
| `INVALID_CHANGED_SINCE` | `changedSince` が空か `-` で始まる場合、またはテストフィルターが実行され、git が変更を測定できない ref を指定している場合。 |
| `run` が記録するコード | 設定が見つからない、ローダーが設定を拒否した、または収集に失敗した場合。 |

#### `openHost`

`openHost<Fixtures>(options?: OpenHostOptions)` は、Playwright Test、Vitest、Jest、または独自のハーネス向けに e2e を準備し、[ホスト](#host)を返します。

```ts
import { openHost } from 'e2e/runner';

await using host = await openHost({ target: 'web' });
await using session = await host.openSession({ name: 'checkout' });
await session.fixtures.app.open('/checkout');
```

- 収集、リトライ、レポートはご自身のランナーが担当します。
- ホストはターゲットのエンジンを準備し、アプリのプロセスを起動し、ワーカーのライフタイムごとに 1 回エンジンを初期化します。ワーカースコープのホストとテストスコープのセッションを使用してください。[Playwright Test の例](#playwright-test-fixtures)を参照してください。
- 各 [`host.openSession`](#host-opensession) は、新しいフィクスチャ、期限、ステップ、アーティファクトを持つ、テストのライフタイムの試行を作成します。
- オープンに失敗した場合、e2e はエラーをスローする前に、起動済みのものをティアダウンします。

##### オプション

| オプション | 例 | 型 | デフォルト |
| --- | --- | --- | --- |
| `config` | `'e2e.config.ts'` | `string \| E2EConfig` | 最も近い `e2e.config.ts`、`.mts`、`.js`、`.mjs` |
| `cwd` | `'apps/web'` | `string` | `process.cwd()` |
| `target` | `'android'` | `string` | 唯一のターゲット |
| `env` | `process.env` | `NodeJS.ProcessEnv` | `process.env` |
| `signal` | `controller.signal` | `AbortSignal` | - |
| `headed` | `true` | `boolean` | `false` |
| `onNotice` | `(target, message) => {}` | `(target: string, message: string) => void` | - |

- `config` は `cwd` からの相対パスで指定する設定ファイルのパス、または `E2EConfig` の値です。省略すると、`list` と同じ探索方法で `cwd` から設定を検出します。
- `cwd` は設定を検出するディレクトリであり、設定の値を渡した場合のプロジェクトルートです。
- 設定が複数のターゲットを宣言している場合、`target` は必須です。
- `env` は、設定、エンジン、プロバイダーが読み取る環境変数です。
- `signal` は、ホストのプロビジョニング、保留中のセッションのオープン、または実行中のフィクスチャ呼び出しをキャンセルします。
- `headed` は、ブラウザエンジンをヘッドありで実行します。
- `onNotice` は、プロビジョニングやアプリのプロセスなど、ステップ外の進捗を受け取ります。スローしてはいけません。

設定のパスを渡されたホストは、そのファイルとそのプロジェクトファイルのインポートを新たに読み込みます。パッケージのインポートは共有されたままなので、それらのシングルトンの状態はホストごとに再作成されません。設定の値は自身のエンジンインスタンスを使用します。各インスタンスはそのホストが閉じるまで 1 つのホストに属するため、2 つ目のホストでは別のインスタンスを使用する必要があります。

| スローされるエラー | 条件 |
| --- | --- |
| `UNKNOWN_TARGET` | `target` が設定されたターゲットを指定していない場合。 |
| `TARGET_REQUIRED` | 設定が複数のターゲットを宣言しており、`target` が何も指定していない場合。 |
| `RUNNER_BUSY` | スイートが実行中の場合。ホストを開く前に await してください。 |

オープン時の失敗は、分類されマスキングされたエラーです。エンジンの生の原因は公開されません。[`isE2EError`](#ise2eerror) と `error.code` で照合してください。

#### `isE2EError`

分類済みの e2e エラーを判別する型ガードです。その `error.code` で分岐してください。

```ts
if (isE2EError(error) && error.code === 'NO_TESTS') process.exitCode = 0;
```

パッケージのコピーが複数ある場合、`instanceof` では e2e のエラーを判別できないことがあるため、`isE2EError` を使用してください。`ConfigurationError` と `isE2EError` はどちらも `e2e/runner` からエクスポートされています。

### ホスト

`E2EHost<Fixtures>` は [`openHost`](#openhost) が返すものです。

| メンバー | 戻り値 |
| --- | --- |
| `runId`, `target` | `string` |
| [`host.openSession`](#host-opensession) | `Promise<E2ESession<Fixtures>>` |
| [`host.close`](#host-close) | `Promise<readonly SerializedError[]>` |

`runId` と `target` は、ホストのセッションが共有する識別情報です。

異なるホストをまたいでも、また設定がファイルか値かにかかわらず、プロセスごとにオープン中、実行中、クローズ中にできるホスト型の試行は 1 つだけです。

- 重複したオープンは、エンジンの試行状態が開始される前に拒否されます。同じホストで次のセッションを開く前に、`session.close()` を await してください。
- 失敗またはキャンセルされた起動は、開いたものを終了させ、ホストを使用可能な状態に保ちます。これは、実行がリトライのためにワーカーを保持するのと同様です。
- エンジンのクリーンアップに失敗したセッションは、その分離状態が不確かになるため、ホストを恒久的に閉じます。新しいホストを開いてください。

| スローされるエラー | 条件 |
| --- | --- |
| `WORKER_PROTOCOL` | ホスト型の試行が重複している場合、または閉じたホストに対して呼び出した場合。 |

#### `host.openSession`

`host.openSession(options: OpenSessionOptions)` は、このホストのターゲットで新しい[セッション](#session)を開きます。セッションはリトライのループを持たない 1 回のテスト試行です。リトライでは、同じワーカーホストで新しいセッションを開きます。

```ts
const session = await host.openSession({
  name: 'checkout',
  timeout: 60_000, // default: the config's timeout
  onStep: (step) => {
    if (step.phase === 'end') console.log(`${step.api} ${step.label}: ${step.status}`);
  },
});
```

##### オプション

| オプション | 例 | 型 | デフォルト |
| --- | --- | --- | --- |
| `name` | `'checkout'` | `string` | 必須 |
| `timeout` | `60_000` | `number` | 設定の `timeout` |
| `signal` | `controller.signal` | `AbortSignal` | - |
| `agent` | `'smart'` | `string` | 最初に設定されたエージェント |
| `onStep` | `(step) => {}` | `(progress: StepProgress) => void` | - |

- `name` は、ステップとトレースのレポートに使われるテスト名です。
- `timeout` は、セッションの操作のミリ秒単位の期限で、正の有限値です。セッションが開いた時点から数えます。プロビジョニングやオープンには適用されず、セッションを閉じることもありません。
- `signal` は、オープンまたは実行中のフィクスチャ呼び出しをキャンセルします。ホストの `signal` も適用されます。プロビジョニングは `openHost` で行われるため、それをキャンセルできるのはホストの `signal` のみです。起動はどちらのシグナルでもキャンセルできます。
- `agent` は、呼び出しでエージェントが指定されていない場合に `agent` フィクスチャが使用するエージェントです。
- `onStep` は、レポーターが受け取るのと同じフィードである、ライブの `StepProgress` を受け取ります。ブロックしたりスローしたりしてはいけません。その `phase` は `start`、`event`、`activity`、`replay`、`end` のいずれかです。`end` イベントには、`status`、`durationMs`、`modelCalls`、およびステップが失敗した場合はマスキング済みの `error` が含まれます。
- `timeout`、`agent`、`onStep` は `openHost` ではなくセッションに属します。

| スローされるエラー | 条件 |
| --- | --- |
| `INVALID_CONFIG` | `name` が文字列ではない、または `timeout` が正の有限値ではない場合。 |
| `CANCELLED` | オープンの前または最中に、セッションまたはホストの `signal` が中断された場合。 |
| `WORKER_PROTOCOL` | 別のホスト型の試行がオープン中、実行中、クローズ中である場合、またはホストが閉じている場合。 |

#### `host.close`

`host.close()` は、アクティブまたは保留中のセッションをキャンセルし、それが閉じるのを待ってから、エンジンを破棄し、アプリのプロセスを停止し、プロビジョニングを解放します。

```ts
const failures = await host.close();
if (failures.length > 0) throw new AggregateError(failures, 'e2e host close failed');
```

- 冪等です。リソースの破棄と解放は 1 回だけ行われます。
- ホストは `AsyncDisposable` です。`await using host = await openHost()` はスコープの終了時にホストを閉じ、クローズで失敗が報告された場合は `AggregateError` をスローします。

### セッション

`E2ESession<Fixtures>` は [`host.openSession`](#host-opensession) が返すものです。

| メンバー | 戻り値 |
| --- | --- |
| `fixtures` | `TestFixtures & Fixtures` |
| `runId`, `attemptId`, `target` | `string` |
| `steps()` | `readonly StepRecord[]` |
| `report()` | `Report \| undefined` |
| `artifactsDir` | `string` |
| `tracePath` | `string` |
| [`session.close`](#session-close) | `Promise<readonly SerializedError[]>` |

- `fixtures` は、`agent`、`app`、`screen`、`platform`、およびエンジンのフィクスチャを保持します。
- `runId` と `target` はホストの実行とターゲットです。`attemptId` はこの試行に固有です。
- `steps()` は、これまでに実行されたステップの読み取り専用の `StepRecord` を、[レポート](/reference/reporters)が記録するとおりに返します。
- `report()` は、クローズとトレースの書き込みが成功した後に、トレースのレンダリング元となるセッションの `Report` を返します。それ以外の場合は `undefined` です。そのステータスは SDK のセッションを表すもので、ご自身のランナーにおけるテスト本体の判定ではありません。
- `artifactsDir` は、この試行のスクリーンショット、録画、トレースを置く絶対ディレクトリです。
- `tracePath` は `trace.md` への絶対パスです。`close()` が完了した後に添付したり読み取ったりしてください。

#### `session.close`

`session.close()` は、残りの操作をキャンセルし、試行を終了し、そのトレースを書き込みます。ソフトな期待値の失敗、放棄された操作（未完了のポーリングやステップ）、クリーンアップの失敗を、スローする代わりに返します。

```ts
const failures = await session.close();
if (failures.length > 0) throw new AggregateError(failures, 'e2e session close failed');
```

- 冪等です。2 回目以降の呼び出しは同じ失敗を返します。
- ホストは次のテストのために開いたままになります。
- セッションは `AsyncDisposable` です。
  `await using session = await host.openSession({ name: 'checkout' })`
  はスコープの終了時にセッションを閉じ、返された失敗の `AggregateError` をスローします。

#### 期限とソフトな失敗

`expect.soft` はセッションのライフタイム全体にわたって失敗を収集します。ホストランナーのテストを失敗させるには、`close()` の結果を確認してください。

- `expect.poll` は、自身のタイムアウトのほうが長い場合でも、セッションの残りの予算を使用します。
- 提供されたフィクスチャの操作も、自身のタイムアウトを無効にする操作を含め、その予算に従います。
- 期限を過ぎると、それを監視していたポーリングや操作は、自身の打ち切りとして報告します。まだ実行中のその他すべてのもの（エンジンやモデルが応答しなかった操作を含む）は、`TEST_TIMEOUT` で失敗します。
- いずれの場合も、セッションの結果はタイムアウトとなり、`close()` はタイムアウトを返します。以降の操作は `TEST_TIMEOUT` で失敗するので、セッションを閉じてください。

#### アーティファクト

アーティファクトは `<output>/results/host/<resultSegment>/` 配下に置かれます。クローズ時に、e2e はレポートと同じマスキング済みのフォーマットで、そこに `trace.md` を書き込みます。

- e2e は、名前と一意の試行の識別情報から安全な `resultSegment` を生成します。名前がそのままパスの構成要素になることはありません。
- 名前の重複やリトライには、別々のディレクトリが割り当てられます。
- プロバイダーが提供するシークレットを使う場合、未解決の値はタイトルのスラッグからマスキングできないため、ディレクトリには識別情報のみのセグメントが使われます。トレースには引き続きマスキング済みの名前が表示されます。
- アーティファクトのパスは、`session.artifactsDir` ではなく `<output>/results` からの相対パスです。
- 動画は、最初の試行ではターゲットのモードに従います。失敗時のみの動画は、ソフトな失敗と、失敗、ブロック、タイムアウト、キャンセルされたステップについて保持されます。

<Note>
ホスト型のセッションが書き込むのはトレースであり、`report.json` ではありません。ご自身のランナーでのレポートには、`onStep`、`steps()`、`report()`、および `close()` の失敗を使用してください。ご自身のランナーにおけるテスト本体の失敗は e2e に渡されません。

`e2e mcp` が使用する単発の試行は内部のものです。トップレベルの `openSession` エクスポートはありません。
</Note>

## 型

`e2e/runner` は、関数と並んで以下の型をエクスポートします。

| 型 | 説明 |
| --- | --- |
| `RunOptions`, `RunResult` | [`run`](#run) のオプションと結果 |
| `ExploreOptions`, `ExploreResult` | [`explore`](#explore) のオプションと結果 |
| `RunEventSink` | `onEvent` コールバック |
| `ListOptions`, `ListResult`, `ListedPair` | [`list`](#list) のオプション、結果、1 つのペア |
| `OpenHostOptions`, `E2EHost` | [`openHost`](#openhost) のオプションと[ホスト](#host) |
| `OpenSessionOptions`, `E2ESession` | [`openSession`](#host-opensession) のオプションと[セッション](#session) |
| `StepProgress`, `StepRecord` | 1 つの `onStep` 進捗イベントと、`steps()` が返す 1 つのステップ |
| `SerializedError` | `close()` が返す 1 つの失敗 |

## 例

### Playwright Test のフィクスチャ

ワーカースコープのホストとテストスコープのセッション：

```ts title="tests/fixtures.ts"
import { test as base } from '@playwright/test';
import { openHost, type E2EHost, type E2ESession } from 'e2e/runner';
import type { Device } from '@e2e-dev/mobile';

type Fixtures = { device: Device };

const test = base.extend<
  { e2e: E2ESession<Fixtures> },
  { e2eHost: E2EHost<Fixtures> }
>({
  e2eHost: [async ({}, use) => {
    const host = await openHost<Fixtures>({ target: 'android' });
    try {
      await use(host);
    } finally {
      const failures = await host.close();
      if (failures.length > 0) throw new AggregateError(failures, 'e2e host close failed');
    }
  }, { scope: 'worker' }],
  e2e: async ({ e2eHost }, use, testInfo) => {
    const session = await e2eHost.openSession({
      name: testInfo.titlePath.join(' › '),
      // Playwright's 0 disables its timeout; e2e then falls back to the config's.
      timeout: testInfo.timeout || undefined,
      onStep: (step) => {
        if (step.phase === 'end') console.log(`${step.api} ${step.label}: ${step.status}`);
      },
    });
    try {
      await use(session);
    } finally {
      const failures = await session.close();
      await testInfo.attach('e2e trace', { path: session.tracePath, contentType: 'text/markdown' });
      if (failures.length > 0) throw new AggregateError(failures, 'e2e session close failed');
    }
  },
});

test('turns on dark mode', async ({ e2e }) => {
  const { agent, app } = e2e.fixtures;
  await agent.act('open settings and turn on dark mode');
  await app.screenshot();
});
```
