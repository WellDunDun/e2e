これらの変数は、ランナーとファーストパーティのパッケージを設定します。表の中で、
`set` は変数が存在すること、`value` は空でないこと、`flag` は空・`0`・`false`
のいずれでもないことを意味します。フラグの値は大文字と小文字を区別しません。

```bash
export E2E_USER_ADMIN_PASSWORD="$ADMIN_PASSWORD"
export E2E_CACHE_DIR=~/.cache/e2e
export E2E_TELEMETRY_DISABLED=1
```

## リファレンス

### モデル

モデルは `e2e.config.ts` で設定します。API キーはそのプロバイダーが読み取ります。
`gateway()` は `AI_GATEWAY_API_KEY`、`openrouter()` は
`OPENROUTER_API_KEY`、`openai()` は `OPENAI_API_KEY` を使います。
`AI_GATEWAY_API_KEY` がない場合、`gateway()` は
[Vercel OIDC トークン](/models#vercel-oidc-instead-of-a-key)を使います。認証情報が
ない場合は、最初のモデル呼び出しで失敗します。サブスクリプションモデルは、代わりに
保存済みのログインを使います。
[モデル](/models)と[サブスクリプション](/subscriptions)を参照してください。

| 変数 | 例 | 読み取り | 効果 |
| --- | --- | --- | --- |
| [`E2E_OAUTH_CREDENTIALS`](#e2e_oauth_credentials) | `E2E_OAUTH_CREDENTIALS="$(cat oauth.json)"` | value | 保存済みのサブスクリプションログインを JSON で指定します |
| [`OPENCODE_API_KEY`](#opencode_api_key) | `OPENCODE_API_KEY=<key>` | value | 保存済みの `opencode-console` ログインを置き換えます |
| `XDG_CONFIG_HOME` | `XDG_CONFIG_HOME=~/.config` | value | 保存済みログインのディレクトリで、`$XDG_CONFIG_HOME/e2e/oauth.json` になります。デフォルトは `~/.config/e2e/oauth.json` です |

#### `E2E_OAUTH_CREDENTIALS`

保存済みのサブスクリプションログインを JSON で指定します。`oauth.json` の内容で、
誰もサインインできないマシン向けです。

- `e2e/oauth/*` モデルと `e2e models` は、
  `$XDG_CONFIG_HOME/e2e/oauth.json` の代わりにこれを読み取ります。
- `e2e login` と `e2e logout` はこれを変更しません。
- 更新されたトークンは書き戻されません。

#### `OPENCODE_API_KEY`

OpenCode Console のサービスアカウント API キー、または OpenCode Go サブスクリプションの
API キーです。`opencodeConsole()` と `e2e models opencode-console` は、保存済みの
`opencode-console` ログインの代わりにこれを使います。OpenCode も同じ変数を読み取ります。

### 認証情報とシークレット

| 変数 | 例 | 読み取り | 効果 |
| --- | --- | --- | --- |
| `E2E_USER_<NAME>_USERNAME` | `E2E_USER_ADMIN_USERNAME=admin@example.test` | set | `credentials.<name>.username` を置き換えます |
| `E2E_USER_<NAME>_PASSWORD` | `E2E_USER_ADMIN_PASSWORD="$ADMIN_PASSWORD"` | set | `credentials.<name>.password` を置き換えます |
| `E2E_SECRET_<NAME>` | `E2E_SECRET_API_KEY="$API_KEY"` | set | `secrets.<name>` の値を置き換えます |

- `<NAME>` は名前を大文字にし、`A-Z0-9` 以外のすべての文字を `_` に置き換えたものです。
  たとえば `power-user` は `E2E_USER_POWER_USER_USERNAME` になります。
- 名前が同じ `<NAME>` に対応する 2 つの認証情報、または 2 つのシークレットは、
  変数が設定されているかどうかにかかわらず、設定の読み込み時に `INVALID_CONFIG`
  になります。これにより、1 回のローテーションで 2 つのエントリーが置き換わることは
  ありません。メッセージには該当するエントリーと変数が示されます。
  たとえば、`api-key` と `api_key` はどちらも `E2E_SECRET_API_KEY` を読み取り、
  `svc-a` と `svc_a` はどちらも `E2E_USER_SVC_A_USERNAME` と `_PASSWORD` を読み取ります。
- 認証情報とシークレットはプレフィックスが異なるため、同じ名前を共有できます。
- 設定にない名前の変数は無視されます。
- 空のパスワードやシークレットは `INVALID_CONFIG` になり、6 文字（コードポイント）
  より短いものも同様です。リダクションは値のすべての出現箇所を書き換えるため、
  それほど短い値では通常のテキストまで巻き込んでしまいます。空のユーザー名は
  受け付けられます。

### 実行モード

| 変数 | 例 | 読み取り | 効果 |
| --- | --- | --- | --- |
| [`CI`](#ci) | `CI=1` | flag | CI モード |

#### `CI`

CI モードを有効にします。

- `retries` のデフォルトは 1、`workers` のデフォルトは 1 になります。
- `cache` のデフォルトは `read-only` になります。
- フォーカスされたテストは `ONLY_IN_CI` になります。
- アプリのコマンドの `reuseExisting` は無視されます。

### リプレイキャッシュ

| 変数 | 例 | 読み取り | 効果 |
| --- | --- | --- | --- |
| [`E2E_CACHE_DIR`](#e2e_cache_dir) | `E2E_CACHE_DIR=~/.cache/e2e` | value | [`cache.dir`](/reference/config#cache) を置き換えます |

#### `E2E_CACHE_DIR`

`e2e run` と `e2e cache` の [`cache.dir`](/reference/config#cache) を置き換えます。
プロジェクトルートから解決されます。

- `~` または先頭の `~/` はホームディレクトリを表します。
- `--cache-dir` がこれより優先されます。
- カスタムの `cache.store` はこれを無視します。
- キャッシュモードは設定どおりのままで、`--no-cache` を指定すればキャッシュは
  引き続き無効になります。

### 診断

| 変数 | 例 | 読み取り | 効果 |
| --- | --- | --- | --- |
| `NO_COLOR` | `NO_COLOR=1` | set | プレーンな CLI 出力にします。設定しない場合、TTY または CI では色が有効になり、パイプ時は無効になります |
| `FORCE_COLOR` | `FORCE_COLOR=1` | set | パイプ時でも CLI 出力に色を付けます |
| `TERM` | `TERM=dumb` | value | `dumb` の場合、CI と同様に `e2e init` のロゴをアニメーションなしの静止状態で描画します |
| `GITHUB_SHA`, `GITHUB_HEAD_REF`, `GITHUB_REF_NAME` | `GITHUB_REF_NAME=main` | value | `git` がプロジェクトルートを読み取れないときに、レポートが `run.vcs` に記録するコミットとブランチです。`GITHUB_HEAD_REF` が `GITHUB_REF_NAME` より優先されます |

`--debug` と `--ai-trace` は変数ではなくフラグです。
[CLI](/reference/cli#e2e-run) を参照してください。

#### `E2E_TELEMETRY_FLEET`

ユーザーのために e2e を実行しているプラットフォームの名前を指定します。

- イベントはマシンごとの ID ではなく `fleet:<name>` に帰属します。
- 設定ファイルは書き込まれず、通知も表示されません。
- 単純なトークンではない値は `other` として送信されます。

#### `EXPO_TOKEN`

`@e2e-dev/eas` の `expoSimulators()` がシミュレーターセッションの開始と停止に使う
Expo アクセストークンです。[Expo Simulators](/integrations/eas) を参照してください。

- 設定されていない場合は、ホームディレクトリ（[`HOME`、`USERPROFILE`](#engines)）の
  `.expo/state.json` にある eas-cli のログインを使います。
- どちらもない場合、デバイスのリースは失敗します。

## アプリのプロセスが継承するもの

アプリの `command` は、`PATH`、`HOME`、`TMPDIR`、`TMP`、`TEMP`、
`SystemRoot`、`COMSPEC` に加えて、`command.inheritEnv` に一致する変数と
`command.env` が設定するものを受け取ります。

スキャフォールドされた設定モジュールは `APP_URL` を読み取りますが、ランナーは読み取りません。
開発サーバーにも必要な場合は、`command.env` で渡してください。
