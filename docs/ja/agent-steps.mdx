エージェントステップとは、`agent.act`、`agent.assert`、`agent.waitFor`、
`agent.extract` のいずれか 1 回の呼び出しです。モデルは画面を読み取り、アクションを要求し、
判定を下してステップを終了します。すべてのステップには期限とモデル呼び出しの予算があります。

## 役割分担

エグゼキューターはアクションを選び、判定を返します。ランナーは画面を秘匿処理し、
各アクションを承認して実行し、予算を適用し、シークレットを入力し、レポートを書き出します。
エージェントのエントリーで [カスタムのエグゼキューター](/executors) を設定しない限り、
組み込みエージェントがエグゼキューターになります。

## モデルに見えるもの

`act` の場合、最初のプロンプトには、指示、パラメーター、完了したステップ、そして
画面の秘匿処理されたテキストスナップショット（ロール、名前、テキスト、状態）が含まれます。
生の HTML、Cookie、ヘッダー、環境変数の値は含まれません。パスワードフィールドはマスクされ、
画面上にある設定済みのシークレットの値は `<secret:name>` になります。

アクションの後、モデルは画面の変更点を受け取ります。画面の大部分が変わった場合は、
新しい完全なスナップショットを受け取ります。ノード ID は、その要素が存在する間は変わりません。
アクションが失敗した場合も現在の画面が返されるため、モデルは次のアクションを選べます。

`assert`、`waitFor`、`extract` のデフォルトの判定では、指示、現在の画面とその場所、
エージェントの `context` が参照され、完了したステップや操作するエージェントの要約は参照されません。
これらは別の [ジャッジモデル](/models#a-judge-of-its-own) を使えます。
組み込みの探索型アサーションは、`judge` が設定されていても `agents.<name>.model` を使います。

`vision: true` はマスクされたスクリーンショットを追加し、`vision: 'only'` はスクリーンショット
だけで判定します。各モードについては [エージェントリファレンス](/reference/agent#vision) を
参照してください。スクリーンショットでマスクされるのはセキュアなフィールドだけです
（[シークレットの入力後](/reference/security#screenshots-after-a-secret-fill)）。

## モデルが行えること

エージェントは、`tap`、`type`、`press`、`select`、`scroll`、`navigate` など、
ターゲットのエンジンがサポートするツールを受け取ります。キーボードのあるエンジンでは、
フォーカスされたコントロールで入力やキーの押下ができます。テキストスナップショットで
コントロールを記述できない場合は、ピクセルツールを使ってスクリーンショットを撮り、
特定の座標で操作できます。
[ツールリファレンス](/reference/agent#pixel-tools-screenshot-and-the-point-verbs) を参照してください。

`Secret` パラメーターを入力するには、モデルは `type_secret` を呼び出します。モデルに見えるのは
シークレットの名前と目的だけです。ランナーはモデルが選んだフィールドを確認してから、
値を自分で入力します。値がプロンプト、トランスクリプト、レポート、AI トレースに入ることはありません。

対象を指定したアクションは、最大 15 秒でタイムアウトします。[プロジェクトツール](/tools) を使うと、
予算とプラットフォームを宣言した独自の操作を追加できます。

ループは、繰り返しの呼び出しや循環を検出します。アクションが 3 回連続で失敗すると、
アプローチを変えるようモデルに伝えます。5 回失敗すると判定を求めます。
予算や期限が近づいたときにも判定を求めます。

## アサーションの探索

`explore: true` を指定すると、`agent.assert` は読み取り専用のツールを使って、スクロールしながら
複数のビューポートの証拠を組み合わせられます。ビューポートは探索が終わった位置のままになります。
現在の画面の別の場所にあるコンテンツにはこれを使い、時間とともに変わるものには `waitFor` を使います。
ツール、予算、判定については [アサーションの探索](/reference/agent#agent-assert) を参照してください。

## ステップの終わり方

ステップは次の 3 つの判定のいずれかで終了します。

- `passed`: ステップが成功したことを画面が示しています。
- `failed`: 必要な条件が偽であるか、示すことができません。証拠が不十分な場合は
  `ASSERTION_INCONCLUSIVE` になります。
- `blocked`: 前提条件、環境、または制限によって、プロダクトに対する判定の前にステップが停止しました。
  エラーコードによって終了コードが決まります。

エラーコードを持つのは `failed` と `blocked` だけです。

| ブロックの原因 | コード | 終了コード |
| --- | --- | ---: |
| アプリに拒否された認証情報、または設定されていない認証情報 | `AUTH_CREDENTIAL_INVALID`, `AUTH_CREDENTIAL_UNAVAILABLE` | 2 |
| ダウンしている環境 | `ENVIRONMENT_UNAVAILABLE` | 3 |
| 存在しないシードデータ、またはプロダクト外の前提条件 | `SEED_DATA_MISSING`, `TEST_SETUP_FAILED` | 2 |
| 予算または時間 | `STEP_BUDGET_EXHAUSTED`, `STEP_TIMEOUT` | 1 |
| ツールセットで実行できない操作 | `AUTOMATION_UNSUPPORTED` | 1 |

判定が持ちうるすべてのコードは [エラーリファレンス](/reference/errors#agenterror) に記載されています。

## ステップのコスト

各呼び出しには、モデル呼び出しの予算とデフォルトのタイムアウトがあります。
[予算](/reference/agent#budgets) を参照してください。

- 探索なしの `assert` と `extract` は 1 回の判定を行い、回答の形式が不正な場合は修正のための
  呼び出しを 1 回追加します。データが画面上にない場合、`extract` は
  `ASSERTION_INCONCLUSIVE` で失敗し、プレースホルダーは返しません。
- `waitFor` は、画面とその場所が変わらない間はモデルを呼び出しません。
- スクリーンショットは、それを含むすべての呼び出しの入力トークンを増やします。`act` は、
  テキストスナップショットでは不十分な場合にだけスクリーンショットを要求します。
- [リプレイキャッシュ](/cache) は、成功した `act` ステップをモデル呼び出しなしで再実行します。
- [カスタムエグゼキューター](/executors#what-the-executor-handles) では、`assert` は
  `act` の予算を使います。

厳密なチェックには `expect` を使い、各 `act` には 1 つの
[アトミックなゴール](/core-concepts#goals) を与えてください。プロバイダーがプロンプトを
キャッシュする場合、`--debug` はステップごとに入力トークンのうちキャッシュされた割合を表示します。
