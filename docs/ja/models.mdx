エージェントステップは `e2e.config.ts` で設定したモデルを使います。デフォルトはありません。
モデルは [AI SDK](https://ai-sdk.dev/providers/ai-sdk-providers) のプロバイダーから取得します。
ゲートウェイ、直接の API キー、ローカルサーバー、または
[サブスクリプション](/subscriptions) のいずれかです。最初のセットアップでは、`e2e init` が
設定を書き込みます。[クイックスタート](/quickstart#use-a-subscription-or-api-key) を参照してください。

エージェントステップのないテストにはモデルは不要です。組み込みのエージェントには、
ツール呼び出しと画像をサポートするモデルが必要です。Clef や Jev などの
[デシジョンモデル](/decision-models) は、代わりにカスタムエグゼキューターを通じて実行されます。

## ゲートウェイまたはプロバイダーを選ぶ

組み込みのエージェントには、プロバイダーにかかわらず `ai` パッケージが必要です。

<CodeGroup>
```bash npm
npm install -D ai
```

```bash pnpm
pnpm add -D ai
```

```bash bun
bun add -d ai
```
</CodeGroup>

プロバイダーは自身のキーを環境変数から読み取ります。ゲートウェイは 1 つのキーで
多くのプロバイダーにアクセスできます。切り替えるには、モデルの import と `model` の値を
置き換えます。スニペットが `agent` を定義している場合は、それを `agents.default` として使います。

<Tabs>
  <Tab title="Vercel AI Gateway">

`gateway` は `ai` パッケージに含まれています。`AI_GATEWAY_API_KEY` を設定するか、
キーなしで [Vercel OIDC トークン](#vercel-oidc-instead-of-a-key) を使います。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
} satisfies E2EConfig;
```
  </Tab>
  <Tab title="OpenRouter">

`@openrouter/ai-sdk-provider` をインストールし、`OPENROUTER_API_KEY` を設定します。

```ts title="Model setup"
import { openrouter } from '@openrouter/ai-sdk-provider';

const agent = { model: openrouter('openai/gpt-6-luna-fast') };
```
  </Tab>
  <Tab title="プロバイダーの API キー">

プロバイダーの AI SDK パッケージをインストールし、その API キーを設定します。OpenAI の場合は、
`@ai-sdk/openai` をインストールして `OPENAI_API_KEY` を設定します。

```ts title="Model setup"
import { openai } from '@ai-sdk/openai';

const agent = { model: openai('gpt-6-luna') };
```

他のプロバイダーも、それぞれのパッケージ、モデル ID、認証情報で同じように動作します。
[AI SDK プロバイダー](#ai-sdk-providers) を参照してください。
  </Tab>
  <Tab title="ローカルまたはセルフホスト">

`@ai-sdk/openai-compatible` をインストールします。エンドポイントの URL と、そのエンドポイントが
提供するモデル ID を設定します。サーバーが必要とする場合は `apiKey` を追加します。Ollama のように
サーバーが JSON スキーマのレスポンス形式を受け付ける場合は、`supportsStructuredOutputs: true` を
設定します。これがないと、AI SDK は `responseFormat` の警告を出してスキーマを外し、
エージェントステップのモデル呼び出しが増える可能性があります。

```ts title="Model setup"
import { createOpenAICompatible } from '@ai-sdk/openai-compatible';

const local = createOpenAICompatible({
  name: 'local',
  baseURL: 'http://127.0.0.1:11434/v1',
  supportsStructuredOutputs: true,
  // apiKey: process.env.LLM_API_KEY,
});

const agent = { model: local.chatModel('your-model-id') };
```
  </Tab>
</Tabs>

ゲートウェイは通常 `provider/model` 形式の ID を使います。直接のプロバイダーは独自の ID を使います。

### キーの代わりに Vercel OIDC を使う

`AI_GATEWAY_API_KEY` がない場合、`gateway()` は有効期間の短い Vercel OIDC トークンで
サインインし、そのトークンを更新します。Vercel CLI にサインインし、プロジェクトを一度だけ
リンクしてください。

<CodeGroup>
```bash npm
npx vercel login
npx vercel link
npx e2e run
```

```bash pnpm
pnpm dlx vercel login
pnpm dlx vercel link
pnpm exec e2e run
```

```bash bun
bunx vercel login
bunx vercel link
bunx e2e run
```
</CodeGroup>

ゲートウェイは有効な `VERCEL_OIDC_TOKEN` を使います。なければ、作業ディレクトリから上位へ
たどって見つけた `.vercel/project.json` のプロジェクト用のトークンを取得します。
e2e は `.env` ファイルを読み込まないため、`npx vercel env pull` で取得したトークンは、
シェルがそれをエクスポートしている場合か、設定が
[`process.loadEnvFile()`](/reference/config#loading) でファイルを読み込む場合にのみ機能します。

## AI SDK プロバイダー

ツール呼び出しをサポートするすべての AI SDK プロバイダーが動作します。各プロバイダーの
パッケージと変数は、その [AI SDK プロバイダーページ](https://ai-sdk.dev/providers/ai-sdk-providers) に記載されています。使用するものを選択してください。

<ModelProvider show="select" />

一覧にないプロバイダーも、AI SDK の言語モデル仕様 v2 以降を実装していれば動作します。

<Steps>
  <Step title="プロバイダーパッケージをインストールする">
  `ai` とプロバイダーパッケージをインストールします。

  <ModelProvider show="install" />
  </Step>
  <Step title="認証情報を設定する">
  シェルまたは CI で変数をエクスポートするか、設定の中で
  [`process.loadEnvFile()`](/reference/config#loading) を使って `.env` ファイルを読み込みます。

  <ModelProvider show="env" />
  </Step>
  <Step title="設定にモデルを追加する">
  `agents.default` にモデルを設定します。モデル ID は例です。

  <ModelProvider show="config" />
  </Step>
</Steps>

<Accordion title="強制的なツール選択を拒否するモデル">
エージェントステップは、すべてのターンでモデルにツール呼び出しを要求します。Claude Opus 5.5、
Sonnet 5.5、Fable 5.1 はその形式のリクエストを拒否し、DeepSeek の V4 モデル
（`@ai-sdk/deepseek`）はデフォルトで思考するため拒否し、Muse Spark のモデルは `auto` しか
受け付けません。e2e は `auto` で続行し、そのモデルの以降のステップは最初からその方法で
開始します。思考は有効のままにできます。
</Accordion>

<Accordion title="Claude Opus 5.5、Sonnet 5.5、Fable 5.1">
これらのモデルは、各思考ブロックをシステムプロンプトとそれより前のメッセージに結び付け、
そのどちらかが変わった後にブロックを再送するリクエストを拒否します。エージェントステップは
プロンプトを固定したまま保ち、以前のメッセージから古くなった画面やスクリーンショットを
省略した時点で、そのメッセージ以降の思考の送信をやめます。ステップの `--debug` の
トランスクリプトにその旨が記録されます。
</Accordion>

## 1 つの設定で複数のモデルを使う

各モデルに独自のエージェント名を付け、`--agent` またはテストの中で 1 つを選びます。
[エージェントとペルソナ](/agents) を参照してください。設定を編集せずにモデルを切り替えるには、
環境変数を読み取ります。

```ts title="Agent setup"
const agent = {
  model: gateway(process.env.MODEL ?? 'openai/gpt-6-luna-fast'),
};
```

### 設定されているキーでモデルを選ぶ

チームメンバーがそれぞれ異なるキーを持っている場合は、設定されている変数でモデルを選びます。
エージェント名を 1 つに保つと、全員が同じ記録をリプレイできます。

```ts title="Agent setup"
import { anthropic } from '@ai-sdk/anthropic';
import { gateway } from 'ai';

const agent = {
  model: process.env.ANTHROPIC_API_KEY
    ? anthropic('claude-sonnet-5-5')
    : gateway('openai/gpt-6-luna-fast'),
};
```

`gateway()` をフォールバックにしてください。[Vercel OIDC](#vercel-oidc-instead-of-a-key) が
確認すべき変数なしでサインインさせます。`.env` にあるキーは、このコードより前に
[`process.loadEnvFile()`](/reference/config#loading) が実行された場合にのみ有効です。

もう一方のモデルで記録されたステップもリプレイされ、そのモデル名が表示されます。
[一致が必要なもの](/cache#what-must-match) を参照してください。

### 専用のジャッジ

デフォルトでは、1 つのモデルが `agent.act` を実行し、`agent.assert`、`agent.waitFor`、
`agent.extract` に答えます。これらの確認に別のモデルを使うには `judge` を設定します。

```ts title="Agent setup"
const agent = {
  model: gateway('openai/gpt-6-luna-fast'),
  judge: gateway('anthropic/claude-sonnet-5'),
};
```

`explore: true` を指定した組み込みの `agent.assert` は、`judge` が設定されていても
`agents.<name>.model` でツールループを実行します。

レポートには各判定のモデル名が記載されます。`judge` は AI SDK の言語モデルを受け取ります。
Clef や Jev には [デシジョンエグゼキューター](/decision-models) を使ってください。
[判定が見るもの](/agent-steps#what-the-model-sees) を参照してください。

## データ保持とコンプライアンス

モデルへの入力は、伏せ字処理された画面、ステップの指示、エージェントが要求した
スクリーンショットです。e2e はレスポンスの後にプロバイダーから何も読み戻さないため、
実行にプロバイダー側で保存された状態は必要ありません。

すべてのモデルリクエストは e2e を名乗ります。`e2e/<version> (<platform>; <arch>)` で始まる
`User-Agent` に加え、Vercel AI Gateway と OpenRouter では `HTTP-Referer:
https://tester.army/e2e` と `X-Title: e2e` を送ります。これらは、プロバイダーインスタンスに
設定された同じヘッダーを置き換えます。

<AccordionGroup>
<Accordion title="OpenAI と Azure OpenAI: ゼロデータ保持">
Responses モデル（`openai(...)`、`azure(...)`、またはゲートウェイ上の `openai/*`）への
すべてのリクエストには、`store: false` とプロンプトキャッシュキーが付きます。
Chat Completions モデルと OpenAI 互換プロバイダーにはどちらも付きません。プロバイダーは
会話のコピーを保持せず、プロンプトキャッシュは引き続き機能します。ゼロデータ保持を
利用している組織は設定不要です。

保存されたレスポンスを残すには、`providerOptions` で `store` を設定します。Azure
OpenAI の場合、キーは `azure` です。

```ts title="Agent setup"
const agent = {
  model: openai('gpt-6-luna'),
  providerOptions: { openai: { store: true } },
};
```
</Accordion>
<Accordion title="BAA の下での Anthropic">
エージェントステップは、ツール使用、プロンプトキャッシュ、画像、構造化出力を伴う
Messages API を使います。これらはすべて Anthropic の HIPAA 対応の対象です。

この契約は `api.anthropic.com` のみを対象とします。ゲートウェイや OpenRouter を経由せず、
`@ai-sdk/anthropic` で呼び出してください。`judge` は未設定のままにして、1 つの契約で
すべてのリクエストがカバーされるようにします。Anthropic の Covered Models には 30 日間の
保持が必要なため、ゼロデータ保持を利用している組織はそれらを使えません。
</Accordion>
</AccordionGroup>

## 何がどこで失敗するか

| 問題 | コード | 対処 |
| --- | --- | --- |
| モデルが AI SDK のインスタンスではなく文字列になっている | `INVALID_CONFIG` | インスタンスを生成します。例: `gateway('openai/gpt-6-luna-fast')`。 |
| 組み込みのエージェントにモデルがない | `MODEL_UNAVAILABLE` | `agents.<name>.model` を設定します。 |
| GitHub Copilot があなたのアカウントにそのモデルを提供していない | `MODEL_UNAVAILABLE` | プランが提供する id を選びます。[モデルを選ぶ](/subscriptions#pick-a-model) を参照してください。 |
| 設定の読み込み時にキーを読み取るプロバイダーにキーがない | `CONFIG_LOAD_FAILED` | キーを設定します。 |
| 最初のモデル呼び出しで認証が失敗する | `MODEL_PROVIDER_FAILED` | プロバイダーの API キーを確認するか、サブスクリプションの場合は `npx e2e login` を実行します。Vercel OIDC の場合、メッセージには `AI_GATEWAY_API_KEY` しか示されません。`vercel login` と `.vercel/project.json` を確認してください。 |
| `ai` パッケージがない | `MODEL_UNAVAILABLE` | `ai` をインストールします。[ゲートウェイまたはプロバイダーを選ぶ](#pick-a-gateway-or-a-provider) を参照してください。 |
| ステップの 2 ターン目が `Item with id 'rs_…' not found` で失敗する | `MODEL_PROVIDER_FAILED` | `providerOptions` の `store` をデフォルトのオフのままにするか、ゲートウェイ経由ではなく OpenAI を直接呼び出します。 |
| カスタムエグゼキューター自身の `model` または `judge` が agents エントリーのものと異なる | `INVALID_CONFIG` | [カスタムエグゼキューター](/executors#keep-the-loop-change-the-vocabulary) を参照してください。 |
