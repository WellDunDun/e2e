`e2e` CLI は匿名の利用データを送信します: どのコマンド、エンジン、機能が使われているか、
そして実行がどこで失敗しているかです。テレメトリーはデフォルトでオンです。送信するのは
件数とバージョンだけで、テストの内容、アプリの内容、認証情報は決して送信しません。

## オプトアウト

次のいずれか 1 つでテレメトリーがオフになります:

<CodeGroup>
```bash npm
npx e2e telemetry disable   # saved in ~/.config/e2e/telemetry.json
export E2E_TELEMETRY_DISABLED=1          # for a shell or a CI job
export DO_NOT_TRACK=1                    # the cross-tool convention
```

```bash pnpm
pnpm exec e2e telemetry disable   # saved in ~/.config/e2e/telemetry.json
export E2E_TELEMETRY_DISABLED=1          # for a shell or a CI job
export DO_NOT_TRACK=1                    # the cross-tool convention
```

```bash bun
bunx e2e telemetry disable   # saved in ~/.config/e2e/telemetry.json
export E2E_TELEMETRY_DISABLED=1          # for a shell or a CI job
export DO_NOT_TRACK=1                    # the cross-tool convention
```
</CodeGroup>

環境変数は保存された設定より優先されます。`e2e telemetry enable` は保存された
`disable` を元に戻します。`e2e telemetry` は状態を表示し、オフの場合はその理由も
表示します。設定ファイルは、XDG_CONFIG_HOME が設定されている場合は `$XDG_CONFIG_HOME/e2e/` に、
Windows では `%APPDATA%\e2e\` にあります。

`disable` は、別のターミナルで既に実行中のコマンドも止めます。設定ディレクトリに
書き込めない場合や、e2e リポジトリのソースチェックアウトからは何も送信されません。

## 送信される内容を確認する

<CodeGroup>
```bash npm
E2E_TELEMETRY_DEBUG=1 npx e2e run
```

```bash pnpm
E2E_TELEMETRY_DEBUG=1 pnpm exec e2e run
```

```bash bun
E2E_TELEMETRY_DEBUG=1 bunx e2e run
```
</CodeGroup>

CLI は正確なペイロードを `[telemetry] {...}` として stderr に出力し、何も送信しません。

## 送信されるもの

各コマンドは `e2e_cli_session` イベントを 1 つ送信します。`run` と `explore` は
`e2e_run_completed` も送信し、`init` は `e2e_init_completed` を送信し (`explore` が
最初に init ウィザードを実行する場合も同様です)、`upgrade` は `e2e_upgrade_completed` を
送信し、`mcp` は MCP セッションごとに `e2e_mcp_session` を 1 つ送信します。`--help` と
`--version` は、どのコマンドでも何も送信しません。`e2e/runner` の `run()` と `explore()` は
セッションイベントを送信せず、レポートを返す呼び出しごとに `e2e_run_completed` を 1 つだけ送信します。

イベントは、コマンド、`run()`、`explore()` の終了時に、2 秒の期限付きで 1 つのリクエストに
まとめて送信されます。`e2e mcp` は各セッションイベントを個別のリクエストで送信し、
`e2e run --watch` は各実行のイベントをその実行の終了時に送信します。

イベントには以下のプロパティだけが含まれます。大文字のトークンではないエラーコードは
`OTHER` として送信されます。エンジン、プラットフォーム、モデル、フリート、MCP クライアントの
名前、または MCP クライアントのバージョンが、英字、数字、ドット、ダッシュ、アンダースコアだけから
なる単純なトークンでない場合は `other` として送信されます。semver ではないエンジンの
バージョンは `unversioned` として送信されます。アクションとツール呼び出しの件数では、
プロジェクト独自のツールはまとめて `tool` として数えられ、それ以外の名前は `other` になります。

## 決して送信されないもの

テレメトリーは、テストのタイトル、ファイルパス、URL、オリジン、指示、観察結果、
ページの内容、スクリーンショット、エラーメッセージ、スタックトレース、環境変数の値、
認証情報、ファイルの内容を決して送信しません。ターゲット、エージェント、認証情報、
シークレット、プロジェクトツールの名前、MCP ツールの引数や結果、探索のゴールやチャーター、
発見事項の文言も決して送信しません。

## CI での動作

CI での実行は、マシンではなく CI ベンダーとして数えられ、設定ファイルも通知もありません。
CI ベンダーの環境外で、シェルに `CI` を設定するコーディングエージェントは、それが動く
マシンとして数えられます。

CI では、環境変数でのみテレメトリーをオフにできます。ジョブの `env` に
`E2E_TELEMETRY_DISABLED: '1'` を設定してください。

## フリートでの利用

ユーザーのために新しいマシン上で e2e を実行するプラットフォームでは、各マシンが新しい
ユーザーとして数えられてしまいます。それらのマシンに `E2E_TELEMETRY_FLEET=<name>` を
設定してください。そのイベントは CI と同様に、設定ファイルも通知もなしで `fleet:<name>` として
数えられます。何も送信しない場合は `E2E_TELEMETRY_DISABLED=1` を設定してください。

## 送信先

イベントは、e2e のメンテナーが運用する PostHog プロジェクトである `eu.i.posthog.com` に
送信されます。PostHog は個人プロファイルを保持せず、リクエスト元のアドレスを保存せず、
各イベントで GeoIP をスキップします。データは集計した形で参照されます。

テレメトリーは[セキュリティポリシー](https://github.com/e2e-inc/e2e/blob/main/SECURITY.md)の
対象です。[外部への接続](/reference/security#outbound-connections)には、実行が行う可能性の
あるその他すべての接続が一覧になっています。

## フィードバック

[`e2e feedback`](/reference/cli#e2e-feedback) はテレメトリーではありません。フラグに含まれる
文言を、上記のマシン情報とともに、同じ PostHog プロジェクトへ 1 つの `e2e_feedback` イベント
として送信します。テレメトリーがオンの場合は、テレメトリーのイベントと同じ匿名 ID を持ちます。

保存された `e2e telemetry disable` ではこれは止まりません。`E2E_TELEMETRY_DISABLED=1` と
`DO_NOT_TRACK=1` で止まります。[CLI リファレンス](/reference/cli#e2e-feedback)では、
リダクション、`--dry-run`、`--repro` なしのバグ報告について説明しています。

## 通知

最初のコマンド、または `e2e/runner` の最初の `run()` や `explore()` は、オプトアウトの方法を
伝える通知を stderr に出力します。`--reporter json` の出力はそのまま保たれます。`e2e init` と
`e2e telemetry` は通知を出力しないので、次のコマンドまで持ち越されます。収集するデータに
大きな変更があった後は、通知が再び表示されます。
