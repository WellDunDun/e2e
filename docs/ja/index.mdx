e2e は、Web アプリとモバイルアプリのためのオープンソースのテストフレームワークです。テストでは、
厳密な [ロケーター](/core-concepts#locators) と
[アサーション](/reference/expect#locator-matchers)、エージェントが達成する自然言語の
[ゴール](/core-concepts#goals) のどちらも使え、同じテストの中で両方を組み合わせることもできます。

```ts title="tests/checkout.e2e.ts"
import { test, expect } from 'e2e';

test('a member upgrades to Pro', async ({ app, agent, screen }) => {
  await app.open('/settings/billing');

  await agent.act('upgrade the workspace to the Pro plan');
  await agent.assert('the invoice preview shows a prorated amount');

  await expect(screen.getByRole('status')).toContainText('Pro');
});
```

## e2e を選ぶ理由

- **テストにかける時間が減ります。** セレクターと待機のスクリプトの代わりに、ゴールを書きます。
  UI が変わってもエージェントが適応するので、修正するテストが少なくなります。
- **実行コストが低くなります。** e2e は、後続のチェックが成功したときに `agent.act` ステップを記録します。
  次回の実行ではモデルを呼び出さずに [それをリプレイし](/cache)、アプリが変わっていれば
  エージェントに処理を戻します。組み込みのエージェントでは、`assert`、
  `waitFor`、`extract` は常にモデルを呼び出します。

## 仕組み

- **ターゲット。** 各テストは、Chromium や iPhone シミュレーターなど、ターゲットごとに 1 回実行されます。
  [Web エンジン](/web) は Playwright を通じてブラウザを操作します。
  [モバイルエンジン](/mobile) は agent-device を通じて iOS シミュレーターと Android
  エミュレーターを操作します。
  [独自のエンジンを書く](/writing-an-engine) こともできます。
- **エージェントステップ。** `agent.act` はゴールを達成します。`agent.assert`、
  `agent.waitFor`、`agent.extract` は画面を判定します。お使いの
  [サブスクリプション](/subscriptions)、[API キー、またはローカルモデル](/models) を使えます。
  エージェントステップのないテストにはモデルは必要ありません。
- **レポート。** ランナーは、モデルへの入力から [登録済みのシークレットを伏せ字にします](/security)。
  ステップ、失敗、アーティファクトを、あなたやコーディングエージェントが読める
  [レポート](/debugging) に記録します。
