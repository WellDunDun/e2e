`e2e explore` は、テストファイルの代わりにゴールを使って、アプリに対してエージェントを実行します。
エージェントはステップを計画して実行し、ゴールを網羅するか予算が尽きるまで発見事項を記録してから、
評価を書き出します。`agent.act()` と同じモデル、ツール、操作のルールを使います。

  `e2e explore --headed` はアプリを操作し、進行に合わせて発見事項を報告します。

## 探索を開始する

フローとユーザーのゴールを指定し、必要に応じて制限を加えます。

<CodeGroup>
```bash npm
npx e2e explore 'Explore the checkout flow like a first-time buyer and report anything off'
```

```bash pnpm
pnpm exec e2e explore 'Explore the checkout flow like a first-time buyer and report anything off'
```

```bash bun
bunx e2e explore 'Explore the checkout flow like a first-time buyer and report anything off'
```
</CodeGroup>

制限としては、たとえば「注文を確定する前に止める」などを指定できます。ゴールを指定しない場合、explore は
`Explore the app and find bugs` を使います。ステップが失敗しても実行は止まりません。

`e2e.config.ts` がない場合、explore は最初に
[`e2e init`](/reference/cli#e2e-init) ウィザードを実行します。手作業で行うことが何も残っていなければ、
その直後に探索が始まります。そうでなければ、init は `npm install` やモデルキーの設定など、
残っている手順を一覧表示します。
CI のようにターミナルがない場合、explore は `CONFIG_NOT_FOUND` で失敗します。

## 結果を読む

ターミナルには、各発見事項と完了した各ステップが発生した時点で表示されます。

```text
 ❯  web  Exploring  Explore this bookshop like a careful first-time buyer: browse the catalog, ...
   ⚑ medium issue  Home greeting exposes an unresolved userName template (/)
   ⚑ high issue  Neuromancer shows an impossible negative stock availability (/catalog)
   ✓ 1  Catalog browsing 31.46s · 7 actions · 4 findings
   ⚑ high issue  Cart total does not update when Hyperion quantity increases (/cart)
   ⚑ trivial warning  Checkout newsletter label misspells Receive (/checkout)
   ✓ 2  Cart quantities and removal 19.47s · 4 actions · 3 findings
   ended: the agent covered the goal
```

`issue` は実行を終了コード 1 で失敗させます。`warning` は失敗させません。最終的な
レポートでは、最も深刻な issue が先頭に並びます。各発見事項には再現手順と、可能な場合はスクリーンショットが含まれます。
発見事項に基づいて対応する前に、それぞれをその証拠と照らし合わせてください。その他の終了コード、JSON の
レポート、アーティファクトのパスについては、[CLI のリファレンス](/reference/cli#e2e-explore)を参照してください。

## ほかの画面サイズを確認する

ターゲットのエンジンがビューポートのサイズを変更できる場合（Web エンジンは可能です）、
ゴールでほかの幅でのレイアウトを確認するよう指示できます。

<CodeGroup>
```bash npm
npx e2e explore 'Check the pricing page at desktop, tablet, and phone widths for broken layouts'
```

```bash pnpm
pnpm exec e2e explore 'Check the pricing page at desktop, tablet, and phone widths for broken layouts'
```

```bash bun
bunx e2e explore 'Check the pricing page at desktop, tablet, and phone widths for broken layouts'
```
</CodeGroup>

## サインインした状態で開始する

`--session <name>` を追加します。名前には、
[セットアップテスト](/authentication)が保存するセッションの名前を指定します。

<CodeGroup>
```bash npm
npx e2e explore --session admin 'Explore the admin settings and find bugs'
```

```bash pnpm
pnpm exec e2e explore --session admin 'Explore the admin settings and find bugs'
```

```bash bun
bunx e2e explore --session admin 'Explore the admin settings and find bugs'
```
</CodeGroup>

explore はそのセットアップテストだけを実行し、セッションを復元します。探索するエージェントは
アプリがサインインした状態で始まることを知っているため、サインインのステップを計画しません。

スクリーンショットではパスワードフィールドがマスクされます。アプリがそれ以外の場所に表示した値は
モデルに届きます。
[シークレット入力後のスクリーンショット](/reference/security#screenshots-after-a-secret-fill)を参照してください。

## プルリクエストの変更を探索する

ブランチが変更した部分を探索するには、`--changed-since <ref>` を追加します。プランナーは、
その ref とのマージベース以降のコミットメッセージとコミット済みの差分を読みます。
そして、その変更が影響しうる画面にステップを費やします。

<CodeGroup>
```bash npm
npx e2e explore --changed-since origin/main
```

```bash pnpm
pnpm exec e2e explore --changed-since origin/main
```

```bash bun
bunx e2e explore --changed-since origin/main
```
</CodeGroup>

`issue` になるのは、その変更が引き起こしうる不具合だけです。アプリのほかの場所にある不具合は
`warning` になり、実行を失敗させません。

ゴールを指定しない場合、ゴールは `Explore what this change affects and find bugs in
it` になります。この場合、プランナーはドキュメントやテストだけの変更など、ユーザーに見えない変更をスキップできます。
実行は `skipped` で終わり、成功となります。スキップするのは変更全体を読んだ場合だけです。
大きな差分、バイナリファイル、コミットされていないファイルがあると、スキップはされません。

ブランチ自体のコミットメッセージやコードが判断に影響する可能性があります。スキップと
問題のない探索を区別するには、`run.explore.ended` を確認してください。

モデルが何を読むかについては、
[セキュリティ](/reference/security#mcp-and-explore)を参照してください。

GitHub Actions では、`pull_request` で独立したジョブとして実行します。設定に
[GitHub レポーター](/github)があれば、発見事項は専用のプルリクエストのコメントに投稿されます。
フォークからの実行は投稿できません。
[何も投稿されない場合](/github#when-nothing-is-posted)を参照してください。

```yaml title=".github/workflows/explore.yml"
on: pull_request

jobs:
  explore:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    # An issue exits 1. Keep the findings as a review aid, not a merge gate.
    continue-on-error: true
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          fetch-depth: 0
      # ...install, browsers
      - run: npx e2e explore --changed-since origin/${{ github.base_ref }} --max-steps 4
        env:
          AI_GATEWAY_API_KEY: ${{ secrets.AI_GATEWAY_API_KEY }}
          GITHUB_TOKEN: ${{ github.token }}
```

`fetch-depth: 0` により、チェックアウトにベースブランチが含まれます。これがないと、実行は
`INVALID_CHANGED_SINCE` で失敗します。

インストールとビルドの後も作業ツリーをクリーンに保ってください。そうしないと、実行がスキップされることはありません。
`.e2e/` とビルドの出力は無視するように設定します。e2e は `pnpm exec` ではなく `npx` で実行してください。
`pnpm exec` は `pnpm-lock.yaml` を書き換えることがあります。

<Warning>
`pull_request_target` では決して実行しないでください。その実行はあなたのシークレットを保持しており、
モデルはフォークが書いた差分とコミットメッセージを読みます。
</Warning>

## 実行が早く止まりすぎる場合

実行は 8 ステップまたは 10 分で停止します。フローのより奥まで到達するには、
`--max-steps <n>`（最大 100）または `--timeout <ms>`（最大 `7200000`、2
時間）を引き上げます。

主要なフローを終えても時間が残っている実行は、それらのフローに戻り、エッジケースの入力、
フィルターの組み合わせ、再読み込みを試します。また、複数のアカウントが設定されていて
`--session` を指定していない場合は、別のアカウントでも試します。早めに終了するのは、
新たに到達できるものが何もない場合だけです。

## ターゲットとエージェントを選ぶ

explore は、`e2e.config.ts` のターゲット、アプリのコマンド、モデル、エージェントを使います。
`--target <name>` と `--agent <name>` で選択します。
`--target` を指定しない場合、explore は最初のターゲットを使います。

## コードから探索する

設定の値、キャンセル、進捗イベントを使って独自のコードから探索を開始するには、
[`e2e/runner` の `explore`](/reference/runner#explore) を呼び出します。
