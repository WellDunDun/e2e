1. 上記の移行ガイドを読んでください。Cypress の設定、コマンド、アサーションを e2e に対応付けており、e2e にまだないものも一覧にしています。
2. プロジェクトに e2e の設定 (\`e2e.config.ts\`、\`.mts\`、\`.js\`、\`.mjs\`) がない場合は、\`npx e2e init --yes\` (または pnpm や bun の同等のコマンド) を実行してください。設定とサンプルテストを書き出し、まだ何もインストールしません。
3. e2e のスキルを読み (\`npx e2e guide\` で表示され、\`npx e2e guide <topic>\` でトピックを表示します)、以下のすべてのステップでそれに従ってください。
4. init を実行した場合は、エージェントのステップに使うモデルを私に尋ねてください: ChatGPT、GitHub Copilot、OpenCode Console、SuperGrok のサブスクリプション、API キー、またはローカルモデルです。そのプロバイダーパッケージで設定してください。サインインが必要な場合は、\`npx e2e login\` コマンドを私に伝え、私が確認するまで待ってください。
5. \`cypress.config.*\` を e2e の設定に移してください: \`baseUrl\` と開発サーバーのコマンドはターゲットの \`app\` になります。spec が \`data-cy\` で要素を選択している場合は、\`screen.getByTestId\` がそれを読むように \`web({ testIdAttribute: 'data-cy' })\` を設定してください。両方のスイートを動かす間は Cypress をインストールしたままにしてください。
6. 依存関係をインストールしてください。
7. Cypress の end-to-end spec を一覧にし、最初にどれを移すか私に尋ねてください。よく壊れるもの、または \`cy.wait(ms)\` で待機しているものを提案してください。コンポーネントテストには e2e で相当するものがないので、Cypress に残してください。
8. ガイドの表を使い、1 行に 1 つの await 呼び出しで、その spec を \`tests/\` 配下の \`.e2e.ts\` ファイルとして書き直してください (e2e はデフォルトで \`tests/**/*.e2e.ts\` を実行します)。テストを移す前に "What e2e doesn't have yet" を確認してください: "Use today" の回避策を使うか、テストを Cypress に残してその理由を述べてください。\`cy.contains\` が部分一致していた箇所では \`{ exact: false }\` を渡してください。各 \`cy.wait(ms)\` は、テストが待っている状態に対するアサーションに置き換えてください。
9. ナビゲーションと最後のアサーションは、\`app.open()\` とロケーターのアサーションで決定論的に保ってください。スクリプト化した一連の操作が頻繁に壊れる箇所では、代わりに \`agent.act\` のゴールを提案してください。
10. \`npx e2e run <file>\` で新しいファイルを実行し、通るまで修正してください。削除してよいと私が確認するまで、Cypress の spec は残しておいてください。
11. どのテストを移行し、どのテストを Cypress に残したか、その理由とともにまとめてください。`;

e2e は、Cypress のコマンドチェーンを Node で動く async な TypeScript テストに
置き換えます。spec を 1 つずつ移す間、両方のスイートをプロジェクトに置いておけます。

複数のセッションにまたがる移行では、[`migrate-to-e2e` スキル](/coding-agents#migrate-an-existing-suite) が移行済みのものを進捗ファイルに記録し、各テストを廃止するまで古いスイートを動かし続けます。

## 設定を移す

<Note>[クイックスタート](/quickstart)で e2e をインストールし、モデルを設定してください。以下の例ではエージェントの呼び出しを使います。</Note>

| Cypress | e2e |
| --- | --- |
| `baseUrl`, `start-server-and-test` | ターゲットの `app: { url, command }`。[アプリの起動](/web#starting-your-app)を参照してください |
| `data-cy` セレクター | `web({ testIdAttribute: 'data-cy' })` の後に `screen.getByTestId` |
| `viewportWidth`, `viewportHeight`, `cy.visit(url, { auth, headers })` | `web({ viewport, basicAuth, headers })` |
| `retries: { runMode: 2, openMode: 0 }` | `retries: process.env.CI ? 2 : 0`、数値のみ |
| `env`, `Cypress.env()`, `cypress.env.json` | `process.env`。サインイン用の値は `credentials` と `secrets` に入れます。[認証](/authentication)を参照してください |
| `cypress run --browser firefox` | `web({ browser: 'firefox' })` を持つターゲットを `--target <name>` で実行 |

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';

export default {
  targets: [{
    engine: web({ testIdAttribute: 'data-cy' }),
    app: { url: 'http://localhost:3000' },
  }],
} satisfies E2EConfig;
```

## spec を 1 つ書き直す

```js title="Cypress"
describe('todos', () => {
  it('completes one', () => {
    cy.visit('/todos');
    cy.get('[data-cy=new-todo]').type('Buy milk{enter}');
    cy.get('[data-cy=new-todo]').type('Walk the dog{enter}');
    cy.contains('li', 'Buy milk').find('[data-cy=toggle]').click();
    cy.get('[data-cy=todo]').should('have.length', 2);
    cy.contains('1 item left').should('be.visible');
  });
});
```

```ts title="e2e"
import { describe, test } from '@e2e-dev/web';
import { expect } from 'e2e';

describe('todos', () => {
  test('completes one', async ({ app, agent, screen }) => {
    await app.open('/todos');
    await agent.act('add todos "Buy milk" and "Walk the dog"');
    await expect(screen.getByTestId('todo')).toHaveCount(2);
    await agent.act('complete "Buy milk"');
    await expect(screen.getByText('1 item left')).toBeVisible();
  });
});
```

## 各コマンドを対応付ける

| Cypress | e2e |
| --- | --- |
| `cy.visit(path)`, `cy.reload()`, `cy.viewport(w, h)`, `cy.setCookie()` | `app.open(path)`, `browser.reload()`, `browser.setViewport({ width, height })`, `browser.setCookies()` |
| `cy.get('[data-cy=x]')`, `.find('[data-cy=x]')` | `screen.getByTestId('x')`, `row.getByTestId('x')` |
| `cy.get('css')` | `browser.locator('css')`、Web のみ。ロールやラベルを優先してください |
| `cy.contains('text')`, `cy.contains('li', 'text')` | `screen.getByText('text', { exact: false })`, `screen.getByRole('listitem').filter({ hasText: 'text' })` |
| `.click()`, `.dblclick()`, `.clear()`, `.check()`, `.uncheck()`, `.focus()`, `.first()`, `.last()`, `.scrollIntoView()` | 同じ |
| `.rightclick()`, `.eq(n)`, `.selectFile(path)` | `.secondaryTap()`, `.nth(n)`, `.setInputFiles(path)` |
| `.type('text')`, `.type('{enter}')`, `.clear().type('text')` | `.pressSequentially('text')` はキーイベントで追記します, `.press('Enter')`, `.fill('text')` |
| `.select('Pro')` | `.selectOption('Pro')` はラベルに一致します。値の場合は `{ value: 'pro' }`、インデックスの場合は `{ index: 1 }` が必要です |
| `.should('be.visible')`, `be.checked`, `be.disabled`, `be.focused`, `exist` | `await expect(locator).toBeVisible()`, `toBeChecked()`, `toBeDisabled()`, `toBeFocused()`, `toBeAttached()` |
| `have.text`, `contain`, `have.value`, `have.attr`, `have.length`, `not.exist` | `toHaveText`, `toContainText`, `toHaveValue`, `toHaveAttribute`, `toHaveCount(n)`, `toHaveCount(0)` |
| `cy.url().should('include', p)`, `cy.title()` | `expect(browser).toHaveURL(/p/)`, `expect(browser).toHaveTitle(t)` |
| `cy.intercept('/api/users', body)` | `browser.route('**/api/users', route => route.fulfill({ json: body }))`、完全な URL に対する glob |
| `cy.on('window:confirm')`, `cy.on('window:alert')` | アクションの前に `await browser.onDialog('accept')`、キャンセルするには `'dismiss'` |
| `cy.session` | `test.setup` と `{ session }` |
| `cy.task`, `cy.exec`, `cy.request`, `cy.fixture` | Node のコード: `fetch`、`fs`、データベースクライアント、`import data from './fixture.json'` |
| `Cypress.Commands.add` | 関数、または `test.extend` によるフィクスチャ |

## e2e にまだないもの

「予定あり」の不足はロードマップにあり、「未定」の不足は時期が決まっていません。「予定なし」の不足は意図的に含めていないものです。

### 予定あり

| Cypress | 現時点での代替 |
| --- | --- |
| `.find('css')`, `.filter('css')`, `.not('css')` | `getBy*` クエリをチェーンするか、1 つのセレクターを書きます: `browser.locator('li.active >> .title')` |
| `.invoke()`, `.its()`, `.then($el => ...)`, `.should($el => ...)` | `getAttribute()`、`textContent()`、`inputValue()`、それ以外は `browser.evaluate`。リトライするには `expect.poll` で包みます |
| `have.class`, `have.css`, `have.prop`, `be.empty` | `expect(browser).toHaveClass(locator, /regexp/)`、`expect(locator).toHaveText('')`。それ以外は `expect.poll(() => browser.evaluate(...))` |
| `.trigger()`, `cy.scrollTo()`, `.blur()` | `hover()`、`dragTo()`、`scrollIntoView()`、`press('Tab')`。それ以外は `browser.evaluate` |
| `cy.intercept('POST', url)` およびその他のメソッドやヘッダーのマッチャー | ハンドラー内で `route.request.method` を確認し、それ以外は `route.fallback()` を呼び出します |
| `cy.wait('@alias')`, `.its('request.body')`, `@alias.all` | アクションの前に `browser.waitForResponse(pattern)` を開始します。リクエストは `browser.route` ハンドラー内で読みます |
| `Cypress.on('uncaught:exception')` | アプリのエラーでテストは失敗しません。失敗させるには、`browser.addInitScript` で `window.onerror` を収集し、`browser.evaluate` でそのリストが空であることをアサートします |
| `--browser chrome`, `edge`, `electron`, `before:browser:launch` | `web({ browser: 'chromium' })`、または `web({ connect: { cdpEndpoint } })` で自分の Chrome に接続します |
| `cypress open`, タイムトラベルのスナップショット | `npx e2e run --headed --watch`、または `--step`。実行後は [トレースページ](/debugging#traces) で各ステップを確認できます |
| アプリを操作する `before()` と `after()`, `describe.only` | UI のセットアップは `beforeEach`、クリーンアップは `afterEach` で行います。サインインはセッションを保存するトップレベルの `test.setup` で行います。各テストに `test.only` を付けます |
| `cy.clock()`, `cy.tick()` | `browser.addInitScript({ path })` で読み込み、`browser.evaluate` で操作するフェイクタイマーのスクリプト |
| ブラウザの Cookie を使う `cy.request()` | `browser.cookies()` を `fetch` で送ります。[サインイン済みのリクエスト](/api-testing#signed-in-requests)を参照してください |

### 未定

| Cypress | 現時点での代替 |
| --- | --- |
| `supportFile`, `blockHosts` | すべてのファイルがインポートする `test.extend` による共有の `test`。そこで `browser.route` を使ってホストへの通信を中止します |
| `cypress run --record --parallel`, Cypress Cloud | 各 CI ジョブで `--shard`、`junit` と `github()` レポーター、アーティファクトとしてアップロードした `.e2e` |
| 4xx や 5xx のページで失敗する `cy.visit()` | `app.open` はステータスを無視します。ページの内容に対してアサートしてください |
| `cy.stub()`, `cy.spy()`, `cy.clearLocalStorage()` | `browser.addInitScript` で関数を包みます。呼び出しの読み取りやストレージのクリアは `browser.evaluate` で行います |

### 予定なし

| Cypress | 代わりに使うもの |
| --- | --- |
| `cy.wait(ms)` | テストが待っている状態に対するロケーターのアサーション |
| `it`, `context`, `specify`, `xit` | `test`, `describe`, `test.skip` |
| chai の `expect(x).to...`, `assert.*` | `expect(value)` に対する `toEqual`、`toContain`、`toMatchObject`、または自分で `chai` をインポートします |
| `cy.window()`, `cy.document()`, `onBeforeLoad(win)` | JSON の値を使った `browser.evaluate` と `browser.addInitScript`。テストはページ内ではなく Node で実行されます |
| Mocha のレポーター, `reporterOptions` | `list`、`json`、`junit`、`markdown`、`htmlReporter()`、`github()`、または独自の[レポーター](/reference/reporters) |
| Cucumber の `.feature` ファイル, `file:preprocessor` | フィーチャーをテストとして書き直します。TypeScript にプリプロセッサーは不要です |
| コンポーネントテスト | Cypress に残してください。e2e は実行中のアプリをテストします |
| `.parent()`, `.closest()`, `.siblings()`, `.next()` | 祖先を見つけて絞り込みます: `card.filter({ has: child })` |
| `{ force: true }` | 表示されているラベルに対して操作するか、アクション可能性のチェックを省略する `tap({ position })` を使います |

## 意図的に異なる点

- コマンドチェーンはありません。Cypress が `.as()`、`.within()`、`.then()` を使う箇所では、各呼び出しを await し、ロケーターや値を変数に保持します。
- [ロケーター](/reference/screen)は厳密です。複数に一致した状態でのアクションや単一ノードのアサーションは `LOCATOR_AMBIGUOUS` で失敗します。`.filter()`、`.first()`、`.nth()` で絞り込むか、`await locator.all()` でループしてください。
- クエリの文字列はテキスト全体に一致します。`{ exact: false }` は大文字小文字を区別せずに部分一致します。`cy.contains` は大文字小文字を区別し、最初の一致を取るので、RegExp を渡すか `.first()` を追加してください。
- テキストマッチャーはレンダリングされたテキストを比較します。CSS の `text-transform` が適用され、非表示の子要素は除外されます。[ロケーターの読み取り](/reference/screen#locator-reads)を参照してください。
- ダイアログは自動では承認されません。Cypress は `alert` や `confirm` を承認しますが、e2e ではハンドラーがないと次のステップが失敗します。

## 異なるデフォルト値

| 設定 | Cypress | e2e |
| --- | --- | --- |
| ビューポート | 1000 × 660 | 1280 × 720 |
| アクションとアサーションのタイムアウト | `defaultCommandTimeout`、4 秒 | `actionTimeout` 30 秒、`assertionTimeout` 5 秒 |
| CI でのリトライ | `0` | `1` |
