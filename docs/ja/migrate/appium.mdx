e2e は、Appium サーバー、そのドライバー、クライアントライブラリを
1 つの Node パッケージに置き換えます。`@e2e-dev/mobile` は、同梱している
[agent-device](https://github.com/callstack/agent-device) を通じて、iOS シミュレーター、Android
エミュレーター、接続されたスマートフォンを操作します。capabilities は `e2e.config.ts` のターゲットになり、`driver`
のコマンドは `app` と `device` のフィクスチャになります。アプリのビルドと
アクセシビリティ ID はそのまま使えます。

例では WebdriverIO を使っています。Java や Python のクライアントも同じように対応付けられます。

## capabilities を移植する

<Note>[モバイルガイド](/mobile) でターゲットを、[クイックスタート](/quickstart) でモデルを設定してください。モデルが必要なのはエージェントステップだけです。</Note>

| Appium | e2e |
| --- | --- |
| `platformName`, `appium:automationName` | `mobile({ platform: 'ios' })` または `'android'` |
| `appium:deviceName`, `appium:udid` | `mobile({ device: 'iPhone 17' })`: 名前、シミュレーターの UDID、または `emulator-5554` のようなシリアル。スマートフォンは名前で指定します |
| `appium:app` | `app: { appPath }`。ビルドは自分でインストールします。[アプリを指定する](/mobile#point-at-your-app) を参照 |
| `appium:bundleId`, `appium:appPackage` | `app: { bundleId }`。`app.open()` が起動するアプリです |
| `appium:processArguments`, `appium:optionalIntentArguments` | `app.launchArguments`。文字列のリストです |
| `appium:permissions` | `app.permissions: { camera: 'grant' }`。各 [`DevicePermission`](/reference/mobile#device-fixture) の名前に `grant`、`deny`、`reset` のいずれかを指定します |
| `appium:noReset` | `true` がデフォルトなので、アプリのデータは何も消去されません。`false` にしたい場合は、テストの最初に `app.clearState()` を呼び出します |
| `appium:fullReset` | `device.installApp(path, { reinstall: true })` |
| `appium:newCommandTimeout`, WebDriverAgent のタイムアウト | 不要です。アクションは `actionTimeout`、アサーションは `assertionTimeout`、テストは `timeout` を使います |
| `bstack:options`, `lt:options` | デバイスプロバイダー: [`browserstack()`](/integrations/browserstack) または [`testmu()`](/integrations/testmu) |
| ホスト型デバイスでの `appium:platformVersion`, `appium:language`, `appium:locale` | `browserstack()` と `testmu()` の `osVersion`、`language`、`locale`。[`limrun()`](/integrations/limrun) の `android.osVersion` |
| 複数の capabilities, `maxInstances` | プラットフォームごとに 1 つのターゲット、`workers`、そしてデバイスごとに 1 つのワーカーを割り当てる `device` のリスト |

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';

export default {
  targets: [
    {
      name: 'ios',
      engine: mobile({ platform: 'ios', device: 'iPhone 17' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'ios/build/MyApp.app',
        launchArguments: ['-e2e', 'YES'],
        permissions: { notifications: 'grant' },
      },
    },
    {
      name: 'android',
      engine: mobile({ platform: 'android' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'android/app/build/outputs/apk/release/app-release.apk',
        launchArguments: ['--ez', 'e2e', 'true'],
        permissions: { notifications: 'grant' },
      },
    },
  ],
  workers: 1,
} satisfies E2EConfig;
```

## テストを 1 つ書き直す

XPath セレクターや明示的な待機が頻繁に壊れるテストから始めます。

```js title="Appium (WebdriverIO)"
describe('login', () => {
  it('signs in', async () => {
    await $('~email').setValue('ada@example.test');
    await $('~password').setValue('hunter2');
    await $('//XCUIElementTypeButton[@name="Sign in"]').click();
    await $('~welcome').waitForDisplayed({ timeout: 10000 });
    await expect($('~welcome')).toHaveText('Welcome, Ada');
  });
});
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('signs in', async ({ app, screen }) => {
  await app.open();
  await screen.getByTestId('email').fill('ada@example.test');
  await screen.getByTestId('password').fill('hunter2');
  await screen.getByRole('button', 'Sign in').tap();
  await expect(screen.getByText('Welcome, Ada')).toBeVisible({ timeout: 10_000 });
});
```

- 何も自動では起動しないため、テストは `app.open()` から始めます。
- アクションは対象の要素を待ち、アサーションはリトライするため、
  明示的な待機は不要になります。

スクリプト化したタップの連続が頻繁に壊れる場合は、1 つの `agent.act` のゴールで置き換えられます。
[リプレイキャッシュ](/cache) は、後続のチェックが成功した時点でそのアクションを記録し、
次回の実行ではモデルを呼び出さずにそれをリプレイします。パスワードは、モデルが一切見ることのない
[設定済みのクレデンシャル](/authentication) に置きます。

```ts
import { credentials } from 'e2e';

const ada = credentials.user('ada');
await agent.act('sign in as {username}', { params: { username: ada.username, password: ada.password } });
```

## セレクターを書き直す

| Appium | e2e |
| --- | --- |
| iOS での `$('~login')`。アクセシビリティ識別子または React Native の `testID` | `screen.getByTestId('login')` |
| Android での `$('~Log in')`。コンテンツの説明または React Native の `accessibilityLabel` | `screen.getByLabel('Log in')` |
| `$('id=com.example:id/email')`, `resourceId` | `screen.getByTestId('email')`。`com.example:id/` の接頭辞は省略できます |
| `-ios predicate string:label == "Sign in"`, `android=new UiSelector().text("Sign in")` | `screen.getByText('Sign in')` または `getByLabel('Sign in')` |
| `-ios class chain`, クラス名（`XCUIElementTypeButton`, `android.widget.Button`） | `screen.getByRole('button', 'Sign in')` |
| `$$(selector)[2]` | `.nth(2)`。`.all()` はすべての一致を返します |
| クエリでは表現できないセレクター | agent-device のセレクター構文を使う `device.locator('role=text label="Total"')` |

- `getByText`、`getByLabel`、`getByTestId` は、大文字と小文字も含めて文字列全体に一致します。
  `RegExp` を渡すか、テキストやラベルの部分文字列に大文字と小文字を区別せず一致させるには
  `{ exact: false }` を渡します。
- Appium の `$()` は最初の一致を返します。e2e のアクションは一致がちょうど 1 つである必要があり、
  複数に一致すると `LOCATOR_AMBIGUOUS` で失敗します。`.filter()`、`.first()`、`.nth()` で
  絞り込んでください。
- `button`、`textbox`、`switch` などのロールは iOS と Android で共通なので、
  1 つのテストが両方で実行できます。[ロール](/reference/mobile#roles) を参照してください。

## 権限とディープリンク

権限は `app.open()` の前に設定してください。iOS では、権限を変更すると実行中のアプリが停止するためです。
すべてのテストで必要な権限は `app.permissions` に置きます。

```js title="Appium (WebdriverIO)"
await driver.execute('mobile: setPermission', {
  bundleId: 'com.example.app',
  access: { location: 'yes' },
});
await driver.activateApp('com.example.app');
await driver.url('myapp://orders/42');
await expect($('~order-title')).toHaveText('Order #42');
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('opens an order from a link', async ({ app, device, screen }) => {
  await device.setPermission('location', 'grant');
  await app.open();
  await device.openLink('myapp://orders/42');
  await expect(screen.getByText('Order #42')).toBeVisible();
});
```

## CI で実行する

起動するサーバーがないので、e2e のジョブはビルドをインストールしてテストスイートを実行するだけです。
プラットフォームごとに専用のジョブが必要です。[モバイルのジョブ](/ci#mobile-jobs) を参照してください。

<CodeGroup>
```bash npm
xcrun simctl install booted ios/build/MyApp.app
npx e2e run --target ios --reporter list,junit
```

```bash pnpm
xcrun simctl install booted ios/build/MyApp.app
pnpm exec e2e run --target ios --reporter list,junit
```

```bash bun
xcrun simctl install booted ios/build/MyApp.app
bunx e2e run --target ios --reporter list,junit
```
</CodeGroup>

## e2e にまだないもの

「予定あり」の行はロードマップに載っているもので、「未定」の行は時期が決まっていません。「予定なし」の
行は意図的に含めていないものです。[`unstable_raw`](/reference/mobile#unstable_raw) を通じた呼び出しは
ステップではないため、レポートにもシークレットの秘匿化にも含まれません。

| `driver.getAlertText()` | iOS では `screen.getByRole('alert').textContent()`、Android では `getByText` |
| `onPrepare` や `afterTest` などの `wdio.conf.ts` のフック | `afterEach`、フィクスチャ、または [カスタムレポーター](/reference/reporters#custom-reporters) |

</Accordion>
</AccordionGroup>

### 未定

| Appium | 現時点での回避策 |
| --- | --- |
| `appium:autoAcceptAlerts`, `appium:autoDismissAlerts` | `app.permissions` を設定するか、`device.alert('accept')` を呼び出します |
| Webview のコンテキスト: `getContexts()`, `switchContext()`, CSS セレクター, `execute(js)` | `getByText` と `getByRole` で Webview のアクセシビリティノードをクエリします |
| モバイル Web: `browserName: 'Safari'` または `'Chrome'` | [スマートフォンのビューポート](/web#viewports) を設定した `web()` ターゲット。レイアウトの確認のみです |
| `appium:unlockType`, `unlockKey` | デバイスのロックを解除したままにします |
| XML としての `driver.getPageSource()` | XML のエクスポートはありません。`screen.tree()` はツリーをテキストで返し、[`unstable_raw`](/reference/mobile#unstable_raw) を通じた `client.capture.snapshot()` はそのノードを返します。XML を利用する処理は Appium に残してください |
| 複数の指や経由点を使う `performActions()` | 単一のジェスチャー、または [`unstable_raw`](/reference/mobile#unstable_raw) を通じた `client.interactions.gesture` |
| `mobile: shell`, `getPerformanceData()` | `device.unstable_raw.deviceId` を使って Node から `adb` または `simctl` を実行します。ローカルのデバイスのみです |
| iPhone 実機での `mobile: setSimulatedLocation`, `mobile: setAppearance`, `mobile: setPasteboard` | それらのテストはシミュレーターで実行します。[物理デバイス](/mobile#physical-devices) を参照 |
| `gpsLocation` や `uploadMedia` などのその他の `bstack:options` のキー | - |
| ローカルのデバイスでの `appium:platformVersion`, スマートフォンの `appium:udid` | そのバージョンが動作するシミュレーターまたはエミュレーターを指定します。スマートフォンの名前は `device` に指定します |
| `appium:avd`, `avdArgs`, `isHeadless` | 実行前にエミュレーターを起動し、そのシリアルを指定します |
| Java、Python、Ruby、C# のテスト | e2e のテストは Node で実行されます。アプリの隣の `e2e/` フォルダーで TypeScript に書き直してください |

### 予定なし

| Appium | 代わりに使うもの |
| --- | --- |
| XPath | クエリをチェーンする（`screen.getByTestId('row').getByText('Delete')`）か、`filter({ has, hasText })` を使います。XPath はテストを 1 つのプラットフォームのツリーに縛り付けます |
| `-image` セレクター, `findImage` | `screen.tapAt({ x, y })`、または `agent.act` のゴール |
| 複数の一致のうち最初の要素を操作する `$(selector)` | `.first()`。[セレクターを書き直す](#rewrite-selectors) を参照 |
| `usePrebuiltWDA` などの WebDriverAgent の capabilities | 設定は不要です。agent-device が独自のランナーをビルドして署名します |
| 複合的な `-ios predicate string` のロジック, `UiSelector` のフラグと `fromParent()` | `filter({ has })` または `RegExp` を使った `getBy*` のクエリ |
| Gherkin のフィーチャーファイル | シナリオごとに 1 つのテスト。ステップは `agent.act` のゴールにできます |
| 保存済みのセッション, `test.setup` と `{ session }` | テストごとにサインインするか、アプリにデータを投入します。デバイスには保存するセッションがありません。[Web との違い](/mobile#what-differs-from-the-web) を参照 |
| デバイスグリッドやハブ, その他のデバイスクラウド | ホスト型のプロバイダー、または自作の `DeviceProvider` |
| `sauce:options` | [`DeviceProvider`](/mobile#hosted-devices) を作成します |
| Appium Inspector | `screen.debug()`、またはコーディングエージェントのライブセッション用の [`npx e2e mcp`](/mcp-server) |
| `driver.updateSettings()`, `appium:settings[...]` | [`mobile()`](/reference/mobile#engine) の `snapshot`、`settle`、`transition` |
| `.getAttribute('clickable')`, `.isClickable()` | 要素を操作します。アクションは要素が操作可能になるまで待ちます |
| リモートの Appium サーバー（`hostname`, `port`） | デバイスがあるマシンで e2e を実行します |
| Allure | `.e2e/junit.xml` を渡すか、`htmlReporter()` を使います |
