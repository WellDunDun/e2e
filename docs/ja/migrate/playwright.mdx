e2e は 1 つのプロジェクトで Playwright と並行して実行できるので、その間にテストを 1 ファイルずつ
移行できます。`@e2e-dev/web` は固定バージョンの `playwright-core` を同梱しているため、
`@playwright/test` のバージョンはこれまでどおり自由に選べます。e2e はデフォルトで `e2e.config.ts` を読み込み、
`tests/**/*.e2e.ts` を探すので、2 つのファイルパターンは分けておいてください。

## 設定を移植する

<Note>[クイックスタート](/quickstart) で e2e をインストールし、モデルを設定してください。</Note>

`testDir`、`baseURL`、`use`、`webServer`、`projects` などの Playwright のキーを使うと、
代わりに使うべき e2e のキーを示すメッセージとともに失敗します。
[設定リファレンス](/reference/config) にすべてのキーが載っています。

| Playwright | e2e |
| --- | --- |
| `use.baseURL`, `webServer` | ターゲットの `app: { url, command }`。[アプリの起動](/web#starting-your-app) を参照 |
| `webServer.reuseExistingServer` | `app.command: { reuseExisting: true }`。CI では無視されます |
| `projects` | `targets`。それぞれが 1 つのエンジンインスタンスです |
| `testDir`, `testMatch`, `testIgnore` | `tests`。プロジェクトルートからの glob で、先頭の `!` で除外します |
| `retries`, `workers`, `timeout` | 同じ名前で、[デフォルト値が異なります](#defaults-that-differ)。`workers` は整数です |
| `expect.timeout`, `use.actionTimeout`, `globalTimeout` | `assertionTimeout`、`actionTimeout`、`maxDuration`。`maxDuration` の計測はアプリの起動ではなくテストの開始時点から始まります |
| `maxFailures`, `use.headless: false` | CLI の `--max-failures <n>` と `--headed` |
| `reporter`, `outputDir` | `reporters: ['list', 'junit', htmlReporter()]`。`htmlReporter` は `@e2e-dev/html-reporter` から読み込みます。`json` と `markdown` も使えます。`output` のデフォルトは `.e2e` です |
| `use.viewport`, `locale`, `timezoneId`, `colorScheme`, `reducedMotion`, `userAgent`, `testIdAttribute` | `web({ ... })` の同じキー |
| `use.browserName`, `httpCredentials`, `extraHTTPHeaders` | `web({ browser, basicAuth, headers })`。`basicAuth` と `headers` はアプリのオリジンにだけ適用され、[`credentialOrigins`](/reference/web#credentialorigins) で追加できます |
| `chromium.connectOverCDP(url)` | `web({ connect: { cdpEndpoint: () => url } })`。chromium のみ |
| `use.trace`, `use.video` | `trace`、`video`。設定、ターゲット、またはテストでモードを指定します。動画のサイズは `web({ screencast: { size } })` で設定します |
| `use.permissions` | ターゲットの `app.permissions`。[ブラウザの権限の付与](/web#granting-browser-permissions) を参照 |
| `setup` プロジェクトからの `use.storageState` | `session.save(name)` を使う `test.setup` と、テストの `{ session }`。[認証](/authentication) を参照 |
| 固定値を持つ `use.storageState: { cookies }` | フィクスチャ内の `browser.setCookies(cookies)` |

## スペックを 1 つ書き直す

ウィザードやチェックアウトのように、ステップが頻繁に変わるフローから始めます。
安定している Playwright のテストはそのままで構いません。

```ts title="Playwright"
import { test, expect } from '@playwright/test';

test('checkout', async ({ page }) => {
  await page.goto('/cart');
  await page.getByRole('button', { name: 'Checkout' }).click();
  await page.getByLabel('Card number').fill('4242424242424242');
  await page.getByLabel('Expiry').fill('12/30');
  await page.getByLabel('CVC').fill('123');
  await page.getByRole('button', { name: 'Pay' }).click();
  await expect(page.getByRole('heading')).toHaveText('Order confirmed');
});
```

```ts title="e2e"
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('checkout', async ({ app, agent, screen }) => {
  await app.open('/cart');
  await agent.act('pay with the test card 4242 4242 4242 4242, expiry 12/30, CVC 123');
  await expect(screen.getByRole('heading')).toHaveText('Order confirmed');
});
```

エージェントがチェックアウトのステップを実行し、フォームが変わっても適応します。
`page.getBy*` の各行に対して `screen.getBy*` の行を書けば、テストを完全に決定論的なままにすることもできます。

## 各 API を対応付ける

どの行も現時点で動作します。ここにない API については、
[e2e にまだないもの](#what-e2e-doesnt-have-yet) を確認してください。`browser` の呼び出しは
ブラウザでのみ実行されるため、それを使うテストは `requires: ['browser']` を宣言し、
ほかのターゲットではスキップされます。

## ページオブジェクトを移植する

ページオブジェクトは、クエリとアクションのために `screen` を、キーボード、マウス、
CSS セレクター、`evaluate` のために `browser` を受け取ります。フィクスチャとして渡します。

```ts title="tests/page-models/account-page.ts"
import type { Locator, Screen } from 'e2e';
import type { Browser } from '@e2e-dev/web';

export class AccountPage {
  readonly accountName: Locator;

  constructor(
    readonly screen: Screen,
    readonly browser: Browser,
  ) {
    this.accountName = screen.getByTestId('account-name');
  }

  async filterByNote(note: string) {
    await this.screen.getByRole('button', 'Filter').click();
    await this.screen.getByRole('button', 'Note').click();
    await this.browser.keyboard.type(note);
  }
}
```

```ts title="tests/fixtures.ts"
import { test as base } from '@e2e-dev/web';
import { AccountPage } from './page-models/account-page.ts';

export const test = base.extend<{ accountPage: AccountPage }>({
  accountPage: async ({ screen, browser }, use) => {
    await use(new AccountPage(screen, browser));
  },
});
```

`browser` を読み取るフィクスチャを使うと、その `test` のすべてのテストが Web 専用になります。
[ポータブルに保つ](/page-object-model#keep-it-portable) を参照してください。フックから `newPage()` と
`page.close()` を削除してください。すべての試行は新しいコンテキストで始まります。

## e2e にまだないもの

「予定あり」はロードマップに載っているものです。「未定」は時期が決まっていないものです。「予定なし」は
意図的に含めていないものです。回避策を使うか、テストを Playwright に残してください。

## 意図的に異なる点

- 文字列はテキスト全体に、大文字と小文字を区別して一致します。Playwright の `getByRole`
  の name、`getByLabel`、`getByPlaceholder`、`getByText` は、大文字と小文字を区別しない
  部分文字列に一致します。一部分に一致させるには `{ exact: false }` または `RegExp` を渡します。
  [クエリ](/reference/screen#queries) を参照してください。

  ```ts
  // <button>Save changes</button>, <label>Email address <input></label>
  screen.getByRole('button', 'Save');                  // no match
  screen.getByRole('button', { name: 'Save', exact: false });    // matches
  screen.getByRole('button', 'save changes');          // no match, case differs
  screen.getByLabel('Email');                                    // no match
  ```
- テキストの読み取りはレンダリングされたテキストを返します。`textContent()`、`toHaveText`、
  `toContainText` は `innerText` が返す内容を読むため、非表示のテキストは除外され、
  `text-transform` が適用されます。[ロケーターの読み取り](/reference/screen#locator-reads) を参照してください。
- `toHaveRole` は `getByRole` の語彙を受け取るため、`paragraph`、`generic`、
  およびそこに含まれないほかのロールは型エラーになり、`img` は `image` として読まれます。
  比較するのはツリーが読み取るロールで、`contenteditable` のエディターは `textbox` になります。
- ロケーターは厳密です。複数の要素に一致した状態でのアクション、読み取り、肯定形のマッチャーは
  `LOCATOR_AMBIGUOUS` になります。Playwright の `page.click(selector)` と
  `isVisible()` は最初の要素を使います。`filter` または `first()` で絞り込んでください。
- `.not.toBeChecked()` はボタンや見出しに対しても成功します。コントロールはロールで
  クエリしてください。そうすれば、コントロールの種類が変わったときにアサーションが失敗します。
- セッションは 1 回の実行の間だけ有効です。`test.setup` は状態を名前付きで保存し、
  `{ session }` がそれを復元します。ファイルは暗号化され、クリーンアップ時に削除されるため、
  再利用できる `.auth/user.json` はありません。
- テストは生の `Page` を受け取りません。そこで行われる操作は記録も、シークレットの秘匿化も、
  マスキングもされないためです。`surfaceOf(engine)` は
  [カスタムエグゼキューター](/executors#driving-the-page-yourself) 用で、テストコード用ではありません。

## 異なるデフォルト値

| 設定 | Playwright | e2e |
| --- | --- | --- |
| テストのタイムアウト | 30 秒 | 120 秒、`timeout` |
| アクションのタイムアウト | なし | 30 秒、`actionTimeout` |
| expect のタイムアウト | 5 秒 | 5 秒、`assertionTimeout` |
| ナビゲーションのタイムアウト | なし | 120 秒、テストの時間枠 |
| リトライ | 0 | CI では 1、ローカルでは 0 |
| ワーカー | CPU コア数の半分 | CI では 1、ローカルでは CPU コア数の半分 |
| トレース | `off`（生成される設定では `on-first-retry`） | `retain-on-failure` |
