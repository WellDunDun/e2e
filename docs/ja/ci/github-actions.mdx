## Web

このワークフローは、決定論的テストとエージェントテストを 1 つのジョブで実行します。
アプリを起動する設定の [command](/web#starting-your-app) があり、モデルの呼び出しに
AI Gateway を使うことを前提としています。モデルキーとユーザーの認証情報はリポジトリの
シークレットから取得します。

```yaml title=".github/workflows/e2e.yml" expandable
name: e2e

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  e2e:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: pnpm/action-setup@9fd676a19091d4595eefd76e4bd31c97133911f1 # v4.2.0
      - uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        with:
          node-version: 26
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - uses: actions/cache@55cc8345863c7cc4c66a329aec7e433d2d1c52a9 # v6.1.0
        with:
          path: ~/.cache/ms-playwright
          key: playwright-${{ runner.os }}-${{ runner.arch }}-${{ hashFiles('pnpm-lock.yaml') }}

      - name: Install browsers
        run: pnpm exec e2e-web install chromium --with-deps

      - name: Run e2e
        run: npx e2e run --reporter list,junit
        env:
          APP_URL: http://127.0.0.1:3000
          AI_GATEWAY_API_KEY: ${{ secrets.AI_GATEWAY_API_KEY }}
          E2E_USER_ADMIN_USERNAME: ${{ secrets.E2E_USER_ADMIN_USERNAME }}
          E2E_USER_ADMIN_PASSWORD: ${{ secrets.E2E_USER_ADMIN_PASSWORD }}

      - name: Upload report
        if: ${{ !cancelled() }}
        uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
        with:
          name: e2e-report
          path: |
            .e2e/report.json
            .e2e/junit.xml
          if-no-files-found: warn

      - name: Upload artifacts
        if: ${{ !cancelled() }}
        uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
        with:
          name: e2e-artifacts
          path: .e2e/results
          if-no-files-found: warn
          retention-days: 7
```

`npx e2e` は、ロックファイルでインストールされたバージョンを実行します。
[インストールコマンド](/reference/web#installing-browsers) は、エンジンが固定している
Playwright バージョン用のブラウザを、そのシステムライブラリとあわせてダウンロードします。
キャッシュステップにより、ロックファイルが変わるまでダウンロードはスキップされます。
リトライで成功したテストは、失敗した試行の証拠をアップロードに残します。

## タイミング履歴をキャッシュする

[`.e2e/timings.json`](/ci#cache-the-timings-history) を `actions/cache` で復元・保存すると、
新しいランナーでも最も時間のかかるファイルから先に開始できます。
実行の前に次のステップを追加します。

```yaml
      - uses: actions/cache@55cc8345863c7cc4c66a329aec7e433d2d1c52a9 # v6.1.0
        with:
          path: .e2e/timings.json
          key: e2e-timings-${{ github.ref_name }}-${{ github.run_id }}-${{ github.run_attempt }}
          restore-keys: |
            e2e-timings-${{ github.ref_name }}-
            e2e-timings-main-
```

各実行と各再実行は新しいエントリーを保存し、そのブランチの最新のエントリーを復元します。
プルリクエストはベースブランチのキャッシュを読み取れますが、書き込むことはできません。
そのため、新しいブランチでの最初の実行は `main` の履歴から開始します。

このステップはジョブが成功した後に保存します。失敗した実行の後にも保存するには、
実行の前に `actions/cache/restore` を、実行の後に `if: ${{ !cancelled() }}` を付けた
`actions/cache/save` を使います。履歴が役立つのは [`workers`](/reference/config#workers)
が 2 以上の場合だけで、上のワークフローはワーカー 1 つで実行しています。

## iOS と Android

このワークフローはプラットフォームごとに 1 つのジョブを実行し、
[モバイルジョブ](/ci#mobile-jobs) のルールに従います。アプリを起動せずにシミュレーター用の
`.app` を書き出すビルドコマンドであれば、どれでも `xcodebuild` の代わりに使えます。Expo の場合、
`npx expo run:ios --configuration Release --device generic --no-bundler --output build/ios`
はシミュレーターなしでビルドし、`.app` を `build/ios` の下に書き出します。

```yaml title=".github/workflows/e2e-mobile.yml" expandable
name: e2e mobile

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  ios:
    runs-on: macos-26
    timeout-minutes: 60
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        with:
          node-version: 26
          cache: npm
      - run: npm ci
      - run: pod install
        working-directory: ios

      - name: Build for the simulator
        run: |
          xcodebuild -workspace ios/MyApp.xcworkspace -scheme MyApp \
            -configuration Release -sdk iphonesimulator \
            -destination 'generic/platform=iOS Simulator' \
            -derivedDataPath build
      - uses: actions/cache@55cc8345863c7cc4c66a329aec7e433d2d1c52a9 # v6.1.0
        with:
          path: ~/.agent-device/apple-runner/derived
          key: agent-device-runner-${{ runner.os }}-${{ hashFiles('package-lock.json') }}

      - name: Boot a simulator and install the app
        run: |
          UDID=$(xcrun simctl create e2e "iPhone 17" com.apple.CoreSimulator.SimRuntime.iOS-26-5)
          xcrun simctl bootstatus "$UDID" -b
          xcrun simctl install "$UDID" build/Build/Products/Release-iphonesimulator/MyApp.app

      - run: npx e2e run --target ios --reporter list,junit
        env:
          AI_GATEWAY_API_KEY: ${{ secrets.AI_GATEWAY_API_KEY }}

      - uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
        if: ${{ !cancelled() }}
        with:
          name: e2e-ios
          path: .e2e
          if-no-files-found: warn

  android:
    runs-on: ubuntu-latest
    timeout-minutes: 60
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        with:
          node-version: 26
          cache: npm
      - uses: actions/setup-java@b843ebf9b913146b38da2eaa7aeddf76074ae1ad # v6.1.0
        with:
          distribution: temurin
          java-version: 17
      - run: npm ci

      - name: Enable KVM
        run: |
          echo 'KERNEL=="kvm", GROUP="kvm", MODE="0666", OPTIONS+="static_node=kvm"' | sudo tee /etc/udev/rules.d/99-kvm4all.rules
          sudo udevadm control --reload-rules
          sudo udevadm trigger --name-match=kvm
      # React Native and Expo templates sign release builds with the debug keystore.
      - name: Build the APK
        run: cd android && ./gradlew :app:assembleRelease

      - name: Run on an emulator
        uses: reactivecircus/android-emulator-runner@a421e43855164a8197daf9d8d40fe71c6996bb0d # v2.38.0
        with:
          api-level: 36
          arch: x86_64
          target: google_apis
          profile: pixel_7
          emulator-options: -no-window -gpu swiftshader_indirect -no-snapshot -noaudio -no-boot-anim
          disable-animations: true
          script: |
            adb install -r android/app/build/outputs/apk/release/app-release.apk
            npx e2e run --target android --reporter list,junit
        env:
          AI_GATEWAY_API_KEY: ${{ secrets.AI_GATEWAY_API_KEY }}

      - uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
        if: ${{ !cancelled() }}
        with:
          name: e2e-android
          path: .e2e
          if-no-files-found: warn
```

エミュレーターランナーのアクションは、`script` の各行を新しいシェルで実行し、
ステップが終了するとエミュレーターを停止します。インストールと実行は同じステップで行ってください。

このリポジトリ自身の
[`mobile.yml`](https://github.com/e2e-inc/e2e/blob/main/.github/workflows/mobile.yml)
は、ネイティブのフィンガープリントごとにキャッシュされた Expo ビルド、2 つのワーカー用の
2 台のシミュレーター、そして `--last-failed` による再実行を追加しています。

## プルリクエストのコメント

[`@e2e-dev/github` レポーター](/github) を追加すると、各ジョブの結果を 1 つのプルリクエストコメントとして
投稿します。このコメントは再実行時に更新され、ジョブサマリーにもコピーされます。

ジョブには `pull-requests: write` が必要で、テストステップの env に `GITHUB_TOKEN` が必要です。
上のワークフローは読み取り専用です。[セットアップ](/github#setup) を参照してください。
フォークからの `pull_request` の実行には読み取り専用のトークンが渡されるため、何も投稿されません
（[理由](/github#when-nothing-is-posted)）。
