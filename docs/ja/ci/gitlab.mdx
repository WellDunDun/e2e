## Web

このジョブは、各マージリクエストとデフォルトブランチへの各プッシュで、決定論的なテストと
エージェントのテストを実行します。アプリを起動する設定の [command](/web#starting-your-app) が
あることを前提としています。プロジェクトの Node のバージョンに合った `node` イメージを
使ってください。

```yaml title=".gitlab-ci.yml" expandable
e2e:
  image: node:26
  interruptible: true
  timeout: 30 minutes
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
  variables:
    APP_URL: http://127.0.0.1:3000
    PLAYWRIGHT_BROWSERS_PATH: $CI_PROJECT_DIR/.cache/ms-playwright
  cache:
    key:
      files:
        - package-lock.json
    paths:
      - .npm/
      - .cache/ms-playwright/
  script:
    - npm ci --cache .npm --prefer-offline
    - npx @e2e-dev/web install chromium --with-deps
    - npx e2e run --reporter list,junit
  artifacts:
    when: always
    expire_in: 7 days
    paths:
      - .e2e/report.json
      - .e2e/junit.xml
      - .e2e/results/
    reports:
      junit: .e2e/junit.xml
```

ルールは `workflow:` ブロックではなくジョブに書かれているため、同じジョブが単独のパイプラインでも
[他のジョブと並べても](#add-it-to-an-existing-pipeline) 動作します。

GitLab はプロジェクト内のパスしかキャッシュしないため、`PLAYWRIGHT_BROWSERS_PATH` で
[ブラウザ](/reference/web#installing-browsers) をそこに移動します。キャッシュは
ロックファイルが変わるまでブラウザを保持します。

アプリのコマンドは、`APP_URL` が指定するホストである `127.0.0.1` で待ち受けるようにしてください。
コンテナ内では、Vite のように `localhost` で待ち受ける開発サーバーが `::1` にしかバインド
されないことがあります。その場合、e2e はアクセスできず、実行は `APP_UNREACHABLE` で失敗します。

`reports: junit` は、結果をマージリクエストのウィジェットとパイプラインの **Tests** タブに
表示します。`when: always` は、テストが失敗した場合もレポートを残します。

GitLab.com では、新しいアカウントは、ホスト型ランナーがそのジョブを受け付ける前に本人確認を
行う必要があります。それまでは、各パイプラインはジョブを開始せずに失敗します。

## 既存のパイプラインに追加する

プロジェクトに既に `.gitlab-ci.yml` がある場合は、`.gitlab/e2e.gitlab-ci.yml` のような
専用のファイルにジョブを置きます。そして `.gitlab-ci.yml` からそれをインクルードします。

```yaml title=".gitlab-ci.yml"
include:
  - local: .gitlab/e2e.gitlab-ci.yml
```

`rules` のないジョブはブランチパイプラインでのみ実行されます。そのため、マージリクエストの
パイプラインは `e2e` ジョブだけを実行し、他のジョブは引き続きプッシュごとに 1 回実行されます。

## モデルのキー

`AI_GATEWAY_API_KEY` などのモデルのキーを、**Settings > CI/CD >
Variables** で、表示設定 **Masked and hidden** を指定して追加します。または、標準入力から値を
読み取る [GitLab CLI](https://gitlab.com/gitlab-org/cli) を使います。

```bash
printf %s "$AI_GATEWAY_API_KEY" | glab variable set AI_GATEWAY_API_KEY --masked --hidden --raw
```

`E2E_USER_ADMIN_PASSWORD` などのユーザーの認証情報も同じ方法で追加します。各ジョブは
それらを環境変数として受け取ります。

- **Expand variable reference** のチェックを外してください（`--raw` がこれを行います）。
  そうしないと、GitLab は `$` やその他いくつかの文字を含むマスク対象の値を拒否します。
- GitLab がマスクするのは、8 文字以上で、1 行で、スペースを含まない値だけです。短いユーザー名など、
  マスクできない値には **Visible** を使ってください。
- テストを保護されたブランチでのみ実行するのでない限り、**Protect variable** のチェックを
  外してください。GitLab は保護された変数を、保護されたブランチとタグのパイプラインにしか
  渡しません。
- フォークからのマージリクエストはフォーク側のプロジェクトで実行され、あなたの変数は一切
  渡されません。メンバーがそれをあなたのプロジェクトで実行すると、そのコードはキーを
  読み取れます。信頼できるコードに対してのみそうしてください。

[リプレイキャッシュをコミット](/cache#commit-the-replay-cache) すると、モデルの呼び出しを
減らせます。リプレイされた `agent.act` はモデルを呼び出しませんが、各 `agent.assert` は
引き続き呼び出します。

## 影響を受けるテストだけを実行する

[テストフィルター](/filters) にマージリクエストが影響しえないテストを除外させるには、
マージリクエストのベースを `--changed-since` に渡します。ジョブの `variables` に
`GIT_DEPTH: 0` を追加して、完全な履歴を取得します。そして `npx e2e run` の行を、
マージトレインではこのフラグを省略する次の行に置き換えます。

```yaml
  script:
    # ...
    - |
      if [ -n "$CI_MERGE_REQUEST_IID" ] && [ "$CI_MERGE_REQUEST_EVENT_TYPE" != merge_train ]; then
        set -- --changed-since "${CI_MERGE_REQUEST_TARGET_BRANCH_SHA:-$CI_MERGE_REQUEST_DIFF_BASE_SHA}"
      fi
      npx e2e run --reporter list,junit "$@"
```

`CI_MERGE_REQUEST_TARGET_BRANCH_SHA` はマージ結果パイプラインで設定され、
`CI_MERGE_REQUEST_DIFF_BASE_SHA` はそれ以外で設定されます。デフォルトブランチでは
スイート全体が実行されます。
[デシジョンフィルターを追加する](/filters#add-the-decision-filter) を参照してください。

## シャーディング

`parallel` は、[シャード](/ci#sharding) ごとに 1 つのジョブを実行します。GitLab は、
すべてのシャードの JUnit レポートをマージリクエストのウィジェットにまとめて表示します。

```yaml
e2e:
  parallel: 3
  script:
    # ...
    - npx e2e run --shard $CI_NODE_INDEX/$CI_NODE_TOTAL --reporter list,junit
```

テストのないシャードは `NO_TESTS` で失敗します。実行で選ばれるテストがシャードより
少なくなりうる場合は、`--pass-with-no-tests` を追加してください。

## iOS と Android

モバイルのジョブは、shell エグゼキューターを使うセルフマネージドランナーで実行します。
iOS には Xcode を備えた Mac、Android には KVM、Gradle ビルドに必要な JDK、Android SDK を
備えた Linux が必要です。
GitLab のホスト型 macOS ランナーはヘッドレスで、XCUITest が必要とする `testmanagerd` を
サポートしていません。ホスト型 Linux ランナーには KVM が記載されていません。

これらのジョブは [モバイルのジョブ](/ci#mobile-jobs) のルールに従います。`tags` を自分の
ランナーのタグに置き換えてください。Android のジョブは、ランナー上に作成した `e2e` という
名前の AVD を起動します。

```yaml title=".gitlab-ci.yml" expandable
.e2e-mobile:
  timeout: 60m
  interruptible: true
  artifacts:
    when: always
    expire_in: 7 days
    paths:
      - .e2e/
    reports:
      junit: .e2e/junit.xml

e2e-ios:
  extends: .e2e-mobile
  tags: [macos]
  script:
    - npm ci
    - (cd ios && pod install)
    - |
      xcodebuild -workspace ios/MyApp.xcworkspace -scheme MyApp \
        -configuration Release -sdk iphonesimulator \
        -destination 'generic/platform=iOS Simulator' \
        -derivedDataPath build
    - export E2E_DEVICE=$(xcrun simctl create e2e "iPhone 17" com.apple.CoreSimulator.SimRuntime.iOS-26-5)
    - echo "$E2E_DEVICE" > .simulator-udid
    - xcrun simctl bootstatus "$E2E_DEVICE" -b
    - xcrun simctl install "$E2E_DEVICE" build/Build/Products/Release-iphonesimulator/MyApp.app
    - npx e2e run --target ios --reporter list,junit
  after_script:
    - xcrun simctl delete "$(cat .simulator-udid)"

e2e-android:
  extends: .e2e-mobile
  tags: [linux-kvm]
  script:
    - npm ci
    - (cd android && ./gradlew :app:assembleRelease)
    - mkdir -p .e2e
    - PORT=$((5554 + 2 * CI_CONCURRENT_ID))
    - export E2E_DEVICE=emulator-$PORT
    - adb -s $E2E_DEVICE emu kill || true
    - $ANDROID_HOME/emulator/emulator -avd e2e -read-only -port $PORT -no-window -no-audio -no-boot-anim -no-snapshot -gpu swiftshader_indirect > .e2e/emulator.log 2>&1 &
    - timeout 300 adb -s $E2E_DEVICE wait-for-device
    - timeout 300 sh -c 'until [ "$(adb -s $E2E_DEVICE shell getprop sys.boot_completed | tr -d "\r")" = 1 ]; do sleep 2; done'
    - adb -s $E2E_DEVICE install -r android/app/build/outputs/apk/release/app-release.apk
    - npx e2e run --target android --reporter list,junit
  after_script:
    - adb -s emulator-$((5554 + 2 * CI_CONCURRENT_ID)) emu kill
```

各ターゲットは、`mobile()` の中で `device: process.env.E2E_DEVICE` によってデバイスを指定します。
これにより、実行はこのジョブが起動したデバイスを操作し、同じマシン上の別のジョブが残した
デバイスを操作することはありません。

GitLab はすべての `script` の行を 1 つのシェルで実行するため、エミュレーターと
`E2E_DEVICE` は後続の行でも使えます。`after_script` は `script` が失敗した後も新しいシェルで
実行されますが、タイムアウトの後は実行されないため、タイムアウトしたジョブはデバイスを
動かしたままにすることがあります。Android のジョブは `CI_CONCURRENT_ID` からポートを
決めるため、1 つのランナー上で同時に実行されるジョブはそれぞれ専用のエミュレーターを持ち、
そのポートでタイムアウトしたジョブが残したエミュレーターを停止します。`-read-only` により、
1 つの AVD から複数のエミュレーターを起動できます。ジョブはエミュレーターのログを
`.e2e/emulator.log` に書き出すため、起動の失敗がアーティファクトに表示されます。
セルフマネージドランナーはジョブ間で `~/.agent-device` を保持するため、XCUITest ランナーは
最初の実行でのみビルドされます。

ランナー上でシミュレーターやエミュレーターを使わずに実行するには、
[ホスト型デバイスサービス](/mobile#hosted-devices) からデバイスをリースしてください。
