## 手動でセットアップする

まず、[Web のテストスイート](/web)と、その GitHub リポジトリに接続された Vercel プロジェクトを用意します。
以下のワークフローは npm と、コミット済みの `package-lock.json` を使います。

### デプロイの URL を設定する

デプロイをテストするには `APP_URL` を読み取ります。これがない場合、この設定はローカルのアプリを起動します。
コマンドとポートはアプリに合わせて変更してください。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';

const appUrl = process.env.APP_URL;
const bypassSecret = process.env.VERCEL_AUTOMATION_BYPASS_SECRET;

export default {
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
  targets: [
    {
      engine: web(bypassSecret ? { headers: { 'x-vercel-protection-bypass': bypassSecret } } : {}),
      app: {
        identity: 'my-app',
        environment: process.env.DEPLOYMENT_ENVIRONMENT === 'production' ? 'production' : 'test',
        ...(appUrl
          ? { url: appUrl }
          : {
              url: 'http://localhost:3000',
              command: { executable: 'npm', args: ['run', 'dev'], reuseExisting: true },
            }),
      },
    },
  ],
} satisfies E2EConfig;
```

ナビゲーションが設定した URL に従うように、テストでは `app.open('/')` を使います。

### イベントとデプロイへのアクセスを有効にする

Vercel プロジェクトの **Settings → Git** で、
[`repository_dispatch` イベント](https://vercel.com/docs/git/vercel-for-github#repository-dispatch-events)を有効にします。
**Settings → Deployment Protection** で、
[Protection Bypass for Automation](https://vercel.com/docs/deployment-protection/methods-to-bypass-deployment-protection/protection-bypass-automation)
のシークレットを作成します。設定はこれを `x-vercel-protection-bypass` ヘッダーとして送信します。

GitHub の **Settings → Secrets and variables → Actions** で、次のシークレットを追加します。

| シークレット | 用途 |
| --- | --- |
| `VERCEL_AUTOMATION_BYPASS_SECRET` | 保護されたプレビューデプロイと、まだリリースされていない本番デプロイを開くため |
| `AI_GATEWAY_API_KEY` | 上の設定でのモデル呼び出し。ロケーターだけのテストスイートでは不要です |

<Note>
このサンプルは、モデルの認証情報が設定されていない場合、明示的にエージェントのテストをスキップします。
e2e が自動でスキップすることはありません。テストスイート全体を実行するには、CI にキーを渡してください。
</Note>

### ワークフローを追加する

ビルドの後、Deployment Checks の前に発火する `vercel.deployment.ready` を使います。
テストが昇格待ちのビルドにアクセスするように、`APP_URL` にはイベントのデプロイ URL を設定します。

```yaml title=".github/workflows/e2e.yml" expandable
name: e2e

on:
  repository_dispatch:
    types: [vercel.deployment.ready]

run-name: e2e - ${{ github.event.client_payload.environment }} - ${{ github.event.client_payload.git.shortSha }}

permissions:
  contents: read
  actions: read
  statuses: write

jobs:
  e2e:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: vercel/repository-dispatch/actions/status@30f760c6640485cd92f8c785ef361382555fb712 # v1
        with:
          name: e2e - ${{ github.event.client_payload.environment }}
      - uses: vercel/repository-dispatch/actions/checkout@30f760c6640485cd92f8c785ef361382555fb712 # v1
      - uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        with:
          node-version: 24
          cache: npm
      - run: npm ci
      - uses: actions/cache@55cc8345863c7cc4c66a329aec7e433d2d1c52a9 # v6.1.0
        with:
          path: ~/.cache/ms-playwright
          key: playwright-${{ runner.os }}-${{ runner.arch }}-${{ hashFiles('package-lock.json') }}
      - run: npx e2e-web install chromium --with-deps

      - name: Run e2e against the deployment
        run: npx e2e run --reporter list,junit --video on
        env:
          APP_URL: ${{ github.event.client_payload.url }}
          DEPLOYMENT_ENVIRONMENT: ${{ github.event.client_payload.environment }}
          AI_GATEWAY_API_KEY: ${{ secrets.AI_GATEWAY_API_KEY }}
          VERCEL_AUTOMATION_BYPASS_SECRET: ${{ secrets.VERCEL_AUTOMATION_BYPASS_SECRET }}

      - name: Upload the report
        if: ${{ !cancelled() }}
        uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
        with:
          name: e2e-report-${{ github.event.client_payload.environment }}
          path: |
            .e2e/report.json
            .e2e/junit.xml
            .e2e/results
          if-no-files-found: warn
          retention-days: 7
```

Vercel の checkout アクションは、デプロイされたコミットを選択します。status アクションは、
そのコミットにジョブの結果を報告します。`e2e - preview` と `e2e - production` のステータスを分けることで、
一方の環境の結果がもう一方の結果を上書きするのを防ぎます。

<Note>
デプロイをテストする前に、ワークフローをデフォルトブランチに置いてください。
プルリクエスト上でワークフローを編集しても、Vercel がトリガーするワークフローは変わりません。
</Note>

このワークフローは、信頼できるデプロイのコードに対してだけ実行してください。このワークフローは、
リポジトリのシークレットと書き込み可能なトークンを使って、そのコミットをインストールし実行します。
[モデルの認証情報](/ci#model-credentials)を参照してください。

### 結果に応じて本番リリースを制御する

最初の本番実行の後、Vercel の
**Settings → Build and Deployment → Deployment Checks** を開きます。
**Add Checks** を選択し、**GitHub** を選んで、`e2e - production` を選択します。

以降の本番ビルドは、Vercel が本番ドメインを割り当てる前にこのチェックを待ちます。
チェックが失敗すると、以前のデプロイが公開されたままになります。
Vercel とワークフローのステータス名は同一にしてください。
[Deployment Checks](https://vercel.com/docs/deployment-checks#adding-github-checks) を参照してください。

## エージェントの記録を再利用する

CI で記録済みの `agent.act` ステップをリプレイするには、[`.e2e/cache`](/cache#commit-the-replay-cache) をコミットします。
設定で固定した `app.identity` と `test` 環境により、ローカルとプレビューの実行は
URL が異なっても記録を共有できます。本番は環境が異なるため、独自のキャッシュエントリーを使います。

CI はデフォルトで記録を読み取り、キャッシュミスの場合はモデルを呼び出します。
`agent.assert`、`agent.waitFor`、`agent.extract` は常にライブで実行されるため、
記録があってもモデルのキーは必要です。

## プルリクエストに結果を投稿する

dispatch のペイロードにはプルリクエストの番号が含まれていません。
[`@e2e-dev/github` レポーター](/github)のために、デプロイされたコミットから番号を調べます。

<Accordion title="ワークフローにプルリクエストのコメントを追加する">

レポーターの[セットアップ](/github#setup)に従って `@e2e-dev/github` をインストールし、
設定の `reporters` に `github()` を追加します。CLI の
`--reporter list,junit` を指定しても、カスタムレポーターは有効なままです。

ワークフローの権限に `pull-requests: write` を追加します。
**Run e2e against the deployment** の前に次のステップを挿入します。

```yaml
      - name: Find the pull request
        id: pull-request
        run: |
          number=$(gh api "repos/$GITHUB_REPOSITORY/commits/$SHA/pulls" \
            --jq '[.[] | select(.state == "open")][0].number // empty')
          echo "number=$number" >> "$GITHUB_OUTPUT"
        env:
          GH_TOKEN: ${{ github.token }}
          SHA: ${{ github.event.client_payload.git.sha }}
```

実行のステップを置き換えます。一時的なイベントファイルによって、レポーターはプルリクエストの番号と、
ソースへのリンクに使うデプロイされたコミットを得られます。

```yaml
      - name: Run e2e against the deployment
        run: |
          export GITHUB_SHA="$SHA"
          if [ -n "$PULL_REQUEST" ]; then
            jq -n --argjson number "$PULL_REQUEST" --arg sha "$SHA" \
              '{pull_request: {number: $number, head: {sha: $sha}}}' > "$RUNNER_TEMP/pull-request.json"
            export GITHUB_EVENT_PATH="$RUNNER_TEMP/pull-request.json"
          fi
          npx e2e run --reporter list,junit --video on
        env:
          PULL_REQUEST: ${{ steps.pull-request.outputs.number }}
          SHA: ${{ github.event.client_payload.git.sha }}
          GITHUB_TOKEN: ${{ github.token }}
          APP_URL: ${{ github.event.client_payload.url }}
          DEPLOYMENT_ENVIRONMENT: ${{ github.event.client_payload.environment }}
          AI_GATEWAY_API_KEY: ${{ secrets.AI_GATEWAY_API_KEY }}
          VERCEL_AUTOMATION_BYPASS_SECRET: ${{ secrets.VERCEL_AUTOMATION_BYPASS_SECRET }}
```

レポーターは、再実行の際に 1 つのコメントを更新し、ジョブサマリーを書き込みます。
開いているプルリクエストがない場合は、サマリーだけを書き込みます。

</Accordion>
