## テストスイート

テストスイートは、独自の `package.json` と `e2e.config.ts` を持つ専用のディレクトリ
（通常は `e2e/`）に置きます。Norrix は、アプリの依存関係を含めずにこれをインストールします。

```text
my-app/
├── app/
├── nativescript.config.ts
└── e2e/
    ├── package.json      # e2e, @e2e-dev/mobile, ai, and your provider package if not the gateway
    ├── e2e.config.ts
    └── tests/
```

```ts title="e2e/e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { gateway } from 'ai';
import { mobile } from '@e2e-dev/mobile';

export default {
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
  targets: [
    { name: 'ios', engine: mobile({ platform: 'ios' }), app: { bundleId: 'org.example.myapp' } },
    { name: 'android', engine: mobile({ platform: 'android' }), app: { bundleId: 'org.example.myapp' } },
  ],
  workers: 1,
} satisfies E2EConfig;
```

- Norrix は、各ターゲットの `app.appPath` をそのビルドに設定します。Norrix が起動した
  シミュレーターまたはエミュレーターを使うには、`mobile()` の `device` を省略してください。
- テストで確認する要素に `testID` を付け、`getByTestId` で見つけます。
  [フレームワーク別のテスト ID](/mobile#test-ids-by-framework) を参照してください。
- Norrix は、組織、プロジェクト、プラットフォームごとに、実行間で [リプレイキャッシュ](/cache) を
  保持します。CI のデフォルトは読み取り専用ですが、Norrix はキャッシュに書き込みます。
  `cache: 'off'` やカスタムの `store` を指定した設定は、独自のキャッシュを使います。

## Norrix で実行する

アプリのディレクトリから、シミュレーター向けにビルドします。

```bash
norrix build ios debug --simulator
```

`norrix build` はビルドが開始すると戻ります。`norrix build-status <id>` が `success` を
報告するまで待ってから、テストスイートを実行します。

```bash
norrix test ios --runner e2e --wait
```

Android の場合は、`norrix build android debug --emulator` でビルドし、
`norrix test android --runner e2e --wait` を実行します。`--wait` は、実行が失敗した場合、
キャンセルされた場合、またはタイムアウトした場合に 0 以外のコードで終了します。

| フラグ | 動作 |
| --- | --- |
| `--suite-dir <path>` | テストスイートのディレクトリ（`.` または `./e2e` でない場合） |
| `--target <name>` | `e2e.config.ts` の 1 つのターゲット。デフォルト: ビルドのプラットフォームのすべてのターゲット |
| `--tests`, `--grep`, `--tag` | 一部のテストファイル、タイトルが一致するテスト、またはタグの付いたテストを実行します |
| `--junit-output <dir>` | `junit.xml` をそのディレクトリにダウンロードします。`--wait` を含意します |
| `--build <id>`, `-n` | CI 向けに、プロンプトなしで 1 つのビルドをテストします |

ダッシュボードの **View Report** には、レポートと、失敗した各試行の動画が表示されます。
ビルドを待つ GitHub Actions ワークフローについては、Norrix のガイドの
[Run in CI](https://docs.norrix.net/guides/e2e-testing/#run-in-ci) を参照してください。

## モデルキー

`AI_GATEWAY_API_KEY` などのプロバイダーのキーを、Norrix の環境変数として保存します。
`agent` を一切使わないテストには不要です。

```bash
norrix env set AI_GATEWAY_API_KEY "$AI_GATEWAY_API_KEY" --project my-app
```

変数のスコープ内で実行されるすべてのテストスイートがその変数を読み取れます。`--project` を
指定しない場合、それは組織が実行するすべてのテストスイートです。そこでは信頼できるコードだけを
実行してください。[モデルの認証情報](/ci#model-credentials) を参照してください。

Norrix の環境変数は、`E2E_SECRET_<NAME>` と `E2E_USER_<NAME>_PASSWORD` を通じて、
設定の [シークレットと認証情報](/authentication) にも使われます。
