`toHaveScreenshot` は、アプリの表示内容を、テストファイルの隣に保存された PNG と比較します。
ピクセルをキャプチャするすべてのエンジンで動作するため、1 つのテストでブラウザ、
iOS シミュレーター、Android エミュレーターを確認できます。

```ts title="tests/checkout.e2e.ts"
import { test, expect } from 'e2e';

test('checkout looks right', async ({ app, screen }) => {
  await app.open('/checkout');
  await expect(screen).toHaveScreenshot('checkout.png');
  await expect(screen.getByRole('button', 'Pay')).toHaveScreenshot('pay-button.png');
});
```

`expect(screen)` は画面全体を比較します。`expect(locator)` は、一致した 1 つの要素を
スクロールして表示し、その領域を比較します。

## 保存されたスクリーンショット

スクリーンショットはテストと一緒にコミットします。最初の実行では比較対象がないため、
スクリーンショットを書き出して失敗します。画像を確認してコミットし、もう一度実行してください。

```text
tests/checkout.e2e.ts
tests/checkout.e2e.ts-snapshots/checkout-web-linux.png
tests/checkout.e2e.ts-snapshots/checkout-ios-darwin.png
tests/checkout.e2e.ts-snapshots/pay-button-web-linux.png
```

フォントやレンダリングが異なるため、ターゲットとオペレーティングシステムごとに別のファイルを保持します。
名前を指定しない場合、ファイル名はテストの名前から付けられます。
たとえば `checkout-looks-right-1-web-linux.png` です。

アプリを意図的に変更した場合は、差分のあるスクリーンショットを書き換え、足りないものを書き出します。
その後、実行は成功します。

<CodeGroup>
```bash npm
npx e2e run --update-snapshots
```

```bash pnpm
pnpm exec e2e run --update-snapshots
```

```bash bun
bunx e2e run --update-snapshots
```
</CodeGroup>

## CI での運用

スクリーンショットは、CI でそれをレンダリングするマシンで撮影します。Web と Android には
Linux のランナーを、iOS には同じシミュレーターを持つ macOS のランナーを使います。

`--update-snapshots` を指定しない場合、CI の実行がプロジェクトに書き込むことはありません。
スクリーンショットがないとテストは失敗し、実行はそれをテストの結果の
`snapshots/<path in the project>` に保存するので、ダウンロードしてコミットできます。
すべてを一度に書き出すには、テストのジョブと同様のジョブで `--update-snapshots` を実行します。

```yaml title=".github/workflows/screenshots.yml"
name: Update screenshots
on: workflow_dispatch
jobs:
  screenshots:
    runs-on: ubuntu-latest
    steps:
      # the same checkout, setup, and install steps as the test job
      - run: npx e2e run --update-snapshots
      - uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
        with:
          name: screenshots
          path: tests/**/*-snapshots/
```

アーティファクトをプロジェクトにダウンロードし、画像を確認してからコミットしてください。

## 失敗したとき

マッチャーは、一致するスクリーンショットが得られるまで、またはアサーションのタイムアウト
（`assertionTimeout`、5 秒）が終わるまでスクリーンショットを撮り続けます。一致しない場合、
失敗メッセージには異なるピクセルの数が示され、テストの結果に 3 つの画像が保存されます。
変更されたピクセルを赤で示す `-diff`、`-actual`、`-expected` です。

```text
2173 pixels (0.24% of the image) differ from tests/home.e2e.ts-snapshots/screen-web-darwin.png; run with --update-snapshots to keep this run's
diff: .e2e/results/home-1a2b3c4d5e6f7a8b/attempt-1/screenshots/screen-diff.png
actual: .e2e/results/home-1a2b3c4d5e6f7a8b/attempt-1/screenshots/screen-actual.png
expected: .e2e/results/home-1a2b3c4d5e6f7a8b/attempt-1/screenshots/screen-expected.png
```

スクリーンショットを書き出すとき、マッチャーは同じスクリーンショットが 2 回続けて得られるまで待ちます。
静止しない画面は、最後の 2 つのスクリーンショットとその差分とともに失敗します。

## 許容範囲とマスク

```ts
await expect(screen).toHaveScreenshot('dashboard.png', {
  maxDiffPixelRatio: 0.01,
  mask: [screen.getByTestId('last-updated')],
});
```

| オプション | デフォルト | 意味 |
| --- | --- | --- |
| `threshold` | `0.2` | 1 ピクセルの色がどれだけずれても同じとみなすか（0〜1） |
| `maxDiffPixels` | `0` | 異なってもよいピクセルの数 |
| `maxDiffPixelRatio` | `0` | 異なってもよいピクセルの割合（0〜1） |
| `mask` | なし | 実行ごとに変わるコンテンツのために、比較の前に塗りつぶすロケーター |
| `maskColor` | `#ff00ff` | マスクの領域の色 |
| `timeout` | `assertionTimeout` | アサーションの予算（ミリ秒） |

Web では、e2e はアニメーションを停止し、テキストのキャレットを非表示にします。iOS と Android では
ステータスバーを固定するため、時計とバッテリーの表示が毎回の実行で一致します。

e2e は、シークレットの入力後も含め、すべてのスクリーンショットでセキュアなフィールドをマスクします。
画面上のすべてのセキュアなフィールドがマスクされていることをエンジンが証明できない場合、
マッチャーは `POLICY_DENIED` で失敗します。
