`@e2e-dev/web` の `browser` フィクスチャは、リクエストのモック、ダイアログの処理、
ファイルのダウンロード、ページ内でのコードの実行を行います。エンジンは
[Playwright](https://github.com/microsoft/playwright) を通じて Chromium、Firefox、
WebKit を実行します。ナビゲーション、操作、チェックには `screen`、`app`、`expect` を
使ってください。

`browser` を使うには、`@e2e-dev/web` から `test` をインポートします:

```ts
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('the dashboard loads', async ({ app, screen, browser }) => {
  await app.open('/dashboard');
  await expect(browser).toHaveURL('/dashboard');
  await expect(browser).toHaveTitle(/Dashboard/);
  await expect(screen.getByRole('heading', 'Overview')).toBeVisible();
});
```

デバイスのターゲットを含むスイートでは、`browser` を使うテストに
`{ requires: ['browser'] }` を追加してください。ランナーはデバイス上でそのテストをスキップします。

## API をモックする

`browser.route` は、試行の残りの間、`app.restart()` やセッションの復元の後も含めて
リクエストをインターセプトします。ページが開く前に登録してください。

```ts
await browser.route('**/api/quote', async (route) => {
  await route.fulfill({ json: { cents: 4200 } });
});

await app.open('/checkout');
await expect(screen.getByText('$42.00')).toBeVisible();
```

- 各ハンドラーは `fulfill`、`continue`、`fallback`、`abort` のうち、ちょうど 1 つを
  呼び出します。
- 最も新しいルートが最初に実行されます。`continue` はリクエストをネットワークに送ります。
  `fallback` はそれより前に登録されたルートに渡します。
- ハンドラー内で失敗した `expect` は、次のステップまたはテストの終わりにテストを
  失敗させます。

`browser.waitForResponse` はリクエストの前に開始してください。これは最初の
`browser.goto` や `app.open` の前でも動作します:

```ts
const [response] = await Promise.all([
  browser.waitForResponse('**/api/orders'),
  screen.getByRole('button', 'Place order').tap(),
]);
expect(response.status).toBe(201);
```

## ダイアログを処理する

処理されない `alert`、`confirm`、`prompt` は次のステップを失敗させます。先にハンドラーを
登録してください:

```ts
const off = await browser.onDialog('accept');
await screen.getByRole('button', 'Delete').tap();
await off();
```

関数のハンドラーはダイアログを受け取り、`accept(text?)` または `dismiss()` を
呼び出す必要があります。

## ファイルをダウンロードする

```ts
import { readFile } from 'node:fs/promises';

const file = await browser.waitForDownload(() =>
  screen.getByRole('link', 'Export CSV').tap(),
);
const csv = await readFile(file.absolutePath, 'utf8');
expect(csv).toContain('Invoice');
```

e2e はファイルを `download` アーティファクトとして保存します。ファイルは
`file.absolutePath` から読んでください。これはホスト型ブラウザでも動作します。`file.path` は
プロジェクトではなく、試行のアーティファクトディレクトリからの相対パスです。

## iframe の中を操作する

`browser.frameLocator` はクエリの範囲をフレームに限定します:

```ts
const payment = browser.frameLocator('#payment-frame');
await payment.getByLabel('Card number').fill('4242424242424242');
```

フレーム内では、`locator` は CSS または XPath のセレクターを受け取り、`frameLocator` は
ネストしたフレームに入ります:

```ts
const editor = browser.frameLocator('#result');
await editor.locator('#upload').setInputFiles('fixtures/photo.png');
await expect(editor.frameLocator('#preview').getByRole('heading', 'Uploaded')).toBeVisible();
```

`browser.locator('css or xpath')` はページに対して同じことを行います。セレクターは、
ロール、ラベル、テスト ID のクエリで要素が見つからない場合にだけ使ってください。非表示の
重複要素のせいで一致が曖昧になる場合は、まず `{ visible: true }` を試してください。

エージェントのセマンティックツリーでは、ホスト型のカード入力欄のような別サイトのフレームは、
その内容を含まない `iframe` 要素として表示されます
([サイトチェック](/reference/security#site-check))。エージェントがその内容に届くのは
スクリーンショットを通じてだけです。そのフレーム内のステップには `frameLocator` を使って
ください。その内容を `agent.assert` で判定するには、[`vision`](/reference/agent#vision) を
渡してください。変化がそのフレーム内だけの `agent.act` は、
[リプレイ](/cache#when-a-recording-is-written)を記録しません。

## ページから読み取る

`browser.evaluate` はページ内で関数を実行します。e2e は関数をシリアライズするので、
関数からテストの変数は使えません。データは 2 番目の引数として渡してください:

```ts
const count = await browser.evaluate(() => document.querySelectorAll('li').length);
const flag = await browser.evaluate((name: string) => window.localStorage.getItem(name), 'featureFlags');
```

`evaluate` は、`screen` で読み取れない状態に対してだけ使ってください。

## ページより前にスクリプトを実行する

init スクリプトは、すべてのドキュメントでページ自身のスクリプトより前に実行されます。
ブラウザ API のモック、`Math.random` のシード設定、アプリが起動時に読むフラグの設定に
使います。すべてのテストに対しては:

```ts
web({ initScripts: [{ path: 'tests/init.js' }] })
```

1 つのテストに対しては、ページが開く前に:

```ts
await browser.addInitScript((value) => { Math.random = () => value; }, 0.5);
await app.open('/raffle');
```

[init スクリプト](/reference/web#init-scripts)を参照してください。

## ダークモードとモーションの軽減をエミュレートする

`colorScheme` と `reducedMotion` は、ページの `@media` ルールと `matchMedia` が読む値を、
最初の描画から設定します。すべてのテストに対しては:

```ts
web({ colorScheme: 'dark', reducedMotion: 'reduce' })
```

1 つのテストに対しては、`browser.emulateMedia` を呼び出します。ページをその値で
読み込むには、ページが開く前に呼び出してください:

```ts
await browser.emulateMedia({ reducedMotion: 'reduce' });
await app.open('/');
```

値はテストの残りの間、`app.restart()` や `app.clearState()` の後も保持されます。
[メディアのエミュレーション](/reference/web#media-emulation)を参照してください。

## Cookie

```ts
await browser.setCookies([{ url: 'http://localhost:3000', name: 'tz', value: 'UTC' }]);
```

パースできない Cookie の URL、`about:blank`、`http:` や `https:` 以外のスキームは
`POLICY_DENIED` になります。ドメイン Cookie は、送信先となるオリジンとしてチェックされます。
1 つのエントリーが拒否されると、e2e はどれも設定しません。

## ブラウザを選ぶ

ブラウザはエンジンのオプションで、デフォルトは `chromium` です。1 つのアプリに対する
2 つのブラウザは、[ターゲットごとに 1 つのサイズ](/web#one-size-per-target)と同様に、
2 つのターゲットになります:

```ts title="Target fragment"
{ name: 'webkit', engine: web({ browser: 'webkit' }), app },
```

CI では、[インストールコマンド](/reference/web#installing-browsers)で追加のブラウザを
インストールします:

<CodeGroup>
```bash npm
npx @e2e-dev/web install webkit --with-deps
```

```bash pnpm
pnpm exec e2e-web install webkit --with-deps
```

```bash bun
bunx @e2e-dev/web install webkit --with-deps
```
</CodeGroup>

`connect` は、Chromium を起動する代わりに CDP 経由でリモートの Chromium に接続します。
または、実行中の [Lightpanda](/integrations/lightpanda) や [Moli](/integrations/moli) の
ような、CDP を話す別のブラウザに接続します。サイズの設定については
[ビューポート](/web#viewports)を参照してください。

## ホスト型ブラウザ

ブラウザプロバイダーは、サービスからブラウザを借り受け、その CDP エンドポイントを
エンジンに渡します。`browser` として渡してください。エンジンは、各ブラウザのスコープが
終わると、どの終了経路でもそのブラウザを返却します。そのため、分単位で課金される
セッションは、実行がそれを使わなくなった時点で停止します。

| サービス | プロバイダー |
| --- | --- |
| [Kernel](/integrations/kernel) | `@e2e-dev/kernel` の `kernel()` |
| 自分のコンピューター上の [smol machines](/integrations/smol) の microVM | `@e2e-dev/smol` の `smol()` |
| 自分のマシン上の、オープンソースのヘッドレスブラウザ [Lightpanda](/integrations/lightpanda) | `@e2e-dev/lightpanda` の `lightpanda()` |
| オンデマンドでレイアウトとスクリーンショットを行うローカルブラウザ [Moli](/integrations/moli) | `@e2e-dev/moli` の `moli()` |
| [TestMu AI](/integrations/testmu#run-web-targets-in-browsers) | `@e2e-dev/testmu/web` の `testmuBrowsers()` |
| [E2B](/integrations/e2b#run-web-targets-in-browsers) のサンドボックス | `@e2e-dev/e2b/web` の `e2bBrowsers()` |
| その他のサービス | 独自のプロバイダー。プロジェクト内の数十行のコードです |

サービスがライブビューでウィンドウを表示する場合は、ページが
[ウィンドウいっぱいに表示される](/web#fill-the-window)ように `viewport: null` を追加してください。

プロバイダーは、エンジンが CDP 経由で Chromium として操作するブラウザ (Chromium 自体、
Lightpanda、Moli) を前提とし、`connect` と組み合わせることはできません。実行するものが
ないターゲットは何も借り受けません。

### プロバイダーを書く

プロバイダーは次のインターフェースを実装します:

```ts
export interface BrowserProvider {
  /** Label in progress lines and error messages. */
  readonly name: string;
  /** `worker` (default): one browser per worker slot for the run. `attempt`: a fresh browser per attempt. */
  readonly scope?: 'worker' | 'attempt';
  acquire(request: BrowserRequest): Promise<BrowserLease>;
  release(lease: BrowserLease, context: BrowserReleaseContext): Promise<void>;
  /** Optional: resolves CDP handshake headers from the worker's environment. */
  cdpHeaders?(lease: BrowserLease, context: BrowserRequest): Readonly<Record<string, string>> | Promise<Readonly<Record<string, string>>>;
  /** Optional: the service's own recording of the browser, in the worker, for an attempt that records video. */
  record?(lease: BrowserLease, context: ProviderRecordContext): Promise<ProviderRecording>;
  /** Optional: serves `browser.waitForDownload` for a browser on another machine. */
  readonly downloads?: BrowserProviderDownloads;
  /** Optional: releases the run's leases a dead worker left open, once the run ends; resolves to their ids. */
  sweep?(context: BrowserReleaseContext): Promise<readonly string[]>;
}

export interface BrowserProviderDownloads {
  /** Absolute directory on the browser's machine the browser saves downloads to. */
  readonly dir: string;
  /** The bytes of one finished download, `file` a path under `dir`, read off the leased browser. */
  read(lease: BrowserLease, file: string, context: BrowserDownloadContext): Promise<Uint8Array>;
}

export interface BrowserLease {
  /** The provider's handle (a session id), handed back to `release`. */
  readonly id: string;
  /** `ws://`, `wss://`, or `http://` DevTools endpoint to attach to over CDP. */
  readonly cdpEndpoint: string;
  /** Endpoint to reattach to the same browser after a transport drop; per-attempt leases only. */
  readonly reconnectEndpoint?: string;
}
```

`acquire` は、実行 ID、ターゲット、ワーカースロットとスロット数、試行ごとのリースの場合は
試行 ID、実行の環境、中止シグナル、そしてレポーターに届く `log` を受け取ります。トークンは
`process.env` ではなく `request.env` から読んでください。

リースは JSON データです。`release` は `acquire` が返したオブジェクトをそのまま受け取るので、
プロバイダーはそこに独自のフィールドを持たせられます。ワーカーに渡るのは `id`、`cdpEndpoint`、
`reconnectEndpoint` だけなので、録画など、ワーカーが使うものはすべて `lease.id` をキーにしてください。

認証付きの CDP 接続には、`cdpHeaders(lease, request)` を実装し、ワーカー内で
`request.env` から認証情報を読んでください。ヘッダーがリースの JSON で運ばれることはなく、
ページのリクエストヘッダーになることもありません。

一般的なセッション API に対して、プロバイダーは 3 つのリクエストを送ります: セッションを
作成し、DevTools エンドポイントを持つまでポーリングし、停止します。

<Accordion title="プロバイダーと設定の例">

```ts title="browser-provider.ts"
import type { BrowserProvider } from '@e2e-dev/web';

/**
 * Leases browsers from a service that starts a Chromium per session and
 * exposes its DevTools endpoint. Replace the three requests with your
 * service's API.
 */
export function hostedBrowsers(options: { serviceUrl: string; scope?: 'worker' | 'attempt' }): BrowserProvider {
  return {
    name: 'hosted-browsers',
    scope: options.scope ?? 'worker',
    async acquire(request) {
      const token = request.env['BROWSER_SERVICE_TOKEN'];
      if (token === undefined || token === '') throw new Error('BROWSER_SERVICE_TOKEN is not set');
      const headers = { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' };
      // 1. Ask for a browser; name the session after the run so it can be found later.
      const created = await fetch(`${options.serviceUrl}/sessions`, {
        method: 'POST',
        headers,
        body: JSON.stringify({
          name: `e2e ${request.runId} ${request.targetName} ${request.attemptId ?? `slot ${request.slot + 1} of ${request.slots}`}`,
        }),
        signal: request.signal,
      });
      if (!created.ok) throw new Error(`browser service: HTTP ${created.status}`);
      const { id } = (await created.json()) as { id: string };
      // 2. Wait until the session exposes its DevTools endpoint.
      for (;;) {
        const response = await fetch(`${options.serviceUrl}/sessions/${id}`, { headers, signal: request.signal });
        const session = (await response.json()) as { status: string; cdpUrl?: string; viewerUrl?: string };
        if (session.status === 'ready' && session.cdpUrl !== undefined) {
          if (session.viewerUrl !== undefined) request.log(`watch at ${session.viewerUrl}`);
          return { id, cdpEndpoint: session.cdpUrl };
        }
        if (session.status !== 'starting') throw new Error(`browser service: session ${id} is ${session.status}`);
        await new Promise((resolve) => setTimeout(resolve, 2_000));
      }
    },
    async release(lease, context) {
      // 3. Stop the session; the run waits for this within cleanupTimeout.
      const token = context.env['BROWSER_SERVICE_TOKEN'] ?? '';
      await fetch(`${options.serviceUrl}/sessions/${lease.id}/stop`, {
        method: 'POST',
        headers: { Authorization: `Bearer ${token}` },
        signal: context.signal,
      });
    },
  };
}
```

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { hostedBrowsers } from './browser-provider.ts';

export default {
  targets: [
    {
      name: 'hosted',
      engine: web({
        browser: hostedBrowsers({ serviceUrl: 'https://browsers.example.com' }),
      }),
      app: { url: 'https://staging.example.com' },
    },
  ],
  workers: 2,
} satisfies E2EConfig;
```

2 つのワーカーが 2 つのセッションを並列に借り受け、実行の間保持します。

</Accordion>

### リースのスコープを選ぶ

デフォルトの `scope: 'worker'` は、実行全体を通してワーカースロットごとに 1 つのブラウザを
保持します。`scope: 'attempt'` は、リトライを含む各試行に、それまでのテストが触れていない
新しいブラウザを与えます。その代わり、試行ごとにセッションの起動コストがかかります。ホスト型の
セッションは実行中に費用がかかるので、`workers` はスイートが使い切れる数にとどめてください。

終了したワーカー (クラッシュ、`process.exit`、kill) は、取得したものを解放できません。
`sweep` を実装すると、実行の終了時にターゲットごとに 1 回、ランナーがそれらのリースを
解放します: `sweep` はサービスのタグ、または実行とターゲットにスコープされた共有のローカルな
リースジャーナルでそれらを見つけ、レポーター向けにそれらの ID を返します。失敗した sweep は
1 行として表示され、何も失敗させません。`sweep` がない場合、そのようなブラウザはサービスが
終了させるまで存続します。

<Accordion title="ワーカースコープ: リースの開始と終了のタイミング">
- エンジンは、実行の開始時にすべてのスロットのブラウザを並列に借り受けます。
  1 つのスロットが失敗すると、どのテストよりも前に実行が終了し、成功したリースは
  解放されます。
- エンジンは、最後のワーカーが終了した後、`cleanupTimeout` 以内に、どの終了経路でも
  リースを解放します: 失敗、中断、例外を投げた `prepare` のいずれでもです。
- ワーカーのブラウザが切断されると、ワーカーは次の試行の開始時に代わりのブラウザを
  借り受け、終了時にそれを解放します。そのため `acquire` はワーカープロセス内でも
  実行されます: ランナープロセスで構築した状態に依存しないでください。
  その `log` は、ターゲットとスロットを接頭辞として付けた上で、引き続きレポーターに届きます。
- リースを取得した側が、ちょうど 1 回だけそれを解放します。
</Accordion>

<Accordion title="試行スコープ: 制限">
試行は、ブラウザの永続的なデフォルトコンテキストの最初のタブで実行されるため、
リモートブラウザにはそのコンテキストだけが含まれている必要があります。
[`connect.reconnectEndpoint`](/reference/web#recovering-a-cdp-transport) の制限が
適用されます:

- `headers`、`basicAuth`、`userAgent`、`locale`、`timezoneId` は使えません。いずれも
  `INVALID_CONFIG` になります。
- `app.clearState()` は使えません。スコープを示した `UNSUPPORTED_CAPABILITY` になります。
- セッション状態の取得や復元はできません。ターゲットで
  [セッション](/authentication)を使うテストを含む実行は、そのセットアップテストが
  サインインする前に `COLLECTION_ERROR` で失敗します。

トランスポートが切断された後、次の操作はリースの `reconnectEndpoint`、それがなければ
`cdpEndpoint` を通じて再接続し、それが同じブラウザであることを確認します。
</Accordion>

### プロバイダーでのダウンロード

`downloads` を実装すると、`browser.waitForDownload` がローカルと同じように動作します。
ホスト型ブラウザはダウンロードを自身のディスクに保存するため、ランナーはそれを開けません。
`downloads` があると、ブラウザはファイルを `dir` の下に保存し、エンジンは完了したファイルの
パスを `read` に渡します。`read` は、ワーカー内で、呼び出しのタイムアウトの範囲内で、
サービスのファイル API を通じてバイト列を取得します。[Kernel](/integrations/kernel#downloads) は
この方法でダウンロードを提供します。

`downloads` がない場合、別のマシン上のブラウザでのダウンロードは、プロバイダー名を示した
`ENGINE_FAILURE` で失敗します。ブラウザがランナーのマシン上で動くプロバイダーには、
何も必要ありません。

### プロバイダーでの録画

`record` を実装すると、サービス独自の録画を試行の動画として使えます。試行が
[動画](/reference/config#video)を録画する場合、ワーカーはページが開いた時点で、エンジンの
スクリーンキャストを開始する代わりに `record` を呼び出します。録画はタブやアドレスバーを
含むブラウザウィンドウ全体を対象にします。

`record` は `e2e/engine` の `ProviderRecording` を返します。試行が動画を収集するとき、
その `stop` は次の 2 つのうちいずれかを行います:

- 受け取ったディレクトリにファイルを書き込み、`{ file }` を返します。e2e はそれを、
  試行の他のアーティファクトと並べて `video/<file>` として保持します。
- サービスが保持する録画について `{ url, mediaType }` を返します。レポートは
  そこにリンクします。

<Accordion title="record メソッドの例">

```ts title="browser-provider.ts"
import type { ProviderRecording } from 'e2e/engine';

// In hostedBrowsers(), beside acquire and release.
async record(lease, context): Promise<ProviderRecording> {
  const headers = { Authorization: `Bearer ${context.env['BROWSER_SERVICE_TOKEN'] ?? ''}` };
  const startedAt = new Date().toISOString();
  const started = await fetch(`${options.serviceUrl}/sessions/${lease.id}/recordings`, {
    method: 'POST',
    headers,
    signal: context.signal,
  });
  if (!started.ok) throw new Error(`browser service: HTTP ${started.status}`);
  const { id } = (await started.json()) as { id: string };
  return {
    startedAt,
    async stop({ signal }) {
      const stopped = await fetch(`${options.serviceUrl}/recordings/${id}/stop`, { method: 'POST', headers, signal });
      if (!stopped.ok) throw new Error(`browser service: HTTP ${stopped.status}`);
      // The service keeps the recording; the report links to its player page.
      return { url: `${options.serviceUrl}/recordings/${id}`, mediaType: 'text/html' };
    },
  };
},
```

</Accordion>

`record` が失敗すると、プロバイダーとリースを示して試行の起動が失敗します。`stop` が
失敗すると、試行の終了時にもう 1 回実行されるため、共有ブラウザ上で録画が動き続けることは
ありません。サービスがブラウザを録画できない場合 (たとえばヘッドレスの場合) は、`record` を
省略すれば、エンジンがスクリーンキャストを録画します。[Kernel](/integrations/kernel#recordings) は
この方法で録画します。

## アイコンフォントと生成コンテンツ

スタイルシートが `::before` や `::after` で追加するテキストは、スクリーンリーダーが
読み上げるのと同様に、コントロールの名前の一部になります:
`.next::before { content: "→" }` を持つボタンは `button "→ Next"` です。`getByLabel` が
読むラベルのテキストには、生成コンテンツは決して含まれません。

アイコンフォントは例外です。Font Awesome などのフォントは各アイコンを私用領域の文字
(`\f090`) で描画し、エンジンはそれらの文字をすべての名前から取り除きます:

- `<button><i class="fa fa-sign-in"> Login</i></button>` は
  `button "Login"` になり、`getByRole('button', 'Login')` で見つかります。
- 2 つの単語の間にあるグリフはスペースとして読まれます。
- アイコンだけのコントロールは、`title` があればそれとして読まれます。ブラウザは
  依然としてグリフでそれに名前を付けるため、その title で `getByRole` を使っても何も
  見つかりません。`aria-label` を付けるか、
  `browser.locator('[title="Sign out"]')` を使ってください。
- `RegExp` の名前はグリフを含むブラウザの名前に一致するので、アンカーを付けないで
  ください: `/Login/`。

## inert なコンテンツ

エージェントは inert なコンテンツを認識しないので、入力を受け付けないコントロールを
狙うことはありません:

- `inert` 属性を持つ要素と、その配下のすべて。
- `showModal()` または `show-modal` コマンドで開かれたモーダルの `<dialog>` の外側のすべて。
  複数開いている場合は、最後に表示されたものだけが残ります。
  e2e がそれを判別できない場合は、何も除外しません。

Playwright と同様に、ロケーターは inert なコンテンツも見つけ、`toBeVisible` も成功します。

## Shadow DOM

`screen` のクエリ、スコープ、`has` フィルターは、open と closed の shadow root の中まで
届き、エージェントもその内容を認識します。`first`、`last`、`nth` は、まず closed root の
外側の一致を数え、次に各 root の一致を順番に数えます。

```ts
// The input and the button live in a closed shadow root a widget attached.
await screen.getByPlaceholder('Access code').fill('SHADOW-42');
await screen.getByRole('button', 'Submit').tap();
await expect(screen.getByText('Access granted')).toBeVisible();
```

`browser.locator`、`frameLocator`、`filter({ hasText })` は closed root で止まります。
代わりに root 内のテキストでクエリするか、`has` でフィルターしてください。HTML で宣言された
closed root (`<template shadowrootmode="closed">`) には届きません。
