セットアップテストが一度だけサインインし、名前付きのセッションを保存します。ほかのテストは
そのセッションを復元し、サインインした状態で開始します。パスワードやその他のシークレットは
ハンドルです。ランナーが値を入力し、モデルへの入力やレポートではその代わりに `<secret:name>` を表示します。
ただし、[いくつかの制限](/reference/security#where-redaction-stops)があります。

<a id="sign-in-once-in-a-setup-test" />

## 認証済みセッションを再利用する

`test.setup` の本体でセッションを保存します。`session` オプションで復元します。
ランナーは、テストに必要なセットアップを、そのテストだけを選択した場合でも実行します。

<Tabs>
  <Tab title="tests/auth.setup.e2e.ts">

```ts
import { test } from '@e2e-dev/web';
import { expect, credentials } from 'e2e';

test.setup('authenticate as admin', { sessions: ['admin'] }, async ({ app, screen, session, browser }) => {
  const admin = credentials.user('admin');

  await app.open('/login');
  await screen.getByLabel('Username').fill(admin.username);
  await screen.getByLabel('Password').fill(admin.password);
  await screen.getByRole('button', 'Sign in').tap();

  await expect(browser).toHaveURL('/dashboard');
  await expect(screen.getByRole('status', 'Greeting')).toContainText('admin');

  await session.save('admin');
});
```

  </Tab>
  <Tab title="tests/dashboard.e2e.ts">

```ts
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('the dashboard opens directly', { session: 'admin' }, async ({ app, screen, browser }) => {
  await app.open('/dashboard');

  await expect(browser).toHaveURL('/dashboard');
  await expect(screen.getByRole('status', 'Greeting')).toHaveText(
    'Welcome back, admin!',
  );
});
```

  </Tab>
</Tabs>

<Note>
`session.save()` はサインインが成功したかどうかを確認しません。保存する前に、URL または
サインイン後に表示される要素をアサートしてください。
</Note>

## セッションのルール

| ルール | 違反した場合 |
| --- | --- |
| セットアップテストはトップレベルに置き、`describe` の中には置かない | 収集エラー |
| 1 つのセッション名を宣言するセットアップはちょうど 1 つ | 収集エラー |
| `sessions` 内のすべての名前を本体で保存する | `SESSION_CONTRACT` の失敗 |
| 宣言した名前だけを保存する | `SESSION_CONTRACT` の失敗 |
| ターゲットのエンジンが状態を保存・復元できる | テストの実行前に収集エラー。試行ごとにリースされるホスト型ブラウザはこれに対応していません |

セットアップが失敗すると、ランナーはそれに依存するテストを `setup-failed` という理由でスキップします。
ほかのテストは実行を続けます。

ブラウザのターゲットでは、セッションが保持するのは Cookie、ローカルストレージ、IndexedDB で、
サーバーやデータベースの状態は含みません。復元後に開いているページはないため、各テストは
最初に `app.open()` を呼び出します。

セッションは 1 回の実行の間だけ有効です。ランナーはメモリ内にのみ保持する鍵でセッションを暗号化し、
後片付けの際に削除します。[セッション](/reference/security#sessions)を参照してください。

## 認証情報

各アカウントを設定で宣言します。パスワードは環境から読み取ります。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';

export default {
  targets: [{ engine: web(), app: { url: 'http://127.0.0.1:3000' } }],
  credentials: {
    admin: {
      username: 'admin@example.test',
      password: process.env.ADMIN_PASSWORD ?? '',
    },
  },
} satisfies E2EConfig;
```

設定の読み込み時に各パスワードが確認されます。`ADMIN_PASSWORD` が未設定であるか
6 文字未満である間は、`e2e list` を含むすべてのコマンドが `INVALID_CONFIG` で失敗します。
有効な[上書き](#override-a-value-per-run)があれば、それで置き換えられます。

<Accordion title="値を環境に置かない">

ランナーが起動するプロセスはどれも、`process.env` の文字列を読み取れます。
`password` には関数も指定できますが、`username` には指定できません。ランナーはこの関数を
許可された入力のときにだけランナープロセス内で呼び出すため、値をボールトから取得したり、
毎回新しいワンタイムコードにしたりできます。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { vault } from './support/vault.ts';

export default {
  targets: [{ engine: web(), app: { url: 'http://127.0.0.1:3000' } }],
  credentials: {
    admin: {
      username: 'admin@example.test',
      password: () => vault.read('e2e/admin-password'),
    },
  },
} satisfies E2EConfig;
```

値が秘匿化されるのは、最初に入力されたとき以降だけです。テストが入力する前にアプリがその値を
表示する可能性がある場合は、文字列を使ってください。`secrets` のエントリーにも同じことが当てはまります。

</Accordion>

## パスワードはハンドル

`credentials.user(name)` は、ユーザー名をプレーンな文字列として返し、
パスワードを `<name>.password` という名前の `Secret` として返します。`Secret` には `.value` がありません。
`fill` やエージェントステップの `params` に渡します。

```ts
await agent.act('Sign in', {
  params: { username: admin.username, password: admin.password },
});
```

モデルが見るのは、シークレットの名前と用途だけです。モデルがパスワードを入力するとき、
ランナーはパスワードフィールドであることを要求し、値を入力します。
[シークレット入力のルール](/reference/security#secret-fills)を参照してください。エージェントは
セキュアなフィールドを読み取れないため、代わりにサインインが成功したことをアサートします。

スクリーンショットではパスワードフィールドがマスクされます。アプリがそれ以外の場所に表示した値は
モデルに届きます。
[シークレット入力後のスクリーンショット](/reference/security#screenshots-after-a-secret-fill)を参照してください。

<Warning>
秘匿化は文字列の一致で行われます。キーの末尾 4 文字のように変換された値は、
表示されてしまう可能性があります。シークレットの入力はセットアップテストに留め、
送信の結果をアサートしてください。
[秘匿化が及ばない範囲](/reference/security#where-redaction-stops)を参照してください。
</Warning>

## パスワード以外のシークレット

API キー、Webhook のトークン、その他テストが入力する値には `secrets` を使います。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';

export default {
  targets: [{ engine: web(), app: { url: 'http://127.0.0.1:3000' } }],
  secrets: {
    'stripe-key': process.env.STRIPE_TEST_KEY ?? '',
    'webhook-token': process.env.WEBHOOK_TOKEN ?? '',
  },
} satisfies E2EConfig;
```

`secrets.get()` はハンドルを返します。パスワードと同じように使います。

```ts
import { secrets } from 'e2e';

await screen.getByLabel('Secret key').fill(secrets.get('stripe-key'));
await agent.act('Connect Stripe with the given key', {
  params: { apiKey: secrets.get('stripe-key') },
});
```

`secrets` のエントリーは、編集可能な任意の入力に入力できます。設定されていない名前は
`SECRET_UNAVAILABLE` を投げます。通常の入力はマスクされないため、入力に値が入っている間は
スクリーンショット（モデルに渡るものを含む）にその値が写ります。`secrets.get()` が
返すのは `secrets` のエントリーだけなので、
`credentials.admin` と `secrets.admin` は両方存在できます。

`e2e.config.ts` では、`secrets.get()` を使って、[`basicAuth`](/web#protected-previews) のような
シークレットを宣言しているエンジンオプションにシークレットを渡せます。設定の読み込み時に名前が確認されます。
スクリーンショットは有効なままなので、アプリのピクセルはマスクされません。
[エンジンオプション内のシークレット](/reference/security#secrets-in-engine-options)を参照してください。

## 実行ごとに値を上書きする

環境変数は、1 回の実行に限って設定の値を置き換えます。

| エントリー | 変数 |
| --- | --- |
| `credentials.admin.username` | `E2E_USER_ADMIN_USERNAME` |
| `credentials.admin.password` | `E2E_USER_ADMIN_PASSWORD` |
| `secrets['stripe-key']` | `E2E_SECRET_STRIPE_KEY` |

変数名にはエントリー名を大文字にしたものが入り、`A-Z` と `0-9` 以外の文字はすべて `_` になります。
`stripe-key` と `stripe_key` のように 2 つのエントリーが 1 つの変数に対応する場合、設定の読み込みは
`INVALID_CONFIG` で失敗します。

<CodeGroup>
```bash npm
E2E_USER_ADMIN_PASSWORD=... E2E_SECRET_STRIPE_KEY=sk_test_... npx e2e run
```

```bash pnpm
E2E_USER_ADMIN_PASSWORD=... E2E_SECRET_STRIPE_KEY=sk_test_... pnpm exec e2e run
```

```bash bun
E2E_USER_ADMIN_PASSWORD=... E2E_SECRET_STRIPE_KEY=sk_test_... bunx e2e run
```
</CodeGroup>

## 複数のサインイン済みユーザー

ユーザーごとに 1 つのセッションを保存します。そのうえで、同じテストを各セッションと
[エージェント](/agents)で実行します。

<Tabs>
  <Tab title="tests/personas.setup.e2e.ts">

```ts
import { test } from '@e2e-dev/web';
import { expect, credentials } from 'e2e';

const PERSONAS = ['buyer', 'admin'] as const;

test.setup('sign in each persona', { sessions: [...PERSONAS] }, async ({ app, screen, session, browser }) => {
  for (const name of PERSONAS) {
    const user = credentials.user(name);
    await app.open('/login');
    await screen.getByLabel('Username').fill(user.username);
    await screen.getByLabel('Password').fill(user.password);
    await screen.getByRole('button', 'Sign in').tap();
    await expect(browser).toHaveURL('/dashboard');
    await session.save(name);
    await app.open('/logout');
  }
});
```

  </Tab>
  <Tab title="tests/checkout.e2e.ts">

```ts
import { describe, test } from '@e2e-dev/web';

for (const persona of ['buyer', 'admin'] as const) {
  describe(`checkout as ${persona}`, { agent: persona, session: persona, tags: [persona] }, () => {
    test('pays for one item', async ({ app, agent }) => {
      await app.open('/cart');
      await agent.act('pay for the item in the cart');
      await agent.assert('the order confirmation is shown');
    });
  });
}
```

  </Tab>
</Tabs>

それぞれの名前は、`agents` のエントリー、`credentials` のエントリー、保存されたセッションを指します。
ペルソナごとに別のセッションが必要ない場合は、代わりに
[1 つのフローを複数のエージェントとして実行](/agents#one-flow-several-personas)します。
