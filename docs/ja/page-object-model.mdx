ページオブジェクトは、1 つの画面のロケーターとアクションを 1 か所にまとめます。
テストは同じクエリを繰り返す代わりに、そのメソッドを呼び出します。これはデザイン
パターンであり、どのテストフレームワークでも同じように機能します。Playwright や
Selenium でページオブジェクトを書いたことがあれば、見覚えのある形でしょう。

e2e では、ページオブジェクトは `screen` を受け取る通常の TypeScript クラスです。
フィクスチャを通してテストに渡します。

## ページオブジェクトを書く

コンストラクターは `screen` を受け取り、ロケーターを組み立てます。ロケーターは遅延
評価されるので、メソッドが使うまで何も検索されません:

```ts title="tests/pages/sign-in-page.ts"
import type { Locator, Screen, Secret } from 'e2e';

export class SignInPage {
  readonly email: Locator;
  readonly password: Locator;
  readonly submit: Locator;
  readonly error: Locator;

  constructor(readonly screen: Screen) {
    this.email = screen.getByLabel('Email');
    this.password = screen.getByLabel('Password');
    this.submit = screen.getByRole('button', 'Sign in');
    this.error = screen.getByRole('alert');
  }

  async signIn(email: string, password: string | Secret) {
    await this.email.fill(email);
    await this.password.fill(password);
    await this.submit.tap();
  }
}
```

ファイル名を `.e2e.ts` で終わらせないでください。終わらせると、ランナーがテストとして収集します。

## フィクスチャとして渡す

`test.extend` を使って、フィクスチャ内でページオブジェクトを作成します。この `test` を
インポートするすべてのテストが、`beforeEach` なしでそれを受け取ります:

```ts title="tests/fixtures.ts"
import { test as base } from 'e2e';
import { SignInPage } from './pages/sign-in-page.ts';

export const test = base.extend<{ signInPage: SignInPage }>({
  signInPage: async ({ screen }, use) => {
    await use(new SignInPage(screen));
  },
});
```

```ts title="tests/sign-in.e2e.ts"
import { expect } from 'e2e';
import { test } from './fixtures.ts';

test('rejects a wrong password', async ({ app, signInPage }) => {
  await app.open();
  await signInPage.signIn('ada@example.test', 'not-the-password');
  await expect(signInPage.error).toHaveText('Wrong email or password');
});
```

## 移植性を保つ

`screen` だけを使うページオブジェクトは、Web とモバイルのどちらのターゲットでも動きます。
`browser` (キーボード、CSS セレクター、`evaluate`) や `device` が必要な場合は、
そのプラットフォームでのみ動きます。

`browser` や `device` を読むフィクスチャがあると、その `test` 上のすべてのテストが
それを必要とします。別のターゲットでは、それらのテストは `beforeEach` で
`UNSUPPORTED_CAPABILITY` により失敗します。代わりにそこでスキップするには、それらの
テストに `requires: ['browser']` を付けるか、移植可能なテストはベースの `test` に置いてください。

## エージェントのゴールの使いどころ

メソッドは `agent` を引数として受け取り、アプリで頻繁に変わるゴールを包むことが
できます:

```ts
async addCard(agent: Agent, name: string) {
  await agent.act('add a new card named {name}', { params: { name } });
}
```

フィクスチャで `agent` を読まないでください。読むと、その `test` 上のすべてのテストが、
決定論的なテストも含めて、設定済みのモデルを必要とするようになります。

ページオブジェクトのメソッドの多くは、フローをクリックして進むためだけに存在します。
1 つの [`agent.act` のゴール](/core-concepts#goals)でそれらを置き換えられます。メソッドは、
すべてのテストが繰り返し、正確さが必要なステップのために残してください。

テストをサインイン済みの状態で始めるために、各テストで `signIn` を呼び出さないでください。
代わりにセッションを 1 回保存します。[認証](/authentication)を参照してください。
